## 模型之间的推导关系（L1129–1167，整理为一条链）

目标树 → 场景与业务链路 → 能力树 → 功能树 → 功能需求与行为规格 → 解决方案与工程设计（架构、UI、数据、接口） → 验证设计（测试矩阵、验收判据） → Spec与Task → 代码实现与实际测试 → 证据 → 验收裁决 → 真实交付。

需求树、问题模型、利益相关者模型作为前段输入及约束，业务规则、状态模型按需要参与行为规格。以上为整理关联，不是要求项目按固定单向顺序生成所有模型。出现问题应回到最早受影响环节。

## 项目结构与多维拆分（L91–105、L346、L877）

- 目标拆分：从目标到子目标。
- 水平拆分：项目 → 子系统 → 模块 → 功能 → 任务（按实际复杂程度选择层级）。
- 垂直拆分：垂直AI工作链，将某项专业工作深入为可执行步骤。
- 横向复用：跨项目可复用能力与Skill。

前两条和后两条为依据原有线索整理的含义，尚需独立验证拆分规则。原文线索文件：`AI-Native项目推进方法论-原始思考结构化整理版.md`、`AI-Native项目推进框架当前结论_v0.2.md`；当前GitHub路径未核验。

## 下一步：模型实际使用价值与拆分研究（整理建议）

按项目复杂度选择表达方式。对一个真实任务比较「只用需求树」与「按问题补充场景、状态、业务规则、证据等模型」：是否发现真实遗漏、减少实现偏差或测试不足？针对分层拆解，分别研究目标拆分、水平业务架构、垂直AI工作链、跨项目复用能力如何配合，不将模型名称和目录层级强制绑定。需要找回的两份历史文档保留在上文，不虚构路径。
