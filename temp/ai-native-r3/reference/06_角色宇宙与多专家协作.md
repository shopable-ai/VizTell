# 角色宇宙与多专家协作

> 资料性质：利益相关者分类、专业能力与协作候选机制。
> 来源：用户原始文本 `粘贴的文本 (1)(5).txt`，L343–345、L372、L510–572、L505（原文行号）。
> 整理版本 R2；新增的分类、关联、研究方案均标为「整理建议」，不视为已验证事实。

## 利益相关者库（L514–528）

| 角色类别 | 候选角色 | 主要发现的问题 |
| --- | --- | --- |
| 使用方 | 直接用户、间接用户、管理员、受益者 | 使用价值、操作困难、特殊场景 |
| 商业方 | 客户、付费者、投资人、产品所有者 | 收益、成本、商业可持续性 |
| 建设方 | 产品、设计、研发、测试、外包团队 | 实现成本、质量、交付风险 |
| 运营方 | 客服、运营、运维、维护人员 | 日常管理、故障、恢复成本 |
| 生态方 | 平台、渠道、供应商、合作伙伴、资源提供者 | 外部依赖、合作条件、资源限制 |
| 约束方 | 审核机构、监管机构、合规部门 | 权限、安全、政策与法律边界 |
| 受影响方 | 非用户、数据主体、竞争者、利益受损方 | 负面影响、利益冲突、外部风险 |

**助力方、阻力方、中立方不应该成为固定身份分类。** 它们是某个利益相关者在特定目标、特定时期下的态度。同一个平台方可能同时提供资源，又限制某些功能。

这七类是初始检查框架，并不声称覆盖所有行业。

## 专业能力库（L530–546）

| 专业领域 | 候选专家 | 核心判断 |
| --- | --- | --- |
| 用户研究 | 用户研究专家、领域专家 | 用户真正需要什么？ |
| 产品与业务 | 产品经理、业务分析师 | 应该开发哪些功能？ |
| 交互与体验 | UI、UX、无障碍专家 | 产品是否容易理解和使用？ |
| 技术与架构 | 架构师、技术选型专家 | 方案是否合理且可实现？ |
| 工程实现 | 前端、后端、浏览器扩展、数据专家 | 怎样可靠实现？ |
| 质量验证 | QA、测试架构师 | 如何发现错误并证明正确？ |
| 安全与合规 | 安全、隐私、平台审核专家 | 有哪些不可接受的风险？ |
| 商业与运营 | 商业、增长、运维专家 | 是否可持续运营？ |
| 决策质量 | 反方、事实核查、独立审计专家 | 是否存在错误假设、遗漏或过度设计？ |

专业能力是可以组合、扩展和复用的，不必为每一种能力创建一个永久运行的 Agent。

例如，修改浏览器扩展侧边栏的按钮间距，通常没有必要调用商业专家、后端专家或监管专家。

## 多专家协作的五项能力（L550–572）

| 协作机制 | 价值 |
| --- | --- |
| 多视角发现 | 避免需求遗漏 |
| 独立判断 | 避免思维污染与盲目认同 |
| 对抗与质疑 | 主动发现错误、反例和盲区 |
| 权衡与决策 | 处理利益及方案冲突 |
| 独立验证 | 用证据判断结论是否成立 |

利益相关者是研究对象；专业角色提供分析视角、专业能力和责任；Agent是实际执行者。助力方、阻力方、中立方是相对于特定目标的关系状态，不是固定角色。候选协作机制需要真实独立Agent验证，不能把同一模型模拟多角色视为已经完成独立验证。

## 后续独立研究（整理建议）

1. 利益相关者：在具体项目目标下识别真实利益、诉求、权限、影响；同一角色在不同目标下可能是助力方或阻力方。
2. 专家能力：按任务类型与专业未知项选择必要角色，而非每次调用全部专家。
3. 协作：固定同一任务，对照单模型、同模型模拟多角色、独立Agent。分别观察有效遗漏、分歧、证据、决策质量和执行成本。

输出角色选择依据、独立判断记录、关键分歧及裁决证据。原文称已有合成验证，但不能因此认定真实独立Agent协作已验证。
