**定位：** 研究从什么输入经过哪些有意义的关系或活动到达什么输出，以及不同链路怎样相互衔接。当前研究的是链路结构而非执行具体任务。原15条专项链路及既有 R3-B 的关系分类保留；不重复建立工作流 I。

## 1. 三层链路地图
- L0：研发总体价值链（从想法到业务价值）：意图/问题 → 需求与业务 → 方案与设计 → 实现 → 验证 → 交付与运营 → 反馈；允许反复、回退、裁剪。
- L1：专项链路族（下表）。各链有独立职责，可嵌入不同阶段。
- L2：某条链内部节点及分支。例如目标推理内有意图澄清、问题界定、价值与成功条件；不把每节点当新的一级流程。

箭头必须有语义：推导、分解、约束、引用、分配、实现、验证、真实运行/状态迁移、决策、反馈。需求 → 测试是验证关系，不是执行顺序；目标 → 需求是带前提的推导，不是因果已证。

## 3. 原15条之外缺少的跨链关联（候选）
这些是需要明确建模的通用关系，不是第16至20个必须走的工作流。
1. 事实与知识恢复：来源→身份/版本/适用范围→当前基线→未知/冲突；支撑全部链路。研究链负责新知识，恢复链避免重复。
2. 变更影响链：变更意图→受影响目标/行为/依赖→差量范围→受影响证据→回归。并非所有变更重新从用户需求开始。
3. 复用与集成链：必要能力→现有能力查找→缺口/兼容/替代→复用或建设→集成；阻断条件为关键契约不满足。
4. 质量风险追溯链：不接受的后果→危险条件/原因→控制约束→检测/恢复→验证；由 H 的审计方法产生内容，B只管理衔接。
5. 证据有效性链：主张→适用判据→证据来源/对象版本→支持或反驳→裁决→变更后重新核验。证据不等于结论。
6. 权限与责任链：目标/任务→有权主体→授权范围→操作→可审计回执→责任；与 L 的执行治理联动。不是默认增加审批。

## 4. 关键衔接与回退
| 上游输出 | 下游消费 | 缺口处理 |
|---|---|---|
| 原始意图、目标、非目标 | C 需求推理、M价值 | 目标冲突先决策 |
| 场景、规则、必要行为 | D模型、产品/技术设计、H | 未知规则回需求或研究 |
| 已选择方案、设计约束 | E任务拆分、I编排 | 方案不可行回决策 |
| 需求/设计及事前验收判据 | 实现、测试、独立验收 | 无可测判据则补规格 |
| 版本化代码/构建/运行结果 | 验证及交付 | 不同候选或证据不符需核验 |
| 验收裁决、缺陷、运营反馈 | C、E、I、K | 回最早实际受影响的知识或执行节点 |
节点可以并行探索、复用当前有效事实，低风险任务可缩短；不存在固定的“十五轮”执行。验证发现问题时，根据失效的关系回到目标、需求、设计、实现、测试或环境，不默认整体重做。

## 6. F2：链路的边类型和选择规则

| 边类型 | 语义 | 成立条件与反例 |
|---|---|---|
| 逻辑推导 | 前提支持结论 | 保留前提；仅有相关性不等于必然 |
| 目标分解 | 子目标组合满足上位目标 | 区分 AND、OR、其他组合；完成一个 OR 分支不要求其他分支完成 |
| 约束 | 限制对象、结果或可行空间 | 不假设条件与时间先后相同 |
| 行为转换 | 事件使状态转换 | 初始状态、触发、守卫、结果；禁止从观察顺序推断因果 |
| 依赖/消费 | 后项需要前项的有效产物 | 已存在但版本失效的产物不能满足依赖 |
| 控制流 | 选择并触发活动 | 由 I 管；不将知识关系误作任务顺序 |
| 证据关联 | 证据支持或反驳主张 | 证据必须与主张、适用条件、对象版本相符 |
| 反馈/失效 | 变化使既有知识需要复核 | 影响沿实际关系传播；不全盘废弃，也不忽略跨链影响 |

每条专项链的最小结构：问题、输入与假设、节点/关系类型、期望输出、条件分支、终止及返工位置。链路是可组合图，不限线性箭头。

**选择：** 目标不清走目标/需求推导；行为不清走场景/业务/状态；候选不明走研究与方案；交付不可执行走任务依赖；主张不可信走验证与证据；变更后先定位失效节点并只恢复受影响路径。共享节点应引用而非复制。抽象反例：需求 R 有实现 A 或 B，若链写成 R→A→B，就把备选方案误成串行依赖。停止于所需输出明确且没有悬空高影响依赖，未证前提显式保留。

本节为F2通用结构推导和概念反例，未进行具体应用；重要分类和完整专业知识仍须独立核验。

### 关系代数与反例（理论推演）

1. AND细化须满足全部必要子条件，OR细化是存在可行备选；两者不能用相同「→」替代。某条件 R 与领域假设 D 共同推出目标 G，边的语义为 {D,R}→G；逐条改写成 D→G、R→G 会制造虚假结论。用集合/合取前提表达联合依赖，不强制图工具。
2. 由 G 向上游追溯 R 是图遍历，不是逻辑逆蕴含；「R实现G」和「G要求R」是不同的主张。需要C的必要性判定，不能看到可达路径就认为需求覆盖。
3. 一个节点可同时由多个链消费。共享的是同一语义对象及版本，不是文本副本；每条链保留自己所需的前提和结论义务。边类型不同不默认可传递：任务先于交付不等于任务验证了交付。
4. 过程反馈环允许跨时刻迭代；逻辑证明若仅由自身循环支持，不产生独立证据；硬执行先后环需拆出初始化或联合活动（E/I）；业务状态环是正常行为。不能统一要求所有图无环。
5. 变化传播按边语义：前提失效→依赖结论待复核；兼容的替代证据可能保住结论；仅引用/浏览不必然改变结论。记录受影响主张和不变条件，而非把整条链标为失败。

与其他专题：A给输入因素，C/G给推理语义，D表达对象，E拆分，I选择实际控制流，K保存版本与证据，H审核主张。未解决的是行业专有链、复杂并发时间模型及各类链的完备性边界；上述不是运行协议。来源：reference/03与原文865–886，结合既有B语义分类；NASA系统设计的公开过程参照已在F1列出。

## R1.1 裁决：链路的关系语义、分支与时间

**结论：** 保留15链及三层地图；链路不是任意箭头集合，更不是控制流。原R1“AND细化须满足全部必要子条件”的措辞须限定：AND说明该细化方案以全部子项为联合条件，不保证每项对原始父目标在所有方案中都必要；OR表达候选析取，不保证备选完备或可实现（见C）。

| 边 | 可以推出什么 | 不可以推出什么 |
|---|---|---|
| 逻辑蕴含 | 同一有效上下文内可传递；多前提保留合取/析取 | 逆蕴含、存在可实现方案 |
| 分解/细化 | 子项联合满足父项须有论证；组成关系与义务分配另述 | 子项独立必要、执行顺序 |
| 先于/依赖 | 严格事件先于可传递；活动所需条件明确 | 先发生就是原因、无边就是无共享资源 |
| 控制/事件触发 | 守卫、状态和实际激活决定活动 | 知识引用就应执行 |
| 证据/追溯 | 可定位来源、检查主张与版本 | 路径越长越真实；支持关系默认传递 |
| 因果/反馈 | 在机制及假设明确时预测干预或状态演化 | 时间先后或观察关联足以确认根因 |

**时序语义：** 对真实事件实例，可用进程内顺序与通信关系形成偏序；两个事件无法由该偏序比较，不等于物理上同时、资源独立或允许同时执行。时间戳全序可作排序，但不是因果证明。连续性、持续时间、截止时间与时钟误差须独立建模。Lamport 1978 的论文摘要（https://doi.org/10.1145/359545.359563，机构公开摘要 https://apice.unibo.it/bin/view/Publication/LamportAcmcomm21）支持偏序区分；不把其通信因果关系等同于G的结构因果识别。

**分支与反馈：** 区分恰选一个、可选多个、全部执行。汇合等待实际激活且有义务完成的分支；不能在排他分支后无条件等待两支。抽象反例：起点只激活A或B，汇合却要求A∧B完成，存在合法路径永远无法通过。循环应区分状态循环、跨时刻反馈与同一时刻互为前置；对反馈说明反馈信息、延迟、停止条件和约束，不从“循环存在”推出必然收敛。对循环证据依赖不得自证。

**回退四类：** 撤销/修订知识主张（K）、重开决策（C/F）、重新开展受影响活动（I）、恢复可恢复状态或采取补偿（L）。已发生的外部事件不会因回退流程而消失。变更沿边的语义传播；合取支持丢一项需复核，析取存在独立有效支持可能保留结论。验收旧版本有效不等于新版本有效，未受影响义务不必重新推导。

依据：R2 03、原文L865–886、Lamport摘要；分支及回退规则为本轮抽象推演。15链的具体运行仍属延期范围，不建设流程引擎。
