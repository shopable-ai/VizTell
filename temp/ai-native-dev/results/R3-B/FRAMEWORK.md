# 链路宇宙 · 总体框架 F1

**定位：** 研究从什么输入经过哪些有意义的关系或活动到达什么输出，以及不同链路怎样相互衔接。当前研究的是链路结构而非执行具体任务。原15条专项链路及既有 R3-B 的关系分类保留；不重复建立工作流 I。

## 1. 三层链路地图
- L0：研发总体价值链（从想法到业务价值）：意图/问题 → 需求与业务 → 方案与设计 → 实现 → 验证 → 交付与运营 → 反馈；允许反复、回退、裁剪。
- L1：专项链路族（下表）。各链有独立职责，可嵌入不同阶段。
- L2：某条链内部节点及分支。例如目标推理内有意图澄清、问题界定、价值与成功条件；不把每节点当新的一级流程。

箭头必须有语义：推导、分解、约束、引用、分配、实现、验证、真实运行/状态迁移、决策、反馈。需求 → 测试是验证关系，不是执行顺序；目标 → 需求是带前提的推导，不是因果已证。

## 3. 原15条之外缺少的跨链关联（候选）
这些是需要明确建模的通用关系，不是第16至20个必须走的工作流。
1. 事实与知识恢复：来源→身份/版本/适用范围→当前基线→未知/冲突；支撑全部链路。研究链负责新知识，恢复链避免重复。
2. 变更影响链：变更意图→受影响目标/行为/依赖→差量范围→受影响证据→回归。并非所有变更重新从用户需求开始。
3. 复用与集成链：必要能力→现有能力查找→缺口/兼容/替代→复用或建设→集成；阻断条件为关键契约不满足。
4. 质量风险追溯链：不接受的后果→危险条件/原因→控制约束→检测/恢复→验证；由 H 的审计方法产生内容，B只管理衔接。
5. 证据有效性链：主张→适用判据→证据来源/对象版本→支持或反驳→裁决→变更后重新核验。证据不等于结论。
6. 权限与责任链：目标/任务→有权主体→授权范围→操作→可审计回执→责任；与 L 的执行治理联动。不是默认增加审批。

## 4. 关键衔接与回退
| 上游输出 | 下游消费 | 缺口处理 |
|---|---|---|
| 原始意图、目标、非目标 | C 需求推理、M价值 | 目标冲突先决策 |
| 场景、规则、必要行为 | D模型、产品/技术设计、H | 未知规则回需求或研究 |
| 已选择方案、设计约束 | E任务拆分、I编排 | 方案不可行回决策 |
| 需求/设计及事前验收判据 | 实现、测试、独立验收 | 无可测判据则补规格 |
| 版本化代码/构建/运行结果 | 验证及交付 | 不同候选或证据不符需核验 |
| 验收裁决、缺陷、运营反馈 | C、E、I、K | 回最早实际受影响的知识或执行节点 |
节点可以并行探索、复用当前有效事实，低风险任务可缩短；不存在固定的“十五轮”执行。验证发现问题时，根据失效的关系回到目标、需求、设计、实现、测试或环境，不默认整体重做。
