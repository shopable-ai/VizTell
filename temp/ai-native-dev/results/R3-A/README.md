# R3-A 因素宇宙：从因素目录到可验证的影响机制

任务 AI-NATIVE-RESEARCH-R3-A。原始目标：让 AI 从不完整想法、功能变更或缺陷出发，发现必要需求和遗漏，实际设计、实现、测试和验收。A 只回答研发需要考虑什么、何时需要考虑及因素怎样影响结果，不接管需求算法 C、审计 H、角色 F、链路 B 或推理 G。

## 1. 结论及总体框架（候选，本轮推断）
R2 的12领域适合作为阅读导航，不是严格互斥的同层本体。真正的使用单位不是名词而是 **一个有上下文的变量及其可观察影响**。例如「时间」不能直接产生需求；「确认延迟>发送超时」可以引出重复发送风险及禁止无证据重试的条件。
- 六类阅读视图（允许交叉），不作为强制数据库 schema：
| 领域 | 二级因素 |
|---|---|
| 目标与价值 | 问题、预期结果、优先级、商业收益、成本收益、冲突目标、用户可观察成功 |
| 主体与对象 | 使用者、购买者、维护者、系统主体、所有权、权限/授权范围、数据实体与身份 |
| 场景与行为 | 任务、触发、前置条件、输入、动作、业务规则、结果、正常/异常/恢复、交互区域与输入所有权 |
| 环境与变化 | 时间/顺序/延迟/并发、空间/视口/区域、平台/设备/版本/语言、网络、生命周期、迁移、外部变化 |
| 实现与约束 | 既有能力、架构边界、API/协议、数据存储、一致性、依赖可靠性、资源预算、法律/平台政策、权限上限 |
| 质量与后果 | 正确性、安全、隐私、可用性、无障碍、性能、可靠性、兼容性、可维护性、可恢复性、损失/风险严重度 |
- 正交证据标签：用户陈述、直接事实、候选假设、推断、桌面分析、可复现机制实验、目标环境验收；附版本和适用条件。质量目标、限制和风险也可以附着在任何对象上，不强行互斥。
- 最小因素记录（只在能改变判断时记录）：对象、变量、取值/范围、适用上下文、改变的行为或约束、受影响需求/测试、来源和未知。不建无用因素卡片。 
- 关系语义：限制、触发、依赖、互斥、放大/抑制风险、改变可见结果。共现不是因果。把“相关”升级为“原因”需要额外证据。
- 适用性：新功能从成功目标、角色、对象、场景开始；缺陷从现象、版本、当前行为、条件差异开始；集成/权限从身份、依赖和失败恢复开始。只有会改变决策/验收的因素进入深挖。无关市场因素在滚动条局部修复中跳过；支付、跨账户、不可逆动作提升安全和权限的优先级。

## 2. R2逐项处置（非删除历史资料）
| R2领域 | 处置及理由 |
|---|---|
| 目标与价值 | 保留；明确可观察成功和冲突目标 |
| 用户与角色 | 保留于主体对象；权限是关系/条件 |
| 市场与商业 | 并入目标价值和资源约束视图；专项 M 负责详细研究 |
| 业务与场景 | 保留于行为；加前后状态、触发、恢复 |
| 产品与交互 | 合入场景行为并关联质量；UI 不是所有项目都有 |
| 数据与状态 | 数据身份与归属在对象，状态转换在行为，一致性在约束 |
| 技术与架构 | 保留于实现约束，已有能力优先，避免重复研发 |
| 时间与空间 | 保留并展开为变化变量；不是仅限时空，扩展到平台、版本 |
| 资源与能力 | 作为实现约束，区别可用资源与系统必要能力 |
| 风险与质量 | 作为后果/目标；风险需事件、条件和损失，不只是分类 |
| 证据与不确定性 | 改为正交认识状态；避免把证据当业务因素 |
| 生命周期与演化 | 作为环境变化和阶段性行为，不复制生命周期链 |
R2 16研究维度继续独立导航：角色/场景/需求/约束/商业/生命周期属于对象和问题；推理/决策属于方法；工作流/Skill/工具属于执行；质量/证据/风险/资产/AI治理属于评价与治理。保留多对多链接，不把它们当六领域的直接子项或新增16个强制步骤。

## 3. 高价值深挖：状态×时间×环境×权限×依赖
例如浏览器浮层：目标=不干扰页面正常滚动；对象=原生或网页自定义滚动容器、目录按钮；变量=滚动区域宽度、位置、视口、折叠/展开/hover、输入命中、拖动起止与捕获。因果候选：区域交叠×接收事件→错误命中→拖动不成立。输出不是“做兼容性”，而是“保持有效拖动区域独立，目录按钮仍可使用；按下目标正确且拖动后 scrollTop 改变”。非同一机制的反例：鼠标已按中滑块、拖动中因捕获丢失而停止；仅移按钮不能保证解决。依赖是站点滚动实现与浏览器/OS；权限是允许操作自身浮层而非强行改变页面事件或禁用系统滚动条。
优先验证单因素（位置、事件命中），再组合宽度与状态、位置与视口，保留高风险的三因素组合。NIST t-way 是缩小试验规模的手段，不保证遗漏为零，实际高风险交互和不可能组合要专门处理。SEI QAW 把业务驱动和真实场景关联，并不是给任何项目穷举因素。

## 4. 实际价值及裁剪
固定输入：「阅读目录右侧收起按钮疑似与滚动条重叠、拖动偶发失败；左移或预留空间？」固定源码版本见 evidence.md。
对照为同一模型桌面构造的直接方案（移动按钮/固定预留/普通拖动）与因素辅助方案（查看当前实现、区分原生/自定义/overlay、状态与实际 hit target、宽度边界及按钮可用性）。并非独立盲评。以是否提出不同可测行为、避免重复实现、是否区分真实根因和假设评估。现有代码已留 28px 并随宽度调整；重新无条件添加 28px 属重复。新增受控浏览器实验显示 24px 区域下 28px 足够，但32px 区域下不够；禁用干扰元素命中可恢复模拟滚动，但会破坏目录按钮，否决为直接产品方案。源码有几何测试但不等价于真实命中测试。
仅当因素导致新判据或新风险时扩展；诸如枚举国家、付费模型、完整组织角色，在此局部缺陷没有价值。新增候选风险需要真实目标环境确认，不能宣布缺陷已修复。
 
## 5. 可复用输出及未解决项
输出给 C：具体条件→行为→候选必要需求；给 H：高影响交互及缺证条件；给 F：主体/权限/责任边界；不重复定义这些专题。
未知：不同浏览器/OS/缩放/RTL/站点容器实测，28px 的合理阈值，输入拦截与 capture 的实际根因，目录状态与宽度组合的最小测试集，多任务盲测的增益与成本。下一步优先以真实已安装候选及安全测试页验证命中/滚动/按钮可用性，再用第二种功能任务评估六类视图是否有遗漏和负担。
