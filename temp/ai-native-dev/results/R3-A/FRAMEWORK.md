# 因素宇宙 · 总体框架与分层目录 F1

**定位：** 研发中需要认识、分析、考虑哪些因素？当前阶段是建立通用因素地图，非具体产品设计。R2 的12领域、16研究维度及此前 R3-A 的六类视图均保留为线索。以下为本轮推导的候选框架，不是已经证实穷尽的本体。

## 1. 必须先区分三种东西

| 对象 | 含义 | 例 |
|---|---|---|
| 研究领域 | 一个可长期补充知识的主题目录 | 数据、技术、市场 |
| 因素 | 对目标、需求、行为、决策或验收有影响的变量/条件/关系 | 数据所有权、响应时限、依赖可用性 |
| 观察属性 | 对任意因素进行描述和评价的维度 | 取值、范围、来源、可信度、变化速度、影响程度 |

同一领域可以有多个对象；同一因素可关联多个领域。不要把对象、因素的取值、风险后果、证据及研究方法列为互斥同级实体。此前六类是快速阅读压缩视图，不取代以下十二类完整入口。证据虽然是正交认识属性，但作为研究/质量领域仍应有独立入口。

## 2. 一级、二级、三级候选目录

下表每行一级领域；分号分隔二级组；括号内是三级因素族。它们是可继续细化的阅读地图，而非固定表单。

| 一级领域（沿用R2） | 二级分支及三级因素 |
|---|---|
| A01 目标与价值 | 意图（原话、现状、期望、非目标）；问题（痛点、频率、损失、机会）；结果（成功条件、衡量指标、受益人）；优先级（紧迫性、价值、风险、相互冲突）；范围（业务边界、系统边界、时间范围） |
| A02 用户与角色 | 主体（个人、组织、系统、第三方）；利益（使用、付费、受益、受损）；权限（所有权、授权、委托、撤销）；能力（知识、技能、可达性、语言）；关系（协作、冲突、依赖、信任、责任） |
| A03 市场与商业 | 需求环境（细分、替代、竞争、趋势）；交易（购买者、价格、付费模式、支付与退款）；成本（研发、运行、获客、支持）；分发（渠道、平台、合作）；价值反馈（转化、留存、满意、收益）；外部性（合规、品牌、社会影响） |
| A04 业务与场景 | 对象与业务词汇（实体、关系、业务边界）；场景（角色、目标、触发、前置、结束、频率）；行为（动作、事件、顺序、分支、循环、并发）；规则（资格、决策、计算、约束、不变量）；异常（拒绝、中断、重复、恢复、人工介入）；跨主体流程（交接、责任、结果） |
| A05 产品与交互 | 功能（能力覆盖、入口、配置、默认）；信息（层级、导航、反馈、可发现性）；操作（输入、触控、键盘、批量、撤销）；体验（理解成本、认知负担、效率、可达性）；一致性（跨端、跨页面、可预期性）；适配（终端、语言、不同用户能力） |
| A06 数据与状态 | 数据语义（类型、身份、主键、关系、来源）；生命周期（生成、读取、更新、删除、保留、导出、迁移）；状态（初始、处理中、成功、失败、未知、终止）；一致性（事务、并发、冲突、幂等、版本）；安全（分类、敏感、访问、审计）；质量（完整性、准确性、新鲜度、缺失） |
| A07 技术与架构 | 既有能力（资产、接口、可复用组件、技术债）；结构（系统边界、模块、职责、耦合）；接口（协议、契约、身份、错误、版本）；基础设施（运行时、网络、存储、部署）；工程实现（语言、构建、依赖、配置、测试）；集成（供应链、外部服务、兼容、替代、故障隔离） |
| A08 时间与空间 | 时间（顺序、周期、延迟、超时、期限、时区）；并发（竞态、同步、重复、事件交错）；空间（位置、尺寸、地域、视口、物理环境）；运行上下文（设备、OS、浏览器、版本、网络、在线/离线）；规模变化（负载、数量、容量、跨域） |
| A09 资源与能力 | 人力（时间、专业、责任、可用性）；AI（模型能力、上下文、工具权限、成本）；工具（可获得性、版本、可靠性）；资金（预算、成本上限、资源分配）；知识（已有事实、缺失知识、获取成本）；基础设施资源（算力、存储、带宽、运行限制） |
| A10 风险与质量 | 正确性（业务规则、完整、精确）；体验（可用性、可访问性）；性能（时延、吞吐、资源）；可靠性（可用性、容错、恢复、数据安全）；安全隐私（威胁、访问、泄露、滥用、合规）；可维护性（可测试、可观测、可修改、兼容、可移植）；后果（影响对象、严重度、发生条件、可逆性、剩余风险） |
| A11 证据与不确定性 | 信息来源（用户、文档、代码、运行、研究）；认知状态（事实、陈述、假设、推断、未知、冲突）；证据质量（来源、版本、可信、覆盖、环境、可复核性）；决策风险（对未知的敏感度、补证成本）；验收状态（未验证、局部验证、反例、通过、失效） |
| A12 生命周期与演化 | 产品阶段（发现、建设、发布、使用、退役）；变更（新增、修复、重构、迁移、兼容）；运营（监控、支持、反馈、事故、恢复）；维护（版本、依赖更新、技术债、数据保留）；知识（沉淀、复用、纠正、淘汰）；退出（停止服务、移交、清理、替代） |

明确补强的内容：配置和版本管理、发布及运营、安全及供应链、维护、专业实践与基础知识。这些不是新增一套相互重复的分类，而是对原领域展开。IEEE SWEBOK V4 的专业知识目录用于横向查漏（见 O 的知识交叉表），不是因素宇宙本身。

## 3. 正交的因素结构

对需要研究的任一因素，可采用「归属对象—影响变量—可能取值/状态—适用上下文—关系—影响结果—证据」表达。
- 关系：属于、影响、限制、触发、依赖、冲突、替代、放大/减弱、随时间变化。因果边须与相关边区别。
- 影响对象：目标、需求、行为、设计、任务、质量、成本、验收。
- 取值维度：离散/连续、单值/集合、已知/未知、稳定/变化、可控/外部。边界、典型值、异常值、非法组合不是新的一级领域。
- 适用范围：全局、业务域、功能、组件、场景、某次执行。范围不应被树目录硬编码。
- 例（抽象，不是实际项目实验）：外部依赖可用性 × 调用时序 × 数据是否可恢复 → 候选中断/重复风险 → 需求/约束 → 验收判据。它们之间需要论证，不可自动推断某实现唯一。

## 4. 与其他专题的边界
A 维护因素与取值；F 维护角色及职责；D 维护表达对象的模型；C 由因素和目标推出候选需求；G 维护推理方式；H 用因素索引审计；B 维护衔接路径；M 深研商业。16研究维度原名通过 O 的索引追踪，不要求16个一级因素。

## 6. F2：因素的正交分类与筛选

一级领域负责检索；因素的语义类型负责推理。对任一关注项按下列类型标记（允许一项涉及多个类型，但分开陈述）。
| 类型 | 要回答的问题 | 应有的关系 |
|---|---|---|
| 对象或主体 | 是什么、谁 | 身份、边界、组成、参与 |
| 属性与取值 | 有什么性质、值如何变化 | 归属、域、单位、状态空间 |
| 事件与行为 | 发生什么变化 | 触发、顺序、状态迁移、影响 |
| 条件与环境 | 在什么情况下成立 | 前置、例外、适用范围 |
| 约束 | 哪些结果或方案不可接受 | 限制、冲突、满足 |
| 目标与评价 | 为什么需要、怎样评价 | 价值、优先级、指标 |
| 不确定性 | 还不知道什么、证据程度如何 | 假设、支持、反驳、失效 |

不能把数值属性与约束本身等同：某属性取值为 x 是描述；要求其不超出阈值是规范。目标希望其更优是偏好，三者不可合并。也不能把风险当成必然结果。风险关系至少区分条件、可能事件、影响和不确定性；H 用其选择审查方法。

**按需展开规则：** 先确定目标与范围→关联主体和业务对象→识别可能影响目标的条件及约束→只展开会改变需求、模型、方案、风险或证据的因素→为未知因素标明影响和调查条件。低影响且不改变任何决策的分支不展开；跨边界影响由B/E记录；高影响未知保留而不是假定不存在。

**反例：** 若 A、B 都不直接改变结果，但 A∧B 才使结果失效，只做逐项因素检查会遗漏组合。先检查已知相互作用和高后果组合；不穷举全部笛卡尔积。若某因素属于两个领域，引用同一语义而不是复制两份事实。
**停止条件：** 当前目标的高影响因素、组合、适用域及未知已可定位；新增因素无法改变当前决策、只能提供重复名称时停止。完整性是相对于目标和假设，不能宣称绝对穷尽。

本节为F2通用结构推导和概念反例，未进行具体应用；重要分类和完整专业知识仍须独立核验。


## R1 深化：因素从目录到有界的发现空间（2026-11-27）

依据：R2 02、原文849–864与370–389；保留12因素域及16研究维度。此节不重新增加一级分类。

### 1. 因素的语义与发现操作

同一名词在不同问题中可以承担不同语义，但每一次具体使用必须可辨认：
- 描述变量（角色身份、状态、环境、资源量等）有取值域、单位、观察或假设来源。
- 关系变量（依赖、交互、因果候选）描述多个对象间关联；不能只罗列对象。
- 规范约束（规则、权限、质量下限）限制允许的取值或行为，不是自然事实。
- 评价目标（价值、质量、成本偏好）决定如何在可行空间比较候选，不能抵消硬约束。
- 认识状态（事实、未知、假设、证据）说明我们为何相信某个因素取值；不等于系统运行状态。

按12域依次寻找受影响主体、行为条件、时间位置、对象/数据、关系、边界、质量、资源与后果，再询问「改变这个条件是否会改变目标可达性、允许行为、方案选择、验收或风险？」若不会，记录裁剪理由；若未知且可能重大，保留未知，不把它直接定为新增需求。16研究维度是独立知识入口，不是12域的重复加项。

### 2. 从分类到组合

用因素 i 的取值域 D_i 和有效组合约束 C 定义分析空间 Ω={x∈∏D_i | C(x)}；未知值不等于任意值均可行。先按可观察行为与规则把连续或巨大取值域分成等价类，再找临界值、状态转移、缺失/过期、重复、极端及受影响角色；按风险保留关键交互，不无条件笛卡尔积。等价类依赖特定目标与模型，不能在未知行为下假设等价。时间顺序不是静态取值，必须交给B/D的行为关系表达；相关因素也不等于因果。

抽象反例：三个布尔条件 a,b,c，各自为真或假都合法，两两组合也都能出现在合法空间，但约束 ¬(a∧b∧c) 排除全真。只检查单因素、或声称每对相容就推得整体相容，均错误。反过来，只要定义了约束也不能声称已经发现所有约束。按风险选择二元、三元或明确的高阶交互，安全不变量与已知严重失效组合单独保留。

### 3. 完整性判据与证据

本专题的完整性是「在给定对象、目标、版本、环境和风险边界内，12域有相关性判断，关键取值与组合约束有来源，遗漏/未知有处置」；不存在无界的因素穷尽证明。风险、质量等公共分类需引用专业目录，不在A复写H。ISO/IEC 25010:2023 的公开摘要说明产品质量参考模型有九类特性，并服务需求、评价和验收；产品质量、使用结果、组织过程质量必须区别。这里不把九类直接当成通用因素唯一分类，也不宣称阅读付费标准全文。NIST SP 800-142 的摘要支持有限交互强度的组合覆盖思路；此处仅借作框架分析规则，并未生成/执行测试。GMA则用于探索与排除不相容候选，二者目标不同。
