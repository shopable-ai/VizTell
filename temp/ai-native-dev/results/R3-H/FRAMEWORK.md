# 盲区审计与成熟方法 · 总体框架 F1

**独立问题：** 哪些类型的错误、遗漏、冲突和证据缺失需要被发现？什么专业方法适合什么审计对象？当前构建审计地图，不进行产品测试。

## 1. 审计的三维框架
维度一：审计对象（目标/事实→需求/场景→方案/模型→任务/实现→验证/交付→运营/知识）。
维度二：审计领域（原R2八领域）。
维度三：缺陷性质（缺失、错误、歧义、冲突、无依据、越界、不适用、失效、过度设计、不可验证）。例如同一需求可同时有条件遗漏与证据缺口，不能仅按阶段分类。

| 八领域（保留） | 二级审计问题 |
|---|---|
| 价值与目标 | 意图漂移、错误问题、非目标扩展、利益冲突、成功条件不明 |
| 需求与行为 | 必要规则、角色场景、正常/异常/替代/恢复、未分配需求 |
| 状态与时序 | 初始/终止、状态转换、不变量、并发、重复、延迟、顺序、未知结果 |
| 数据与环境 | 身份、归属、生命周期、数据一致性、设备/版本/规模/网络、迁移 |
| 依赖与执行 | 依赖缺失、接口、可行性、输入输出、资源、集成、现有能力与重复建设 |
| 风险与质量 | 安全、隐私、供应链、性能、可靠性、体验、可维护、失败后果 |
| 责任与证据 | 授权、责任空白、裁决权、来源/版本、独立性、真实验收、证据失效 |
| 生命周期 | 变更影响、运营观测、回滚、维护/更新、反馈、知识失效、退役 |
因素A供输入，G供推理，H按目标和风险选择检查，不重复造因素及推理目录。

## 2. 不同阶段的关键审查
| 阶段对象 | 主要审查输出 |
|---|---|
| 目标/来源 | 不一致目标、缺事实、假设及需决策事项 |
| 需求/业务 | 必要需求缺失、冲突、可测判据缺口 |
| 方案/设计 | 约束违反、接口/状态/质量风险、替代方案 |
| 任务/实现 | 需求无映射、越界实现、依赖与集成缺口 |
| 测试/验收 | 判据不完整、证据与对象/版本不匹配、错误放行 |
| 运行/知识 | 事故或长期风险、变更失效、未沉淀/过时经验 |

## 4. 审计输出与停止
问题→影响目标/对象→证据/假设→修正建议→返回对应链路→验证/保留风险。发现类型分为已证实缺陷、待证假设、无效新增、可接受/延期风险；只因缺少文档不自动判缺陷。优先检查不可接受后果、关键约束与高影响未知，按风险控制组合。不以审计数量或专家一致为完成。后续才独立验证命中率、误报、成本及方法适用边界。

## 5. F2：审计方法路由及否决规则

| 缺陷性质 | 优先审查方式 | 输出 |
|---|---|---|
| 目标/需求遗漏 | 目标反推、主体和场景覆盖、需求追溯 | 未覆盖目标、候选补项与依据 |
| 矛盾、边界或例外 | 逻辑一致性、边界值与组合推演 | 冲突条件、反例、修正范围 |
| 局部失效及影响 | FMEA类失效模式分析 | 可能失效、局部及下游影响 |
| 严重后果及系统交互 | STPA类控制约束、系统性分析 | 不安全控制、约束、待查因果 |
| 架构取舍与质量 | 质量属性场景、ATAM类权衡 | 敏感点、风险、取舍依据 |
| 事实或声明错误 | 来源、主张/证据关联、反证检查 | 证据范围及声明上限 |
| 过度设计 | 必要性、替代、裁剪和成本审查 | 可去除、延期或需保留的依据 |

先由 A/C/D 确定审计对象与目标，按风险及未知选择方法，不叠加全部成熟方法。STPA 与 FMEA 视角不同，不互相替代：组件均无局部失效而交互形成危险，单靠局部失效清单未必覆盖。ATAM参照 SEI 公开资料，用于架构质量属性权衡，不直接证明架构正确；NIST SSDF是安全实践指导，不证明任何项目合规。本表是概念性路由。

**否决与回流：** 已知重大逻辑错误、关键遗漏、硬约束冲突、虚假证据或越界声明优先阻断；分数高不能抵消。输出区分发现、证据、严重度、影响对象、可修正范围、待定责任；B 将问题返回对应节点，K 保存反例。审计停止于高影响问题已处置或明确阻断，新增检查不改变结论。框架自审仅验证定义与逻辑，不执行产品测试，也不宣称成熟方法的实际效果。

本节为F2通用结构推导和概念反例，未进行具体应用；重要分类和完整专业知识仍须独立核验。
