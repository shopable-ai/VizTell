# 角色宇宙与多专家 · 总体框架 F1

**独立问题：** 涉及哪些真实主体、哪些专业判断、谁承担责任和决策权，以及怎样组织协作？不启动Agent或模拟独立专家。

## 1. 四张相互关联的角色地图
| 视图 | 分类入口 |
|---|---|
| 利益相关者（研究对象） | 使用方（直接/间接用户、管理员、受益者）；商业方（购买、付费、投资、产品所有者）；建设方（产品、设计、研发、测试、交付）；运营方（客服、运维、维护）；生态方（平台、渠道、供应商、合作）；约束方（监管、审核、合规）；受影响方（非用户、数据主体、利益受损） |
| 专业知识与视角（工作能力） | 领域/用户研究、产品/业务分析、设计/体验/无障碍、架构/技术选型、工程实现/集成、测试/质量、信息安全/隐私/合规、商业/运营、证据/反方/审计；补充工程管理、发布与维护、配置/供应链、数据及研究方法作为二级专长 |
| 责任与权限（治理） | 提供事实、提出需求、执行、评审、批准/裁决、验收、运营、受影响/被通知；权限限制、委托、冲突、替代、责任转移 |
| 实际参与者（实例） | 人、团队、AI Agent、外部组织、自动化服务；一个参与者可承担多个角色，一个角色可由多人协作 |
R2七利益类别、九专业领域、五协作机制保留。助力、阻力、中立是相对目标和时间的关系，不是固定身份。购买者与使用者可不同，专业意见与批准权限也可不同。SFIA把专业技能和责任层级区分，且分类不等同岗位；这支持区分专业能力与角色，不代表采用SFIA的完整等级。

## 2. 关系与选择原则
主体→利益/目标→场景/影响→必要问题→需要的专业能力→有责任和权限的参与者。选择专家由未知项、决策影响及风险触发，不由角色数量触发。一个领域专家可能不知道实际用户情况；反方可质疑但不能自动否决授权决定。高风险冲突需明确裁决者，不能以多数票替代证据。独立性是执行/信息条件，不是专家名称。

## 3. 协作结构
| 协作机制 | 最小输入 | 输出 |
|---|---|---|
| 多视角发现 | 同一原始目标、事实和范围 | 不同主体问题和遗漏 |
| 独立判断 | 同一冻结输入、评价规则；先不看他人答案 | 独立结论及不确定性 |
| 对抗质疑 | 候选结论、依据、风险 | 反例、证据缺口、否决理由 |
| 权衡裁决 | 分歧、利益、约束、证据 | 决策、责任、保留分歧 |
| 独立验证 | 事前判据、受测产物身份、环境 | 可信证据及独立判断 |
独立程度：单次多角色扮演→同模型独立调用/独立上下文→不同模型/工具链的独立分析→人工/外部独立核验。独立上下文并不必然独立错误；模型可能共享训练偏差。记录谁看过前序结果、独立输入、实际执行回执。无工具时只能单模型自审。

## 4. 框架边界
A维护角色作为因素，F维护主体/知识/责任/协作，G维护思考方法，H维护检查对象，L管理权限和执行，J管理Agent实际能力。新增角色不是新软件功能。待验证专业覆盖、选择成本和独立审查的收益；本阶段不对具体项目组建专家队伍。来源：R2 06；IREB stakeholder https://cpre.ireb.org/en/downloads-and-resources/glossary ；SFIA https://sfia-online.org/en/about-sfia/how-sfia-works 及 https://sfia-online.org/en/about-sfia/sfia-professional-skills 。

## 5. F2：角色与专业视角选择、协作裁决

先选择问题而非专家数量。目标与价值不确定→产品/领域/利益相关者视角；复杂行为→业务与系统分析；可行性→架构与对应技术；体验→交互及可达性；高风险→安全、质量或相关专业；交付→执行、测试及运营；争议→有权裁决者与独立审查。原九类专业域是候选索引，具体选择依风险和未知，不每轮模拟全部专家。

职责最小结构：关注对象、具备/需要的知识、输出、责任、授权、利益冲突、审查独立性。实际参与者可以承担多个角色，但身份、职责、权限和独立性分别记录。SFIA 的技能与责任等级框架为此提供区分参照；本表不是 SFIA 角色目录。

**协作结构：** 共享目标/事实及判据→独立形成专业结论（若条件具备）→比较依据和分歧→反证及修正→有权主体裁决→保留未决与责任。不能多数投票制造事实，硬约束优先于加权偏好。反例：同一模型连续生成三个不同角色答案，仍可能共享同一错误前提；只能称多视角自审，不能称三位独立专家。停止于重要问题有明确责任、冲突已裁决或保留阻断、进一步增加视角不再带来新的相关风险。

本节为F2通用结构推导和概念反例，未进行具体应用；重要分类和完整专业知识仍须独立核验。
