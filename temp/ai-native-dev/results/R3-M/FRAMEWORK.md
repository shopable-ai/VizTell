# R3-M 商业与运营体系：框架 F1

## 独占问题
软件研发怎样连接实际用户价值、商业可持续性和长期运营？它不是所有软件都必须盈利的假设，更不是立刻研究某个竞品或做市场测算。

| 一级领域 | 二级研究分支 |
|---|---|
| 价值与问题 | 用户价值、社会/组织价值、问题强度、现有替代、目标结果 |
| 市场与对象 | 用户与购买者区分、细分、需求环境、竞争、渠道、生态、地域/法规 |
| 产品策略 | 定位、范围、差异化、优先级、生命周期、组合和取舍 |
| 经济模型 | 收入来源、定价、成本结构、资源约束、风险、可持续性；非商业项目改用目标达成和资源效率 |
| 获取与服务 | 发现、评估、获取、激活、使用、留存、支持、退出；不同产品路径可裁剪 |
| 运行与运营 | 质量与服务保障、运维、反馈、事件、知识支持、数据与隐私治理 |
| 价值反馈 | 目标指标、指标定义、观测、解释、因果不确定性、决策、再验证 |

## 关系与推导链
价值目标→受益主体与实际问题→价值假设→必要能力→可交付产品与服务→使用和运行事实→价值评价→保留/调整/停止。价值是关系而非单一指标。购买者、使用者、运营者、监管者的诉求可能冲突；评价方案需保留不同目标。增长与收入也可能与安全、隐私、可靠性冲突，不能用总分抵消硬约束。

## 边界
A 提供商业因素导航；F 定义相关主体及权责；C 将价值假设转为候选需求；D 表达产品与业务模型；H 审查目标和证据；M 专门研究价值实现及运营反馈机制。指标定义与真实测量分开，未经市场验证的判断必须标为假设。实际行业、用户、价格、竞品及财务数据暂不研究；本轮不输出市场预测、不确定某产品方向、不建立业务系统。

## F2：价值框架的选择与反馈

先区分项目目标：商业产品关注受益者、付费方、价值兑现及可持续性；组织内部项目关注目标结果、效率、治理和长期资源；公共/公益项目关注公共结果、公平性、风险及责任。不能把盈利作为所有系统的硬约束。

| 问题 | 需要的框架 |
|---|---|
| 价值是否成立 | 目标、问题、受益主体、现状/替代、假设和证据要求 |
| 多方目标冲突 | 利益关系、约束、偏好和有权决策者 |
| 是否值得投入 | 备选方案、成本、风险、长期影响和机会成本 |
| 如何判断运营 | 指标定义、边界、测量方式、未知与反证 |
| 如何支持演化 | 反馈→原因假设→目标/需求或设计修正→再评价 |

NASA 6.8 Decision Analysis（https://www.nasa.gov/reference/6-8-decision-analysis/）为目标、权衡及不确定性提供通用系统工程参考，不是商业理论的完整覆盖。反例：一个方案在点击、收入或交付量上更高，却违反用户权限或质量下限；不能用加权总分接受。另一个方案观察到运营指标上升，不能仅凭共变归因为某项变更。应区分行为信号、解释假设和价值证据。

原始公司体系（产品研发、商业化、增长、运营、组织、财务、法务、资本）保留为相邻知识边界。只有与软件价值、约束、责任和可持续性直接相关时纳入，企业管理通用理论不在当前专题内展开。不做市场/竞品/价格或任何具体商业应用分析。
