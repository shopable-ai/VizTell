## 双向推演与增量修正（L610–686）

输入：原始想法／需求树／设计方案／代码／验收结果。

1. 确定推理范围：目标、边界、已知事实、未知条件。
2. 选择推理模式：正向、逆向、因果、反事实、组合等。
3. 使用完整性检查矩阵查找角色、状态、数据、依赖、生命周期等遗漏。
4. 双向场景推演：条件 → 行为 → 结果；失败 → 原因 → 缺失条件。
5. 证据审核与价值收敛：真实遗漏／待验证假设／无效需求／延后处理。

输出：补充需求、修正设计、新增测试、剩余风险；返回原研发主工作流。对应五阶段的审计：需求遗漏、业务链路、方案风险、实现偏差、证据与演化审计。

> 资料性质：通用思考方法库候选。
> 来源：用户原始文本 `粘贴的文本 (1)(5).txt`，L390–437、L575–590、L715–733（原文行号）。

## 十三种候选推理模式（L719–733）

| 推理模式 | 核心问题 | 输入 | 输出与停止条件 |
| --- | --- | --- | --- |
| 正向推理 | 这样执行会发生什么？ | 条件、行为 | 结果与状态路径明确 |
| 逆向推理 | 要实现结果，必须具备什么？ | 目标或失败结果 | 必要条件及候选原因明确 |
| 因果推理 | 为什么会发生？ | 现象、变量 | 有证据支持的原因或待验证假设 |
| 对抗推理 | 怎样可能使方案失败？ | 方案、规则 | 高影响反例及防御措施 |
| 反事实推理 | 如果改变某个条件会怎样？ | 原条件、替代条件 | 可比较、可验证的预测 |
| 类比推理 | 其他成熟系统怎样解决？ | 相似案例 | 可复用机制及适用边界 |
| 组合推理 | 多个条件同时发生会怎样？ | 状态、变量 | 达到预设组合覆盖要求 |
| 约束推理 | 哪些方案实际上不可行？ | 规则、资源、限制 | 可行方案与冲突处理 |
| 场景推理 | 用户实际怎样使用？ | 角色、环境、行为 | 正常、异常及恢复场景 |
| 边界推理 | 到达极限或越界会怎样？ | 数量、时间、权限等 | 临界条件与越界处理 |
| 价值推理 | 这个功能真的有必要吗？ | 目标、收益、成本 | 保留、延期或删除的理由 |
| 证据推理 | 凭什么认为结论正确？ | 主张、测试、事实 | 证据适用范围及剩余未知 |
| 时间演化推理 | 系统长期运行后会怎样？ | 当前系统、变化条件 | 维护、升级、迁移与退役策略 |

这不是每次研发必须执行的13个步骤。早期12项清单少了时间演化推理，保留较完整13项版本。

## 原始12项简版的典型使用方向

早期表述与后续13项表不完全相同。以下保留早期版本的简明应用语义（L391–437），尤其是从目标推导需求、从失败反推遗漏；不另建一套推理模式。

| 模式 | 原始应用表述 |
| --- | --- |
| 正向推理 | 从目标推导必要需求 |
| 逆向推理 | 从失败结果反推遗漏 |
| 因果推理 | 找到问题的真正原因 |

| 对抗推理 | 主动攻击当前方案 |
| 类比推理 | 借鉴其他行业的成熟方案 |
| 场景推理 | 模拟完整用户使用过程 |
| 约束推理 | 在资源限制下寻找最优解 |
| 组合推理 | 分析多个功能之间的交互 |

| 边界推理 | 发现异常、极端和临界条件 |
| 价值推理 | 判断是否值得做、是否过度设计 |

## 怎样继续研究（整理建议）

以13项候选模式为索引，逐项明确适用条件、输出、停止条件及失败边界；比较不同模式是否提供独立价值。例如正向推理验证行为结果，逆向推理发现必要条件或失败原因，因果推理需要额外证据确认原因，证据推理核验主张是否成立。比较不能仅依靠定义差异或模型自我评分。

每个真实任务按问题选择模式，不要求执行全部13种。需求推理和盲区审计分别使用本模式库，不重复维护各自的通用模式清单。
