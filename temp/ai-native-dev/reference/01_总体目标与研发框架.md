# 总体目标与研发框架

> 资料性质：共同目标、总体框架与阅读导航。
> 来源：用户原始文本 `粘贴的文本 (1)(5).txt`，L1–60、L107–228、L865–866、L887–897、L949–1039（原文行号）。
> 整理版本 R2；新增的分类、关联、研究方案均标为「整理建议」，不视为已验证事实。

## 一、原始目标

用户只需提出不完整的原始想法、需求变更或缺陷反馈，AI 能理解目标、发现需求、选择合适的专业方法、组织开发与真实验收，最终解决用户问题。用户不需要提前整理完整需求。

## 二、研发主工作流（五阶段）

| 阶段 | 主要工作 |
| --- | --- |
| 01 需求理解与推理 | 目标、问题、角色、场景、潜在需求、需求树 |
| 02 工程模型与业务设计 | 业务链路、能力树、功能树、业务规则、用户旅程 |
| 03 解决方案与技术设计 | 资料研究、竞品分析、多方案比较、MVP、UI、系统架构、数据模型、接口契约 |
| 04 工程执行 | 项目拆分、输入输出契约、任务树、Workflow、Skill、Agent、代码开发、构建部署 |
| 05 真实验收与持续演化 | 测试矩阵、代码审查、反方审计、真实运行、修复、错题库、知识沉淀、持续迭代 |

输入：用户原始想法／需求变更／缺陷反馈。入口：恢复已有知识、判断任务类型、确定范围。输出：实际可用的软件、真实验收证据、可维护工程资产及可复用经验。发现问题后返回相应环节局部修正。

贯穿各阶段：上下文恢复、事实与证据、关系追溯、输入输出契约、知识复用、防止目标漂移。知识层包括决策记录、错题归纳、上下文交接、Skill 优化。

研发总链路：原始想法 → 需求推理 → 业务与产品设计 → 技术方案 → 工程研发 → 测试验收 → 发布运营 → 持续演化。

## 三、原文中另外两种有价值的分层视图

### 3.1 研发职责分层（原文 L4–60）

| 层 | 完整职责 |
| --- | --- |
| 需求层 | 目标提取、需求发现、需求树生成、盲区审计 |
| 研究层 | 竞品研究、开源检索、商业分析、可行性研究 |
| 设计层 | 产品设计、UI/UX 设计、系统架构、接口契约 |
| 执行层 | 任务拆解、Agent 调度、代码实现、构建部署 |
| 验收层 | 测试生成、代码审查、反方审计、真实验收 |

### 3.2 研发能力分层（原文 L128–174）

| 层 | 完整职责 |
| --- | --- |
| 认知与推理层 | 目标理解、需求推理、领域知识、多专家协作 |
| 工程模型与设计层 | 需求与功能模型、角色与场景模型、业务与交互模型、架构与数据模型 |
| 研发执行层 | 任务拆分 Task、工作流 Workflow、技能 Skill、智能体 Agent |
| 验证与演化层 | 测试与修复、真实验收、错题与知识库、持续迭代 |

贯穿全部环节的基础能力：上下文恢复、事实与证据、关系追溯、输入输出契约、知识复用、防止目标漂移。

原文明确这一框架是整合候选，尚未经过完整实证验证。

## 四、九类不同职责（不是九个连续步骤）

| 体系 | 核心职责 | 类比 |
| --- | --- | --- |
| Workflow 工作流 | 决定怎样推进工作 | 研发路线图 |
| Model 工程模型 | 表达需要理解的对象与关系 | 工程图纸 |
| Role 角色 | 提供专业视角及承担责任 | 产品经理、架构师、测试专家 |
| Skill 技能 | 提供可复用的局部工作方法 | 需求分析、技术选型、测试设计 |
| Reasoning 推理 | 从已知发现未知、必要条件与异常 | 反向推理、因果分析 |
| Tool 工具 | 完成具体操作 | 浏览器、Git、编译器 |
| Agent 智能体 | 使用上述能力执行工作 | 实际工作的 AI |
| Evidence 证据 | 证明特定结论成立 | 测试记录、真实运行结果 |
| Knowledge 知识 | 保存和复用事实、决策与经验 | 项目知识库 |

**它们不是九个连续执行的步骤，而是九类不同职责。**

## 五、怎样理解不同视图之间的关系（整理建议）

| 视图 | 回答的问题 | 应用 |
| --- | --- | --- |
| 因素宇宙 | 有哪些因素需要考虑？ | 知识目录、遗漏发现 |
| 链路宇宙 | 怎样从已知得到目标结果？ | 专项推导与业务过程 |
| 五阶段主工作流 | 研发总体怎样推进？ | 总体阅读导航 |
| 五层职责视图 | 需要开展哪些工作？ | 研发活动分类 |
| 四层能力视图 | 需要哪些专业知识、能力？ | 方法和能力组织 |
| 七环节输入输出简表 | 每一环节主要产出什么？ | 简明执行与交接 |
| 十环节综合矩阵 | 在具体阶段怎样组合模型、角色、Skill？ | 详细执行参考 |
| AI Project OS | 怎样将经过验证的方法转为可运行的系统？ | 候选软件建设目标 |

五阶段作为主导航，其他视图是按用途观察同一体系，不是新增生命周期。因素、角色、推理模式、Skill 等可在不同阶段按需使用；项目规模小、既有成果明确时可以裁剪工作，但不能跳过必要验收。
