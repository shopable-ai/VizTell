# Markdown 文档整理与修复通用提示词

请整理并修复我提供的 Markdown 文件。

目标不是重新创作、总结或改写正文，而是在**尽量保持原文内容完整、原意不变、图片引用不变**的前提下，修复 Markdown 的标题层级、排版、OCR / 转换错误、表格、错误换行、页眉页脚等问题，并最终输出一个可以直接阅读和下载的 `.md` 文件。

---

# 一、核心原则

1. **以语义为准，不机械沿用原 Markdown 格式。**
2. **不总结、不压缩、不重写正文。**
3. **不随意删除原始正文。**
4. **所有 Markdown 图片引用必须完整保留，图片路径不得修改。**
5. **不确定是否属于错误时，优先保留原文。**
6. **如果原文为繁体中文，应统一转换为简体中文。**
   - 只进行繁体 → 简体转换；
   - 不借机改写句子；
   - 专有名词、书名、人名等按正常简体中文习惯处理；
   - 英文、数字、公式、代码、URL、图片路径不要因为简繁转换而被修改。

---

# 二、标题与层级修复

## 1. 按语义重新判断标题层级

不要机械沿用原文件中的 `#`、`##`、`###`、`####`。

对于书籍、电子书、PDF / OCR 转写文档，**默认优先采用下面这条主层级**：

```md
# 书名

## 第一章 章节名

### 章节内部的重要小节

#### 小节下面确实存在的进一步细分
```

推荐层级：

- `#`：整本书 / 整个文档的书名，只使用一次；
- `##`：主要章节、编号章节，尤其是“第一章 / 第二章 / 第 X 章”这一类正文主章节；
- `###`：章节内部的重要小节、方法、主题、案例组或独立论点；
- `####`：`###` 小节下面确实存在从属关系的进一步细分；
- `#####`、`######`：只有原文确实存在稳定的更深层结构时才使用，不要因为 OCR / 转换结果已经很深就机械保留。

### 1.1 先识别“标题候选”，再决定 Markdown 层级

标题不一定已经带有 `#`。以下内容都应进入“标题候选”判断：

- 已经写成 `#`、`##`、`###`、`####` 等，但层级可能错误的行；
- `第一章……`、`第二章……`、`第 1 章……`、`Chapter 1……` 等章节编号行；
- `第一节……`、`第 1 节……` 等节级编号行；
- `第十七诀……`、`第一套……`、`第一招……`、`第一计……` 等在同一文件中稳定重复出现的编号主题；
- `一、……`、`（一）……`、`1. ……` 等可能承担结构作用的独立短行；
- 原本应是标题，但 OCR 后变成普通纯文字的独立短行；
- 原本用粗体、居中、特殊符号、较大字号表达，但转成 Markdown 后丢失标题语义的文字；
- 在同一章节内反复以相似长度、相似句式、相似位置出现，并且后面都跟随一段或多段正文的短语；
- 与前后段落之间有明显空行，并且自身不像完整正文句子的独立主题语句。

判断标题时要综合：

- **编号模式**：章、节、篇、卷、Part 等；
- **上下文关系**：它后面的内容是否都在解释这个短语；
- **平行结构**：附近是否连续出现多个功能相同的短标题；
- **长度和标点**：标题通常较短，但不能仅凭“短”就判定；
- **正文完整性**：完整陈述句、长句、引用句、列表项通常不应被误判为标题；
- **跨页重复**：重复出现的页眉、栏目名、书名不等于正文标题。

不要只扫描已有 Markdown 标题；**必须同时检查可能丢失 `#` 的纯文字标题**。

### 1.2 章节层级优先，不要让“栏目词 / 页面主题词”把整本书压深一层

电子书转换中经常出现这种错误结构：

```md
# 书名

## 某个栏目词 / 大主题词

### 第二章 怎样不战而屈人之兵

#### 向对方摆明利害关系
```

如果“某个栏目词 / 大主题词”只是栏目、页面主题、装饰性分组、重复标签，或者并没有构成稳定且必要的“篇 / 部 / 卷”结构，就**不要让它占用一级正文层级，导致所有真正章节和小节整体下沉**。

这类情况下应优先恢复为：

```md
# 书名

## 第二章 怎样不战而屈人之兵

### 向对方摆明利害关系
```

也就是说：

- `第 X 章` 默认优先判断为 `##`；
- 章内相互平行的主题标题默认优先判断为 `###`；
- 只有某个 `###` 下面确实还有稳定、重复、明确从属于它的子主题时，才使用 `####`；
- 不要因为文件前面出现一个短词、栏目名、宣传语、页面主题或视觉大字，就把后面几十个章节全部降为 `###`、把正常小节全部降为 `####`；
- `上篇 / 中篇 / 下篇`、`第一部`、`第一卷` 等只有在**确实覆盖多个章节、具有稳定多章分组意义**时，才可以作为额外结构层；如果只是装饰或页面标签，应避免占用目录层级；
- 如果保留某个非章节分组标题会造成正文主结构整体过深，应优先保证“书名 → 章 → 章内小节”的可读目录结构。

### 1.3 根据同级重复关系校准层级

不要只看单个标题，要看一整段甚至整本书的重复结构。

例如，在同一章内连续出现：

```text
向对方摆明利害关系
抓住对方最在意的东西
不要急于暴露真实目的
给对方留下选择空间
```

如果这些短语后面各自都有正文，并且功能平行，那么它们通常应统一为同一级 `###`，而不是有的作为正文、有的作为 `####`、有的作为 `#####`。

如果多个“第 X 章”都处在同一层，而每章内部又存在一批相互平行的短标题，则应以这种**跨章节重复模式**反推正确层级。

必须注意：

- **书名和内部章节不能使用相同层级。**
- 避免明显的标题跳级，例如 `##` 后直接出现 `####`。
- 如果原文件标题符号数量明显错误，应根据内容关系重新调整。
- 不要因为某一页视觉字号较大，就自动判断为更高层级，必须结合上下文语义。
- 不要为了追求层级多而制造 `#####`、`######`；能用 3 层清楚表达，就不要机械保留 5 层。
- 修改一个标题时，要检查它前后的同级标题，避免只修一处造成全书层级不一致。

## 2. 合并被错误拆开的页面标题

转换文件中经常出现：

```md
## 走近博弈论

### 博弈的构成要素
```

如果判断两者实际上共同表达当前页面的完整主题，而第二行并不是正文中的独立子章节，应合并为：

```md
## 走近博弈论：博弈的构成要素
```

判断原则：

- 第一行通常是章节编号 / 章节名；
- 第二行通常是当前页面主题；
- 两者组合后语义更完整；
- 第二行下面没有多个同级子主题需要继续展开。

**不要机械合并所有连续的 `## + ###`。**

如果 `###` 确实是章节内部独立小节，则应保留原有从属关系。

## 3. 处理跨页重复章节标题

如果同一章节跨越多页，每页都重复相同章节名，但每页实际主题不同，可以根据语义整理为：

```md
## 重复博弈：天长地久的聪明策略
```

```md
## 重复博弈：为什么不带剑的契约必然无效
```

避免大量连续页面只出现完全相同的标题，影响阅读和搜索。

# 三、正文与排版修复

## 4. 修复错误换行

OCR / PDF / PPT 转换后，常出现一句话被错误拆成多行。

需要根据语义判断：

- 本来属于一句话的内容 → 合并为正常句子；
- 本来属于一个段落的内容 → 恢复为正常段落；
- 本来属于列表、步骤、关系结构的内容 → 整理成 Markdown 列表；
- 不要机械把所有短行合并。

重点保证：

- 阅读自然；
- 原意不变；
- Markdown 渲染正常。

## 5. 修复列表与缩进

检查并修复：

- 无序列表 `-`；
- 有序列表 `1.`；
- 多级列表；
- 列表缩进；
- 列表与正文之间的空行；
- OCR 导致的层级错乱；
- 孤立的缩进行；
- 本应从属于上一条内容却被拆平的项目。

应根据语义恢复合理层级，而不是只按空格数量处理。

## 6. 修复 Markdown 表格

检查所有表格是否存在：

- 列数不一致；
- 表头错位；
- 分隔线错误；
- 单元格内容被拆到表格外；
- 多余或缺失的 `|`；
- OCR 导致的错误换行；
- 无法正常渲染的结构。

可以在**不改变原始信息含义**的前提下修复表格。

如果内容明显原本就是表格，但转换后结构损坏，可以根据上下文恢复为合理 Markdown 表格。

不要为了美观而重写表格内容。

## 7. 清理 OCR / AI 转换异常

可以修复或删除：

- 明显乱码；
- 孤立无意义字符；
- OCR 错误符号；
- 明显错误的断词；
- 多余空格；
- 重复文字；
- 无意义数字或字母；
- 转换工具自动插入的辅助说明；
- 明显不是原书正文的 AI 转写提示。

但不要根据自己的知识擅自“纠正”作者观点或大幅修改原句。

# 四、页面杂质清理

## 8. 删除顶部目录

如果文档开头包含从原书、PDF、PPT 等提取出的目录页，可以删除顶部目录内容。

但必须注意：

- 保留书名；
- 保留副标题（如果它属于正式书名信息）；
- 不要误删真正正文；
- 只有在目录内容已由后文正文完整覆盖时才删除。

## 9. 删除页眉、页脚、页码和转换标记

删除明显不属于正文的内容，例如：

- 页眉；
- 页脚；
- 独立页码；
- 每页重复出现的书名；
- 每页重复的宣传文字；
- `<!-- page:24 -->` 等页面定位标记；
- `<!-- Image (...) -->` 等无实际正文意义的转换注释；
- PDF / PPT 转换工具生成的辅助说明。

但不要误删：

- 正文中的年份；
- 正常编号；
- 章节编号；
- 公式数字；
- 表格数据。

---


## 9.1 删除明显广告、联系方式和资源引流信息

如果原始电子书或转换稿中混入第三方广告，应删除，例如：

- `加微信：Sm99%10`；
- `添加客服微信：xxxx`；
- `朋友圈每日更新，获取请添加微信……`；
- `感谢您的阅读，如需要更多精品优质电子版书籍……`；
- 与正文无关的公众号、微信号、VX / V信、资源群、电子版获取方式等。

执行边界：

- 只有能够高置信判断为广告、联系方式或资源引流时才删除；
- 正文正常讨论“微信”“朋友圈”“公众号”等概念时必须保留；
- 如果广告被错误拼接在正文句尾，只删除广告片段，保留前面的正常正文；
- 不得因为清理广告而删除整段有价值正文。

- 广告可能被错误包装成 `#` / `##` / `###` 等标题、列表项、引用块或粗体短句；识别时应先去掉 Markdown 外壳再判断；
- **广告清理的默认单位是“广告片段”，不是“整行”。** 一行中只要仍包含正常正文，就必须保留正文，只删除广告前缀、广告尾巴、括号联系方式或嵌入式引流片段；
- 广告可能直接粘在正文前后，例如“更多资料加威信xxxx，正文……”或“正文……添加作者微信xxxx获取资料”；必须只剥离广告串，不能删除整句正文；
- **不能因为正文出现“微信、朋友圈、公众号、扫码、微信群、微信号、电子书、资源”等词就删除。** 正文讨论微信获客、朋友圈运营、扫码案例、公众号营销、联系人微信等，都属于正文；
- 高置信广告通常同时包含“书外引流目的 + 行动指令 + 联系方式/资源领取”中的两项以上，例如“添加作者微信获取资料”“扫码添加老师私人微信”“关注本公众号领取模板”；单纯叙述“老师的微信”“客户加微信”不是广告；
- 广告若被错误识别成标题，应删除该广告标题，并只修复由这个伪标题直接造成的子标题下沉；不得借广告清理之名批量重排与广告无关的标题；
- 删除广告后若留下残缺括号、孤立标点、空标题或标题跳级，应同步修复；
- 批量处理目录时必须递归检查目标目录下全部 `.md` 正文文件，而不是只扫描根层；完成后必须再次扫描高置信广告残留和标题跳级，并保留审计报告。

# 五、图片处理

## 10. 所有 Markdown 图片引用必须完整保留

例如：

```md
![第1页原始页面图](assets/page-001.png)
```

或：

```md
![](image.png)
```

或外部图片链接。

必须做到：

- 不删除；
- 不改名；
- 不修改路径；
- 不修改相对路径；
- 不替换图片；
- 不因为图片看起来重复就擅自删除。

处理完成后，应核对处理前后的图片引用数量和路径是否一致。

## 11. 区分“整页原始截图”和“正文插图”

### 整页原始截图

如果某张图片明显是当前页面的完整原始截图，而页面文字只是从该图片 OCR / AI 转写出来的，则页面顺序应调整为：

```text
标题
↓
整理后的可搜索正文文字
↓
原始页面图片
```

也就是：

> **标题 → 文字 → 页面原始图片**

不要继续保留：

> 标题 → 原始页面图片 → 文字

### 普通正文插图

如果图片本身属于正文中的具体位置，例如：

- 图表；
- 流程图；
- 示意图；
- 案例图片；
- 插画；
- 某一段文字直接对应的视觉内容；

则应尽量保持它与相关文字的原始位置关系，**不要统一移动到页面末尾**。

# 六、低频 / 特殊情况

以下规则只有检测到对应问题时才执行，不要为了套规则破坏正常文件。

## 1. 复杂图表或关系图页面

如果一页主要是：

- 流程图；
- 思维导图；
- 关系图；
- 复杂图表；
- 大量箭头与空间布局；

而 OCR 后的文字顺序明显混乱：

1. 尽量把可确定的文字关系整理成结构化 Markdown；
2. 保留原始页面图片；
3. 不要为了强制线性化而虚构关系；
4. 无法确定结构时，宁可少改，也不要凭空补充。

## 2. 无法确定是否属于正文的异常内容

如果某段文字看起来可能是：

- 页眉；
- 页面装饰；
- 图中标签；
- 正文；
- OCR 误识别；

且无法可靠判断，则优先保留，避免误删。

# 七、输出文件要求

## 12. 根据仓库位置确定文件名

先识别真实书名，再根据文件所在位置确定 Markdown 文件名：

### `temp/` 根目录中的独立 Markdown

如果文件直接位于 `temp/` 根目录，文件名使用真实书名，例如：

```text
temp/博弈论.md
```

不要附加 `-修正版`、`-clean`、`-最终版` 等后缀。

### `temp/<书名目录>/` 中的主 Markdown

如果一本书已经有独立子目录，则该目录中的**主 Markdown 文件固定命名为 `index.md`**，例如：

```text
temp/《人性要诀》/index.md
```

不要保留：

```text
temp/《人性要诀》/人性要诀.md
temp/《人性要诀》/《人性要诀》.md
```

这样目录名负责表达书名，`index.md` 作为统一内容入口，便于脚本、工作流和后续知识库处理。

如果子目录中存在多个 Markdown 文件，必须先判断哪一个是主文档；不能在无法确定时把多个不同文件互相覆盖。

# 八、完成前的最终校验

输出前必须再完整检查一次：

1. 是否只有一个一级标题 `#`，并且它是书名；
2. 书名与章节是否使用不同层级；
3. `第 X 章` 是否被无意义地整体压成 `###` 或更深层；
4. 章内相互平行的小节是否被无意义地整体压成 `####` 或更深层；
5. 是否还有可能已经丢失 Markdown `#` 的纯文字标题没有被识别；
6. `第 X 诀 / 第 X 套 / 第 X 招 / 第 X 计` 等稳定重复编号标题是否已按语义恢复；
7. 是否还有明显错误的标题层级；
8. 是否还有可以合理合并的“章节标题 + 页面主题”；
9. 是否存在明显标题跳级；
10. 同级章节、同级小节的层级是否在整本书中保持一致；
11. 是否仍有错误换行；
12. 列表缩进是否正常；
13. 表格是否可以正常渲染；
14. 是否仍残留页眉、页脚、页码；
15. 是否仍残留转换工具标记或 AI 辅助说明；
16. 繁体中文是否已经统一转换为简体中文；
17. 所有 Markdown 图片引用是否完整保留；

## 仓库批处理：完成判定与防漏检规则

当任务要求处理 `temp/` 中全部 Markdown 时，**不能以“脚本运行过”“文件最近被修改过”“Git 历史存在 format/cleanup/finalize 提交”“旧进度报告标记已完成”作为完成依据**。这些信息只能作为弱辅助证据，最终必须以当前文件内容为准。

### 1. 每轮都要重新递归扫描当前内容

- 递归枚举 `temp/**/*.md`，不得只读取旧的待处理名单或旧进度 JSON；
- 新增、改名、移动过的文件必须重新进入检查；
- 文件修改时间、最后提交时间、提交信息只用于帮助定位可疑文件，**不能直接判定“已格式化”**；
- 若 Git 历史显示“已格式化”，但当前内容仍违反本提示词，则以当前内容为准，重新修复。

### 2. “完成”必须同时通过内容级验收

至少检查以下项目：

1. 全文只有一个一级标题 `#`，且为书名/文档主标题；
2. 长文不能只有书名而完全没有正文结构；应结合当前内容恢复真实章节、小节层级；
3. 不得残留已抽取的顶部文字目录；原始目录页图片如属于需要保留的图片引用，则继续保留；
4. 不得把目录项本身误当正文标题；正文标题应在正文实际出现位置恢复；
5. 检查“标题与第一句正文粘连”，例如 `小节标题正文第一句……`，必须拆成标题与正文；
6. 检查显式章节标记是否仍未恢复，例如 `□如何……正文`、独立的“第X章/第X节/第X课”等；
7. 检查标题层级跳级、异常巨大标题、把整段正文误升为标题、OCR 乱码标题；
8. 检查正文中的页码、页眉页脚、转换器标记、`视觉补充`、`<!-- page:N -->` 等残留；
9. 检查异常超长 OCR 行、明显未分段的整页文本，并判断是否仍需结构整理；
10. Markdown 图片引用必须逐条守恒：路径、文件名、顺序和出现次数不得因格式化被破坏；
11. URL、代码块、表格、引用块等特殊结构必须继续满足本提示词中的保护规则；
12. 对无法高置信自动修复的文件，必须列入 `needs_review`，不能为了让报告显示 0 问题而强行修改或忽略。

### 3. 必须识别“假通过”

以下情况均视为**假通过**，不得宣告完成：

- 文件有近期修改记录，但正文仍是原始 OCR 连续文本；
- 文件只有 `# 书名`，长篇正文没有任何章节/小节；
- 文件已有很多后半部分标题，但前半部分仍存在大量标题与正文粘连；
- 旧脚本因缺少某种页面标记而跳过正文格式化；
- 顶部目录被部分删除，但目录文本或目录编号仍残留；
- 自动校验只检查 Markdown 语法，却没有检查语义标题覆盖率；
- 历史提交名包含 `format` / `cleanup` / `finalize`，但当前内容仍不合格。

### 4. 推荐的仓库级验收输出

批处理结束后应生成或更新一份内容级审计报告，至少包含：

- 扫描的 Markdown 总数；
- 实际修改文件数；
- 通过文件数；
- 高风险 / 中风险待人工或深度语义检查文件数；
- 目录残留、显式章节标记残留、标题粘连、标题密度异常、超长 OCR 行等问题计数；
- 图片引用总数与守恒结果；
- 每个仍未通过文件的具体路径、问题类型和证据；
- 对“历史显示已处理但当前内容失败”的单独标记。

批处理的最终目标不是“脚本成功退出”，而是：

> **当前 `temp/` 中每个 Markdown 文件都经过内容级重新检查；能安全修复的已修复；不能安全自动修复的被明确列出，且不存在用修改日期、旧报告或提交信息掩盖的遗漏。**
