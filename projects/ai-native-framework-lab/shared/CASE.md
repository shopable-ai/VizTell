# 统一实验案例与验收基线

## 1. 原始需求（两个框架必须接收同一文本）

在模拟 ChatGPT 项目页面中增加一个按钮，点击后在新标签页创建当前项目的独立对话，并且不影响原有页面。

## 2. 验收条件

1. 正确识别当前项目。
2. 正确产生新标签页操作。
3. 不改变原有页面状态。
4. 缺少项目身份时不执行错误操作。
5. 自动化测试能够发现错误实现。

## 3. 模拟环境约定

只模拟页面交互，不连接真实 ChatGPT，不访问真实账号，不修改真实 OpenDesk Browser 扩展。

- 当前项目身份来自项目根元素的 data-project-id。
- 当前页面包含对话 ID、草稿文本和滚动位置，用于检测原页面状态是否被改变。
- 新标签页目标是同一模拟站点的 conversation.html。
- 新标签页操作通过 openTab(url) 适配器表达；浏览器演示页使用 window.open(url, "_blank", "noopener,noreferrer")。
- 项目身份缺失或为空时必须失败关闭：不调用 openTab，不回退到其他项目。
- 允许更新状态提示，但不得改变当前 URL、对话 ID、草稿或滚动位置。
- 项目 ID 必须正确编码并可在目标 URL 中还原。

## 4. 共享测试基线

运行命令：

~~~bash
npm test
~~~

测试使用 Node.js 内置 node:test，不依赖第三方测试库。

src/project-page.js 是故意不完整的起始骨架。基线预期为 RED：打开新标签页、缺失身份反馈和 URL 编码相关测试失败。失败必须来自功能未实现，而不是语法错误或模块加载错误。

两个框架必须从同一 shared 案例复制独立工作副本，各自保存实现前测试输出。不得修改共享基线来让某个框架容易通过。

## 5. 必须保留的测试行为

- 点击后只创建一个新标签页。
- 新标签页 URL 包含当前项目 ID，而不是当前对话 ID。
- 当前页面 URL、对话 ID、草稿和滚动位置保持不变。
- 缺少项目 ID 时不打开标签页，并显示明确失败关闭提示。
- 含特殊字符的项目 ID 能正确编码并从 URL 还原。

## 6. 浏览器级验收

Node 测试验证事件处理和 openTab 调用契约，不等于浏览器真实创建了标签页。

实现完成后还必须在隔离的本地浏览器页面验证：

1. 打开模拟项目页。
2. 点击按钮。
3. 确认新标签页真实出现，且显示同一个项目的独立对话页。
4. 返回原标签页，确认 URL、草稿、对话 ID 和滚动位置没有改变。
5. 删除或清空 data-project-id 后再次点击，确认没有创建错误标签页。
6. 保存浏览器操作记录或截图，并与自动化测试结果关联。

## 7. 隔离要求

- Superpowers：独立工作副本、独立会话、独立文档和日志。
- BMAD：独立工作副本、独立会话、独立 _bmad 配置和产物。
- shared/CASE.md 是只读基线；框架输出不得写回 shared。
- 只有真实框架会话生成的 SPEC、Plan、Memlog、Ledger、Review 和运行日志才属于框架实验结果。
