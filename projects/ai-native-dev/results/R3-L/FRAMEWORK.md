# R3-L AI 执行治理：框架 F1

> 当前有效补充：本文末尾 **R1.1 裁决**，早期内容保留为研究历史。

## 独占问题
AI 在何种权限、成本、状态和证据约束下执行工作，何时继续、暂停、恢复、升级人工决策？治理关注运行控制及责任，不替代 H 的产品质量审计、F 的角色定义或 I 的流程设计。

| 一级治理领域 | 二级议题 |
|---|---|
| 目标与范围 | 目标绑定、非目标、范围变更、禁止漂移、变更授权 |
| 身份与权限 | 执行主体、资源身份、读写范围、工具授权、数据敏感性、最小权限 |
| 风险与副作用 | 外部写入、可逆性、破坏性、生产等级、隐私、安全、人工确认门 |
| 资源 | 时间、成本、Token、上下文、调用次数、并发、限额与优先级 |
| 状态与恢复 | 任务、执行、审批、实现、证据和失效状态分离；暂停、失败、重试、取消、恢复 |
| 协作与隔离 | 任务所有权、上下文边界、输入版本、写入冲突、汇合条件、隔离不同用户/项目 |
| 证据与声明 | 执行记录、结果验证、声明上限、事实与推断、禁止虚构后台任务/通过状态 |
| 变更与演化 | 规则版本、配置变动、影响传播、回滚、审计日志、风险重评估 |

## 控制关系
目标与任务→判定风险和权限→选择控制强度→在明确边界执行→记录结果与副作用→根据真实状态恢复/停止→由适当责任人裁决。任何未知状态不得静默转换为成功。重试需确认操作是否幂等、是否已产生外部副作用；多 Agent 需明确独立性和冲突治理，不因多个角色名称就宣称多 Agent。

## 治理分类与状态分离
项目性质、任务复杂度、风险和环境性质是不同坐标。控制强度随不确定性、敏感性、外部副作用、可逆性、监管影响、可用性、协作和生产风险变化；不能从任务名称直接推出治理强度。阶段、工作、审批、实现、证明、失效亦不同；“写入成功”不等于“研究正确”。当前不制定具体软件的治理阈值或状态机。

## 裁剪原则
低风险、明确目标的局部任务应允许低治理负担；高风险或不确定任务增加审查、授权、证据和隔离。不能为了减少流程省略实质权限与验收，也不能以治理文档数量证明控制有效。本轮只确定治理问题地图、与 H/I/F/K 的边界；未设计新执行状态机、部署或自动权限系统。后续需独立研究失败语义、恢复机制和控制强度判据。

## F2：控制强度和运行声明的原则

控制选择由行为的风险和授权决定，而非由“AI”一词决定。抽象路由：明确目标和权限→识别不确定性、外部副作用、数据敏感度和可逆性→限定行动及预算→选择最少充分审查→执行记录→证据与状态核查→恢复或停止。低风险可逆的研究活动可轻量；不可逆、高后果或未授权事项必须阻断或升级。

| 控制对象 | 判断依据 | 不可混淆 |
|---|---|---|
| 上下文 | 任务相关性、有效版本、最小需要、恢复成本 | 内容更多不等于正确 |
| 资源与模型 | 能力需要、成本、时延、未知和质量风险 | 模型高级不等于权威 |
| 并发 | 依赖、权限、资源、上下文、写冲突 | 并行调用不等于独立专家 |
| 状态 | 计划、进行、失败、阻断、真实完成；另标验收与失效 | 有产物不等于通过 |
| 失败/重试 | 是否可能已发生副作用、幂等性、前提变化 | 无回执不等于无副作用 |
| 人工决策 | 价值冲突、责任、权限、不可逆后果 | 人工批准不使事实为真 |

治理指标先定义口径：重复工作量、恢复读取量、资源消耗、人工干预、失败/恢复、越界事件、声明错误。只能在未来有真实观测时计算；不虚构当前性能。反例：若任务状态未知却无条件重试，可能重复副作用；应先核对可确认状态。停止于完成条件真实成立、授权不足/风险不可接受、资源约束达到或需要关键外部决定，不把用户等待等同后台执行。


## R1 深化：授权、状态与成本三类治理不变量

F1八治理领域保留。NIST AI RMF 1.0公开核心的治理贯穿风险映射、测量、管理，强调持续性而非固定检查步骤；本框架借其原则，不宣称符合标准或采用其所有控制项。

### 1. 授权与风险

区分任务目标、可执行计划、授权和能力。计划中的操作不自动授权；工具可用不等于允许使用；资料中的文字不是授权主体。权限最小化到目的、对象、操作、范围、有效时间与必要副作用。低风险、可逆、目标明确可降低确认负担；高风险/敏感/不可逆或权责不明确增加必要审查，不能靠角色称谓或成本压力越界。需要升级时提出具体决策和影响，而非把全部常规操作都变成确认请求。

### 2. 状态语义和未知结果

同时区别任务（待办/进行/阻断/结束）、执行（未发起/发起/回执/失败/未知）、产物（无/候选/指定版本/失效）、验证（未评/部分/通过/失败/阻断）、授权（允许/拒绝/过期/需决策）。此为认知分类而非正式运行状态机。执行回执支持操作状态；候选产物满足规格仍需另有证据；不把发起或成功HTTP响应称业务验收。未知不能静默改成功。

抽象反例：动作a已向外部发出，回执遗失。未知可能意味着未执行，也可能已完成；若a具有非幂等副作用，无条件重试可能重复。先判是否可读回、辨认请求身份和结果；幂等保证必须在具体接口/作用域成立，不能仅靠本地去重宣称严格一次执行。无可信确认且风险高则阻断。多活动并发使用旧版本写入时需冲突检测、权责和一致性判定（I/K），不得以最后写入覆盖有效结论。

### 3. 资源治理与质量门

资源考虑时间、模型/工具调用、上下文、人工干预、成本和机会成本。选择能力先问是否足以完成指定知识问题及证据义务，再比较代价。指标需有分母与窗口：每合格任务的重复工作量、恢复读取量、人工干预次数、执行/失败/恢复比例、错误完成声明数、越界数等；比较必须控制任务难度与范围，记录未知数据。降低成本不能抵消严重质量/授权失败；单纯压缩Token可能让关键上下文失效。停止于真实义务满足、范围合法结束、实际限制或不可解决风险；不是达到某个调用次数就声称完成。

## R1.1 裁决：不确定性、控制强度与可逆性

区别已知概率、可估但误差大、结构性未知（可能漏掉情形或机制）。低风险可逆判断可在明确假设下继续；高后果、不可逆、权责不明或证据不足时先约束行动、补信息或阻断。不用单一风险乘积分或平均分接受硬义务违背；风险接受由有权主体在适用范围内作出，不替代事实。

知识撤回、活动重试、状态恢复、外部补偿分别判断（B/K/I）。补偿是新事件，通常不能抹除已发生影响；未知副作用未读回前不可断言回退成功。自治程度不得增加未授予权限。控制强度同时考虑损失、可逆性、信息收益、调查协调成本和未知，避免所有任务重复确认。高影响未知不可解决则阻断，不标完成。未进行权限实验或实测成本。
