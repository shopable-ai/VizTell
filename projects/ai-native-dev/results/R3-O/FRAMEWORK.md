# R3-O AI-Native 软件研发总体框架 F1

> **当前有效裁决：R1.1 §11。** 早期F1/F2/F3/R1为研究演进记录；优先读§11.1、11.2、11.6。

## 原始目标与本轮边界
用户只需提供不完整想法、变更或缺陷，AI 应理解目标、主动发现必要知识及需求、设计方案、组织研发、执行测试、修复、真实验收和演化。本轮根据 2026-11-27 用户纠偏，优先建立总体框架与专题子框架。已有 A/B/G 应用研究作为历史证据保留，不再扩大具体应用。F1 是结构候选基线，不是已经独立验证的研发方法，更不是系统实现规范。

## 1. 总体阅读视图：与当前 framework/README.md 统一

|---|---|---|

| 工程知识表达与拆分 | 如何表达对象及关系、划分知识和工作单元 | D、E、K |
| 推导与行为关系 | 怎样由目标及已知条件得到其他知识或结果 | B、C |
| 专业分析与判断 | 如何思考、选择视角、查漏、质疑与裁决 | G、F、H |
| 工作组织与执行能力 | 怎样组合活动、方法、工具与执行者 | I、J、E |

N 是可能的工程化载体研究；O 管理总体关系。视图不是排他分类、研发阶段或软件引擎。每个专题有唯一主问题，其他视图引用它而非复制定义。

## 2. A–N 独占问题与交接
| 专题 | 独占问题 | 交给其他专题的知识 |
|---|---|---|
| A 因素 | 哪些对象、因素、取值、影响关系需要考虑 | 有结构的因素地图、条件与影响线索 |
| B 链路 | 从何种输入通过什么语义关系到何种输出 | 链路族、节点、衔接、回退语义 |
| C 需求 | 如何从意图推导、收敛必要需求 | 目标/需求/场景/判据关系与待决项 |
| D 模型 | 如何准确表达不同工程对象、行为和关系 | 模型族、适用性与语义边界 |
| E 拆分 | 从哪个轴拆分、怎样确定粒度和关联 | 结构与工作单元、分解和依赖 |
| F 角色 | 谁受影响、谁具备能力、谁负责与决策 | 主体、专业能力、责任及协作结构 |
| G 推理 | 通过何种思考方法得到候选判断 | 推断方式、探索操作、证据要求 |
| H 审计 | 如何发现错误、遗漏、冲突与过度设计 | 审查维度、反例、修正及验证要求 |
| I 工作流 | 如何裁剪、组织与控制实际活动 | 活动族与编排关系 |
| J Skill/Tool/Agent | 哪些能力可复用、如何消费与执行 | 能力分类、执行单元与边界 |
| K 知识 | 如何保存、引用、更新、复用并淘汰知识 | 资产分类、来源、有效性、复用机制 |
| L 治理 | 如何管理执行权限、资源、状态及风险 | 控制问题地图、停止/恢复条件 |
| M 商业运营 | 如何连接业务价值和长期反馈 | 价值假设、约束、运营评价 |
| N 系统价值 | 何时值得把方法工程化 | 工程化必要性及裁决条件 |

核心区别：因素是考虑变量，模型是对象及关系的抽象语义结构，树图文字是表示形式，推理是认知操作，链路是语义转换/依赖路径，工作流是活动控制。角色是责任与视角，Skill 是局部能力包，Tool 是操作接口，Agent 是执行主体。知识是可追溯的资产，证据是支持/反驳特定主张的依据，裁决是基于判据的判断。不能把这些当成一个大树中的同类节点。

## 3. 通用研发主链（关系视图，不是新的正式阶段）
来源/原始意图→目标、问题与边界→角色、场景和业务→必要需求及验收判据→方案研究与选择→工程设计→可执行任务→实现→验证/裁决→交付、运营与演化。
- A/F/M 提供前提，G 提供推断操作，D 提供表达，C 收敛需求；B 描述各交接语义。
- E 确定分解粒度，I 编排，J 提供执行能力，L 限制行动并保持真实状态。
- H 的审查贯穿所有环节，不仅末端测试；K 保存有依据的结果、版本与反例。
- 需求或证据不成立时回到相应上游问题，优先差量修改；并不要求每项任务全部重复。
- 原五阶段、七环节、十环节保留为不同用途和粒度的阅读视图；reference/09 已给出概念映射，见 I。不把它们另立为新的正式生命周期。

## 8. F3 总体收敛：跨专题共同语义与冲突处置（第一轮）

| 关键冲突 | 裁决 | 责任与结果 |
|---|---|---|
| 领域、因素、维度、模型混层 | 一级领域为检索，因素为关注条件，模型为表达；不追求同一互斥大树 | A/D/H 引用而非复制 |
| 意图、目标、需求、方案混层 | 目标是期望结果；需求是有依据的义务/约束；方案是满足要求的候选 | C/G/D：充分不等于必要 |
| 链路与流程混层 | 逻辑、行为、约束、证据、控制边分别表达 | B/I；保持分支和回退 |
| 各类树强制同步 | 分解轴和表达模型独立，多对多关联 | D/E；接口和组合验收不能遗漏 |
| 专家、角色、能力、Agent混层 | 权责/视角/知识/实际参与者/执行接口分别记录 | F/J/L；模拟多视角不计独立专家 |
| 13推理模式视为同类逻辑 | 逻辑、方向、认知操作、探索、证据、决策分别组织 | G/C/H；方法可组合 |
| 审计与治理重复 | 审计判断主张和产物；治理约束执行权限、风险和声明 | H/L；同一证据引用 |
| 事实与批准混层 | 证据支持事实主张，授权裁决确认需求和行动；批准不制造事实 | C/F/H/K |
| 资产存在与有效性混层 | 知识类型、历史版本、证据、采用及失效状态分开 | K/B；选择性回流 |
| 商业价值与质量互相抵消 | 先判断硬约束，再比较价值和成本；非商业项目以其真实目标为准 | M/A/G/L |
| 研究与系统建设混层 | 研究对象、可复用方法、工程组件三层；不要求七个引擎 | N/O |
| 结构通过与实际效果混层 | 当前只评框架覆盖、正确、深度、可读、一致；应用证据另行验证 | O/H；不得把框架分数当实际效果 |

共同交接最小语义：目标及范围、前提/有效事实及未知、输入对象、所选方法及条件、输出主张/对象、来源及依赖、裁决/责任、何时失效或返回。不是强制建立八个文件或新协议；根据任务风险裁剪记录形式。上游提供的是知识或条件，不是所有下游工作必须串行等待。

### 通用选择路由（非应用试验）
| 首要未知 | 优先专题组合 | 何时扩展 |
|---|---|---|
| 目标、问题或必要需求不明 | A/C/F/G | 价值冲突→M；表达不清→D；重大遗漏→H |
| 业务行为与状态关系不明 | B/C/D | 跨界职责→F；组合/失效→H；多轴分解→E |
| 方案选择困难 | G/D/A | 高后果、复杂、不确定、多属性→H/F；成本和价值→M |
| 不知道怎样组织工作 | E/I/J | 权限/风险/资源→L；基线不明→K |
| 结论、产物或声明不可信 | H/B/K | 责任或独立性→F；权限和状态→L |
| 需要长期复用或系统支持 | K/J | 方法已成熟且重复需求明确→N；仍不得提前工程化 |

NASA 6.8（https://www.nasa.gov/reference/6-8-decision-analysis/）支持分析强度与复杂度、不确定性、属性和主体相关；IREB elicitation（https://cpre.ireb.org/en/concept/requirements-elicitation）支持来源、冲突和情境选择；SEP abduction（https://plato.stanford.edu/entries/abduction/）支持区分候选解释与必然推断；W3C PROV（https://www.w3.org/TR/prov-overview/）支持来源/派生/版本关系。均为本轮查阅的通用来源。跨专题定义、表格、路由是本轮推断，不宣称来自某标准或已经实证。

## 9. F3补充：专业知识导航与剩余框架收敛

SWEBOK 18知识领域的主要价值不是要求AI阅读18份资料，而是让AI识别当前问题缺少哪类专业知识。以下二级入口为本轮工程研究导航候选，不是SWEBOK官方章节逐字复刻。范围触发优先于目录遍历。

### 10.3 一条通用的思考路径（抽象研究，不是实际业务）

1. 若G=A∨B且两者均可行，A是充分方式而非必要义务（C/G）；A不能被B链路的逆向追溯强制为唯一功能（B/D）；同样不能强制I执行A路线（I）。此前原始需求链的箭头必须按B的有条件、多对多关系解释。

3. 若证据E仅支持版本v1的命题P，而v2改变了P依赖的假设，K标待复核，H拒绝旧证据放行，L不能用成功写入冒充验收，I仅回到失效前提。若独立证据E2仍支持P，则允许重建证据链。

**知识选择机制（非工作流引擎）：**
- 定位能改变判断的未知及主张性质：概念/形式性质、真实环境事实、规范义务、经验效果、价值裁决。不可由模糊名词直接调用固定角色。
- 按问题定位领域及子领域：可实现性→计算/系统及逻辑；效果归因→统计、因果及机制；权利义务→适用规范及权责；质量阈值→测量科学、用户目标及质量专业。跨域时分别满足证据义务。
- 来源随主张选择：形式性质需定义、证明和假设；标准规范核发行者、版本、范围和效力；技术环境核官方材料及适用版本；经验结论核观察、测量和偏差。教材综述作导航，高影响争议取原始来源；相互转述不算独立。
- 提取可用命题、适用条件、方法及反例，映射当前对象，检查前提与迁移边界；无法证实则保留未知或阻断，不虚构阈值、事实与资格。
- F选胜任主体、责任和权限，G/H选方法及审查，K保存依据、版本与失效条件。专业知识、模型（抽象语义）、推理（推断/探索/评价）、角色（责任视角）、Skill（可复用能力包）、Tool（操作接口）、Agent（执行主体）不可互相替代。关键问题已有相称依据或重大未知已明确即停止。

### 11.3 共同语义与跨专题关系

保留10.2关系表，补强如下。箭头必须标明关系，不能自动理解为证明、因果或执行。

| 对象关系 | 责任与正确交接 | 排除错误 |
|---|---|---|
| 因素→模型→审计 | A选影响对象与条件；D保留关注性质；H按风险、判据检查 | 模型数量=因素覆盖=审计完备 |

| 角色→专业知识→能力/Skill→Tool/Agent | F主体与权限；O导航；J方法、能力、执行；I编排/L约束 | 角色即专业资格、可调用即授权 |

共同定义：事实是成立的事态，记录的是可被支持/反驳的事实主张；假设是条件化推断或决策前提；证据是特定来源/观察对主张的支持或反驳依据；决定是有权主体的规范选择；验收是针对对象、版本、范围及判据的裁决。模型是抽象语义而非图形载体；业务能力与工作者专业能力须分层。全局一致性需边类型、范围、量词、前提、身份版本及责任相容，不强制新格式。
