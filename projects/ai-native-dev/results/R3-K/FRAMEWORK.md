# R3-K 知识资产与知识复利：框架 F1

> 当前有效补充：本文末尾 **R1.1 裁决**，早期内容保留为研究历史。

## 独占问题
研发过程中产生的哪些知识应保留，如何区分事实、观点、决策、方法和证据，如何降低重复研究和错误复用？文件数量不等于知识质量。

## 知识分类
| 一级资产 | 二级内容 | 有效性条件 |
|---|---|---|
| 原始来源 | 用户原话、文档、专业资料、外部事实、观测 | 真实出处、时间、可回溯 |
| 项目事实 | 目标、范围、现状、约束、已验证行为 | 适用项目、版本、证据 |
| 工程知识 | 术语、领域规律、模型、方法、设计原则 | 适用情境与反例 |
| 决策 | 候选、判断依据、选择/否决、取舍、责任 | 条件与版本、可重审 |
| 执行资产 | 规格、工作流、Skill、测试资产、代码引用 | 可消费、可识别版本、边界 |
| 证据资产 | 观测、实验、测试结果、验收裁决 | 主张关联、来源、可信范围 |
| 失败与学习 | 缺陷、根因假设、修复、反例、回归 | 区分假设、已确认原因与修复证据 |
| 演化知识 | 变更历史、兼容性、失效项、迁移与退役 | 新旧版本和影响范围 |

类型和成熟度是不同坐标。原始资料不能直接标记为事实；已接受的决策也可能被新证据否决。证据支持或反驳主张，但不是主张本身。

## 知识复利链
记录原始来源→区分事实与待证主张→形成可引用知识→关联消费活动→应用取得反馈→补充条件与反例→修订或废止。检索时先识别项目与任务边界，再取相关索引和有效资产，核验版本及来源；仅在缺少证据时补读原文。不是让每次对话全量重读所有文件，也不是把旧摘要当权威原文。

## 组织结构
项目知识、跨项目专业知识、组织治理规则、执行资产分开维护；同一事实/契约应有可定位的责任来源，其他视图引用它；保留冲突而非静默拼接。知识关系至少包括来源、支持、反驳、适用、依赖、取代、失效、消费。F1 不规定数据库、目录层级或向量检索算法。

## 与其他专题接口
A/D/G 提供研究知识内容，H 管证据质量与裁决，I/J 消费有效知识，L 管访问范围和执行上下文，O 管专题索引及重复冲突。K 不承担所有事实的专业验证责任；需要专业责任人与证据。后续研究最小知识记录、失效传播、检索质量和复用收益。本轮没有迁移真实项目资料或创建检索系统。

## F2：知识生命周期、有效性与复用

原“想法→候选→验证→采用→实施→测量→优化→退役”作为资产演化视图保留，不作为任何知识都必须走的单线状态机。事实的证据状态、决策的批准状态、资产的使用/版本状态和方法的适用范围应分别描述。新事实可以使旧结论失效，但旧结论仍是有时间边界的历史记录。

W3C PROV-Overview（https://www.w3.org/TR/prov-overview/，本轮查阅）以实体、活动和参与者描述来源，并关注版本和派生关系。其作用是帮助评估可信程度，而非保证内容真实；本框架不采用或实现其完整数据模型。

| 复用对象 | 复用前核对 | 失效处理 |
|---|---|---|
| 来源与事实 | 时间、对象、适用范围、支持证据 | 保留历史，当前主张待复核 |
| 决策 | 目标、约束、候选和取舍依据 | 重新开放受到影响的决策 |
| 方法/Skill | 适用条件、反例、版本与边界 | 修订方法或切换，不宣称普适 |
| 经验/错题 | 原因是推断还是真实确认、修复及证据 | 保留反例，不能把失败猜想变成稳定知识 |
| 规格/测试资产 | 上游需求、接口和版本是否相容 | 沿实际依赖更新，不全库重做 |

最小恢复上下文包括当前目标和边界、有效事实及冲突、已经完成/未完成的实际状态、最近决策及依赖、下一需要判断的问题。不是固定全文；重要来源能按需回溯。反例：归纳得到的经验只在条件 C 成立，当前为非C，即使文本完全匹配也不能直接复用。知识复利的目标是减少重复错误和研究并提升正确性；真实收益待后续阶段。


## R1 深化：知识的认知性质、有效性和跨对话复用

保留原资产演化链，不强制一种状态机。F1「项目事实」分类中含目标、范围、约束，需进一步校正：它们的文本可被事实记录（某主体在时点作出声明/决策），但其内容可能是规范义务、期望或候选；「已批准」不证明真实。「证据资产」中的验收裁决是评价结果，不是证据本身。

### 1. 最小知识语义
- 描述性：原始观察、事实主张、假设、推断和外部材料；记录来源、证据与适用条件。
- 规范性：目标、需求、禁止条件、授权、决定；记录主体、适用范围、依据和有效期。
- 方法性：理论、方法、模型、经验、反例及候选Skill；记录所解决问题、前提、结论强度及不适用情形。
- 执行与评价：活动、产物、运行/观测、证据、裁决；分别记录身份、版本、时间、依赖和关联主张。

同一资料可包含多种知识，保存原件、抽取主张、记录语义与来源，不覆盖原文。W3C PROV-DM区分entity/activity/agent及派生、修订、引用、失效等关系；来源记录能帮助审查，不保证主张真实。本框架不要求采用该标准的数据格式。

### 2. 有效时间、版本和回流

分别记录事件发生或规则有效时间与资料记录时间；“后来录入”不表示事实后来发生。事实状态可为待证、支持、争议、否定；规范状态可为候选、批准、撤销、过期；资产状态可为未采用、有效、替代、退役。维度不同，不相互覆盖。版本身份决定当前可消费对象，旧知识可作为历史证据保留。证据依赖图不能靠循环自证，普通关联图可有循环；新的独立证据可支持或反驳旧主张，但不是每个来源变化都必然使全部结论为假。

当条件或版本改变：定位受影响主张→沿真实支持/派生/约束关系检查→保留不依赖该条件的结论→有替代有效证据则重建支持链→其他标待复核→修订决策与消费方索引。反例：经验 E 在 C 下成立，当前 ¬C；直接复用E是迁移错误，旧E历史事实不被删除。若只有描述格式或无关内容变化，不应触发全库重读。

### 3. 知识复利的独立判断

恢复顺序为当前目标/边界→已完成与未完成→有效基线和关键决策→直接相关知识与反例→按必要性取原始出处；对当前未知开展差量研究。可复用知识需有触发、前提、适用范围、结论或操作、反例、证据与失效条件。一次失败不自动提炼普适规则，原因未知则保留假设；只有跨场景共性有依据、复用成本低于重复研究且有维护责任，才考虑方法/Skill化。衡量复利用质量门保护下的重复研究、恢复读取量、重复错误和失效误用率，不在本轮虚构收益。

来源：https://www.w3.org/TR/prov-dm/ （2013 Recommendation，本轮核对公开模型与关系）；本节认识/规范状态和失效规则为本轮推导，不做数据库或检索系统。

## R1.1 裁决：知识冲突、支持依赖和局部失效

事实指实际成立的事态，知识记录保存关于事态的主张及证据。P的真假与认识状态不同；接受为工作假设不是使P为真。冲突处理先核主张的语义、身份、环境、有效时间、版本及量词；不同范围可同时成立，同范围不相容时核查来源、推断与反证，不以更新时间或来源数量裁决。共同原件的转述不是独立证据（既有W3C PROV-DM来源）。

若联合支持E1∧E2的E1失效，该路径失效；若另有独立充分支持路径(E1∧E2)∨E3，E3仍有效时可保留受支持主张。证据失效不直接推出主张为假。图循环不能代替外部支持。保留历史并区分待复核、已反证、被取代和不适用。反例：旧依据P撤回，Q可由独立R在同范围推出；全库作废会误删Q，直接保留旧证明又虚报。重建有效支持，仅复核真实依赖的决策和产物。不实现数据库。
