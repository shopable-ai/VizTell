# R3-G 推理模式宇宙：按问题选方法，而非执行13轮

任务 AI-NATIVE-RESEARCH-R3-G。原始目标：让AI从不完整想法或缺陷发现必要条件、真实原因、合理方案和可验证验收。G 只研究通用推理方式及组合价值，不复制C需求推理步骤或H审计流程。
 
## 1. 总体框架与关键修正
R2 13项有价值，但不是同一层级：
- 逻辑/证据基础：演绎（前提成立且有效时推出必然结论）、归纳（由样本提出概括/预测，可能失败）、溯因（由观测提出解释假设）。专业来源SEP。R2没有清楚列出这三者。
- 方向与目的：由条件预测结果、从目标找必要条件、从失败找解释；三个不同操作。原早期“正向从目标推导需求”与后期“逆向由目标推出条件”不一致，应以输入和输出语义定义，不纠结方向标签。
- 探索/检验策略：因果、反事实、类比、组合、边界、场景、时间演化、对抗。可以组合，不能强制互斥。
- 决策和认识约束：约束、价值、证据评估。不是都属于形式逻辑。
关键新增：从“目标G必须达成”逆推条件C，只有在证明G⇒C或受已选架构约束下才可称必要；能实现G的一个方案不代表C必须存在。由症状反推根因是溯因，必须通过可区别实验检验；相关、可复现及原因证明不能混同。反事实是假设或模型下的替代预测，控制变量实验给出限定条件下的因果证据，不保证外部效度。证据评估贯穿所有模式，不只是最后一轮。
 
## 2. R2 13项逐项去留、用法与停止规则
| 原模式 | 处置/触发和操作 | 输出/停止条件 | 典型错误 |
|---|---|---|---|
|正向|改名条件预测；给已知状态与规则，沿行为推到结果|状态路径与可反驳预测；遇未知停|把预测当运行结果|
|逆向|拆为目标逆推与失败溯因；前者检查反例，后者列竞争原因|必要条件或候选原因与区分试验|把一个可行方案当必需|
|因果|症状/变量/机制；控制改变并观察，排除共同原因|限定条件因果证据/未决原因|相关=因果|
|对抗|高影响方案；主动构造破坏目标反例|有效反例、修正或接受剩余风险|无限攻击/无关假设|
|反事实|比较假设改变与原条件，明确保持不变项|差异预测及可测条件|假设推演=实证|
|类比|已有类似系统；比较机制与不同前置|可借鉴机制和不适用边界|外观像=实现可用|
|组合|多个交互变量；筛合法组合、风险优先和t-way|覆盖表/交互风险，预算达到或无新高风险|全笛卡尔积或pairwise保证完备|
|约束|权限、时间、技术、预算；硬约束先排除、软约束权衡|可行集/冲突升级|为可行而擅改目标或授权|
|场景|角色、目标、触发、环境；走正常、异常、恢复|可观察行为及待确认规则|编造用户或业务规则|
|边界|数量、时间、状态转换阈值；测试边界两侧|临界规则和观测|只测极端不测正常/邻界|
|价值|功能必要性与投入；比较有无功能、收益和风险|保留/删减/延期，依据足够|把主观喜好当商业数据|
|证据|任何重要主张；找版本、反证、适用性和可信度|可支持的主张与剩余未知|自评、测试数量替代实证|
|时间演化|有状态、有版本或长期运行；模拟延迟/迁移/恢复|状态不变量、失效及恢复判据|所有小修都写生命周期|
以上各项的输入/操作/输出和错误边界是方法索引，不是互斥的13种形式逻辑，也不是自动执行全部。可读性优先。需要研究新理论时按具体未知检索而非添加名词。
 
## 3. 方法选择（本轮候选）
|问题|优先方法|最低必要证据|
|---|---|---|
|从不完整想法发现遗漏|目标逆推+场景+约束，必要时对抗|反例和可测行为|
|偶发缺陷|溯因→预测→区分性受控实验→证据审查|实际症状、版本、改变和观察|
|交互/并发状态|条件预测+组合+边界|时序及可复现断言|
|多个方案|硬约束+价值+反例，必要时类比|关键权衡、可行性、失效条件|
|验收/宣称完成|证据审查+反证|目标对应同一版本的真实结果|
停止：一个新方法不再改变关键假设、决策或测试，或剩余问题超预算/需权限，记录待证，不增加推理轮数。
 
## 4. 真实缺陷：网页剪藏有时选中大区域
固定用户输入：「鼠标点选网页区域时有时小区域无法选中而选中大区域，应该选择精确小区域。」固定项目源 2d98a00128cf77a7587f62729aee8d5a61a07c5a。
预设判据：相同坐标/元素，记录 trusted event.target、document.elementFromPoint、候选第一项；只改变一个CSS条件；不把意图等同命中。现有 regionCandidates 由DOM命中开始向父级走，preferredRegionIndex=0；pre代码块有意整体选择；blocked controls及跨轮容器有安全限制。已有tiny span 与 Ctrl/Meta 测试，fixture直接提供 target，并不证明所有页面真实 hit testing。
- 直接推理候选：调整大小阈值/优先小节点。源码反证：当前没有固定最小面积，默认真实DOM命中；不能据此断言修好，也不应盲改阈值。
- 溯因：至少四个竞争假设：H1 CSS/真实命中变化；H2 代码块或安全边界刻意排除；H3 动态页面/路由使高亮失效；H4 事件目标相同但候选/确认逻辑错误。H2/H3有源码机制，未在用户页面证实。H1 可区分实验最便宜。
- 条件预测：若可见子元素 pointer-events:none，则 event.target 为其可命中的祖先（本构造内）；仅沿祖先遍历无法找到该子元素。
- 受控改变/反事实实验：固定页面/位置，auto→none→auto。实际隔离 Chromium 144 输出 tiny→parent→tiny，候选首项相同，三个事件均 trusted。具体结果见 evidence.md。证明这种DOM命中机制可能造成症状，而不是证明用户故障根因。
- 对抗/边界：改成按几何强找最小元素可能选择隐藏、安全排除、非交互或被遮盖的内容；不能绕过密码、编辑区、跨文档限制。预/代码块原本故意原子化，选择更小不一定符合产品目标。
- 价值/决策：先记录真实页 target/路径、候选理由、状态/路由，再区分需要修算法还是正确行为提示。若可见但 pointer-events:none 的文本确需选中，考虑有界候选搜索/显式选择，先验证权限与边界；不能默认强行改站点CSS。未实现扩展修改。
 
## 5. 比较与消融（单模型桌面+局部真实实验）
固定原始问题与预设判据。直接“调阈值”被源码检查否决；仅正向预测给出可检验条件，但没有真实观察；仅溯因会留下多个假设而无法裁决；源码+溯因+预测+受控改变实际确认H1机制，恢复auto反向控制降低偶然解释；再加边界审查排除危险的全局选最小策略。各步骤输出不同，不能把这当独立随机A/B或实际增益百分比。此实验只测试一种CSS机制，未验证当前用户站点、Shadow DOM/iframe、Ctrl/Cmd或连续追加。时间与成本未测。未用类比、市场推理、全部组合，因为未改变当下诊断。以后以相同输入、预定义判据和多任务独立评审/固定预算测误报、独特有效发现、可复现率及成本。
 
## 6. 去留与接口
保留R2的13项作为方法入口；补逻辑基础与证据等级，拆逆向，修正方向命名冲突；否决固定13步、单次自我推理确认因果和无限对抗。C/H/I可按触发条件引用，而不各自复制方法库。未知：组合选择是否稳定胜过直接推理、哪些任务收益为负、终止标准的阈值、真实页面根因。下一步真实页面只读诊断/安全测试、独立固定预算对照。
