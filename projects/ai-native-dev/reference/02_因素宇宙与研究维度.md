## 一、12个因素领域：需要考虑什么

| 因素领域 | 需要考虑的内容 |
| --- | --- |
| 目标与价值 | 用户目标、商业目标、成功标准、价值大小 |
| 用户与角色 | 使用者、购买者、维护者、能力、权限、利益 |
| 市场与商业 | 用户需求、竞争、付费意愿、成本、盈利能力 |
| 业务与场景 | 使用条件、业务规则、频率、异常、环境 |
| 产品与交互 | 功能、操作成本、易用性、界面、用户体验 |
| 数据与状态 | 数据类型、归属、有效性、状态变化、一致性 |
| 技术与架构 | 技术可行性、模块耦合、接口、外部依赖 |
| 时间与空间 | 时序、周期、并发、设备、平台、地域 |
| 资源与能力 | 人员、AI、工具、资金、时间、知识、算力 |
| 风险与质量 | 安全、可靠性、性能、兼容性、失败损失 |
| 证据与不确定性 | 已知事实、假设、测试结果、未知条件 |
| 生命周期与演化 | 使用、运营、反馈、维护、升级、迁移、退役 |

## 二、16个宇宙研究维度：哪些方向需要深入研究

| 研究维度 | 要解决的问题 | 研究优先级 |
| --- | --- | --- |

| 推理模式宇宙 | AI 应该采用哪种思考方式？ | P0 |
| 场景宇宙 | 用户在什么情况下使用，会发生哪些异常？ | P0 |
| 需求宇宙 | 如何发现显性、隐性、潜在及冲突需求？ | P0 |
| 约束宇宙 | 时间、资金、技术、权限、资源如何限制方案？ | P0 |
| 质量宇宙 | 如何衡量正确性、安全性、体验、性能？ | P0 |
| 证据宇宙 | 如何区分事实、假设、推断和真实验证？ | P0 |
| 决策宇宙 | 如何选择、否决、撤销、重新评估方案？ | P0 |
| 工作流宇宙 | 不同任务应该选择怎样的执行流程？ | P0 |
| Skill 宇宙 | 哪些专业能力可以独立复用？ | P1 |
| 工具宇宙 | 如何选择模型、MCP、API、浏览器及本地工具？ | P1 |
| 风险宇宙 | 系统会怎样失败？如何恢复和回滚？ | P0 |
| 资产宇宙 | 文档、代码、模板、测试、知识如何长期复用？ | P1 |
| 商业宇宙 | 产品价值、定价、增长、市场和竞争如何验证？ | P1 |
| 生命周期宇宙 | 发布之后如何运营、维护、升级、退役？ | P1 |
| AI 治理宇宙 | 如何控制成本、权限、上下文、执行状态？ | P0 |

优先级沿用原文，不是本轮重新排序或已批准计划。

## 三、因素领域与研究维度的区别（整理建议）

因素目录回答项目可能受到什么影响；研究维度目录回答哪些方向值得深入研究。16个研究维度混合了对象、方法、执行与治理，不能强行将每个宇宙都作为12个因素领域的直接子项。

| 归类 | 研究维度 | 主要用途 |
| --- | --- | --- |
| 研究对象 | 角色、场景、需求、约束、商业、生命周期 | 发现业务对象与问题 |
| 推理与决策 | 推理模式、决策 | 发现未知、判断和选择 |
| 执行与能力 | 工作流、Skill、工具 | 将工作组织成可执行任务 |
| 质量与治理 | 质量、证据、风险、资产、AI 治理 | 判断正确性、控制风险并长期复用 |

## 五、下一步：因素宇宙的独立研究（整理建议）

以12个领域为初始输入，对每个领域逐步建立子因素、定义、适用情境、典型遗漏和验证方法。例如原文已有时间与空间因素的时序、周期、并发、设备、平台、地域；可以先研究这些因素是否造成实际研发遗漏。不要先追求无限枚举，也不要将所有因素强制应用到每个项目。

预期交付：因素树、因素之间的重叠与依赖说明、基于真实业务的遗漏案例。现有8个审计领域负责检查，不另造重复审计表。
