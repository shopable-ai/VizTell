## 七环节输入输出简表（原文 L487–494）

| 研发环节 | 主要输入 | 主要输出 |
| --- | --- | --- |
| 目标理解 | 用户原始想法 | 目标、问题、范围 |
| 需求推理 | 目标、领域知识 | 需求、场景、约束 |
| 产品设计 | 需求与场景 | 功能、规则、交互设计 |
| 技术设计 | 产品设计 | 架构、数据、接口、技术方案 |

## 工作流裁剪条件（L1080–1096）

**已有成果可以复用，不适用的工作可以裁剪，但必要的业务正确性和验收义务不能跳过。**

| 环节 | 裁剪条件 |
| --- | --- |
| 项目恢复 | 当前上下文和有效基线已经明确 |
| 专业研究 | 不存在需要额外研究的关键未知项 |
| 需求重新推理 | 业务需求已经明确且未发生变化 |
| 多方案比较 | 没有真正需要重新选择的技术方案 |
| UI设计 | 不涉及界面和交互变化 |
| 架构设计 | 不改变既有架构与组件边界 |
| 数据设计 | 不改变数据语义、存储或生命周期 |
| 多专家扩展评审 | 没有需要新增专业视角的问题；保留正式审核要求 |
| 生产环境验证 | 本轮交付范围明确不包含生产发布 |

裁剪依据引用现有正式框架的[项目类型与治理配置路由](https://github.com/shopable-ai/ai-native-project-os/blob/1a1867640b7ee538bac21cd1a16d50f6a7e19c0f/docs/workflows/PROJECT_TYPE_AND_GOVERNANCE_ROUTING.md?utm_source=chatgpt.com)。

## 按任务复杂度应用（整理建议）

| 任务 | 重点工作 | 不需要机械执行的工作 |
| --- | --- | --- |
| 新产品 | 目标、研究、需求、产品及技术设计、实现、验收 | 无须为每个模型创建独立文档 |
| 复杂功能变更 | 恢复现有基线、差量需求、受影响的状态/数据/架构、实现、回归验收 | 不重做无关需求和现有架构 |
| 局部缺陷 | 复现、事实与根因、修复、定向回归与证据 | 不默认重做产品设计、技术选型或全量研究 |

下一步应在真实项目中验证上述裁剪和能力编排，重点检查实际输入输出是否衔接、是否减少重复工作，以及是否真实完成。原文所述正式阶段映射、角色编号、Skill引用等仍须读取相应仓库确认。
