# AI-Native Dev · FRAMEWORK R1 执行规则（当前有效）

本文件取代此前 launch/RESEARCH-RUNBOOK.md 的执行范围与完成条件；README和所有启动入口同时生效。原始 prompts/ 和 reference/ 是只读研究输入，不是独立执行授权。

## 当前阶段：FRAMEWORK（只完善通用框架）

建立一套通用的 AI 原生软件研发框架，使 AI 能从用户不完整的原始想法、功能变更或缺陷反馈出发，理解目标、发现必要需求和遗漏、设计合理方案、组织研发、测试、修复、真实验收与持续演化。当前交付对象是框架知识、分类、模型、推理方法、关系和选择规则本身，而不是某个软件产品。

- 当前阶段只做总体框架、专题框架、分层分类、概念定义、关系与推导、方法选择、框架完整性及一致性研究。原始资料是高质量线索，允许扩展、合并、修正、推翻。
- **禁止进入具体业务、产品功能、真实项目应用、源码诊断、缺陷修复、原型或程序实现、浏览器/网站实验、实际产品测试、部署、Skill开发及AI Project OS建设。** 不访问 OpenDesk Browser 或 ai-native-project-os 的代码/项目资料。商业专题不开展特定产品、市场、竞品和价格研究。
- 允许定向查阅通用软件工程、系统工程、需求工程、逻辑推理、决策等成熟理论/论文/标准的原始资料；允许极简的抽象逻辑反例与通用结构推演，不把示例发展为具体业务需求、设计或测试。
- prompts/ 中旧的实际项目、实际运行、产品级验证、实验与工程化要求均是后续研究线索，**在本阶段全部延期，不执行，不作为框架完成门槛**。保留其原始目标、专题知识问题和附录；与本阶段矛盾的旧任务不构成执行指令。
- 框架阶段完成后停止；实际应用及工程化须用户另行明确启动。框架结构自洽不代表实际研发效果已经证实。

## 2. 当前框架研究次序（F1/F2/F3）

F1 总体及专题一级框架：先建立共同总体地图和专题职责，保留原12因素、16研究维度、15链路、17常用模型、13推理模式、七类主体/九专家领域、八审计领域、13候选Skill、七OS组件等线索入口。检查每个专题的一级结构、主要分支、与其他专题边界。优先让A–N都有可读候选，再针对关键分支深挖。允许O早期局部整合。
F2 专题框架深化：针对各专题尚未解决的知识问题，研究分类是否同层、遗漏、关系、包含、独立用途、输入输出、适用和选择条件、组合、反例与停止标准。按需扩展二/三级，不机械追求术语数量或固定互斥。引用邻近专题而非重建其框架。以通用理论核查、逻辑反例和结构比较支撑结论；不开展真实业务对照。
F3 总体收敛：O对照所有现有框架，整理共同定义、跨专题交接、必要视图、重叠与冲突裁决、原始资料去留及剩余问题。发现框架缺口返回相应专题继续完善，不必等待真实项目测试。直到框架本身满足完成条件。

专题职责：
- R3-A 因素宇宙：12领域、16维度与六类候选视图；因素、对象、属性、条件、取值、约束、质量、证据状态的区别，分层、关联、组合与选择。
- R3-B 链路宇宙：15专项链、总链及详细推导链；节点、边类型、输入输出、条件、共享节点、分支/循环/反馈/回退。区分推导、业务行为、执行与证据。
- R3-C 需求推理：八节点需求链、四组机制；意图、目标、问题、场景、能力、功能、规则、需求与验收的定义、必要性、异常、冲突、裁剪、收敛。
- R3-D 工程模型：17常用条目；模型、对象、视图、表示；模型家族的职责、最小语义、独立价值、适用性、关联与选择。35/14历史清单缺失须如实标明。
- R3-E 项目多维拆分：目标、业务、产品、技术、交付、垂直专业方法和横向复用等拆分轴；独立边界、粒度、依赖、交叉关系及可验收性。
- R3-F 角色与多专家：七类利益相关者、九类专业知识、责任权限、实际参与者；动态利益、专家选择、独立判断、分歧与裁决。
- R3-G 推理模式：13模式及演绎、归纳、溯因；区分逻辑、方向、探索策略、证据与评价；方法语义、条件、组合、停止与反例。
- R3-H 盲区审计：八审计领域、审计对象及缺陷性质、双向推演；15成熟方法线索按用途研究，风险优先、结果处置、回流和审计边界。
- R3-I 研发工作流：五阶段、七环节、十环节视图的关系；抽象任务路由、模型/方法/角色/能力编排、条件、裁剪、复用、并行及回退。
- R3-J Skill、工具与Agent：13候选专业能力的分类、边界、选择、接口、权限、失败处理；能力、工作方法、工具、执行者及工作流的区别；不实现Skill。
- R3-K 知识资产与知识复利：来源、想法、假设、事实、证据、决策、资产、方法和经验的分类与状态；索引、恢复、失效、回归知识和复用。
- R3-L AI执行治理：上下文、状态、权限、模型及工具选择、成本、并发、重复、失败、人工干预与质量的控制原则、观测指标定义。
- R3-M 商业与运营框架：用户/购买者/受益者、价值、市场因素、商业假设与反馈、运营及企业经营边界；仅研究通用框架。
- R3-N AI Project OS概念框架：七个候选组件的职责、关系、替代性、必要性假设与系统边界；暂不判断真实项目实施收益，不建设系统。
- R3-O 总体框架整合：整合总体地图、处理分类重叠和跨专题接口，审查覆盖、逻辑、理论依据、可阅读性、必要性，分离未决框架问题和后续实证待办。

## 3. 实质推理，不是计划或文档生产

先回答总体结构、再回答各分支问题，再审查跨体系关系。选择目标反推、归纳演绎、抽象分解、逻辑反例、对抗审查、条件/约束、价值判断等适合问题的方式，必要时针对通用知识疑问检索原始专业资料。不要求每轮使用全部推理方式，不因为深度要求转为具体产品试验。每个结论说清解决什么问题、为什么有用、何时适用、与其他定义的区别以及尚未确认事项。对原始重要线索进行保留/补充/修正/合并/否决/延期/未知的明确处置。优先输出可读总图和重要结论，细节只在真正有价值时展开。

支持真实独立Agent时可以分派独立专题（建议最多3个活动专题），但所有执行者遵守同一FRAMEWORK边界。没有独立Agent时直接逐专题研究，不假称后台执行；同模型自审不等于独立专家。脚本最多负责本目录资料读取、状态和结构核对，不运行产品实验、部署、外部任务或未经授权的付费API。实际能力允许时持续完成下一个未完成框架问题；不能只返回新计划或新提示词，也不能为了分数无限循环。遇实际资源/工具限制及时保存可用成果和续跑点。

- 提交前读取最新main和目标文件；若其他对话正在写入，合并已有结果，不覆盖并发增量。非强制提交；提交后核验实际差量、路径和内容。无权限提供可下载成果，如实报告。

## 5. 框架阶段完成条件（Q1–Q6）

Q1 相关性：所有研究服务原始框架目标，阶段无偏移，职责与非目标明确。
Q2 知识及证据：关键定义正确，理论支持与推断分开，有可追溯依据和重要反例；不能把理论假设当事实。
Q3 覆盖及结构：原始重要线索有明确归属和去留；分类层级、维度、概念、关系和缺失可审查，不宣称绝对穷尽。
Q4 深度及新增价值：重要分支有实际可理解的语义、用途、适用条件、选择/组合规则及失败边界；不是重复整理。
Q5 可读及可用：先总图、后细节，非必要的概念、冗余文件和复杂协议已裁剪；未来能够指导应用，但不提前应用。
Q6 整体一致性：专题职责、共享定义、交接及关键冲突已处理；保留的不同视图有清楚理由。重要未决框架问题有明确处置，后续实证待办单列。

按100分分别对Q1–Q6评价，等权平均，目标各项及综合≥95；每项列依据与不足，区分自评/真实独立评审；不可评则标未评并报告覆盖，不能虚构专家分数。重大知识错误、严重遗漏、框架冲突、越界应用、无实质增量、虚假证据或评审具有否决权。达到框架条件才能报告框架阶段完成。真实产品效果、实际运行成本、性能、真实项目收益及后续系统建设没有验证不构成本阶段阻断；这些仍必须如实标为后续待验证，不能从框架评分推断实际有效性。

本轮最终输出：语义化关键结论、框架实际新增成果、原始资料差量、已完成/未完成、理论/结构审查依据、剩余框架问题、真实提交和下一步最小必要任务。完成F1不等于整个框架完成；F2/F3继续做。框架收敛后停止，等待用户明确授权实际应用阶段。
