# 跨宇宙多维推理与节点续研协议（V0.1）

> **归属**：现有“思维与方法宇宙”的共享方法文件，不另建“所有知识的大一统宇宙”。补充 [链路垂直深挖与审计框架](../通用链路宇宙/19_链路垂直深挖与审计框架.md)，不取代其 A—H / 30 维审计，也不新增通用链 C31。

## 1. 两个互补层次：空间框架与局部执行

**第一层：推理空间框架（Map）**回答“有哪些可能的解释、对象、时间尺度、证据和研究方向，缺了哪里”；主要控制**广度、分类、依赖及优先级**。它不保证每个节点都深入。

**第二层：节点续研（Run）**回答“现在要解决其中哪一个问题，怎么查证、何时停止、怎样回写并恢复”；主要控制**深度、证据、行动与反馈**。它不能无限扩张当前节点而遗忘原始目标。

两层互相作用：Map 产生可研究节点 → Run 产生证据、修订或新节点 → 增量回写 Map → 重新排序；不以“内容越来越长”作为进度。

## 2. 横向、纵向之外的十个推理坐标

| 坐标 | 功能 | 典型提问 | 主要产物 |
| --- | --- | --- | --- |
| B 广度（Breadth） | 横向扩展相关领域、参与方、候选机制、方案和反例 | 还遗漏哪类解释？ | 候选地图/覆盖矩阵 |
| D 深度（Depth） | 纵向拆因果、前提、层次、边界、可验证机制 | 为何成立，下一层是什么？ | 分解链/机制卡 |
| T 时间（Temporal） | 周期、生命周期、时滞、转折、路径依赖、窗口 | 何时成立，怎样变化？ | 时间轴/阶段模型 |
| S 尺度（Scale） | 微观到宏观、数量/频率/复杂度跃迁 | 规模变化后还有效吗？ | 条件跃迁矩阵 |
| C 因果（Causal） | 假设、混杂因素、竞争性解释与识别方法 | 真正造成结果的是什么？ | 因果候选/验证设计 |
| P 视角（Perspective） | 不同利益相关者、角色、目标与价值权衡 | 换谁的立场结论会变？ | 参与者利益表 |
| E 证据（Evidence） | 事实、主张、样本、反证、置信、版本 | 我凭什么相信这个结论？ | 证据链/未知表 |
| G 关系/系统（Graph） | 依赖、网络、反馈、边界、跨域联系 | 哪些节点相互影响？ | 关系图/反馈图 |
| F 反事实（Counterfactual） | 对照、替代路径、条件改变、失败预演 | 假如没有 X 会如何？ | 情景/反例 |
| A 行动（Action） | 干预、实验、优先级、风险、退出 | 下一步如何低成本验证？ | 决策与行动契约 |

这些是**观察/推理轴，不是十种并列宇宙目录**。时间 T 可以调用独立 [周期与演化宇宙](../周期与演化宇宙/README.md) 的专业知识；因果 C、证据 E 可以调用既有“思维与方法宇宙”的专业方法。根据任务需要选坐标，不强制每次填十轴全表。

## 3. 横向扩展的边界

横向不等于随意联想：候选节点必须说明与问题的关系（解释、条件、反例、依赖或行动价值）。优先遍历**主要竞争解释、缺失利益相关方、不同层级、边界场景和外部约束**。停止条件是新增方向预计不会改变当前重大决策，或继续搜索成本高于收益；保留未探索区作为 backlog。

## 4. 纵向深挖的边界

对选定节点依次检查：定义 → 前提条件 → 作用机制/状态 → 反馈/时间 → 证据 → 竞争解释/反例 → 可测指标 → 决策含义。若发现根本是目标、问题或需求定义错误，先返回上层；若继续细拆不能提高可检验性或行动价值，则停止，不制造虚假的无限深度。

既有 [19_链路垂直深挖与审计框架](../通用链路宇宙/19_链路垂直深挖与审计框架.md) 已涵盖语义、结构、时间、规模、价值、执行、韧性和系统等专业深挖维度；本文件只增加“**跨宇宙空间导航 + 节点续研状态**”这一接口。

## 5. 节点续研最小状态机

- **candidate**：被识别但尚未排入研究；
- **selected**：因与原目标和价值相关被选中；
- **researching**：采集事实、整理竞争解释；
- **testing**：设计实验或对照验证关键未知；
- **provisional**：有条件性结论但证据未完全闭合；
- **validated**：达到预先声明的验证门槛（不是宣称绝对真理）；
- **blocked**：等待来源/权限/成本或上游决定；
- **revised**：被新证据修订，保留版本；
- **archived**：价值不足、失效或被替代，仍可回溯。

状态可以按关系返回；不存在强制线性推进。**未经证据支持的 AI 推断不能直接跳成 validated。**

## 6. 一轮研究节点的操作契约

输入：
1. 原始问题与明确决策目标；
2. universe_owner、node_id、node_type（机制、周期命题、失败模式、项目案例等）；
3. 当前结论、事实/主张/未知、关联节点、版本；
4. 可用时间和信息、风险约束、最重要的待验证假设。

执行：
1. **恢复上下文**：只读节点摘要、证据和未完成项，不重跑整个宇宙。
2. **决定扩或钻**：广度不足选 B/G/P，机制不清选 D/C，时机不清选 T，可信度不足选 E/F，无法行动选 A。
3. **选择最小有价值问题**：最多优先处理会改变结论/行动的关键未知，不因追求条目数扩大任务。
4. **研究并记录来源**：区分事实、引用主张、假设、推论、未知和争议。
5. **反方/对照检查**：至少一种替代解释或反例；必要时跨其他宇宙检索专业知识。
6. **验证或注明阻塞**：能测试就定义指标、可复现步骤和完成条件；不能测试则标记待核。
7. **差量回写与决策**：只改受影响节点、关系与索引；更新版本、决定继续/暂停/终止。

输出：
- 结论变化摘要（新增/修订/推翻/不变）；
- 证据与来源链接、反例和不确定性；
- 新关系及其证据状态；
- 下一轮一个清楚的切入点，完成/退出条件；
- 对实际项目建议的动作与需要人批准的关口。

## 8. 演示：从一个问题触发多个独立宇宙

原问题：“新平台抢走了用户注意力，大公司是否必然反击？”

- **先扩 B/P**：枚举被争夺的变量（时长、份额、收入）、参与者与合作/忽略/反制的不同路线。
- **再钻 D/C/E**：打开社会规则 SR-004，查实威胁感知、回应能力及成本收益证据。
- **时间 T**：如存在产品窗口、竞争反馈滞后，引用“周期与演化宇宙”；并非自动升级成固定经济周期。
- **行业失败**：若问题转为“产品/系统为何失效”，打开“软件 IT 失败宇宙”；若问“企业项目怎样错误立项和交付”，打开“企业项目失败宇宙”。
- **行动 A**：为现实项目建立观测指标、验证条件、阶段门和止损机制。
- **回写**：保留各宇宙的专业解释以及同一证据的稳定来源引用，不将四个目录合并。

## 9. 质量门槛与防漂移

- **目标忠实**：每个扩展或深挖都能说明如何帮助原始决策。
- **语义归属**：同名不同义不能合并，同义不同名不能重复造真相。
- **时序正确**：周期、生命周期、阶段和冲击不混淆。
- **因果克制**：不把相关性、单案、专家主张提升为已验证因果。
- **来源和反例**：可追溯，至少保留一个竞争性解释入口。
- **轻重适配**：简单问题只用必要轴；复杂问题才全面审计。
- **状态与退出**：明确完成/待核/阻塞/继续/归档，不声称后台执行。
- **独立验证**：评分可作为审查工具，**未做真实评审不能自称 95 分或已验收**。
