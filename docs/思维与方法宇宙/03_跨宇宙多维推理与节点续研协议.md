## 1. 两层架构与唯一职责

| 层 | 输入 | 输出 | Owner与边界 |
| --- | --- | --- | --- |
| Global Map | 真实资产清单、候选因素、开放缺口、已完成Run的增量、当前目标和风险 | 对象类型、稳定ID、专业归属、关系、研究队列、优先级及重算触发 | [全局入口](../00_知识宇宙目录与跨域关联.md)负责路由；[候选矩阵](../01_全局宇宙候选与研究优先级.md)负责排程；不替代专业正文 |

## 2. 十个坐标保留，明确它们不是数学正交轴

| 坐标 | 类型 | 具体工作 | 合适的可核验产物 |
| --- | --- | --- | --- |
| B 广度 | 搜索动作 | 扩展宇宙、参与者、变量、观点、备选方案与反例 | 有相关性理由的候选/遗漏表 |
| D 深度 | 搜索动作 | 分解定义、前提、机制、中介、边界、根因假说 | 能区分解释/论证、暴露反例或产生适用预测的分解 |
| T 时间 | 情境坐标 | 时序、窗口、阶段、趋势、周期、时滞、路径依赖 | 时间线、阶段依据和观测区间 |
| S 尺度 | 情境坐标 | 个体/团队/项目/企业/行业/社会，以及数量、密度、频率跃迁 | 尺度外推边界，避免生态与个体推断互换 |
| P 视角 | 情境坐标 | 主体、利益、目标、规范价值及受益/受损差异 | 多主体结果向量，目标冲突不藏进平均分 |
| C 因果 | 解释透镜 | 共同原因、选择偏差、中介、交互、竞争解释与识别 | 候选因果图、识别假设与反证设计 |
| G 系统关系 | 解释透镜 | 网络、约束、依赖、反馈、存量流量、非线性与涌现 | 类型化关系及动态假说；连线不是证据 |
| F 反事实 | 解释透镜 | 在明确模型及条件下改变行动/前提，比较可行替代 | 对照设计、潜在结果问题；不是虚构历史事实 |
| E 证据 | 质量约束 | 来源定位、测量、方法、偏倚、独立性、反证、时效 | Claim—Evidence链接及证据不足范围 |
| A 行动 | 落地约束 | 将结论转成观察、实验、规则、风险门或不行动 | 可验证的下一步、责任、成本、停止和撤回 |

D可深入T/C/G，E检查所有坐标，P影响A；这种交叉是工作机制，不是假装正交。短任务只选择会改变判断的坐标，但语境、证据边界和下一状态不能省略。

### 2.1 反向推理是算子，不强造第十一宇宙或第十一正交轴

- 从结果倒推候选原因：`reverse(C)`；由果不能推出唯一因。
- 从目标倒推必要条件：`backcast(T,A)`；必要条件不等于充分条件。
- 从失败倒推防线：`premortem(G,A)`；设想失败不等于预测失败。
- 反事实F问“如果条件或行动不同会怎样”，反向问“要解释/达到这个结果需要哪些前提”；两者可组合但不同。

### 2.2 本轮补足四类语境，不无限增加轴

每个Run先用一小段说明：

1. **空间/环境/人群**：国家地区、制度、平台、生态、样本选择与适用范围；没有数据就标未知。
2. **目标/价值**：谁的结果、什么期限、什么底线、哪些利益冲突；不默认短期收入最大化。
3. **测量/可观察性**：变量定义、单位、分母、数据缺失、代理指标；无法测量时写出可检验方式或局限。
4. **不确定性/可干预性**：随机性、知识缺口、概率依据、不可观测与可控变量；主观置信不冒充统计概率。

它们分别约束T/S/P/G、E/C和A；长期出现稳定独立缺口才考虑扩展坐标，不为对称凑数。

## 3. 周期为何能承担不同角色

| 使用方式 | 它此时是什么 | Owner与错误防线 |
| --- | --- | --- |
| 研究什么形成周期、如何识别相位和非平稳变化 | 独立研究对象/模型 | [周期与演化宇宙](../周期与演化宇宙/README.md)；不假定每次重复间隔相等 |
| 在任何领域标出窗口、阶段、时滞和观测期 | T时间坐标 | Run引用动态定义；有时间标签不代表已发现周期 |
| 横向比较经济/技术/资金/项目节奏 | B×T比较操作 | 可比较但不因名称都叫周期就认定相同机制 |
| 向下追踪反馈、存量、阈值和延迟 | D×C×G×T深挖 | 回到19号深挖框架相关维度；需要机制和数据 |
| 将周期阶段作为条件或变量 | 某模型中的动态使用关系 | 阶段测量与阈值有依据；观测窗口、去趋势、冲击与竞争解释要声明 |

周期不是任意结果的万能原因。生命周期、单次冲击、累积演化、趋势不能都重命名为周期。社会演化、生物演化、技术演化只先建立语义相关，不能直接跨域等价。

## 4. 有界研究的输入契约

短Run与长Run使用同一记录，不另建平行表单。以下**八组底线不可省**，可用短句或指向已读记录的明确链接继承；未知写明原因，不能为了完整而虚构。运行开始时填写前六组的计划，结束时补第七、八组的实际结果。

| 所有Run必填组 | 最小内容 | 继承或缺失处理 |
| --- | --- | --- |
| 1 身份与责任 | run_id、node_id/type、正文位置、run_owner | 文档Owner可引用原入口；本轮执行者必须承接，未承接则不假称运行 |
| 2 唯一问题 | parent_goal、focus_question | 用一条主问题说明本轮要改变什么判断；不把全部未知变为本轮任务 |
| 3 来源与恢复基线 | base_ref、已用来源定位、旧结论或“首轮” | 从旧Run继承但重新核对本轮依赖；来源变化按§7.4处理 |
| 4 研究边界 | scope_in/out、claim_kind/evidence_regime、validation_scope、行动上限 | 引用本节证据制度；假设演示显著标hypothetical，未授权现实动作保持research_only |
| 5 证据与未知 | 已知、来源陈述、假设、反证、未解决项 | 可明确“暂无”；不默认未观察=不存在，不把同源转述当独立证据 |
| 6 预算与验收停止 | budget、acceptance_criteria、stop_when | 可继承默认两轮；没有有界问题/验收门则先路由，不无限搜索 |
| 7 实际差量与状态 | delta_types、state、evidence_status、run_outcome、写回位置 | 按实际结果填写；无增量也记录，不由运行完成提升证据或权限 |
| 8 恢复入口 | unresolved、next_action、resume_trigger | 指向下一证据或条件；已结束也说明何种变化才重开 |

**按需继承**：`priority_profile`直接引用01的队列条目，仅在首次排队或重排时补评分；Outcome/指标、选用坐标、因素映射可指向已核对的专业记录，不复制整表。**按触发追加**：提出因果解释时补竞争解释/识别；跨尺度或网络时补§4.1；实际风险暴露时补01风险门；新语义映射或来源变更时补§7.4。未触发的分支无需填空表。所有继承需可定位到记录及版本，不能写“同前”却无法恢复。

`validation_scope`按主张类型选择，不能形成“所有知识最终升级为因果”的阶梯。共同记录`claim_kind / evidence_regime / acceptance_criteria`：

| 主张类型 / 证据制度 | 合法验收范围 | 必需检验及停止边界 |
| --- | --- | --- |
| 结构/身份契约 | structure | ID、字段、Owner、引用和运行状态一致；不推导科学有效性 |
| 来源/历史事实 | source_statement / historical_claim_for_scope | 原始定位、年代、人群、来源角色、交叉核验和材料冲突；证实“作者说过”不等于事件因果 |
| 经验描述/关联/因果 | empirical_association / causal_for_scope | 测量、样本选择、竞争解释；因果主张还需识别假设、共同原因、可区分预测和相应数据 |
| 形式命题 | formal_validity_for_assumptions | 定义、公理/前提、推导步骤、反模型或独立证明检查；逻辑有效不表示前提符合现实 |
| 规范/伦理/价值论证 | normative_coherence_for_stated_values | 事实—价值分离、声明价值前提、各方权利/利益、逻辑一致性、反驳与权衡；不宣布单一普遍价值已被实验验证 |
| 诠释/历史意义/艺术理解 | interpretive_fit_for_corpus | 材料、语境、解释透明度、竞争阅读与反例；允许有依据的多解，不伪造唯一客观审美分 |
| 工程设计/现实决策 | requirement_satisfaction / decision_outcome | 显式需求、约束、验收对象、测试/观察、成本和副作用；设计合格与现实收益分开 |

混合问题拆成不同主张并分别验收。例如一个政策问题的“能否产生效果”与“是否正当”不共用证据状态。单条主张的`validation_scope`使用一个字符串标签；多范围时拆分主张/验收行，不在同一字段交替使用字符串与数组。`validated`只能指上述指定范围，不能跨制度转授。医学/法律等具体领域仍需其专业证据与权限要求，本表不取代。

### 4.1 跨尺度与网络外推的触发契约

从个体转群体、单项目转行业、局部参数转系统结论，或跨国家/平台迁移时，必须补：`analysis_unit`（单位）、`population_boundary`（总体）、`aggregation_rule`（汇总方式）、`heterogeneity`（分布差异）、`transport_assumptions`（迁移前提）。不能用均值掩盖尾部和分配效应，也不能把群体相关当个人机制。

网络/反馈结论另记`node_definition / edge_definition / observed_coverage / topology_or_dependency / feedback_sign / lag / common_cause`。未观察边不能直接当不存在；连接密度不代表影响强度。存在反馈时用时间展开或动态模型说明，不能在要求无环的因果图中直接画循环并宣称识别。

关键字段未知且可能翻转结论时，只保留原尺度结论，建立有界的补测问题；不得凭语词相同外推。该契约补充既有19号深挖的规模/系统审计，不另写一套方法。

默认一轮只保留一个主问题；最多优先处理三种可区分的竞争解释。预算由任务确定；未给预算时先设两个“检索—判定”回合，每回合结束检查是否仍会改变选择。这是成本治理起点，不是科学充分性标准；达到预算只能结束本轮，不能强制把结论升为验证通过。

## 5. 运行、知识与行动状态分开

延续V0.1的`state`研究状态：

| 状态 | 含义 | 允许进入/退出的条件 |
| --- | --- | --- |
| candidate | 已登记未选择 | 具备相关性/风险理由后可selected |
| selected | 当前有界问题已确定 | Owner承接、预算与门槛明确后researching |
| researching | 查证事实、机制与竞争解释 | 有可执行验证设计才testing；没有数据可blocked |
| testing | 按预先声明的门槛验证 | 按实际结果进入provisional、validated或revised |
| provisional | 有条件性结论，关键未知未消除 | 可结束本轮或继续；不能假装因果已定 |
| validated | 只在声明的scope/版本上达到门槛 | 必须记录门槛、实际证据、范围、局限与复核触发 |
| blocked | 来源、测量、Owner、预算等阻塞 | 触发条件满足后回selected；不后台无限重试 |
| revised | 新证据改变结论或边界 | 保留旧版本与来源，再选择/验证 |
| archived | 已被替代、价值下降或明确停止 | 新场景/新证据可重新candidate，旧ID保留 |

同时单独保留：

- `evidence_status`：沿用专业Owner/Canonical的证据词汇；没有证据不能因state改变而自动上调。
- `action_permission`：research_only / observe_or_measure / conditional_guidance 等是允许使用的上限，不替代实际用户授权。风险、专业与伦理约束按场景另核验。
- `run_outcome`：continue / paused / revised / ended；运行结束不代表节点已证真。
- `delta_types`：去重数组，合法项为new_evidence、new_condition、new_boundary、counterexample、changed_relation、changed_decision、no_change。单项也用数组；no_change不能与其他项共存。只有新增名词或改写用语记[no_change]。

例：本轮来源检查完成，可以 `state: provisional`、`run_outcome: ended`、`validation_scope: source_statement`、`evidence_status: unresolved`。不要为了体现“已完成”把整条因果链标validated。

## 6. 一轮Focused Run的八步

1. **恢复**：读原节点结论、证据定位、差量和复核触发，核对最新版本；不重跑全库。
2. **框定**：一个主问题、结果Owner、作用范围、预算、停止条件；检查当前风险与前置依赖。
3. **召回**：从全局地图和因素表取最小相关集合，找既有专业解释和同义条目；无关新方向进backlog。
4. **选方法**：按B/D/T等组合；机制不清才深挖，口径不清先定义指标，可信度不足先找反证。
5. **搜证据**：记录来源、日期、定位、语句类型、数据口径与独立性；将支持、反对、未知分开。
6. **按主张类型检验**：采用第4节相应分支。经验机制问题比较竞争解释和可区分预测，说明所需数据、对照与识别假设；形式问题检查推导/反模型，规范问题检验价值前提与反驳，诠释问题比较材料与竞争阅读。不能把差异比较自动当因果识别，也不强迫所有知识走因果实验。
7. **判定和停止**：按预设门槛写条件化结论；不能测试则写阻塞。分别结束本轮与保留节点问题。
8. **差量回写**：先更新专业正文/证据，再更新关系、索引和队列；读回确认。只报告实际变更和实际验收结果。

## 7. 停止、漂移与回归

### 7.1 停止条件

- 当前证据已足以支持本问题在声明范围内的决策，新增研究不会改变它；
- 到达预算，或关键信息不可获得，转paused/blocked并写恢复触发；
- 连续一轮只有同义改写、相同来源或同一解释，记no_change并停止重复；
- 原目标或测量定义错误，回到最近受影响环节；
- 风险/行动权限/专业边界不允许继续原动作，调整为观察或有界核验；
- 失去维护Owner，冻结更新，保留引用，不删除来源。

高风险问题停止无证据行动，不等于停止所有研究。风险门有暴露对象、证据/未知、有限核验任务、负责人、解除条件；不能用无限想象的灾难永久阻塞全部队列。

### 7.2 回写顺序与并行冲突

提交前重读 `main` 并记为`expected_head`。若与base_ref不同，检查本轮触及的文件与Owner差量，先合并并行内容，再以最新HEAD为唯一父提交构建增量。采用非强制快进和CAS条件更新：`expected_sha=expected_head`、`force=false`；不能只“读过一次”就无条件覆盖分支。

CAS或非快进拒绝后，先读新HEAD确认远端是否已包含本次提交（回执不明时禁止盲目重放）；尚未包含才比较差量，在新HEAD上重基文档、复核受影响链接/ID/状态并重新提交。一次重基后仍持续竞争时暂停该次提交，保留可复审差量与具体冲突，不强推、不扩大覆盖范围。提交成功后读回分支HEAD及变更文件blob SHA，报告实际提交和读回结果。

来源事实、专业解释、索引关系各写唯一位置；一个事件可多视角引用，不能多处维护原始时间线。

被推翻结论保留ID、旧版本和反证，标记superseded/revised。跨仓库只更新引用状态，不擅自修改外部Owner。AI人生系统的个人结果或资料永不复制进公共样例。

### 7.3 有界回归

| 变更 | 最小回归范围 |
| --- | --- |
| ID/别名/Owner/链接 | 检查唯一性、引用可解析、受影响案例路由 |
| 因果关系/条件/证据 | 回跑该主张的支持/反证、竞争解释与行动边界 |
| 评分权重/阈值 | 重算受影响队列、缺失区间、低频高风险与敏感性 |
| 状态/接口 | 回跑恢复、阻塞、无增量、修订、结束的分支 |
| 动态定义/周期命题 | 检查观测窗口、重复性与冲击/趋势的区分 |

本轮三例是固定结构夹具：A注意力竞争、B采用失败、C假设跨维。它们不覆盖全部宇宙；新专业宇宙准入时必须增加能挑战其边界的例子，不能只增加更多相似成功样例。

### 7.4 来源或语义Owner变化：核对、局部暂停与恢复

`semantic_owner_ref`是正文责任位置，不是已接受任务的真实人员。本次`run_owner`负责在**实际使用节点**及提交前核对来源版本和语义依赖；不扫描全库，不任命外部Owner。跨仓字段统一引用[全局地图§7](../00_知识宇宙目录与跨域关联.md)；Run只记录或引用`semantic_source_ref=repo@commit:path#原ID/精确小节`、`review_status`及必要的`review_reason / affected_refs`。

- `current_for_scope`仅表示本次已核对的使用范围；不等于原Owner已确认候选构念等价。实际使用的近邻构念要在专业记录留一句裁决：原定义定位、范围差异、采用/拒绝映射的理由；因素总表只留指针和状态。
- 发现路径失效、同路径定义改变、原ID弃用、Owner迁移或契约冲突，受影响**新用途**先标`needs_review`；无法安全解释则`frozen`，本轮可转`blocked / paused`。`affected_refs`只列已知受影响引用，不要求全库反向索引。旧来源及旧scope的历史记录保留；新用途不得继承旧行动上限。暂停仅限受影响写回/复用，不冻结无关队列。
- 恢复由本次run_owner核对本次选用的来源版本及适用边界，解决冲突或明确缩小scope，检查受影响ID/路由/证据权限并读回，记录核验日期及差量后改为`current_for_scope`。仅研究可核验旧版本时明确限定历史，不宣称当前有效。无法完成则保持blocked并写具体恢复触发；不得只改状态字样。

上述是既有Run中的引用复核合同，不是新增全局状态机。Owner无人承接时不能声称映射获准；研究仍可保留候选和来源缺口。维护失效/恢复的合成挑战见[R2验收§6.2](../03_全局路由样例与R2验收.md)。
