## 1. 覆盖等级与字段

### 1.1 覆盖等级

- **A 丰富覆盖**：正式名称之外，已有多个问题、目标、场景、搜索句或大众表达入口，并且可以较稳定地落到该知识。
- **B 基本覆盖**：至少存在 2—3 种非正式名称入口，能够实际路由，但表达多样性仍有限。
- **C 稀疏覆盖**：主要依赖正式名称、方法族或一级任务入口；普通用户不知道名称时仍较难找到。
- **D 无自然语言入口**：几乎只能先知道正式名称，或必须经过专业人员二次解释才能发现。

### 1.2 矩阵字段缩写

| 字段 | 含义 |
|---|---|
| 名 | 正式名称入口 |
| 标 | 规范标签入口 |
| 问 | 用户问题入口 |
| 目 | 用户目标入口 |
| 场 | 场景入口 |
| 搜 | 搜索问题句 |
| 大 | 大众表达 |
| 传 | 传播语言入口 |
| 歧义 | L 低 / M 中 / H 高 |

`名=Y` 只是证明“知道名字就能找到”，不能代替自然语言覆盖。

## 4. 明确保留为 C / D 的专业长尾入口

以下并不是“低价值知识”，而是**普通用户很少在不知道名称时直接搜索到它们**。当前宁愿保留稀疏，也不制造伪口语入口。

### 4.1 C 级：有任务入口，但实体入口稀疏

- 统计与测量：ANCOVA、等效性检验、非劣效性检验、判别分析、SEM、稳健统计、过程能力指数；
- 因果：前门准则、d-分离、IPW、负对照、安慰剂检验、因果敏感性分析；
- 运筹：整数规划、混合整数规划、凸优化、动态规划、MDP、最大流 / 最小割、EOQ、报童模型；
- 安全：STAMP、STPA、LOPA、FRAM、GSN、可靠性增长；
- 系统 / 建模：VSM、CATWOE、N² 图、DSM、ArchiMate、SysML 参数图；
- 研究：理论抽样、文献耦合、共被引分析、多阶段抽样、注册报告；
- 未来研究：交叉影响分析、风洞测试、因果层级分析。

典型入口策略：

```text
用户问题 / 场景
→ 先路由到方法族
→ 再根据数据条件、研究设计或专业约束选择具体方法
```

### 4.2 D 级：当前几乎只有正式名称入口

- 赔率形式贝叶斯；
- GSN 目标结构化表示法；
- 某些 UML / SysML 低频专用图；
- 部分高级组合优化启发式；
- 部分统计检验细分变体；
- 部分专业安全工程分析法。

D 级不是要求“赶快补标签”，而是要求：只有真实用户语料、真实检索失败或明确使用场景出现后再升级。

## 6. “正式知识 → 用户怎么说”入口包

### 6.1 实施意图

用户不一定会搜“Implementation Intentions”，更可能说：

- 我每次都说“等会儿做”，怎么才能到点自动开始？
- 能不能给自己设一个“如果发生 X 就做 Y”的规则？
- 我怎么减少临场再做决定？
- 为什么计划到了具体场景就忘了？
- 怎样把“想做”变成遇到触发就做？

### 6.2 贝叶斯更新

- 有了新信息后，我原来的判断该改多少？
- 之前我觉得八成会发生，现在出现反证怎么办？
- 我怎么避免一次新消息就彻底翻转观点？
- 新证据到底应该怎样影响旧判断？
- “根据证据不断修正概率”有什么方法？

### 6.3 金字塔原理 / BLUF

- 领导总说我讲半天没重点。
- 我汇报时是不是应该先说结论？
- 怎么把一堆细节压缩成三层结构？
- 对方只有一分钟，我应该先讲什么？
- 怎样让邮件开头就告诉对方要什么？

### 6.4 检索练习

- 我看懂了为什么过几天还是想不起来？
- 不重看书，怎么检查自己到底记住没有？
- 为什么做题比反复看笔记更容易记住？
- 我该怎么用自测代替重复阅读？
- 复习是不是应该先回忆再看答案？

### 6.5 决策停止规则

- 我到底还要查多少资料才算够？
- 我总能找到新的信息，所以一直不敢结束分析。
- 什么时候继续研究，什么时候直接做决定？
- 如果没有百分之百确定，我怎么知道该不该停？
- 怎样给“继续搜索信息”设一个终点？

### 6.6 来源追溯

- 这句话最早是谁说的？
- 一堆文章互相引用，我怎么找到第一手来源？
- 这个数据到底来自研究还是营销稿？
- 我怎样判断十篇文章其实都来自同一个消息源？
- 怎么查一个爆款观点的原始上下文？

### 6.7 COM-B

- 我不行动到底是不会、没条件还是没动力？
- 为什么我明知道重要还是做不起来？
- 一个习惯失败应该先查能力、环境还是动机？
- 我不想把所有执行问题都怪在意志力上。
- 行为改变前有没有一个诊断框架？

### 6.8 信息价值 VOI

- 再查一个小时资料值不值？
- 我应该花多少钱买更准确的信息？
- 信息不完整时，是先行动还是继续调查？
- 一个测试结果能不能改变我的选择？
- 什么信息值得先获取，因为它最可能改变决定？

## 7. 覆盖缺口分型

### A：语言太宽，需要消歧

典型：`提高认知`、`内核稳定`、`强者思维`、`人性真相`、`格局`、`情商高`。

处理：不增加单一强映射；增加拆解问题。

### B：标签层缺入口

典型：正式知识已有，但用户不会说名称，如 `信息价值`、`停止规则`、`共享信息偏差`、`独立判断后汇总`。

处理：补问题句、目标句、场景句。

### C：上游正式知识可能缺口

典型：`自我接纳`、`自我关怀`、`主体性 / personal agency`、`人际边界`、`情绪调节`、`心理韧性`。

处理：进入 `09_上游正式知识缺口候选池_V1.md`，不在本层冒充正式知识。

## 9. 本文件结论

1. **V1 架构不需要重做。**问题主要是入口数据覆盖深度，而不是分类轴错误。
2. 28 个一级类都有入口，但专业长尾实体仍大量为 C/D；这是当前真实状态，应保留。
3. 高需求区域——判断、决策、执行、学习、沟通、自我调节、问题解决——已经建立更密集的“正式知识 ↔ 真实问题”入口包。
4. `爱自己 / 内核稳定 / 主体性 / 强者思维` 等不能因为高传播就统一成一个标签。
5. 下一步验证必须由独立 Benchmark 检查，而不是继续靠“看起来合理”的人工例子自我确认。
