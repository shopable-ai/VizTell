# 3. 心理大众词的专业边界样本

## 3.1 精神内耗

安徽理工大学心理健康教育中心的公开材料明确指出：

> “精神内耗”并非心理学或精神病学专业名词，很难从专业文献中找到统一明确定义；材料把它描述为围绕同一事情反复产生相互冲突的想法、犹豫和心理资源消耗。

来源：  
https://xljk.aust.edu.cn/info/2430/1606.htm

澎湃新闻 2022 年采访多位心理 / 精神科专业人士时，也有专家明确表示该词不是心理学专有名词或医学术语，并指出它可能覆盖焦虑、担忧、内心冲突、迷茫等多种状态。

来源：  
https://www.thepaper.cn/newsDetail_forward_19261796

**V1 结论**：

- 保留为高价值用户问题标签；
- 不把它当正式诊断；
- 必须分型后再映射知识；
- 若状态持续严重影响生活，标签系统不能用简单自助方法替代专业评估。

## 3.2 内核稳定

山东大学学生心理健康教育与咨询中心 2025 年公开内容以“内核稳定”作为个人成长大众语言讨论，说明该表达已经具有稳定现实使用。

来源：  
https://www.xljk.sdu.edu.cn/info/1008/11296.htm

**V1 结论**：它适合作为复合目标 / 身份入口，但不升格为一个统一心理学理论。

## 3.3 自我接纳

公开心理专业讨论中，“自我接纳”有比“爱自己 / 内核稳定 / 强者思维”更稳定的专业语义；最新上游正式知识清单仍没有完全同名条目。

**V1 结论**：保留为 A/B 级稳定入口，同时标记 `GAP`，不拿“认知重构”或“自我效能”冒充同义词。

# 4. 知识组织标准校准

V1 的词表关系设计借鉴成熟知识组织原则，但保持 Markdown 优先、人工可读。

## 4.1 W3C SKOS

SKOS 提供：

- `prefLabel`：首选标签；
- `altLabel`：替代标签；
- `broader / narrower`：上下位；
- `related`：相关；
- 以及直接层级与传递查询关系的区分。

来源：  
https://www.w3.org/TR/skos-reference/  
https://www.w3.org/TR/skos-primer/

## 4.2 ISO 25964

ISO 25964-1 面向信息检索中的叙词表建设；ISO 25964-2 讨论叙词表与其他词汇之间的互操作 / 映射。

来源：  
https://www.iso.org/standard/53657.html  
https://www.iso.org/standard/53658.html

## 4.3 仓库内部校准

最新上游已直接收录：

- `标签体系（Tagging / Faceted Classification）`；
- `分面分类法（Faceted Classification）`；
- `受控词表（Controlled Vocabulary）`；
- `叙词表（Thesaurus）`；
- `术语管理（Terminology Management）`；
- `同义词与查询扩展（Query Expansion）`。

**V1 采用的关键思想**：

> 标签层首先是知识检索与语义路由层，而不是第二套学科分类树。

> **能稳定帮助理解用户认知 / 行动问题、检索思维方法、连接正式知识或发现长期内容需求的语义入口。**

# 7. 八个入口验收

## 7.1 用户问题入口

输入：

> 我不知道自己想要什么。

输出链：

```text
E3 用户自然语言
→ F02 目标模糊 + F03 目标澄清
→ 价值澄清 / 目标澄清
→ 02 价值、目标、边界与问题定义
→ 价值澄清、价值聚焦思维、目标层级 / 手段—目的链
```

通过。

## 7.2 心理状态 / 问题入口

输入：

> 我最近一直很内耗。

输出链：

```text
E3 用户语言
→ 精神内耗
→ 分型：反复思考 / 决策冲突 / 评价压力 / 拖延 / 关系
```

通过；保留非诊断边界。

# 8. 新增正式入口回归测试

并行上游修订后增加四个回归测试，防止标签层与正式知识层漂移。

## 8.1 “怎么扩展搜索关键词？”

```text
用户查询
```

# 9. “标签 → 创作者”应用压力测试

假设要找长期讨论“内核稳定”的公开创作者，搜索扩展不应只用一个词：

```text
内核稳定
├─ 稳定内核
├─ 内心稳定
├─ 情绪稳定（相关）
├─ 自我接纳（相关）
├─ 主体性（相关）
├─ 边界感（相关）
├─ 松弛感（相关）
└─ 停止内耗（问题侧入口）
```

然后：

```text
搜索公开视频 / 图文
→ 聚合同一创作者多个内容
→ 判断是否长期主题，而不是偶发一条
→ 统计规范标签与传播词
→ 抽取实际知识实体
→ 检查证据 / 定义 / 过度泛化
→ 形成动态创作者研究数据
```

**不应做**：搜到一个热门词就把所有使用该标签的人认定为该领域专家。

# 10. 标签生命周期

## 10.1 候选

发现新词，保存：原始表达、来源、日期、上下文。

## 10.2 归一

判断：

- 已有标签别名；
- 近义词；
- 上下位；
- 新稳定语义；
- 平台包装；
- 动态热点；
- 应排除。

## 10.3 映射

至少连接一个：

- 问题；
- 目标；
- 场景；
- 角色；
- 正式知识类 / 知识实体。

否则不得仅因为“看起来像成长词”就升级核心标签。

## 10.4 审核

检查：

- 同义关系是否过度；
- 是否误把共现当语义；
- 是否过度专业化；
- 是否流量词污染；
- 是否存在上游知识缺口。

## 10.5 发布

分为：

```text
core         稳定核心
propagation  传播索引
dynamic      动态 / 时间性
excluded     排除 / 外部词
```

## 10.6 复审

建议稳定核心半年级复审；传播层按季度或大型样本采集后复审；动态层按平台研究任务单独更新。

# 12. 数据质量指标

未来可量化：

## 12.1 覆盖率

- 28 类知识至少有多少自然语言入口；
- 高频问题是否能路由；
- 核心标签有多少已连接知识；
- 新增正式知识中有多少已生成自然语言入口。

## 12.2 歧义率

- 一个词平均有多少潜在语义；
- D / E 类词中有多少需要上下文；
- “无法直接映射”比例。

高歧义不是必然坏事，关键是系统有没有显式标记。

## 12.3 同义错误率

人工抽查 `exact_synonym`，判断是否真的可以在主要语境互换。

## 12.4 映射精度

给定用户句子，人工判断 Top-3 推荐知识是否至少有 1—2 个真正相关。

## 12.5 传播词污染率

检查正式知识实体中有多少是从平台包装词未经验证直接升格而来。目标应接近 0。

## 12.6 动态词滞留率

短期热点是否在过时后仍污染核心词典。

## 12.7 上游漂移率

检查：

- 正式知识改名；
- 正式知识移动主分类；
- 新增正式知识；
- 删除 / 合并知识；

是否已经同步更新标签映射。

# 14. 下一版本的增长顺序

V1 之后不要先“想更多词”，而按真实数据增量推进：

```text
公开用户语言 / 搜索 / 内容样本
→ 候选表达池
→ 语义聚类
→ 同义与歧义审计
→ 核心 / 传播 / 动态分流
→ 正式知识映射
→ 上游缺口候选
→ 人工抽检
→ V1.x / V2
```

最值得优先增加的数据不是更多空泛标签，而是：

1. 每个高价值标签的真实用户问题句；
2. 当前正式知识清单中自然语言入口稀疏的条目；
3. 每次上游正式知识新增后自动生成的候选入口；
4. 同一问题在不同人群 / 场景下的语言变体；
5. 跨平台长期稳定的传播词；
6. “无法映射”案例，因为它们最容易发现上游知识缺口或边界问题。

# 15. V1 版本治理结论

本轮出现的并行更新本身暴露了一个未来必须制度化的问题：

> 标签层和正式知识层会各自持续增长，不能靠一次性手工记忆保持同步。

因此 V1 将以下规则正式化：

```text
每次正式知识基线更新
→ 比较上游 diff
→ 找新增 / 改名 / 移动 / 删除知识
→ 检查标签是否已有 DIRECT / ROUTE 入口
→ 生成缺口清单
→ 只更新受影响映射
→ 保留 upstream_baseline_commit
```

这样标签宇宙才会成为长期语义基础设施，而不是一份很快失真的静态关键词表。
