# 标签、自然语言入口与语义索引宇宙 V1.1｜语义路由 Benchmark 与测试集

> 本文件建立独立的“问题 → 标签 → 正式知识”金标准测试集（Gold Set）。
>
> **重要边界**：Gold Set 用来规定“什么答案算对”，不是一个已经部署的搜索模型，因此不能把金标准本身的完整率伪装成模型准确率。后续任何关键词、向量检索、LLM 路由器或混合检索系统，都必须在本测试集上单独运行后才能报告 Top-1 / Top-3 实测指标。
>
> 本测试集与 `07_正式知识自然语言入口覆盖矩阵_V1.md` 中的建设语料使用不同措辞，避免“建设集 = 测试集”的自我验证。

---

## 1. Benchmark 数据契约

每个样本至少记录：

```text
id
level
raw_input
primary_label
acceptable_secondary_labels
problem
goal
scene
correct_knowledge_class
gold_top3_knowledge
acceptable_alternatives
forbidden_or_misleading_knowledge
needs_disambiguation
disambiguation_question
```

其中：

- `gold_top3_knowledge` 表示在已有上下文下最有价值的三个正式知识候选；
- 对 Level 5—6 高歧义表达，Top-3 是**待消歧候选池**，不是允许系统直接把第一项当唯一答案；
- `forbidden_or_misleading_knowledge` 专门测试错误路由；
- `needs_disambiguation = Y` 时，系统如果直接给出唯一正式知识，即使该知识“看起来相关”，也记为强制映射错误。

---

## 2. 六级难度定义

| Level | 输入特点 | 主要测试能力 |
|---|---|---|
| L1 | 正式名称直接出现 | DIRECT 对齐、正式知识名称识别 |
| L2 | 问题明确但不说方法名 | 问题理解、问题标签路由 |
| L3 | 只说目标 | 目标 ≠ 问题；需要推断可能障碍但不能过度诊断 |
| L4 | 具体场景 | 场景、事件、问题三者分离 |
| L5 | 高歧义大众语言 | 主动拆解、追问、保留不确定性 |
| L6 | 平台包装语言 | 包装词治理、传播价值与知识精度分离 |

本版共 **72 个主测试样本，每级 12 个**；另有关系判别测试 30 组。

# 10. 语义路由指标

## 10.1 Top-1 标签准确率

```text
Top1TagAccuracy = 第一规范标签被 Gold 接受的样本数 / 全部样本数
```

目标：

- L1—L4 ≥ 92%；
- 全集 ≥ 90%。

## 10.2 Top-3 标签召回率

```text
Top3TagRecall = Gold 主要语义至少有一个出现在前三标签的样本数 / 全部样本数
```

目标：≥ 97%。

## 10.3 Top-3 正式知识命中率

只在 `needs_disambiguation=N` 或已有足够上下文的样本上计算：

```text
Top3KnowledgeHit = Top-3 至少命中一个 Gold 高价值知识 / 可直接路由样本数
```

目标：≥ 95%。

对于 `needs_disambiguation=Y` 的样本，不能靠“候选池碰巧命中一个”获得满分；还必须通过强制映射检查。

## 10.4 错误路由率

```text
WrongRouteRate = Top-3 出现 forbidden_or_misleading_knowledge / 全部样本数
```

目标：≤ 3%。

## 10.5 强制映射率

```text
ForcedMappingRate = needs_disambiguation=Y 但系统输出唯一确定知识 / 应消歧样本数
```

目标：≤ 5%。

## 10.6 同义误判率

```text
SynonymFalseMergeRate = 非同义关系被标 exact_synonym / 关系测试中非同义样本数
```

目标：≤ 2%；高风险包装词目标为 0。

## 10.7 包装词污染率

```text
PackagingPollutionRate = E5/F11 包装词未经上游核验直接升格为正式知识 / 包装词样本数
```

目标：0。

# 11. V1 静态映射人工基线审计

> 这是对 V1 现有 Markdown 标签与映射规则的**人工逐条校准**，不是线上检索系统、向量模型或 LLM 的性能跑分。作用是发现 V1 数据层在哪些类型上会路由不足。

审计口径：

1. 只使用 V1 原有 `01—06` 的标签、自然语言与映射关系；
2. 不使用 `07` 新增建设语料为答案提示；
3. 对 72 个样本逐条判断：首标签是否已有稳定入口、前三知识能否由既有映射推出、是否应消歧；
4. 高歧义样本如果 V1 已有 `DISAMBIG/GAP` 规则，则视为具备正确拒绝强映射能力；
5. 该结果只作为数据层基线，不声称代表任何未来软件实现。

### 11.1 基线结果

经逐条复算，本测试集中 `needs_disambiguation=Y` 共 **34 例**，`N` 共 **38 例**。

| 指标 | V1 人工基线 | V1.1 目标 | 主要缺口 |
|---|---:|---:|---|
| Top-1 标签可接受率 | 64 / 72 = 88.9% | ≥90% | 情绪/边界/主体性与部分专业场景标签不足 |
| Top-3 标签语义召回 | 69 / 72 = 95.8% | ≥97% | 宽泛目标和复杂组织场景仍可能漏一层语义 |
| Top-3 正式知识命中（可直接路由 38 例） | 35 / 38 = 92.1% | ≥95% | 信息价值、组织协作、部分学习/验证入口较稀疏 |
| 错误路由风险样本 | 4 / 72 = 5.6% | ≤3% | 关键词容易把“内耗/边界/情商/底层逻辑”导向固定答案 |
| 应消歧样本保留不确定性 | 31 / 34 = 91.2% | ≥95% | 个别大众目标仍可能被单一路由 |
| 关系测试同义误合并 | 0 / 30 | ≤2% | V1 的严格同义政策有效 |
| 包装词升格正式知识 | 0 / 12 | 0 | V1 的传播层隔离有效 |

**解释**：V1 的架构方向正确，但数据覆盖还不足以把“28 类都有入口”解释成“具体知识实体都容易被找到”。V1.1 的新增价值主要发生在前五项，而不是推翻 V1 的关系治理。

### 11.2 V1.1 当前可验证到什么程度

新增 `07`、`07A` 与本文件后，可以确认：

- 72 个 Gold 样本均有主要标签、知识类、Top-3 候选、错误候选与消歧规则；
- 34 个应消歧样本全部明确记录 `Y` 与所需追问信息；
- 12 个包装语言样本没有任何一个被升格成上游正式知识；
- 30 组关系测试明确区分同义、近义、上下位、部分重叠、相关、高共现；
- 38 个可直接路由样本均已有 Gold Top-3，可用于后续真实检索器跑分。

但**尚不能宣称“V1.1 系统 Top-3 命中率已经 ≥95%”**，因为当前仓库建设的是语义数据与测试集，不是已运行的路由程序。真正的软件系统上线前必须实际执行 Benchmark。

```text
“论文改了十遍还不敢交，特别内耗”
→ 完美主义式卡住 / 停止规则 → 01 + 20
```

### “边界”

```text
“同事总把他的任务塞给我”
→ 人际边界 / 职责 → 24 + 25 + GAP

“这个系统要把哪些模块算在分析范围内”
→ 系统边界设定 → 02
```

### “提高认知”

```text
“网上消息太多，想提高认知”
→ 证据审查 / 信息核查 → 06

“做生意总看不懂市场，想提高认知”
→ 商业判断 → 27

“预测事情总过于自信，想提高认知”
→ 信心校准 / 概率 → 01 + 10
```

任何只根据一个关键词给固定知识的实现，都不应通过本 Benchmark。

# 13. Benchmark 数据隔离与防自我验证

正式执行时建议至少三层数据：

```text
建设集
= 07 中的入口扩展语料

开发验证集
= 本文件 72 个 Gold 样本中的 48 个

冻结测试集
= 本文件剩余 24 个 + 未来外部真实样本
```

更严格版本应：

- 冻结测试集不参与提示词/词典调参；
- 新增真实平台或用户样本时先进入候选池，不立即回写 Gold；
- 每次修改标签、同义关系或正式知识映射后跑回归；
- 报告按 L1—L6 分层指标，禁止只报告平均数；
- L5—L6 单独报告强制映射率。

# 15. Benchmark 验收标准

一个未来语义路由实现只有同时满足以下条件才算通过：

1. 全集 Top-1 标签准确率 ≥90%；
2. Top-3 标签召回率 ≥97%；
3. 可直接路由样本 Top-3 正式知识命中 ≥95%；
4. 错误路由率 ≤3%；
5. L5—L6 强制映射率 ≤5%；
6. 同义误判率 ≤2%；
7. 包装词污染率 = 0；
8. R-23—R-28 不出现 exact synonym；
9. R-30 不发生同名合并；
10. 按六级分别报告，不允许总平均掩盖高歧义失败。

本 Benchmark 的核心不是追求“每句话都必须命中一个模型”，而是检验：

> **系统是否知道什么时候应该推荐知识，什么时候应该给候选，什么时候必须先问。**
