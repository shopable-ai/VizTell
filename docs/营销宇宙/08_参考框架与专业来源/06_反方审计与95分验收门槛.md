# 反方审计与95分验收门槛

> 状态：REVIEW｜第一轮反方问题与验收规则。
> 当前结论：营销宇宙 v0.4 仍是候选知识架构；Owner Registry 已建立初稿，不授予整体 95 分认证。

## 一、主要反方观点与处理要求

### 1. 24 个领域是否过多或分类混乱？

反方观点：24 个入口包含专业领域、整合框架、渠道、运营模型和技术系统，不是完全同质的学科分类。

处理：
- 保留现有 ID，避免破坏已有引用；
- 增加 domain_type；
- 将商业模式、行业、渠道、生命周期、地域、组织阶段和研究方法作为正交视图；
- 通过真实任务判断是否需要合并或拆分；
- 不因分类不整齐就立即重编号。

### 2. 是否遗漏传统营销和线下营销？

反方观点：如果主要研究 SEO、广告、社交和 AI 工具，体系会过度数字化。

处理：
- 保留产品、价格、分销、零售、贸易、服务、活动、赞助、直邮、电话、销售和门店等专业内容；
- 在专业分支审计中持续检查线下、传统媒体和全渠道营销；
- 真实任务必须包含零售、服务、B2B 和线下业务。

### 3. 是否遗漏 B2B、服务和专业行业？

反方观点：B2B 采购、服务质量、零售购物者和社会营销具有独立理论与方法。

处理：
- 建立专业应用包和唯一 Owner；
- 为 Buying Center、服务蓝图、Shopper Marketing、Trade Marketing、社会行为改变等建立 L2-L4 专业地图；
- 只有独立方法和真实任务证明有必要时才升级 L1。

### 4. 是否把营销等同于企业利润增长？

反方观点：营销还涉及客户福祉、公共利益、社会影响、隐私、消费者保护和环境责任。

处理：
- 把责任营销、伦理、隐私、公平、可访问性、可持续性和公共政策作为横向约束；
- 为非营利、公共部门和社会营销保留专业应用；
- 不把商业利润作为所有营销场景的唯一目标。

### 5. 是否混淆归因、相关性和因果？

反方观点：渠道报表、点击、转化和归因收入常被误解为营销增量。

处理：
- 明确归因与增量的区别；
- 对重要预算决策优先考虑实验或可信准实验；
- 披露样本、时间窗、数据质量和模型假设；
- 把经济性、毛利、履约和现金流纳入结果。

### 6. 是否把 AI 工具和 Skills 当作营销能力本身？

反方观点：安装 Skill、部署软件或使用 Agent 不等于具备专业营销能力。

处理：
- 先有专业方法和知识节点，再决定是否 Skill 化；
- 外部 Skill 只作为参考资产，必须审查来源、许可、权限和失败处理；
- 软件生态用于反推真实工作流，不替代理论和研究；
- AI 输出必须保留来源、未知和人工监督边界。

## 二、95 分硬门槛

以下任一项未通过，整体不得判定达到 95 分：

- 重要专业任务无法映射到领域或应用分支；
- 关键领域存在重复 Owner 或无 Owner；
- 核心结论没有可追溯来源、适用范围和证据状态；
- 将用户自述、相关性或归因结果误当成真实需求或因果效果；
- 忽略毛利、退款、履约、现金流或客户生命周期经济性；
- 高影响行动缺少权限、合规、停止条件和失败处理；
- 跨知识宇宙存在重复事实源或冲突 Schema；
- 真实任务测试出现严重错误且没有修复；
- 领域路由和知识引用不准确；
- 文件、链接、ID、来源许可或版本校验存在关键错误。

## 三、分阶段验收

### Gate A：架构与分类

- 24 个领域都有 domain_type、唯一 Primary Owner、Scope In/Out 和质量门槛；
- 不同分类轴有明确区分；
- 业务模式、行业、渠道、生命周期和地域视图可组合；
- 主要交叉分支有映射；
- 没有未经论证的 D25+；
- 所有重大重叠都有边界裁决。

### Gate B：专业知识深度

- 每个领域有二级和三级知识地图；
- 重要节点有理论、模型、方法、适用条件和反例；
- 研究来源可追溯；
- 重要专业分支有完整地图；
- 不以概念数量或文章数量代替专业深度。

### Gate C：行动与决策

- 高频任务有 SOP；
- SOP 有输入、步骤、决策门、输出、验收和失败处理；
- 不同业务模式有条件分支；
- 指标和经济性口径明确；
- 伦理、隐私和风险检查可执行。

### Gate D：真实任务验证

至少执行：
- 新产品探索；
- B2B 市场进入；
- SaaS/订阅留存；
- 零售/贸易/购物者营销；
- 服务体验改善；
- 平台/Marketplace；
- 非营利/社会营销；
- 国际化；
- 品牌危机；
- 广告增量和预算重分配。

### Gate E：AI 调用与维护

- 能识别主领域和关联领域；
- 能选择最小充分上下文；
- 能正确引用知识节点和来源；
- 能区分事实、推断、假设和未知；
- 能发现重复、冲突和过时内容；
- 能增量更新并保留历史版本；
- 高风险任务有人工审批和停止条件。

## 五、审计报告要求

每轮评分必须记录：
- 评价对象和版本；
- 审计范围与实际读取文件；
- 每个维度的评分和证据；
- 未通过项目、严重度和影响；

- 复核者与复核日期。
