# 专业 SOP 执行 Benchmark 测试集

> 版本：v0.8
> 状态：DRAFT｜测试用例设计已建立，尚未执行模型/Agent 盲测。
> 目标：验证六份首批专业 SOP 能否把知识地图转化为有证据、有决策门、有失败处理的实际工作流程。

## 一、测试原则

- 评价对象是 SOP 的实际执行结果，不是模型是否复述了 SOP 标题。
- 每个任务必须输出输入假设、研究/执行步骤、证据、决策门、交付物和未知。
- 不提供真实数据时，不允许模型编造市场数字、访谈结果、价格弹性或实验效果。
- 允许合理选择不同方法，但必须解释选择依据和适用边界。
- 每个任务至少使用 3 种语义改写，保存完整运行记录。
- 任何严重伦理、隐私、虚假证据或因果错误均触发 Hard Fail。

## 二、SOP-01｜市场边界与规模估算

**测试场景**

一家企业计划评估是否进入日本市场，为中小型电商商家提供 AI 客服 SaaS。现有材料只有若干竞品官网、少量行业报告和内部初步估算，没有可靠的日本目标客户总数。

**Gold SOP**
- MKT-PB-001。

**Required Domains**
- D01、D02、D04、D05、D06、D07、D08、D20、D21。

**Required Outputs**
- 决策问题和市场定义；
- 客户/产品/地域/时间边界；
- Top-down 和 Bottom-up 估算方案；
- TAM/SAM/SOM 的项目定义；
- 来源与证据登记；
- 关键假设、敏感性和不确定区间；
- 下一步数据收集和市场进入决策建议。

**Forbidden Errors**
- 编造日本商家数量或 SaaS 渗透率；
- 用全球市场报告直接替代日本市场；
- 用搜索量当作付费客户数；
- 用任意市场份额百分比生成 SOM；
- 把市场规模当作进入市场的充分理由。

## 三、SOP-02｜JTBD 用户访谈与行为研究

**测试场景**

一家公司准备开发面向跨境卖家的订单/客服整合工具。现有团队主要依靠内部想象，尚未访谈卖家、客服人员和决策者。

**Gold SOP**
- MKT-PB-002。

**Required Domains**
- D02、D03、D04、D06、D08、D18、D19。

**Required Outputs**
- 研究问题和目标总体；
- 样本/角色矩阵；
- 招募和知情同意；
- 最近一次真实事件的访谈提纲；
- JTBD、替代方案和改变障碍编码框架；
- 事实、自述、推断和未知分层；
- 交叉验证计划；
- 研究限制和洞察交付模板。

**Forbidden Errors**
- 直接问“你是否愿意购买我们的产品”作为核心研究；
- 把模拟访谈或 AI 生成回答冒充真实客户；
- 用少量访谈估算市场比例；
- 只访谈高满意客户；
- 忽略付款者、使用者和决策者差异。

## 四、SOP-03｜需求与市场机会验证

**测试场景**

团队从论坛和客户反馈中发现“自动生成商品描述”需求，准备投入开发。现有证据主要是用户点赞、评论和口头兴趣。

**Gold SOP**
- MKT-PB-003。

**Required Domains**
- D02、D03、D04、D06、D08、D09、D21。

**Required Outputs**
- 可证伪需求假设；
- 用户情境和当前替代方案；
- 需求证据阶梯；
- 最小验证设计；
- 样本、指标、时间窗口和成功/失败阈值；
- 真实行为/交易信号；
- 风险、披露和停止条件；
- Continue / Iterate / Pause / Stop 决策模板。

**Forbidden Errors**
- 把点赞、评论或搜索量当真实需求；
- 不披露测试就假装产品已上线；
- 用免费试用制造虚假付费意愿；
- 不预先定义成功标准；
- 隐藏退款、退出和失败结果。

## 五、SOP-04｜STP 与定位决策

**测试场景**

一家 B2B 数据分析 SaaS 企业服务多个行业，但销售周期长、客户差异大。团队想用一个宽泛 Persona 代表所有客户，并将定位统一为“最智能的分析平台”。

**Gold SOP**
- MKT-PB-004。

**Required Domains**
- D02、D03、D04、D05、D06、D07、D08、D09、D10、D18。

**Required Outputs**
- 市场和决策边界；
- 细分变量与候选细分；
- 细分质量评估；
- 目标市场吸引力/能力匹配；
- 不服务群体和战略取舍；
- 定位陈述、竞争参照和可信理由；
- 产品证据矩阵；
- 定位验证计划。

**Forbidden Errors**
- 把 Persona 当成市场细分；
- 只按市场规模选择目标客户；
- 把“最智能”当作有证据的差异化；
- 细分没有可测量或可触达条件；
- 不检查不同细分的实际响应差异。

## 六、SOP-05｜定价研究与价格测试

**测试场景**

一家 B2B SaaS 企业准备把单一订阅套餐改成三档套餐。团队希望用一次问卷确定最优价格，但没有交易实验，也没有完整客户成本数据。

**Gold SOP**
- MKT-PB-005。

**Required Domains**
- D03、D04、D06、D08、D09、D18、D19、D21、D24。

**Required Outputs**
- 定价目标和计费单位；
- 套餐/版本假设；
- 支付意愿研究设计；
- Van Westendorp / Gabor-Granger / Conjoint 等方法选择依据；
- 真实交易/试点测试建议；
- 指标、样本、观察窗口和停止条件；
- 客户迁移、公平性和沟通方案；
- 收入、毛利、退款、留存和经济性分析接口。

**Forbidden Errors**
- 把问卷愿付当真实支付；
- 在缺少数据时声称得出最优价格；
- 只优化转化率而忽略毛利、退款和留存；
- 忽略老客户迁移和价格公平；
- 把收入增长当作利润增长。

## 七、SOP-06｜营销增量实验与因果测量

**测试场景**

一家多渠道电商企业同时投放搜索、社交和视频广告。平台报告显示 ROAS 良好，但总利润没有明显改善。管理层要求判断广告是否带来真实新增贡献。

**Gold SOP**
- MKT-PB-006。

**Required Domains**
- D09、D10、D14、D15、D18、D19、D21、D22。

**Required Outputs**
- 因果问题和估计对象；
- 结果指标和反事实；
- RCT/Holdout/Geo/准实验等设计比较；
- 样本量、随机化、污染和统计功效；
- 数据质量与归因窗口审查；
- 实验执行和停止规则；
- 增量客户、收入和贡献利润分析；
- 不确定性、外部效度和预算决策。

**Forbidden Errors**
- 把平台 ROAS 当增量；
- 不定义对照组或反事实；
- 忽略自然需求、季节性和渠道迁移；
- 样本不足却声称确定结论；
- 只看收入，不计算退款、折扣、履约和贡献利润。

## 八、统一评分表

| 维度 | 分值 | 评价重点 |
|---|---:|---|
| 问题与边界定义 | 1 | 是否明确决策、对象、范围和约束 |
| 方法选择 | 2 | 方法是否适合问题和数据条件 |
| 证据与不确定性 | 2 | 是否区分事实、自述、推断、假设和未知 |
| 执行步骤 | 1 | 是否可复现，步骤和角色明确 |
| 决策门与失败处理 | 1 | 是否有停止、回退和反证条件 |
| 输出质量 | 1 | 是否交付可用成果 |
| 经济性/伦理/风险 | 1 | 是否考虑成本、客户保护和合规 |
| 跨域引用 | 1 | 是否正确使用主领域和支持领域 |
| **总分** | **10** | |

### Hard Fail 条件

以下任一情况，该题直接判定失败，不允许由其他维度分数抵消：
- 编造来源、访谈、市场数字、交易或实验结果；
- 将自述意愿、平台归因或相关性冒充因果事实；
- 隐瞒重大样本偏差、研究限制或负面结果；
- 未经授权收集/使用敏感数据或执行高影响外部动作；
- 缺少重大决策所必需的经济性、隐私或停止条件。

## 九、执行要求

- 六个 SOP 每个至少 3 种语义改写，共至少 18 次执行；
- 每次保存模型/Agent 版本、输入、输出、引用、耗时、错误和评分；
- 每个 SOP 至少在两个不同业务情境复测；
- 错误修复后必须回归受影响的任务；
- 当前状态：测试设计已建立，实际执行次数为 UNKNOWN，SOP 质量 NOT CERTIFIED。
