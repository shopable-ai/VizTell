# 分类层级与知识节点规范

> 本文件定义营销宇宙内部的分类与导航规则。通用 Knowledge Atom、Canonical Knowledge、Source、Evidence、Relation 等对象定义复用 AI 原生知识系统，不在此重新定义第二套通用本体。

## 一、分类层级

- **L0：营销宇宙** — Universal Marketing Universe。
- **L1：一级知识域** — 当前 24 个候选领域。
- **L2：二级模块** — 一级领域内相对稳定的专业模块。
- **L3：三级主题** — 具体专业主题、理论族或能力主题。
- **L4：四级问题与方法单元** — 研究问题、分析任务、方法、机制、决策问题或行动单元。
- **L5：执行表示与资产链接（可选）** — 操作步骤、检查清单、模板、工具、指标定义、数据 Schema 或可执行规则的引用。

L5 不意味着所有知识都必须变成工具。模板和文件资产应作为独立资产管理，再通过引用关联知识节点。

## 二、分类轴与知识类型分离

分类回答“知识属于哪个专业领域”；知识类型回答“这是什么类型的知识”。两者不可混为一套树。

知识类型可复用 AI 原生知识系统中的定义，例如：

- Concept / Definition；
- Fact / Data；
- Claim / Hypothesis；
- Theory / Principle；
- Mechanism / Model；
- Method / Procedure；
- Decision Rule；
- Metric / Measurement；
- Case / Experience；
- Anti-pattern / Risk；
- Forecast / Scenario。

同一个专业领域可以包含多种知识类型；同一种知识类型也可以出现在多个领域。

## 三、营销域内 ID 建议

为避免与商业模式宇宙 U/P/PR 编号、AI 原生知识系统的 K/S/E/R 对象 ID 冲突，营销分类使用独立命名空间：

- 一级领域：MKT-D01 至 MKT-D24。
- 二级模块：MKT-D02-M01。
- 三级主题：MKT-D02-T001。
- 四级研究问题：MKT-D02-Q001。
- 方法条目：MKT-METHOD-001。
- 行动手册：MKT-PB-001。
- 决策模型：MKT-DEC-001。
- 营销资产：MKT-ASSET-001。

以上编号是当前建议方案，正式大规模使用前需完成唯一性检查并在 MANIFEST 中登记。编号一经被外部引用，不得静默重排；拆分、合并和废弃必须保留迁移映射。

通用知识对象继续使用 AI 原生知识系统定义的对象 ID，例如 S-*、F-*、A-*、K-*、E-*、EG-*、R-*。不要为营销宇宙另造同义对象。

## 四、适用等级

每个重要节点可标记：

- CORE
- CONDITIONAL
- SPECIALIZED
- EMERGING

适用等级与知识成熟度、证据状态、风险等级、优先级相互独立。一个 EMERGING 节点也可能有高质量证据；一个 CORE 能力下的某种工具也可能仅适用于少数情境。

## 五、节点最小内容契约

重要节点建议包含：

- 身份：node_id、名称、别名、上级节点、版本、状态。
- 分类：所属领域、层级、适用等级、知识类型。
- 定义：核心定义、研究对象、解决的问题、商业意义。
- 边界：包含什么、不包含什么、相邻概念区别。
- 适用性：业务模式、组织类型、市场、地域、生命周期、前提条件。
- 专业内容：理论、机制、模型、成熟方法和代表实践。
- 研究：关键问题、研究设计、数据来源、样本、分析方法、局限。
- 行动：输入、具体动作、决策门、风险检查、输出。
- 测量：指标定义、计算口径、解释边界、验收标准。
- 关系：前置节点、下游节点、平行节点、共享数据和反馈关系。
- 证据：source_refs、evidence_refs、claim 状态、反面证据和验证时间。
- 生命周期：创建、复核、更新时间、适用时间、过时风险和替代关系。

并非每个节点都必须机械填满全部字段。概念节点、研究方法、决策规则和行动手册应采用相应的内容模板。

## 六、分类治理

- 一个节点只设一个主要归属；跨领域用途通过关系引用，不复制节点。
- 分类粒度应在同一层级保持相对一致。
- 不用渠道、用户阶段、知识类型、工具类型等不同分类轴混杂构成同一层级。
- 领域边界无法稳定区分时，先记录重叠和归属规则，不急于增加分类。
- 新增一级领域必须证明：它具有独立研究对象、稳定专业方法、足够知识规模、明确边界和独立维护价值。
- 对合并、拆分、重命名和迁移，保留旧 ID、旧路径和引用兼容关系。

## 七、节点状态

- PROPOSED：候选节点。
- DRAFT：已有初稿。
- RESEARCHING：补充理论、证据或案例。
- REVIEW：待审查。
- ACTIVE：已通过对应验收，当前可用。
- SUPERSEDED：被新节点或版本取代。
- ARCHIVED：不再活跃维护但保留历史价值。

状态必须反映实际验证程度，不得因为文档已写入仓库就标记 ACTIVE。


## 八、L1 领域类型与正交维度

当前 24 个 L1 是知识导航入口，不应被误解为 24 个完全同质、互斥的学科。每个 L1 节点必须增加以下元数据：

- domain_type：领域类型；
- primary_owner：唯一专业 Owner；
- scope_in：主要包含范围；
- scope_out：明确排除范围；
- related_domains：关联领域；
- context_tags：适用业务模式、行业、客户类型、地域和阶段；
- channel_tags：相关渠道和触点；
- lifecycle_tags：相关客户旅程阶段；
- cross_cutting_refs：研究、证据、决策、绩效、责任治理和知识资产接口。

domain_type 建议值：
- FOUNDATION_CONTEXT
- INTELLIGENCE_DISCIPLINE
- BEHAVIORAL_DISCIPLINE
- OPPORTUNITY_DISCIPLINE
- STRATEGY_DISCIPLINE
- POSITIONING_DISCIPLINE
- COMPETITIVE_DISCIPLINE
- PRODUCT_VALUE_DISCIPLINE
- PRICING_COMMERCIALIZATION
- BRAND_DISCIPLINE
- INTEGRATION_FRAMEWORK
- CONTENT_COMMUNICATION
- DISCOVERY_CHANNEL_SPECIALTY
- PAID_MEDIA_SPECIALTY
- DISTRIBUTION_DISCIPLINE
- SOCIAL_COMMUNITY_SPECIALTY
- PR_REPUTATION_SPECIALTY
- REVENUE_INTERFACE
- RELATIONSHIP_DISCIPLINE
- INTERNATIONAL_SPECIALTY
- ANALYTICS_SCIENCE_CAPABILITY
- GROWTH_OPERATING_MODEL
- TECHNOLOGY_ENABLER
- ORGANIZATION_GOVERNANCE_SYSTEM

完整 D01-D24 类型分配和边界见 [分类轴、领域类型与边界矩阵](../08_参考框架与专业来源/04_分类轴、领域类型与边界矩阵.md)。

正交视图至少区分：
- 业务模式与客户关系；
- 行业/服务情境；
- 渠道与媒体；
- 客户生命周期；
- 地域与文化；
- 组织发展阶段与资源约束；
- 研究方法与证据类型；
- 风险、伦理和监管约束。

不得把这些视图的标签混入同一 L1 分类树。


## 九、横向支撑系统 ID

横向支撑系统使用独立于 D01-D24 的 H 命名空间：

- H01：研究方法与研究运营；
- H02：证据、来源与不确定性；
- H03：决策科学与风险；
- H04：绩效测量与组织学习；
- H05：知识资产与生命周期；
- H06：AI 协作与能力路由。

H01-H06 不计入 L1 专业领域数量，不拥有 D 域的专业知识定义。专业领域负责营销问题和领域适配，横向系统负责共用方法、对象和治理规则。详细职责见 [24 域专业领域权威登记表](../01_知识地图/01_24域专业领域权威登记表.md)。
