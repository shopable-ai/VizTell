## 一、领域任务与边界

D08 负责把客户需求、产品能力和市场价值连接起来，回答：

- 产品/服务为谁解决什么问题？
- 客户如何获得可验证的价值？
- 产品能力如何形成价值主张、定位证据和市场信息？
- 产品如何上市、被理解、采用和持续改进？
- 产品营销如何与产品管理、工程、销售和客户成功协作？

### 与相邻领域的边界

- D12-D17 负责内容、媒体、渠道和传播执行；

产品管理负责产品问题、路线图和优先级；产品工程负责技术实现；D08 负责营销侧的市场适配、价值表达、上市和反馈接口。

## 三、Product Marketing 的专业工作链

1. Discovery：客户、市场、竞争和产品反馈研究；
2. Strategy：市场选择、价值主张、定价、GTM 和目标；
3. Define：细分、定位、信息架构、Buyer Persona 和 Use Case；
4. Get Ready：销售赋能、渠道准备、内部沟通和发布资产；
5. Grow：上市分析、客户反馈、采用、留存和优化。

该结构参考 Product Marketing Alliance 的 Product Marketing Core Framework。它是专业实践框架，不是学术本体或所有企业必须照搬的固定流程：[PMA Core Framework](https://support.productmarketingalliance.com/en/articles/10453971-the-product-marketing-core-framework)。

## 四、研究方法与选型

| 研究问题 | 方法 | 主要注意事项 |
|---|---|---|
| 产品解决的是否是真问题？ | JTBD、客户访谈、行为观察 | 回到最近一次实际行为 |
| 价值主张是否成立？ | Value Proposition Canvas、概念测试、原型测试 | 画布只整理假设，必须测试 |
| 产品是否适合目标市场？ | 使用数据、队列、留存、交易和客户研究 | 不能只看注册/试用 |
| 哪些产品能力最重要？ | Conjoint/DCE、功能优先级、任务研究 | 偏好不等于实际使用 |
| 如何上市？ | GTM readiness、渠道/销售/客户成功准备度审计 | 检查依赖、容量和风险 |
| 产品价值如何证明？ | 客户案例、ROI 模型、试点和对照评估 | 证明必须可核验，不夸大结果 |

## 五、标准交付物

- Product Value Map：目标客户、问题、能力、结果和证据。
- Value Proposition：客户价值主张和可信理由。
- Product Positioning Input：产品定位、竞争参照和差异。
- Product Marketing Brief：市场、客户、信息、用例和销售赋能。
- GTM Plan：目标、阶段、渠道、定价、销售/服务准备和指标。
- Launch Readiness Checklist：发布准备度、依赖和停止条件。
- Product Feedback Loop：使用、客户反馈、销售反馈和改进决策。

## 六、质量门槛与常见反例

- 价值主张必须对应真实产品能力；
- 产品市场适配需要行为、使用、交易或持续价值证据；
- GTM 必须明确目标客户、价值、价格、渠道、销售和服务准备；
- 产品营销不能替代产品管理和工程决策；
- 不把功能数量等同于客户价值；
- 不把 Value Proposition Canvas 当需求已验证；
- 不把发布成功等同于长期采用；
- 不承诺产品无法兑现的功能、ROI 或结果。
