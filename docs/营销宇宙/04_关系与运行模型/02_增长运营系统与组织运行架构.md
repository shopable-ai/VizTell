# 增长运营系统与组织运行架构

> 状态：DRAFT｜通用架构提案，待跨业务模式任务验证
> 版本：v0.9
> 归属：通用营销宇宙 / 04_关系与运行模型
> 适用范围：商业企业、产品型业务、服务业务、B2B、B2C、订阅、平台、零售及非营利组织
> 边界：本文件定义通用运行架构，不定义任何具体品牌、产品或公司的现状、能力和商业结论。

## 一、结论与架构定位

增长运营系统（Growth Operating System，GOS）是一套把组织目标、市场与客户情报、战略选择、产品/服务价值、商业模式、市场进入、客户生命周期、经营测量和资源再配置连接起来的持续管理系统。

它不是营销知识分类的替代品，不是 SEO 或获客系统的别名，不是 AARRR、SOSTAC、RACE 等单一框架的扩展版，也不是要求所有业务严格按顺序执行的固定漏斗。

### 1.1 与相邻概念的区别

| 概念 | 回答的问题 | 核心产物 |
|---|---|---|
| 营销知识宇宙 | 有哪些专业知识、方法、领域和边界 | D01-D24 知识地图、方法与专业定义 |
| Growth Intelligence Loop | 信号、判断、行动、结果和学习怎样形成反馈 | 跨领域反馈关系与学习回路 |
| Growth Operating System | 组织怎样持续运行这些能力 | 目标、责任、节奏、预算、决策门、工作流和治理 |
| Growth Model | 特定业务的增长变量、机制、约束和因果假设是什么 | 可检验的业务增长模型 |
| Growth Experiment | 某项干预是否改变目标结果 | 实验设计、结果、不确定性和决策 |

本文件补充组织运行层；现有《增长情报闭环与跨领域运行模型》继续作为情报反馈模型，不被替代。

### 1.2 设计原则

1. 以客户价值和组织使命为目标，不以流量、活动数量或短期收入作为唯一目标。
2. 以现有 D01-D24 专业领域为知识 Owner，不创建第二套营销学科目录。
3. 以问题和决策路由知识，不把模块数量当成完整性。
4. 区分战略选择、情报输入、决策审批、执行工作和结果测量。
5. 允许并行、回退、等待、暂停和退出；不强制串行。
6. 区分事实、推断、假设、建议、批准决策和实际结果。
7. 业务模式、客户购买周期、产品使用频率和组织规模不同，运行配置必须不同。
8. 先用人类可执行的最小流程验证，再决定是否自动化或机器化。

## 二、整体架构：五个运行层与四个横向控制平面

### 2.1 五个运行层

| 层 | 名称 | 核心职责 | 主要输出 |
|---|---|---|---|
| L1 | 战略与组合层 Strategy & Portfolio | 使命/目标、市场选择、竞争取舍、预算与能力配置 | 战略选择、目标、资源边界 |
| L2 | 情报与发现层 Intelligence & Discovery | 市场、客户、竞争、需求、机会与趋势研究 | 情报、需求证据、机会假设 |
| L3 | 价值与商业设计层 Value & Business Design | 产品/服务价值、定位、商业模式、定价、市场进入设计 | 价值方案、商业假设、GTM 设计 |
| L4 | 市场交付与生命周期层 Delivery & Lifecycle | 需求创造、渠道分发、销售、转化、激活、留存、客户成功和扩展 | 客户结果、使用、交易和服务记录 |
| L5 | 测量、学习与再配置层 Measurement & Reallocation | 指标、实验、因果评估、经济性、复盘和资源重配 | 结果判断、决策更新、下一轮行动 |

五层是管理视图，不代表五个部门，也不代表每个任务都必须经过五层。

### 2.2 四个横向控制平面

| 控制平面 | 负责什么 | 不应做什么 |
|---|---|---|
| CP-01 数据、来源与证据治理 | 数据口径、来源、证据等级、质量、时间和权限 | 不替代专业判断或研究设计 |
| CP-02 决策、责任与组合治理 | 决策权、责任人、审批、资源、风险接受和复审 | 不把会议或签字本身当作有效决策 |
| CP-03 知识与组织学习 | 知识复用、版本、冲突、经验沉淀、失效和迁移 | 不建立重复事实源或文档孤岛 |
| CP-04 技术、AI 与风险控制 | 数据工具、自动化、AI 工作流、隐私、安全、合规和人工监督 | 不允许 AI 将推测升级为事实或越权执行 |

横向控制平面优先复用 VizTell 的 AI 原生知识系统、思维与方法宇宙、通用链路宇宙及 D23/D24 专业定义，不在营销宇宙重新定义通用 Schema、推理方法或 Agent Runtime。

## 三、十二组运行能力：能力组合，不是新增一级知识域

下列十二组能力用于组织工作，不是新增 D25-D36，也不是十二个必须独立设立的部门。每组能力由现有领域承担唯一专业定义，复杂任务可跨域协作。

| ID | 能力组 | 主要职责 | 主要知识 Owner（候选映射） |
|---|---|---|---|
| GOS-C01 | 战略与业务组合 | 使命/目标、战略选择、市场组合、资源分配、风险偏好 | D01、D05、D24 |
| GOS-C02 | 市场与环境情报 | 市场结构、规模、趋势、宏观因素、区域与监管信号 | D01、D02、D20 |
| GOS-C03 | 客户与需求情报 | 客户细分、JTBD、购买角色、行为、VoC、旅程与需求强度 | D03、D04、D06、D19 |
| GOS-C04 | 竞争与替代情报 | 直接/间接竞争、替代方案、行业结构、竞争反应和壁垒 | D02、D07 |
| GOS-C05 | 机会与产品发现 | 问题框定、机会评估、假设、解决方案探索和验证计划 | D04、D06、D08、D21 |
| GOS-C06 | 产品、服务与价值管理 | 价值主张、产品/服务策略、价值交付、PMF 证据和路线图接口 | D08、D10、D19 |
| GOS-C07 | 商业模式与经济性 | 价值捕获、收入/成本结构、定价接口、单位经济和投资回报 | D01、D09；商业模式宇宙为机制与经济性 Owner |
| GOS-C08 | 品牌、定位与市场进入 | STP、定位、品牌承诺、GTM、信息与上市准备 | D05、D06、D08、D10、D11 |
| GOS-C09 | 需求创造与渠道分发 | 内容、搜索、广告、社交、公关、伙伴、分销和销售协同 | D11-D18，按具体任务选取 |
| GOS-C10 | 客户生命周期与成功 | Onboarding、Activation、价值实现、Retention、Renewal、CS 和流失 | D18、D19 |
| GOS-C11 | 收入与客户扩展 | 交易、定价执行、续费、升级、交叉销售、扩展和收入质量 | D09、D18、D19；商业模式宇宙 |
| GOS-C12 | 测量、实验与增长学习 | 指标体系、诊断、实验、归因、增量、因果和组合复盘 | D21、D22、D24 |

**映射规则：**
- 表中的 Owner 是任务路由建议，最终定义以《24 域专业领域权威登记表》为准。
- GOS-Cxx 是运行能力 ID，不得当成专业知识节点 ID 或新增一级知识域。
- 一个能力组可以调用多个领域；一个领域也可以服务多个能力组。
- 商业模式机制、价值捕获和完整单位经济性以商业模式宇宙为权威来源；营销宇宙只维护营销专业接口和应用口径。
- 研究方法、证据、通用决策、知识对象和 AI 路由分别复用对应横向系统。

## 四、主循环、并行工作流与动态入口

### 4.1 主循环：Sense → Decide → Design → Deliver → Learn → Reallocate

```text
Sense 感知
  市场 / 客户 / 竞争 / 技术 / 渠道 / 组织信号
       ↓
Decide 判断
  问题定义 / 机会比较 / 战略取舍 / 决策授权
       ↓
Design 设计
  产品价值 / 商业模式 / 定位 / GTM / 测量设计
       ↓
Deliver 交付
  需求创造 / 渠道 / 销售 / 产品体验 / 客户成功
       ↓
Learn 学习
  行为 / 体验 / 留存 / 收入 / 成本 / 实验 / 风险
       ↓
Reallocate 再配置
  预算 / 人力 / 产品优先级 / 渠道 / 停止与新探索
       ↺ 回到 Sense
```

该主循环是经营管理总览。真实工作可能从任何节点进入，并通过反馈改变任一上游决策。

### 4.2 并行工作流

| 工作流 | 运行内容 | 典型触发器 | 主要交付 |
|---|---|---|---|
| W-01 市场扫描 | 市场、宏观、技术、监管和区域变化 | 周期扫描、重大外部事件 | 信号与影响评估 |
| W-02 客户发现 | 访谈、任务观察、反馈、流失与购买行为 | 新机会、体验问题、流失异常 | 客户证据与需求解释 |
| W-03 竞争监控 | 产品、价格、渠道、定位和竞品变化 | 核心竞品变化、战略复审 | 竞争更新和反例 |
| W-04 产品与价值验证 | 原型、可用性、产品行为和结果验证 | 机会进入探索、价值假设变化 | 产品证据和缺口 |
| W-05 商业模式与经济性 | 定价、成本、毛利、现金、回收和敏感性 | 新定价、预算、扩张或利润恶化 | 经济性判断 |
| W-06 GTM 与渠道 | 定位、内容、销售、媒体、伙伴和分发 | 新市场进入、渠道表现变化 | GTM 计划和渠道实验 |
| W-07 生命周期与客户成功 | 首次价值、复用、留存、支持、续费和流失 | 激活下降、留存异常、客户风险 | 生命周期诊断 |
| W-08 实验与经营复盘 | 实验设计、增量测量、结果解释和预算复审 | 预注册实验、固定复盘周期 | 实验结论和资源建议 |

工作流可并行，但共享目标、证据、决策和数据定义；并行不等于互不协调。

### 4.3 动态入口

系统至少支持市场/监管/技术突变、新客户群或未满足需求、竞争者进入或价格变化、产品可靠性和价值交付失败、渠道边际成本变化、留存/收入/毛利恶化、品牌危机，以及组织能力、现金流或合规约束变化等入口。

## 五、决策门：把研究变成可审查的资源选择

决策门不是机械审批流程，而是明确何种证据和风险条件下可以承诺下一阶段资源。

| Gate | 决策问题 | 最低输入 |
|---|---|---|
| DG-01 战略适配 | 是否符合使命、战略、能力和资源约束？ | 战略目标、机会成本、风险边界 |
| DG-02 市场与客户证据 | 是否有足够证据说明目标市场和客户问题存在？ | 市场来源、客户证据、替代解释 |
| DG-03 机会投资 | 该机会相对其他选择是否值得投入？ | 机会比较、可服务性、经济性初估 |
| DG-04 产品/服务价值 | 方案能否可靠交付目标客户结果？ | 原型/产品测试、任务结果、失败记录 |
| DG-05 商业可行性 | 价值捕获、价格、成本和风险是否可接受？ | 价格证据、成本、毛利、现金和敏感性 |
| DG-06 市场进入准备 | 定位、渠道、产品证据和运营能力是否一致？ | GTM、渠道计划、声明证据、支持准备 |
| DG-07 生命周期健康 | 用户是否实现并持续获得价值？ | 激活、复用、留存、支持和流失数据 |
| DG-08 扩张与再配置 | 是否有证据支持扩大、维持、转向或停止？ | 增量结果、边际经济性、容量和风险 |

每个 Gate 允许 PASS、CONDITIONAL_PASS、FAIL、INCONCLUSIVE。条件通过必须写明条件、负责人、期限和未满足时的动作。合规、安全、隐私和重大声誉风险可独立否决，不可被平均评分抵消。INCONCLUSIVE 不得改写成成功或失败。

## 六、模块运行合同：统一输入、输出、责任和验收

每个能力组及其重要工作流使用统一运行合同：

| 字段 | 定义 |
|---|---|
| Module / Workflow ID | 稳定标识及版本 |
| Purpose / Trigger | 业务理由、触发条件或周期 |
| Scope In / Out | 纳入和排除范围 |
| Inputs / Dependencies | 必需数据、知识、证据和前置条件 |
| Activities | 关键研究、判断或执行活动 |
| Outputs | 可复用成果和记录 |
| Decisions | 决策权限及升级条件 |
| Metrics | 过程、结果、质量和护栏指标 |
| Owner / Approver | 执行责任人、最终决策人和协作方 |
| Automation / AI Role | 可自动化步骤、AI 角色与边界 |
| Human Review | 必须人工核验或批准的事项 |
| Risks / Failure Handling | 风险、失败、回退和停止条件 |
| Evidence / Acceptance | 来源、样本、时间、口径、限制和验收 |
| Review Cadence / Status | 复核频率、状态和版本 |

模块没有独立 Owner、输入输出、决策边界或验收标准时，不应仅凭名称被认定为已建立能力。

## 七、决策记录与资源组合管理

### 7.1 决策记录最小结构

Decision ID、Decision Question、Context/Scope、Evidence References、Assumptions/Unknowns、Alternatives、Expected Impact、Cost/Opportunity Cost、Risk/Guardrails、Decision Owner、Approvers、Decision Date、Effective From/Until、Review Trigger/Date、Status、Actual Outcome、Supersedes/Superseded By。

决策记录属于通用知识/决策治理对象，应复用 AI 原生知识系统的 canonical schema；本节是营销运营字段视图，不构成第二套 Schema。

### 7.2 资源组合原则

- 资源配置单位应是可比较的战略举措、机会或经营约束，而不是内容数量或功能数量。
- 同时比较客户价值、战略适配、证据强度、投入成本、机会成本、风险、时间窗口和可逆性。
- 对不确定性高的事项，优先购买信息、做低成本探索，而不是直接大规模建设。
- 区分探索预算、验证预算、规模化预算和维护预算。
- 设定停止规则；沉没成本不是继续投入的充分理由。
- 考虑相关性与集中风险，避免所有资源押注同一渠道、客户群或平台。

## 八、用户生命周期与价值指标

### 8.1 生命周期是任务与价值模型，不是统一漏斗

通用阶段可包括认知与需求触发、信息搜索与方案比较、访问/接触/销售沟通、试用/首次购买/首次使用、首次价值实现、持续使用/服务交付/复购、留存/续费、推荐/口碑、升级/扩展，以及流失/暂停/迁移/重新激活。

不同业务可能跳过、合并、重复或反向经过这些阶段。AARRR、RACE、客户旅程地图和服务蓝图是不同用途的分析视角，不应被拼成强制漏斗。

### 8.2 激活与留存定义规则

- 激活应定义为首次完成能够代表客户价值的关键行为或结果，而非注册、安装、打开或点击。
- 留存围绕核心价值行为和合理使用周期定义；高频产品可观察日/周，低频任务、耐用品和长采购周期业务可能需要月/季度或事件周期。
- 自然复用必须与人工催促、强制任务、内部测试和自动化噪声区分。
- 服务型和 B2B 业务还要观察客户结果、服务质量、采购/续约状态和多角色使用情况。
- 流失应区分客户主动停止、需求消失、产品失败、服务失败、预算变化、竞争替代和数据不可观测。

### 8.3 指标分层

| 指标层 | 例子 | 用途 |
|---|---|---|
| 客户结果 | 任务完成、节省时间、风险降低、业务结果 | 证明客户价值 |
| 价值行为 | 核心任务成功、有效复用、服务完成、复购 | 观察价值实现 |
| 生命周期 | Time-to-Value、Activation、Retention、Renewal、Churn | 诊断关系健康 |
| 商业结果 | 收入、毛利、贡献利润、现金回收 | 判断经营结果 |
| 效率 | CAC、回收期、支持成本、交付成本 | 判断资源效率 |
| 增量与风险 | Incrementality、退款、投诉、失败率、合规事件 | 判断可持续性和副作用 |

North Star Metric 只能是特定业务阶段下的候选指标。必须说明客户价值逻辑、领先/滞后关系、可操纵性、数据可得性和护栏指标；不能把单一指标当作所有业务的统一北极星。

## 九、市场进入与渠道组合管理

渠道是可选择的分发机制，不是必须全部部署的清单。每个候选渠道至少评估：
- 目标客户和购买/使用角色是否匹配；
- 需求意图和触达场景；
- 可触达规模及其证据；
- 到首次价值的完整路径；
- 直接成本、人员成本和维护成本；
- 转化周期、销售周期和回款周期；
- 客户质量、留存与贡献利润；
- 数据可观测性和归因限制；
- 平台政策、合规和渠道依赖风险；
- 边际成本、容量和可扩展性；
- 是否能形成复利、口碑或合作网络。

不要用未经校准的主观权重公式制造精确排名。早期采用证据说明、区间估计和小规模试验；有足够数据后再使用加权模型，并披露权重敏感性。

渠道可按自有、付费、赢得、共享、平台/市场、销售与伙伴渠道分类。分类用于检查组合和控制权，不代表所有渠道都适合所有业务。

## 十、实验、测量与因果纪律

### 10.1 实验卡最低字段

Experiment ID、问题、可证伪假设、目标人群、干预、对照/比较条件、基线、主要指标、护栏指标、样本与功效依据、观察窗口、数据质量、分析计划、结果、限制、决策和后续复审。

### 10.2 证据类型与推断边界

| 类型 | 可以支持 | 不能自动支持 |
|---|---|---|
| 定性访谈/观察 | 机制、情境、问题和解释线索 | 总体比例和因果效应 |
| 描述性数据 | 发生了什么 | 为什么发生 |
| 相关性/队列分析 | 变量共同变化、群体差异 | 干预造成变化 |
| 归因模型 | 按指定规则分配触点功劳 | 渠道增量或因果贡献 |
| 随机实验 | 在设计和执行条件成立时估计处理效应 | 无条件外推到所有市场 |
| 准实验/因果推断 | 在识别假设成立时估计因果效应 | 忽略假设和敏感性分析 |
| 预测模型 | 在适用数据分布下预测 | 因果解释或保证未来结果 |

### 10.3 结果状态

- POSITIVE：主要指标达到预设标准且护栏未触发；
- NEGATIVE：证据支持假设不成立或产生不可接受副作用；
- INCONCLUSIVE：样本、测量、执行或观察窗口不足；
- INVALID：实验执行或数据质量破坏预定设计；
- MIXED：主要指标与护栏、细分群体或不同时间尺度存在实质冲突。

不得把 INCONCLUSIVE/INVALID 改写成“基本成功”。实验前应预先登记主要指标、分析窗口、排除规则和停止条件；事后探索必须标记为探索性分析。

## 十一、AI 与自动化权限边界

| 级别 | 可执行范围 | 典型控制 |
|---|---|---|
| A0 整理 | 格式校验、去重、索引、摘要草稿 | 保留原始来源 |
| A1 研究辅助 | 公开来源扫描、信息提取、初步分类 | 标注时间、来源和缺失 |
| A2 分析建议 | 生成假设、备选方案、异常解释 | 明确推断与不确定性 |
| A3 审批后执行 | 更新受控资产、发布内容、运行营销活动 | 人工批准、权限和回滚 |
| A4 受控验证 | 调用真实产品/数据系统、运行测试并读取回执 | 真实环境、日志、独立验收 |
| A5 人类专属决策 | 战略承诺、预算、价格、合同、法律/风险接受 | 指定决策责任人 |

AI 不得把模拟数据、合成用户或模型推断冒充真实客户证据；未经授权联系客户、发广告、承诺价格、签约或处理敏感数据；自行审批高风险 Claim、重大预算、定价或法律风险；自动升级未验证状态；删除失败样本和反例以美化结论。

自动化优先级由重复频率、规则稳定性、数据权限、错误成本、可回滚性和人工复核成本共同决定。

## 十二、经营节奏与责任机制

节奏按业务风险、数据刷新频率和组织规模配置，不是硬性要求。

| 节奏 | 主要议题 | 典型输出 |
|---|---|---|
| 事件触发 | 重大客户/产品/市场/风险异常 | 快速判断、止损或升级 |
| 每周/双周 | 关键指标、客户反馈、实验和执行阻塞 | 行动调整、责任人与期限 |
| 每月 | 渠道质量、生命周期、收入成本、机会组合 | 经营复盘和预算微调 |
| 每季度 | 战略假设、市场组合、资源配置和风险 | 战略/组合决策 |
| 年度/战略周期 | 使命、竞争位置、能力组合和长期投资 | 战略更新与能力建设 |

责任分工应明确业务/战略负责人、专业 Owner、工作流 Owner、数据/分析负责人、风险/合规负责人和最终决策人。小团队可由同一人兼任多个角色，但每个关键决策必须明确唯一最终责任人。

## 十三、成熟度模型与实施顺序

| 级别 | 名称 | 可观察状态 |
|---|---|---|
| M0 | Ad hoc | 工作依赖个人经验，记录零散 |
| M1 | Defined | 核心流程、Owner、指标和决策记录已定义 |
| M2 | Evidence-driven | 证据、决策门、失败处理和复盘可追溯 |
| M3 | Integrated | 情报、产品、渠道、生命周期和经济性共享口径 |
| M4 | Adaptive | 可靠数据支持持续实验、预测和资源再配置 |

实施顺序：选一个高价值且边界清楚的问题；定义最小运行合同；人工运行至少一个完整周期；记录失败与返工；复盘后再标准化和自动化；在不同业务情境中重复验证后再提高成熟度。不得以文档、模块、Agent 或流程图数量作为成熟度证据。

## 十四、反方审计与禁止的架构膨胀

每轮复审必须检查：
1. 这是新的业务能力，还是现有 D 域/横向系统的重复命名？
2. 是否有独立输入、输出、决策权和验收标准？
3. 是否把专业领域、组织部门、流程阶段、渠道、指标和技术工具混成同一层级？
4. 是否把信息收集误当成决策能力？
5. 是否忽略客户价值、产品质量、履约、支持和服务成本？
6. 是否只追踪短期归因而没有增量和长期经济性？
7. 是否把用户旅程强行压成线性漏斗？
8. 是否忽略低频业务、B2B 采购周期、非营利目标和公共利益？
9. 是否用未经校准的权重、评分或样本制造虚假精确？
10. 是否让 AI 执行超出授权和证据能力的动作？
11. 是否建立无法维护的数据、流程或自动化？
12. 是否有明确停止、回退、失效和历史迁移机制？

### 硬性失败条件

关键决策没有责任人或依据；核心客户价值没有定义或观察证据；重大数据/隐私/安全/法律风险未处理；归因被错误表述为增量或因果；经济性遗漏关键成本；重大实验没有预设指标和护栏；AI 生成内容被冒充真实证据；多个系统争夺同一事实源；没有真实工作流执行记录。出现任一项，不得认定相应业务范围的 GOS 已验证。

## 十六、专业理论与来源接口

本文件是架构综合，不声称任何单一理论能完整定义 GOS。按问题选择理论并保留边界：
- AMA Marketing Definition：价值创造、沟通、交付和交换的范围锚点。https://www.ama.org/the-definition-of-marketing-what-is-marketing/
- Porter Five Forces：行业结构与长期竞争压力，不等于功能竞品表。https://www.isc.hbs.edu/strategy/business-strategy/Pages/the-five-forces.aspx
- Jobs to Be Done：在具体情境下理解用户希望取得的进步，不等于 Persona 模板。https://www.christenseninstitute.org/theory/jobs-to-be-done/
- Strategyzer Business Model Canvas：描述价值创造、交付和获取的商业模式假设，不证明模式成立。https://www.strategyzer.com/library/the-business-model-canvas
- Product Talk Opportunity Solution Tree：连接结果、机会、解决方案和假设，不替代市场规模或商业经济性研究。https://www.producttalk.org/opportunity-solution-trees/
- SOSTAC：营销规划与控制骨架，不替代专业研究和因果测量。https://prsmith.org/sostac/
- RACE：客户旅程/数字营销规划视角，不是所有业务的统一漏斗。https://www.smartinsights.com/digital-marketing-strategy/race-a-practical-framework-to-improve-digital-marketing/
- Amplitude North Star Framework：将用户价值与业务结果关联；指标必须按业务行为定义。https://amplitude.com/north-star
- Growth Loops：检验输入、动作、输出和再投入是否形成可持续循环。https://amplitude.com/blog/growth-loops
- ICC/ESOMAR International Code：研究伦理、透明、数据主体保护和专业责任。https://esomar.org/what-we-do/code-guidelines

更完整的理论摘要、许可和适用边界，以《专业理论、标准与方法框架索引》为准；使用前核验动态来源版本。
