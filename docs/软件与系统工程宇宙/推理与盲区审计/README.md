# R1-C · 软件研发推理模式与盲区审计（候选实践）

任务 ID：AI-NATIVE-REASONING-UNIVERSE-R1｜2026-11-26

**目标**：在从想法到实际产品及运营的全过程中发现高价值遗漏，并能说明覆盖范围、剩余风险与停止理由；不保证发现所有未知问题。

**状态**：文献与仓库案例静态核对、候选方法及回归义务已整理；未独立盲测、未复跑业务测试、未批准 Skill、未获得独立95分。本文只是已有方法在软件工程领域的应用索引，不增加工程内核类型、状态或工作流阶段。

## 1. 最小框架

当前对象/目标/版本/边界 → 选择推理方式 + 扫描适用维度 → 正向成功与逆向失败推演 → 区分事实、推断和证据缺口 → 只交付有价值的差量与剩余风险 → 回现有审核/决策/验证流程。

沿用[五阶段总体框架](../00_AI原生研发总体框架与关键结论.md)、[四组九算子](../需求推理与需求工程/README.md)、[十坐标与停止协议](../../思维与方法宇宙/03_跨宇宙多维推理与节点续研协议.md)、[八母维度/30维深挖](../../通用链路宇宙/19_链路垂直深挖与审计框架.md)。这里不另定义母宇宙或覆盖分母。推理模式是操作，审计维度是对象切面，证据是质量约束。三者可组合，不假装数学正交。本文的 R1-C 不等于父专题未来的关系一致性 R1-C。

## 2. 13种推理模式：选择索引而非新算子协议

| 模式 | 触发/输入 | 输出与局部停止 |
|---|---|---|
| 正向 | 已知条件、动作和规则 | 可观察结果与异常分支；关键动作的前后条件均明确 |
| 逆向 | 期望结果或不接受的失败结果 | 必要条件、候选原因、防线；可追踪至责任/验证，或明确未知 |
| 因果 | 有现象但原因不明 | 竞争解释、区分性测试；证据足以支持当前决策或报告无法识别 |
| 对抗 | 关键假设、权限、发布或完成声明 | 反例、攻击面、失败判据；高影响反例已处置或阻断 |
| 反事实 | 可选方案/可删除前提 | 改变条件后的预测与对照；假设和可判别结果明确，不虚构历史 |
| 类比 | 新领域、既有相似案例 | 可迁移机制与不适用条件；找到实际可验证映射 |
| 组合 | 多状态、参数、版本或组件交互 | 有约束的场景/测试集合；达预定t-way与指定高风险组合 |
| 约束 | 硬约束、冲突、资源有限 | 可行方案、冲突及取舍；可行性已证或阻断 |
| 场景 | 用户旅程、用例、实际行为 | 正常/替代/异常/恢复路径；关键状态转换有判据 |
| 边界 | 对象、权限、输入、数量、时限 | 等价类、边界值和越界行为；相关临界与跨边界案例已定义 |
| 价值 | 功能扩展、运营结果、成本 | 必须/可延后/拒绝及理由；不再改变本轮优先级 |
| 证据 | 事实、因果、已完成声明 | 来源/版本/环境/判据映射与缺口；证据支持对应主张或保留未知 |
| 时间演化 | 长期运行、升级、迁移、反馈 | 变化路径、兼容/回退/观察触发；关键演化场景有负责人与策略 |

对应旧算子：正向/逆向承接DECOMPOSE/REVERSE；场景/边界/组合承接EXPAND/JOURNEY/OBSTACLE；因果/对抗/反事实承接OBSTACLE并继承十坐标C/F；约束承接DEPENDENCY/CONFLICT；类比与时间演化服务DISCOVER/JOURNEY；价值与证据承接PRUNE_VERIFY。不是一一等价关系，不删除旧算子。正向+逆向+证据+必要性判断是默认轻量骨架；其他按触发选择。

## 3. 全链路检查矩阵（软件领域投影）

| 检查面 | 问题 | 重点阶段/证据 |
|---|---|---|
| 角色/目标/商业 | 为谁创造什么价值？谁负责、付费、受损？ | 需求/运营；原话、实际旅程、结果指标 |
| 场景/功能/需求 | 每个成功条件是否有能力，异常是否有处置？ | 需求/设计/验收；追溯、场景、测试 |
| 状态/时间 | 重入、暂停、竞态、延迟、重复、UNKNOWN怎样处理？ | 设计/执行；状态与时序、异常运行 |
| 数据/空间环境 | 数据身份、归属、隐私、读写、保留、删除、跨设备/平台/窗口？ | 设计/运营；接口、边界测试 |
| 依赖/资源/工具 | 外部服务、共享运行时、容量、版本、权限、工具真的可用？ | 设计/执行；依赖图或简表、容量与授权证据 |
| 风险/质量 | 最坏结果、兼容、性能、安全、可用性、可恢复性？ | 所有阶段；关键风险、可测约束 |
| 证据/责任 | 哪个版本、安装、环境与判据被验证？谁处理失败、批准剩余风险？ | 所有阶段；可定位的执行记录、决定 |
| 生命周期 | 安装、升级、运行、维护、迁移、退役与反馈如何闭环？ | 早期定义影响，交付时验证适用义务；发布/运维记录 |

每次先确定适用性，逐行标识已查（引用）、发现缺口、待证、未查或不适用（理由）；已查不是产品通过。不要要求每行生成新文档，不要删掉待证项来抬高覆盖率。

交付后重点检查：安装/撤权及首次使用；实际目标达成/失败/耗时/用户反馈；外部站点改变与维护责任；升级旧数据兼容、重复迁移与失败恢复；降级/回滚（受平台能力限制）；退役关闭任务、处理数据和通知受影响用户。商业验证看用户结果、留存或成本等适用指标，不默认强加付费/遥测，先验证需求、隐私及授权。

## 4. 场景双向推演协议

输入：目标G、当前范围/版本、已知事实与假设、起始状态、动作、可观察成功S、不接受的失败F、预算。正向从条件→行为→状态→真实结果；在每个关键动作问不做、做错、过早/晚/乱序、过短/长、重复、反馈未知。逆向从S找必要前提；从F建立可能原因（AND/OR仅作分析表达），不把逆推当唯一根因。把候选防线再代回正向路径，同时检查正常功能是否受损。生成可观察验收与负例；已存在的需求只引用；可行性未知先验证。缺口记录：来源定位｜现象/反例｜受影响目标｜事实/推断｜建议最小修正｜验收/剩余未知｜现有责任与决策入口。沿用现有需求卡/缺陷/测试记录，不再创建审批门。

## 5. 盲区审计与过度设计防御 Skill（候选说明，非已安装）

触发：需求或方案进入现有决策门，重要变更，失败/用户反馈，发布及迁移，完成声明。输入：目标/范围/基线、当前产物、已有场景和证据、风险和预算。先恢复资产，做轻量8面扫描；按风险选择：
- UI小改动：场景/边界/证据；复杂异步或自动化：追加状态时序、对抗、组合，优先STPA提示词。
- 现象原因不明：因果与反事实；重大失败：Premortem+FTA，已有详细设计时FMEA。
- 多方案冲突：约束/价值、TRIZ、QAW/ATAM；新领域：类比+实证；升级/数据：时间演化、迁移/兼容、回滚、组合。
- 数据泄漏、不可逆副作用、越权及关键目标阻断：定向深查，不以平均分放行。

先用真实变量/状态和依赖筛选组合；低风险可用代表性和边界样例，交互多时对建模的有效组合使用2-way起步、高风险用3-way或指定更高阶与事件序列，禁止将其等同穷举。用约束剔除不可能组合，保留剔除理由。按目标损失/发生依据/可探测性/修复成本决定优先级，不虚构概率。删除或延期不能改变目标、约束、实际损失或决策的新增项；优先复用，不以审计需要的证据强制新增运行时功能。

停止：已有协议优先；默认先做一轮扫描、一轮针对性反例，作为可调预算，不是充分性阈值。满足关键义务的证据与适用性、无未处置阻断风险，且剩余低价值前沿有记录与复核触发，可结束本轮；预算耗尽/证据缺失只结束工作，不宣布通过。变更仅重审影响范围；共享依赖变化可扩大影响范围。

覆盖声明分开记录：A=已判定适用性检查项/预设检查项（含有理由N/A）；B=有符合判据证据的适用义务/全部适用义务（未知或未执行不能剔除）；C=已执行有效t-way组合/预先建模的有效组合（报告t、变量和值域、约束及指定高风险序列）；D=已知金标准缺口召回与提案精确率（需要独立金标准）。报告分母、版本、环境、未知、例外与非覆盖范围；不适用须有理由，关键缺口不能被平均数掩盖。100%有限集合覆盖不证明真实世界全部未知。独立审查由不同运行或真实审核者形成；同一AI视角不称独立。

## 7. 主框架增量与验证接续

只建议：在现有质疑与补漏、裁剪与收敛中引用本索引；在设计/变更审核时按触发选择推理，在验收中核对证据分母与版本，在运营中补反馈、维护/退役义务；把已证历史问题回归到相应产品现有测试/经验记录。正式契约及产品代码均不修改。不得创建平行R3评测或重复工程模型应用任务；建议在现有R1-B.1应用验证之后判断是否需独立验证本Skill，与R3.2需求推理盲测共用可复用的冻结资产但不污染盲测。

未来效果实验建议：以未见过的案例做基础方法A/启用审计B，同一输入、模型、预算，冻结独立金标准、随机匿名判卷。报告重要遗漏召回、误报/过度设计、目标保持、证据适切、成本、可读性和新增决策价值；不以已知答案的案例宣称前瞻发现能力。可做消融，但先证明整体增量。正式多维100分算术平均≥95且无关键门阻断；目前独立评分NOT_SCORED。R3.2原计划36槽不能因本文写成执行完成。没有全未知集合的分母，不证明全局完备性。
