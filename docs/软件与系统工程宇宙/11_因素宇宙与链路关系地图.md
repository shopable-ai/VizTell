## 1. 一屏框架

- 因素宇宙：**需要考虑什么**——用户与需求、商业与价值、产品与业务、技术与系统、数据与状态、资源与约束、质量与风险、环境与演化。
- 链路宇宙：**需要推进什么**——机会与价值 → 目标与需求 → 产品与方案 → 技术与计划 → 开发与集成 → 验收与发布 → 使用与价值 → 运营与演化。完整主链/专项/基础链入口见 [08 R2 链路地图](../通用链路宇宙/08_软件IT与AI原生.md#r2-chain-map)。
- 推理方法、工程模型、角色专家、Skill、Workflow、Tool、知识与证据负责**如何分析、表达、判断、推进、核验**；继续引用原专题，不把能力和因素混成同一分类，不改 [五阶段共同入口](00_AI原生研发总体框架与关键结论.md) 或 AI-Project-OS。

**因素减少考虑遗漏，链路减少过程遗漏；两者不保证穷尽未知。** 业务链（用户或产品如何运转）是研发设计的对象，不等同研发链（如何开发或改造它）。链路可并行、回退和复用；局部改动不从零走全链。

## 3. 两张地图怎样互相使用

下表 L1–L8 是 [08 链路地图](../通用链路宇宙/08_软件IT与AI原生.md#r2-chain-map) 的八组；主因素是默认优先查的范围，次因素按变化/风险触发。不是八乘八全勾，也不要求每次输出所有因素。每行给出能影响下一决定的实例。

| 链路 | 优先查因素 | 条件触发的其他因素 | 会改变的决定 |
| --- | --- | --- | --- |
| L1 机会与价值 | F1/F2/F6/F8 | F3–5/F7（已有资产或风险） | 需求频率低、替代已够好 → 暂缓/不做；价值高但未知 → 最小试验 |
| L2 目标与需求 | F1/F2/F3/F6 | F4/F5/F7/F8 | 真实场景、规则例外或约束不同 → 补必要需求/验收，拒绝伪需求 |
| L3 产品与方案 | F1/F3/F4/F7 | F2/F5/F6/F8 | 小屏或非 UI 使用条件 → 调整交互/接口，不强制同一方案 |
| L4 技术与计划 | F3/F4/F5/F6/F7 | F1/F2/F8 | 平台权限不支持、并发冲突 → 调整技术机制/任务依赖 |
| L5 开发与集成 | F4/F5/F6/F7 | F1/F2/F3/F8 | 共享组件影响其他模块 → 复用并增加必要回归，而非复制 |
| L6 验收与发布 | F3/F4/F5/F7/F8 | F1/F2/F6 | 测试候选与正式包身份不同 → 只承认可证明的结果 |
| L7 使用与价值 | F1/F2/F3/F8 | F4/F5/F6/F7 | 用户用不起来、成本过高 → 返回采用/体验/价值链，不只加功能 |
| L8 运营与演化 | F4/F5/F6/F7/F8 | F1/F2/F3 | API 变化、数据升级、运行退化 → 定向维护/迁移/回归或退出 |

**反向使用**：变化的因素 → 受影响的业务/工程对象及依赖 → 需要重审的链路 → 最小修正与证据。F5 状态由“确认失败”变成“结果未知”会影响 L3 的反馈、L4 的副作用/重试设计、L5 的实现、L6 的异常验收和 L8 的恢复；F8 平台版本改变可能同时影响 L4/L5/L6/L8，若只是局部样式问题则不重启商业研究。这里是影响分析导航，不是无条件因果规律；须具体指出条件及受影响对象。

每轮只记录：当前问题/链路 → 相关因素及现值/未知 → 是否改变必要需求/方案/验收 → 下一项最小证据。事实、推断、建议分开；候选影响只有核对真实证据才更新。与 [盲区审计](推理与盲区审计/README.md)、[跨域因素关系索引](../02_跨宇宙因素与关系索引.md) 和 [链路深挖](../通用链路宇宙/19_链路垂直深挖与审计框架.md) 复用，不新建协议、评测体系或强制 Skill。

### 4.2 纵向：从一个因素深入到必要规则和验证

连播助手——视频总时长 D。[需求 K0/K1/F3](https://github.com/shopable-ai/opendesk-browser/blob/e351c1e9bb4dd84b38d3554c118edb6711a09baf/projects/video-auto-skip/REQUIREMENTS.zh-CN.md)，blob 00745575334e1121398b0b26f65a1a92cd6e752d。

F5 当前视频时长 → 未加载/有效有限值/无效或直播/换源过期 → 判断规则适用性（F3/F4）→ 片尾保存相对 N，实际开始 D−N；未知或不合法不执行 → 真实新视频重算并确认跳转（F7）。

- 已有例子：45:00、最后90秒得43:30；48:00重新算46:30。相同时长不证明作品身份或规则兼容。
- 已有 K0 优先：核心视频控制不必先识别作品；K3/K4 是增强。换源、时长变化、原生连播竞争及 UNKNOWN 均已有要求，不能为本轮声称新发现或要求新增 AI 识别。
- 本轮提出的验证视角：只在相应真实视频/规则身份中比较 D 变化、有效与未知条件，核对跳过或安全不跳的结果；实现验收仍属于 OpenDesk。

这说明因素纵向深入不是多列形容词，而是找出条件变化导致的不同业务行为和验证义务。
