# AI 原生研发工作流与工程能力关系 R2

> 原研究：AI-NATIVE-DEVELOPMENT-WORKFLOW-R2 · 2026-11-26。当前验证：AI-NATIVE-DEVELOPMENT-WORKFLOW-R2-VALIDATION · 2026-11-27。五阶段和三案例仍是候选使用视图；本轮仅修正文档、核对已有能力与证据并独立审阅，不是产品运行或正式框架认证。主入口：[总体框架](00_AI原生研发总体框架与关键结论.md)；本轮结果见[第8节](#r2-validation)。

## 1. 先理解主线，而不是学习全部名词

用户只需要提出不完整想法、功能变更或缺陷反馈。AI 应恢复已有知识，找准目标，发现必要需求，选择方案，组织开发与测试，真实验收并沉淀经验。

**五阶段：需求理解与推理 → 工程模型与业务设计 → 解决方案与技术设计 → 工程执行 → 真实验收与持续演化。** 保持总体框架原有划分；以下细分是阅读和能力选择，不是新增阶段。正式 R0/S0–S7、路由、审批和证据权威不变。

- 工作流决定下一步；工程模型表达当前需要理解的事实；角色提供专业判断和责任；Skill 提供一种单阶段可复用能力；推理机制帮助发现未知；Tool 实际调用；Agent 承担任务；验证机制判断结论是否有证据。知识贯穿全程。
- 项目/模块/功能是范围维度，与研发阶段正交。选择最早需要重开的受影响环节，读取其依赖与下游影响。已有有效产物引用即可，不重写；只有确实不适用才记录 N/A，不能把缺证据写为 N/A。
- 同一任务先选风险路由：符合低复杂、低不确定、低敏感、无外部写、完全可逆、非生产且经批准裁剪才能采用 lite；信息不足默认 standard；正式生产才叠加 production，其他授权、隐私等控制仍按条件启用。复杂度不等于权限或风险。
- 区分规划、批准、实现与验收；可探索和试验，但不能把未经批准的候选需求变成 active Spec。研究或验证不自动批准业务事实。真正完成取决于当前范围、候选版本、实际环境、预定判据和有效裁决。

研究不是独立的必经流水线；S1 是正式领域与技术认知位置，S3 等阶段可触发定向研究，结果按现有决策流程回写。行为验收从 S0/S2 提前开始，S4 设计验证，S5 可作 TDD/ATDD，S6 收集真实证据。发现失败按原因回到最早受影响的节点：目标→S0；事实→S1；业务期望→S2；架构→S3；契约→S4；实现→S5。上游变更依既有失效规则重审，不能只修改实现后宣称闭环。

## 5. 三个案例：同一主链，不同执行路径

比较口径先固定：A 能否解释用户结果与验收；B 能否识别必要行为/设计差量；C 能否在不重建已有产品知识的前提下定位缺陷，并防止误完成。下列为人工桌面推演，非新增真实执行或盲测；实际历史证据单独引用。

| 环节 | A 新产品：网页阅读目录（假设） | B 连播助手：指定片尾区间保留彩蛋（历史需求回放） | C 发送队列：原生追加提问后队列停滞（历史缺陷回放） |
|---|---|---|---|
| 入口/目标 | 新建目标：快速定位长文段落 | 恢复既有 K0/K1/K2 与规则 | 恢复既有 FIFO、草稿与未知发送保护 |

### A. 全新想法：“网页阅读时自动生成目录，点击就能跳转”

这是本轮假设输入，并非对现有 Reading TOC 的重新需求研究。核心结果：长文能快速定位，原文不被破坏。范围暂定普通长文网页；动态网页适用性、无标题时是否支持及权限由研究/决策处理，暂不假设必须 AI 分析全文或建云服务。M01–M05/M08/M10/M11/M15/M17/M20/M23/M26–M28 是优先知识，动态更新再启用 M12。E1/E2/E3/E5/E6 按阶段选择，平台权限加 E7。P1–P8、P10–P12 按触发，P9 仅失败时，P13 在反馈/运营范围适用时使用。拟定验收：真实文章标题结构正确、点击落到对应正文、无标题/动态内容有明示处理、关闭目录不改变原页面；以已批准浏览器/站点范围逐项验证。假设无实际运行、无批准基线、无当前结论；不能宣布完成。

### B. 连播助手：从“最后 N 秒”扩展到“指定片尾区间、保留彩蛋”

这是历史能力变更的回放，不是声称当前缺少功能。[需求 K1/K2](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/video-auto-skip/REQUIREMENTS.zh-CN.md) 已明确固定区间保留彩蛋、片尾和自动下一集分离、时长优先。优先 M05/M10/M12/M13/M15/M19/M20/M26–M28/M30；E2/E3/E5/E6；涉及站点协作才加 E4；P1/P2/P4/P6/P7/P8/P10/P11/P12（必要时 P3/P5/P9）。复用已有规则与系统边界，不引入完整剧名识别、AI兜底、公共规则云或另一个播放器引擎。拟定验收：相对尾段随 D 重算；固定区间结束后继续彩蛋；未知时长不跳；换源旧动作失效；关闭连播自然结束留本集，开启时实际进入正确集并起播；保存/查看不混同。

历史证据： [rules.test.mjs](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/video-auto-skip/tests/rules.test.mjs) 已有45/48分钟相对片尾及非法时长、规则继承/禁用等测试定义；本轮未执行。[本机R1验收记录](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/video-auto-skip/LOCAL-R1-ACCEPTANCE.zh-CN.md) 报告 2026-11-22 同一0.2.0候选本机原生侧栏实测：片尾从120.197跳130秒并继续播放，连播关闭自然结束留第1集、开启第2集实际起播。报告同时明确双站整体验收未通过，不是生产证明；本轮仅读取历史报告，未复查其本地原始附件或当前包运行。不能将历史局部通过外推到新版本。

### C. AI 发送队列：原生追加提问后停滞

[历史验收报告](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/ai-send-queue/ACCEPTANCE-FOLLOWUP.zh-CN.md) 记录的症状：原回复完成，仍有待发项，“提前发送”也无法强制发送。DOM 同一个原生 turn 有两条 user 节点后跟一个 completed assistant；旧回复栅栏要求已确认 user 持续是最后一条，造成可能永久不满足。报告说定向回归支持该解释，但未读到故障页私有 answerGate 或执行 sourceHash，实际卡点仍是有证据支持的判断，不能把同时出现的429写成根因。已有需求：FIFO、恰好一次可观察入站、草稿保护、未知结果不重放。优先 M01/M05/M12/M13/M22/M26–M28/M30；E5/E6，必要时E2/E9；P1/P9/P6/P7/P8/P10/P11/P12按需。无需重新研究产品、重做全量用户旅程、架构或队列引擎。预定复归：C 已入站并回复中，D 待发，原生追加 E；等待最新 E 回复真实完成后 D 自动发送一次，原有顺序及草稿保护不破坏；unknown 无确认不得重放。

### 反方检查与裁剪结论（桌面判断）

| 反例 | 正确处理 |
|---|---|
| 新产品一句话直接生成 Task | 缺批准需求、行为与判据，不能生成 active Spec；先完成必要上游 |
| B 要先构建完整作品识别和云规则才可改片尾 | 与已有 K0–K2 不依赖 K3/K4 冲突；排除无必要前置 |
| C 已知业务语义却要求重写全套模型 | 恢复已有引用、局部复现/回归；只在语义或接缝被推翻时重开更早节点 |
| 单测通过就宣称真实完成 | 不满足真实环境和同版本证据义务，保持对应证明上限 |
| 变更后复用全部旧证据，或删掉失败样本 | 按影响与版本/环境复核；无有效证据则重验，保留失败记录 |
| 简单改动直接默认为 lite 或跳过批准/权限 | 按已批准治理路由；未知默认 standard；外部动作依授权 |
| 让一个“万能 Skill”跨需求/设计/执行/批准 | 与 single_stage_only 冲突；拆成局部能力并由原 Workflow 编排 |
