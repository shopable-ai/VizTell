## 1. 一句话结论：统一引用语义，不统一全部知识形态

AI 要知道一件事情是什么、谁维护、哪个版本可用、为什么成立、它依赖什么，以及现有证据能证明到哪里。35 个模型家族只是知识关注点；不等于35种内核对象，不重新建设知识本体或运行时。

选择 **联邦式轻量语义映射：现有薄内核 + 领域权威 + 局部契约 + 可失效的派生视图**。不选择全模型平面化或按文件名/图类型定义新对象。复用既有六原语（目标范围、受控产物、稳定 ID/关系、状态迁移、门禁声明、Run/Evidence）和42种已审计对象；不新增正式 object_type，不改变正式关系 allowlist，不引入数据库、建模框架、独立服务或工作流。不是数学最小性的证明。

### 3.1 从现有字段读取，而非双写

| 语义槽位 | 复用 | 缺口及候选处置 |
|---|---|---|
| 身份 | O:stable_id、object_type、version、canonical_path；KV:knowledge_id | 跨仓 collision：候选查询键为（权威命名域，类型命名域，稳定ID），版本引用再加 version/hash；不替换仓内 stable_id |
| 权威定位 | O:canonical_path、owner；领域文档、契约包与局部键 | 路径移动不变身份；嵌入表行用包身份+行键；旧引用保持可定位、显式迁移；不发明每条规则的新受控对象 |
| 认识状态 | KV:Claim/Fact、epistemic_status；O:source/fact/assumption/unknown/research | 推断是有理由的候选断言，非新 object_type；事实必须有观察/核验，批准政策不证明世界事实；unknown 与 false、null 与 N/A 区分 |

### 3.3 去重和派生边界

- 同一事实判定键：命名域 + 语义主体/谓词/对象或值 + 条件/时间/scope + 修订；用 KV 的 identity/adjudication，不以文本 hash、embedding 或名称自动合并。
- 每个 active 原子事实指定唯一可编辑权威。功能卡规则、非目标引用稳定小节/行键；行为规格保留可观察行为、必要的批准规则引用，展示文本为锁定版本派生，不允许两处自由编辑。同词不同条件/时间/角色不合并。
- 现有 chain/spec v2 模板要求的文本字段不得删除；先用只读比较与引用建议。若需改变字段含义、增加规则 ref 或生成器，提交 CP-02；本轮没有批准写入。
- 视图派生时记录源引用、版本/hash、提取/生成规则版本、覆盖/排除、生成时间与人工差异，输出不反向成为事实权威。无可重复生成器时只标手工视图、不可声称自动同步。历史02和冻结JSON不改；本页是新增候选映射唯一编辑源，不建另一份 JSON 可编辑表。
- 识别重复不代表删除权威。不同来源相同命题先去重来源独立性，再裁决；历史证据和被驳回主张仍保留。

### 4.5 关系断言、基数和循环的实际治理

- KV Relation Assertion 已提供独立认识层关系身份、adjudication、evidence 与替代。工程映射只需能定位关系类型（如 ER-F03）、权威原字段/关系行、端点版本与范围；对有争议的映射使用 KV 或既有 research/unknown/复审记录。没有争议的专属引用直接投影，不为每条边另建受控对象或维护两份边。
- 合法例：Requirement v1→Task 的消费者链中 Task 发现不可能实现，创建 requests_review_of 指回需求；批准后 Requirement v2、新 Task、新 Run。反馈事件与依赖边不同，旧节点不修改。状态机 loop 只有显式退出、恢复条件和 attempt 上限时合法。
- 非法例：Task A 必须等 Task B 成功、B 必须等 A 成功，无外部触发/退出；版本 v2 supersedes v1 与 v1 supersedes v2；Spec 需要自身输出才能启动；未授权跨 namespace 读取关系。任何此类错误只阻断相关执行并记录复审。
- 不能把所有关系当 DAG，也不能把所有环路当作业务状态机。R1-C 按 relation/edge kind 建立硬依赖子图和独立反馈/历史子图。未知关系保守标记阻断或 review_required；不猜传播方向、不自动删除受控事实。

### 5.1 四段意图及批准闭包

### 5.3 公共状态、专属状态和证据适用性

不创建一个新状态机。O/S 六坐标（生命周期、工作、审批、实现、等级、失效）保持；影响分类是 S:56 的独立分析，不替代审批或历史验证。Evidence 采用 W:135 专属 stale_status；verification_status 保留 captured/verified/rejected 的历史判断。当前用途适用性为**派生判断**，不是新 L1 对象/状态或修改旧 Run。

候选谓词（CP-04，供研究和 R1-C 验证）：对目标主体版本、hash、判据版本、baseline、scope、环境及输入类别、路由/overlay/control、授权快照、适用审核策略、attempt 全量/选择策略、原始证据 hash、有效期、proof 和责任独立性逐项比较；对 W/Z 各自要求进行精确绑定。未找到、过期、冲突或无法证明等价，默认不适用，分类为待复核/失效或专属错误，不自动升格。版本隔离/等价必须有合法影响分析批准。Evidence 验证为 verified 仍可能对另一版本或环境无效；如果对旧版本有效，应保留旧观察和裁决历史，只禁止新用途消费。是否将既有 stale_status 写入全局记录或按消费范围记录，需 CP-04 正式解释，不能自行覆盖权威状态。

有效 Claim 受 Z/P 当前 verdict、关键路径最低 proof、scope 和禁止声明约束；无判据/Evidence、pending、unknown side effect、无有效权限或存在阻断审核时不可 issued。证明等级仅引用 P，研究日志不具有正式 proof_level。
