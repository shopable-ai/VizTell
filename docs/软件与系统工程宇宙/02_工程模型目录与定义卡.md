## 定义卡

### M01 · 问题与机会模型 / Problem and Opportunity Model

领域：D01 战略价值与问题。状态：候选。

- **别名／常见视图：** Problem frame; Current-state assessment
- **核心问题与不可替代价值：** 确定真实痛点与机会，不把用户提出的解决手段当成问题
- **输入来源：** 用户叙述、观察、数据、现状调查
- **输出结果：** 有来源的问题、受影响对象、假设与机会
- **核心实体、属性与关系：** Problem(id,context,frequency,severity); Observation; Opportunity; causes/affects
- **推荐表示：** 问题陈述、因果图、证据链接
- **典型上游：** 无指定
- **典型下游：** M02、M03、M04
- **必要性／适用条件：** 核心；有新需求或故障时使用
- **完整性与正确性检查：** 问题指向对象及来源；原因与症状分离；未知原因显式记录
- **可自动生成程度：** 低：AI归纳候选，不能观察未取得的数据
- **人工参与和确认：** 用户或领域人员确认真实痛点、机会
- **维护成本（预估）：** 低
- **缺失风险：** 错误地解决伪问题、过早锁定方案
- **理论依据（见索引）：** S01、S10、S12

### M02 · 目标与价值模型 / Goal and Value Model

领域：D01 战略价值与问题。状态：候选。

- **别名／常见视图：** Goal model; Outcome model; Goal graph
- **核心问题与不可替代价值：** 说明为何投入、期望什么结果及成功尺度
- **输入来源：** 问题、需求方、经营目标、研究事实
- **输出结果：** 目标、优先级、收益指标、替代目标和权衡
- **核心实体、属性与关系：** Goal(outcome,target,scope); Metric(unit,threshold); Benefit; refines/contributes/conflicts
- **推荐表示：** 目标网络、指标表、AND/OR分解
- **典型上游：** M01、M03
- **典型下游：** M05、M06、M08、M28
- **必要性／适用条件：** 核心；微小修改可只保留目标与原目标引用
- **完整性与正确性检查：** 目标有可检验成功条件或显式未知；AND/OR分组；冲突有处理状态
- **可自动生成程度：** 中：可提议分解，成功尺度不能臆造
- **人工参与和确认：** 目标所有者批准价值、取舍、指标阈值
- **维护成本（预估）：** 低至中
- **缺失风险：** 目标漂移，完成许多任务却未解决问题
- **理论依据（见索引）：** S10、S11、S12、S08

### M03 · 利益相关者、关注点与需要模型 / Stakeholder Concern and Need Model

领域：D02 利益相关者与系统边界。状态：候选。

- **别名／常见视图：** Actor-need model; Stakeholder expectations
- **核心问题与不可替代价值：** 表达谁受到影响、需要什么和彼此依赖，而不是重建角色宇宙
- **输入来源：** 访谈、权限角色、角色宇宙中的角色ID
- **输出结果：** 关注点、需要、冲突、确认责任引用
- **核心实体、属性与关系：** Stakeholder(roleRef,scope); Concern; Need; expresses/dependsOn/conflicts
- **推荐表示：** 关注点矩阵、演员依赖图
- **典型上游：** M01、M02、M04
- **典型下游：** M05、M14、M28
- **必要性／适用条件：** 核心；只有明确相关角色时缩减
- **完整性与正确性检查：** 每项关键需要有来源和责任方；冲突不自动抹平；角色ID可解析
- **可自动生成程度：** 低至中：提取和建议，非独立访谈
- **人工参与和确认：** 真实需求方确认其需要，治理方解决冲突
- **维护成本（预估）：** 低至中
- **缺失风险：** 只服务开发者，遗漏用户、运营或平台要求
- **理论依据（见索引）：** S02、S03、S11、S08

### M04 · 系统上下文与范围模型 / System Context and Scope Model

领域：D02 利益相关者与系统边界。状态：候选。

- **别名／常见视图：** Context model; Boundary; ConOps context
- **核心问题与不可替代价值：** 区分系统内外、负责与不负责、外部环境
- **输入来源：** 问题、目标、已有系统、外部平台事实
- **输出结果：** 边界、外部系统、运行情境、排除项
- **核心实体、属性与关系：** SystemOfInterest; ExternalSystem; Actor; Boundary; interactsWith/inScope
- **推荐表示：** 上下文图、范围表
- **典型上游：** M01、M02、M03
- **典型下游：** M05、M10、M17、M20、M24
- **必要性／适用条件：** 核心；接口、权限、跨系统时细化
- **完整性与正确性检查：** 边界明确；外部依赖有依据及责任人；排除项不被暗中纳入
- **可自动生成程度：** 中：代码可提取部分依赖，边界需确认
- **人工参与和确认：** 产品/架构负责人确认范围与外部假设
- **维护成本（预估）：** 低至中
- **缺失风险：** 越权、范围失控、误将外部站点行为当产品行为
- **理论依据（见索引）：** S03、S07、S08、S22

### M05 · 需求模型 / Requirement Model

领域：D03 需求、质量与约束。状态：候选。

- **别名／常见视图：** Requirements graph; Requirement tree (view)
- **核心问题与不可替代价值：** 定义可验收的系统义务及其来源，而非功能清单
- **输入来源：** 目标、需要、规则、约束、场景
- **输出结果：** 需求语句、适用条件、验收条件及追溯关系
- **核心实体、属性与关系：** Requirement(statement,scope,priority,acceptance,revision); derives/refines/satisfies
- **推荐表示：** 结构化条目、需求树视图、追溯矩阵
- **典型上游：** M02、M03、M04、M06、M07、M10、M13
- **典型下游：** M08、M15、M17、M20、M26
- **必要性／适用条件：** 核心；所有变更至少有一个需求或缺陷约束
- **完整性与正确性检查：** 批准项可验证且有来源；冲突已处置；分解满足覆盖；排除项有理由
- **可自动生成程度：** 中：可生成候选、去重和检查，确认前非事实
- **人工参与和确认：** 需求所有者批准范围、验收条件与冲突处置
- **维护成本（预估）：** 中
- **缺失风险：** 需求遗漏、无法知道实现是否满足承诺
- **理论依据（见索引）：** S02、S07、S08、S37

### M06 · 质量属性与度量模型 / Quality Attribute and Measurement Model

领域：D03 需求、质量与约束。状态：候选。

- **别名／常见视图：** Quality model; Quality scenarios
- **核心问题与不可替代价值：** 定义质量特性、量化尺度和预算，避免只描述功能
- **输入来源：** 目标、环境、用户/安全关注、质量分类
- **输出结果：** 质量属性、测量条件、目标值及测量方法
- **核心实体、属性与关系：** QualityAttribute; Metric(unit,threshold,window); QualityScenario; measures/qualifies
- **推荐表示：** 质量属性场景、指标表、预算分配
- **典型上游：** M02、M03、M04、M24
- **典型下游：** M05、M17、M26、M31
- **必要性／适用条件：** 核心覆盖检查；独立详细模型在性能、可靠性、安全等显著时启用
- **完整性与正确性检查：** 单位、负载、环境、阈值明确或未知；度量对应目标；不把产品分类当实际达标
- **可自动生成程度：** 中：分类检查可自动，目标值需事实
- **人工参与和确认：** 产品与质量负责人确认容许误差与取舍
- **维护成本（预估）：** 中
- **缺失风险：** 功能可用但过慢、误操作、不可维护
- **理论依据（见索引）：** S06、S08、S03

### M07 · 约束与政策模型 / Constraint and Policy Model

领域：D03 需求、质量与约束。状态：候选。

- **别名／常见视图：** Constraint catalog; Compliance obligation
- **核心问题与不可替代价值：** 分离外部强制规则、设计限制、权限政策与偏好
- **输入来源：** 平台合同、法规、业务治理、已批准决策
- **输出结果：** 有作用范围和来源的义务、禁止项、豁免
- **核心实体、属性与关系：** Constraint(predicate,scope,authority,hardness); Policy; Exception; constrains
- **推荐表示：** 约束表、谓词、策略规则
- **典型上游：** M03、M04、M24、M29
- **典型下游：** M05、M13、M15、M17、M20、M26
- **必要性／适用条件：** 核心覆盖检查；存在权限、合规、兼容性时细化
- **完整性与正确性检查：** 强制性及有效期明确；外部规则版本可查；豁免有授权；冲突需处置
- **可自动生成程度：** 中：机械检查高，法律/平台解释需人工
- **人工参与和确认：** 有权决策者批准政策和豁免
- **维护成本（预估）：** 中
- **缺失风险：** 架构越界、违反权限、把偏好当不可改变约束
- **理论依据（见索引）：** S02、S04、S07、S26

### M08 · 产品能力与功能模型 / Capability and Feature Model

领域：D04 产品能力与变体。状态：候选。

- **别名／常见视图：** Feature catalog; Capability map; Feature tree (view)
- **核心问题与不可替代价值：** 组织产品提供的可感知能力，映射需求而不重复其义务
- **输入来源：** 目标、需求、场景、产品范围
- **输出结果：** 能力层次、功能关系、可交付边界
- **核心实体、属性与关系：** Capability; Feature(scope,availability); realizes/supports/dependsOn
- **推荐表示：** 功能目录、能力地图、关系图
- **典型上游：** M02、M05、M10
- **典型下游：** M09、M15、M17、M23、M26
- **必要性／适用条件：** 核心或并入需求；多功能产品独立维护
- **完整性与正确性检查：** 核心功能有需求依据；未交付功能状态明确；无虚构功能；依赖区分价值与顺序
- **可自动生成程度：** 中：可从需求候选提取或从代码发现
- **人工参与和确认：** 产品负责人确认能力范围与交付优先级
- **维护成本（预估）：** 低至中
- **缺失风险：** 需求与产品功能错配、范围膨胀
- **理论依据（见索引）：** S12、S13、S14

### M09 · 变体与产品配置模型 / Variability and Product Configuration Model

领域：D04 产品能力与变体。状态：候选。

- **别名／常见视图：** Feature variability model; Product-line configuration
- **核心问题与不可替代价值：** 表达版本、站点、套餐、可选组合及合法配置
- **输入来源：** 能力、平台支持范围、商业政策
- **输出结果：** 变体组、可选项、互斥和依赖规则
- **核心实体、属性与关系：** Variant; FeatureGroup(min,max); Configuration; requires/excludes/selects
- **推荐表示：** 特征模型、约束表达式、配置表
- **典型上游：** M07、M08、M20
- **典型下游：** M17、M21、M26、M30
- **必要性／适用条件：** 条件：多站、多版本、插件或套餐
- **完整性与正确性检查：** 组合可满足；不存在死特征；覆盖关键配置；区分编译和运行变体
- **可自动生成程度：** 高：约束求解与组合校验；语义来源需人工
- **人工参与和确认：** 产品/平台负责人确认可用配置和套餐
- **维护成本（预估）：** 中
- **缺失风险：** 配置组合冲突、仅测试一种版本
- **理论依据（见索引）：** S13、S14、S12

### M10 · 场景与用例模型 / Scenario and Use Case Model

领域：D05 场景、行为与业务规则。状态：候选。

- **别名／常见视图：** Use case; Scenario catalog
- **核心问题与不可替代价值：** 表达参与者在前置条件下如何完成目标及异常情境
- **输入来源：** 目标、需要、范围、规则、观察
- **输出结果：** 主路径、替代路径、失败路径、后置条件
- **核心实体、属性与关系：** Scenario(actor,precondition,trigger,outcome); Step; Alternative; exercises
- **推荐表示：** 用例文本、场景图、Given/When/Then
- **典型上游：** M02、M03、M04、M05、M13
- **典型下游：** M11、M12、M14、M15、M26
- **必要性／适用条件：** 核心；Bug可仅写最小复现场景
- **完整性与正确性检查：** 关键目标覆盖主/失败路径；前置条件和可观测结果明确；禁止将缺失场景当不可能
- **可自动生成程度：** 中：生成候选/组合；真实场景需观察
- **人工参与和确认：** 需求/用户代表确认重要场景与异常期望
- **维护成本（预估）：** 中
- **缺失风险：** 漏测暂停、换源、超时、无权限等
- **理论依据（见索引）：** S07、S08、S17、S20

- **典型下游：** M12、M14、M15、M20、M26
- **必要性／适用条件：** 条件：多步骤业务、异步审批、多人交接
- **完整性与正确性检查：** 有可达终点和异常路径；责任明确；消息匹配；有界/可终止条件
- **可自动生成程度：** 中：可发现路径和机械检查
- **人工参与和确认：** 业务负责人确认实际过程及例外
- **维护成本（预估）：** 中
- **缺失风险：** 业务交接错误、错误时序、无限等待
- **理论依据（见索引）：** S15、S17、S19

### M12 · 行为、状态与事件模型 / Behavior, State and Event Model

领域：D05 场景、行为与业务规则。状态：候选。

- **别名／常见视图：** State machine; event model; interaction behavior
- **核心问题与不可替代价值：** 描述系统在事件和状态下允许的变化及时间约束
- **输入来源：** 场景、领域事件、接口、业务规则
- **输出结果：** 状态、迁移、守卫、不变量、事件/时间规则
- **核心实体、属性与关系：** State; Event; Transition(guard,action,deadline); Invariant; transitionsTo/triggers
- **推荐表示：** 状态机、时序图、事件表
- **典型上游：** M10、M11、M13、M16、M20
- **典型下游：** M15、M18、M22、M26
- **必要性／适用条件：** 条件：状态、异步、并发、定时或副作用显著

### M26 · 验证与确认规格模型 / Verification and Validation Specification Model

领域：D11 验证、证据与保障。状态：候选。

- **别名／常见视图：** V&V plan; Test model; Test matrix (view)
- **核心问题与不可替代价值：** 定义用什么方法和条件证明义务或用户目标，独立于执行结果
- **输入来源：** 需求、质量、规则、风险、场景、接口
- **输出结果：** 验证义务、测试/分析/审查规格、接受准则
- **核心实体、属性与关系：** VerificationObligation; TestCase(precondition,oracle,method); ValidationCriterion; verifies/validates
- **推荐表示：** 测试用例、覆盖矩阵、属性检查
- **典型上游：** M02、M05、M06、M10、M12、M13、M20、M24
- **典型下游：** M23、M27、M28
- **必要性／适用条件：** 核心；高风险项需独立验证方法
- **完整性与正确性检查：** 每项有效义务有方法及可观测判据；风险/负面场景覆盖；验证与确认分开
- **可自动生成程度：** 中至高：可生成候选及覆盖计算；oracle需验证
- **人工参与和确认：** 质量/需求所有者确认测试判据与用户确认方法
- **维护成本（预估）：** 中
- **缺失风险：** 有测试但不测关键需求，或测试了错误行为
- **理论依据（见索引）：** S02、S07、S08、S09

### M27 · 验证执行与证据模型 / Verification Execution and Evidence Model

领域：D11 验证、证据与保障。状态：候选。

- **别名／常见视图：** Test run; Evidence record; Provenance view
- **核心问题与不可替代价值：** 记录实际执行、环境、版本、结果、原始证据与适用性
- **输入来源：** 验证规格、实际产物、执行器、环境
- **输出结果：** 可追溯结果、证据定位、有效/失效/未知状态
- **核心实体、属性与关系：** TestRun; Result(outcome); Evidence(hash,source,scope,validity); Environment; generatedBy/observedOn/supports
- **推荐表示：** 结构化回执、日志、截图引用、证据表
- **典型上游：** M21、M22、M26、M30
- **典型下游：** M25、M28、M30
- **必要性／适用条件：** 核心；未执行必须明确记录
- **完整性与正确性检查：** 结果可追溯到用例、版本、环境；不可将历史通过推广；失败/阻塞不伪装通过
- **可自动生成程度：** 高：捕获与校验可自动；真实结果由实际执行产生
- **人工参与和确认：** 验证人确认环境与证据适用性；批准重用
- **维护成本（预估）：** 中（自动后低）
- **缺失风险：** 伪验收、旧版本证据误用、跨设备不能复核
- **理论依据（见索引）：** S08、S09、S24、S27

### M28 · 保障论证与验收模型 / Assurance Argument and Acceptance Model

领域：D11 验证、证据与保障。状态：候选。

- **别名／常见视图：** Assurance case; Claim-argument-evidence; Acceptance record
- **核心问题与不可替代价值：** 区分证据与结论，说明为何足以接受目标及残余风险
- **输入来源：** 目标、验证义务、证据、风险、批准规则
- **输出结果：** 主张、论证、反证、覆盖范围及验收决定
- **核心实体、属性与关系：** Claim(scope); Argument; EvidenceRef; Rebuttal; Acceptance; supports/refutes/accepts
- **推荐表示：** 轻量验收表；高风险用GSN/SACM式论证
- **典型上游：** M02、M03、M24、M26、M27、M29
- **典型下游：** M30、M31、M32
- **必要性／适用条件：** 核心简要；高可靠性/高风险用结构化论证
- **完整性与正确性检查：** 主张依赖证据及论证；反证未解决不能接受；确认者有权限；范围版本清楚
- **可自动生成程度：** 低至中：可检查链路，不能由AI自动批准
- **人工参与和确认：** 用户/授权验收者接受，必要时独立审查
- **维护成本（预估）：** 中至高
- **缺失风险：** 把测试PASS当需求已全面满足
- **理论依据（见索引）：** S08、S25、S24

### M29 · 工程决策与理由模型 / Engineering Decision and Rationale Model

领域：D12 决策、基线与变更。状态：候选。

- **别名／常见视图：** ADR; Decision log; Trade-off
- **核心问题与不可替代价值：** 记录为什么选择方案、哪些备选被否决及适用条件
- **输入来源：** 目标、约束、候选、事实、评审
- **输出结果：** 决策、备选、权衡、后果、重新评估条件
- **核心实体、属性与关系：** Decision(status,owner,reason); Alternative; Criterion; AssumptionRef; selects/supersedes
- **推荐表示：** ADR、决策表、权衡记录
- **典型上游：** M02、M06、M07、M17、M24
- **典型下游：** M05、M07、M17、M20、M23、M30
- **必要性／适用条件：** 条件：有重要取舍；简单任务可内嵌批准理由
- **完整性与正确性检查：** 保留未选方案与理由；依赖假设有来源；授权及版本明确；触发条件
- **可自动生成程度：** 低至中：可总结权衡，不自动代替决策
- **人工参与和确认：** 有权决策者批准取舍
- **维护成本（预估）：** 低至中
- **缺失风险：** 重复讨论、隐式决策导致漂移
- **理论依据（见索引）：** S23、S03、S11

### M30 · 配置基线与变更模型 / Configuration Baseline and Change Model

领域：D12 决策、基线与变更。状态：候选。

- **别名／常见视图：** Versioned configuration; Change impact model
- **核心问题与不可替代价值：** 定义可复现版本、变更意图、影响分析、批准与历史
- **输入来源：** 已批准实体、代码/产物版本、证据、变更请求
- **输出结果：** 基线、变更集、冲突、影响候选、处置结果
- **核心实体、属性与关系：** Baseline(version manifest); ChangeSet(expectedRevision); Approval; Impact; changes/supersedes/invalidates
- **推荐表示：** 变更记录、版本清单、影响图（派生）
- **典型上游：** M05、M22、M23、M27、M29
- **典型下游：** M05、M22、M26、M27、M28、M32
- **必要性／适用条件：** 核心；多个Agent/设备时需细化并发冲突
- **完整性与正确性检查：** 固定引用可解析；并发写入需版本比对；影响有理由；不得删除历史证据
- **可自动生成程度：** 高：差异/图查询；语义影响和批准需人工
- **人工参与和确认：** 配置所有者批准基线与冲突处理
- **维护成本（预估）：** 中
- **缺失风险：** 跨对话覆盖、版本证据错配、无法追溯
- **理论依据（见索引）：** S04、S05、S24、S28、S31

### M31 · 运行、服务水平与可观测性模型 / Operations, Service Level and Observability Model

领域：D13 部署、运营与演化。状态：候选。

- **别名／常见视图：** Operational model; SLI/SLO; Telemetry
- **核心问题与不可替代价值：** 表达真实运行状态、服务目标、告警、支持和反馈
- **输入来源：** 目标、质量、部署、运行遥测、事件
- **输出结果：** 运行指标、监测策略、响应责任与改进候选
- **核心实体、属性与关系：** Service; SLI; SLO; Signal; Alert; RunbookRef; observes/measures
- **推荐表示：** 运行指标表、服务依赖图、告警策略
- **典型上游：** M06、M21、M22、M28
- **典型下游：** M01、M24、M25、M32
- **必要性／适用条件：** 条件：持续运行、云服务、付费产品；本地扩展可轻量记录错误
- **完整性与正确性检查：** 指标定义含窗口和来源；告警责任和隐私；数据质量与环境标注
- **可自动生成程度：** 中至高：遥测可自动获取，目标/阈值需确认
- **人工参与和确认：** 运营/服务所有者确认目标、监测和响应
- **维护成本（预估）：** 中
- **缺失风险：** 上线后未知故障、无法识别退化或需求反馈
- **理论依据（见索引）：** S04、S05、S06、S24

### M32 · 演化、迁移与退役模型 / Evolution, Migration and Retirement Model

领域：D13 部署、运营与演化。状态：候选。

- **别名／常见视图：** Transition model; Compatibility; Decommissioning
- **核心问题与不可替代价值：** 表达从现状到目标的版本迁移、用户数据兼容、回滚与退役
- **输入来源：** 当前基线、目标变更、数据结构、风险、运行反馈
- **输出结果：** 迁移策略、兼容范围、回滚、废弃条件
- **核心实体、属性与关系：** Migration(from,to); Compatibility; Deprecation; Rollback; migrates/supersedes
- **推荐表示：** 迁移矩阵、过渡图、版本策略
- **典型上游：** M19、M21、M24、M30、M31
- **典型下游：** M05、M22、M23、M26、M27
- **必要性／适用条件：** 条件：升级、兼容性、数据迁移、服务下线
- **完整性与正确性检查：** 旧数据不丢失；迁移幂等或明确约束；回滚/不可逆声明；淘汰有影响评估
- **可自动生成程度：** 中：可生成迁移候选与测试，真实数据风险需确认
- **人工参与和确认：** 产品/数据/发布负责人批准兼容与退役策略
- **维护成本（预估）：** 中至高
- **缺失风险：** 旧数据失效、升级破坏用户、无法恢复
- **理论依据（见索引）：** S04、S05、S12、S35
