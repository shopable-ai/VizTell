### 两例最小追踪

| 连播 | 求职 |
|---|---|
| 目标：不误跳剧情且正确连续观看 | 目标：减少筛选与沟通准备劳动 |
| 场景：播放、暂停、回拖、换源、下一集不明 | 场景：岗位发现、缺字段、已沟通、规则变化、撤权 |
| 链路：绑定正片→核实D/规则→自然进入→定位→下一集目标→到达+起播 | 链路：真实岗位→筛选解释→稳定身份→待审→事实草稿→独立批准后受控外发（后续） |
| 能力/功能：媒体识别、跳过、导航、持久规则、人工校准 | 能力/功能：只读发现、匹配、队列、草稿、状态反馈 |
| 验收反例：等长不同作品不得复用，保存不能执行旧动作，倒序分页末项非作品结束，UNKNOWN不重复导航 | 验收反例：未知薪资不等于匹配，缺ID不得入队，复制不是发送，真实会话未知不得重复发送 |
| 不做项：AI视频识别、云共享不阻塞基础 | 不做项：未获授权自动海投、编造简历、绕过平台 |

两案例同属浏览器软件，非跨行业独立验证。原连播记录旧候选本机及部分站点通过、实站完整项仍阻断/未测试；原求职记录78/78 Node及候选检查、共享CI 33/435失败、真实 Chromium/实站外发未验。不能提升为当前版本已完成。
