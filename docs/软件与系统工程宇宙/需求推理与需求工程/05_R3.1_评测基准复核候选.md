## 2. 逐行审核口径
E=可见输入明确；R=实现可见目标的合理必要义务；D=只有特定领域条件/流程成立才必要（模型可通过识别条件与提出验证来表现，不要求猜历史）；U=需负责人决定；O=可选；H=历史或实现约束，不计自主发现漏项。以下逐行判断依据是冻结可见输入、目标必要性与源文，原 v1 权重/类别保留。建议“主”进入待审核心候选，“条件”单独在可见或模型主动识别的适用条件下评分，“非”不计核心遗漏，“合”去重/移到独立验收维度，“拆”改为可分别观察义务。E/R/D 并非已批准类别；U 或 H 不得作为必须猜到的答案。风险权重也需独立复核：S 专门识别错误对象、未授权行为、严重业务/数据损害及虚假结果等关键风险，区分普通体验损失；不能因所有 W 权重3或浏览器误操作就自动降低安全标准，也不能把每个历史 UX 项都定义为一票否决。任何权重更改在首槽运行前版本化批准。

## 3. v2 冻结前必须解决的实验设计问题
1. 将核心可推断义务、条件义务、历史/可选和验收质量分成不同判卷轨道。核心分母在任何输出前固定；条件条目预先固定触发条件及“未发现风险 vs 不适用”判法，不能由模型选择是否提到条件来缩小分母。历史决策可用于误报/过度设计的对照，不能奖励背诵或惩罚没猜中。逐项拆分复合谓词、合并重复；保存 v1→v2 ID 追踪、批准理由和权重。以上 61 行是完整映射候选，不是已批准的 v2 表。独立审核人需要确认/拒绝每个变更，确定全新分母、权重和关键风险；目前不报告任何 v2 计数或成绩。
2. 独立评测者先仅见 §1 可见输入与共同方法、自己提出义务，再与 v1 及历史来源比对，说明哪些可可靠推断、哪些需领域条件或负责人；至少由独立负责人解决冲突。运行者仅见用户短句、阶段、oracle、两份固定 OS 文本及本组指令；不能得到本文件、03全篇、历史仓库和新候选。公开仓库和重建短句有知识污染可能，不能宣称绝对盲测。未来非公开持出案例须另批次预注册，当前不扩到无限研究。
