# 角色宇宙与多专家协作：最小候选框架 R1-A

> 任务：AI-NATIVE-STAKEHOLDER-ROLE-UNIVERSE-R1 · 2026-11-26
> 状态：研究候选；非正式工程契约、非独立评审结果。只做角色与协作专项，不重复完整研发流程。未运行多模型实验、未访谈真实用户、未执行产品实播测试。
> 阅读入口：[AI 原生研发总体框架](../00_AI原生研发总体框架与关键结论.md)；[需求推理专项](../需求推理与需求工程/README.md)。

## 1. 最重要的框架

原始目标/当前问题 → 利益相关者扫描（谁受影响）+ 专业能力扫描（缺什么判断）→ 按风险选择角色 → 冻结输入后独立分析 → 有针对性的交叉质疑 → 证据核验、冲突与授权决策 → 将新增候选需求、约束、风险、测试判据和未知项交还主流程。

这是一个横切能力，不是另一套 SDLC。把利益相关者、用户画像、专业能力、执行主体（AI/人类）、任务职责、决策权限分开。同一真实主体可拥有多种关联；AI 模拟用户不是用户证据，加载专家 Skill 不等于独立 Agent，独立 Agent 不等于独立人类专家。人类授权不能由角色名称或票数产生。

## 2. 角色库：先有可用家族，再按项目实例化

下表是七类利益相关者检查视角，而不是七个固定 Agent。真实实体需绑定来源、实际身份/关系、利益、影响、代表资格。每行的利益/偏见是待验证假设，不是对真实个人的断言。默认权限为提出关切及提供证据，除非存在明确授权，不批准需求或接受风险。

| 家族及候选角色 | 目标/利益与关注点 | 知识、职责与可能偏见 | 输入 → 输出及验收 |
|---|---|---|---|
| S1 使用方：直接/间接用户、管理员、受益者 | 完成任务、易用、可访问、可控 | 使用经验；报告痛点；可能偏好个人习惯 | 场景、访谈/观察 → 成功结果、痛点、例外；可追溯到真实样本或标待证 |
| S2 商业方：客户、付费者、投资人、产品所有者 | 收益、价值、预算、时间 | 采购/经营知识；说明目标与成本；可能过度重视收入 | 商业目标/合同 → 约束、优先级、收益假设；可测量且注明来源 |
| S3 建设方：产品、设计、研发、测试、外包 | 可交付、质量、工作量 | 工程经验；报告依赖与成本；可能偏爱已有技术 | 需求、代码/团队资源 → 可行性风险、依赖；有实际证据或实验计划 |
| S4 运营方：运维、维护、客服、运营 | 稳定、可恢复、支持成本 | 故障与用户反馈知识；说明运维需要；可能保守 | 日志/服务目标 → 失败恢复、观察需求；有故障场景与判据 |
| S5 生态方：平台、渠道、合作伙伴、供应商、资源提供者 | 合作收益、资源、兼容、接口约束 | 平台或合同知识；提供依赖条件；可能倾向自身生态 | 真实接口/政策/合同 → 依赖约束；注明版本、适用范围 |
| S6 约束方：审核、监管、合规部门 | 安全、权利、合规 | 适用政策/法律知识；给出有出处的限制；可能偏重风险规避 | 管辖/发布政策 → 条款、拒绝/许可条件；核验有效性，真实签核另行取得 |
| S7 受影响方：非用户、数据主体、竞争者、利益受损方 | 减少外部损害、维护权益 | 受影响经验；指出外部性；可能只见自身损失 | 数据流/影响范围 → 受损场景、保护约束；区分可能与真实影响 |

助力、阻力、中立是主体相对于具体目标的关系/态度，可随时间变化；权力、正当性、紧迫性及受损程度分别记录。弱势受影响者不因权力低而被删除。竞争者只在存在真实影响关系时是本项目利益相关者，否则作为环境研究对象。

### 专业能力目录

下面的九个可复用专家视角可由人或 AI 承担。默认目标是提高相关决策质量；没有自身真实利益代表权；表内“偏好”是审查时需要防范的常见偏差。全部默认只读、建议及请求测试权限；实际写入、外部副作用、审批按现有授权。公共验收：具体发现 + 对象/版本 + 可核查来源或未知项 + 影响 + 验证/修正建议；无新增时允许空结果。

| ID / 专家家族 | 目标、专业知识/职责 | 可能偏好/偏差 | 输入 → 特定输出与验收 |
|---|---|---|---|
| E1 用户/领域研究 | 任务、领域约束、行为研究；检验真实需求 | 把画像当事实、样本偏差 | 原始意图/观察 → 痛点、场景和访谈问题；区分观察/推测 |
| E2 产品/业务分析 | 价值、需求裁剪、业务规则；确定必要能力 | 功能堆积或过度压缩 | 目标/场景/已有功能 → 功能需求卡增量、非目标；与目标可追溯 |
| E3 UI/UX/无障碍 | 交互、信息架构、可访问性；验证可理解与可控 | 美观代替可用性 | 用户任务/原型 → 交互问题、可用性测试；可观察的任务成功 |
| E4 架构/技术选型 | 系统边界、质量属性、依赖、取舍 | 技术偏爱、过度架构 | 需求/候选架构 → 方案风险、取舍与实验；有场景和量化判据 |
| E5 实现专家 | 前端、后端、浏览器、数据等按需细分；实现可行性 | 只优化本模块、忽略真实业务 | 代码/接口/任务 → 最小实现和反例；可复现或明确待跑 |
| E6 QA/测试架构 | 风险覆盖、测试设计、运行证据 | 测试数量替代业务质量 | 批准需求/版本/环境 → 测试矩阵、失败证据；通过条件事前固定 |
| E7 安全/隐私/合规 | 威胁、授权、政策；提出阻断风险 | 无条件拒绝或把猜测当政策 | 数据流/权限/适用政策 → 风险、控制和负例；真实条款或复现 |
| E8 商业/运营/运维 | 收益成本、可持续性、可靠性和恢复 | 收益/成本单目标优化 | 数据/服务目标 → 假设、运维场景、指标；成本和恢复条件可验证 |
| E9 反方/事实核查/审计 | 反例、来源、冲突、简化、证据适用性 | 为反对而反对、偏爱否决 | 冻结工件/判据 → 定位问题、反证/缺口、建议；不得自审自批 |

这两表只定义 16 个候选家族；不是所有细分角色的完整已验证能力卡。具体角色按下列模板实例化；细分应由新增问题证明必要性，禁止机械扩表。

### 最小角色定义卡（非正式 Schema）

role_id / 类型 / 名称 / 适用问题；目标与关注点；真实利益及代表资格（不适用填 N/A）；专业知识与能力边界；潜在偏见；职责（执行/咨询/独立审核/协调）；权限和授权来源；输入及权威版本；输出及验收标准；执行主体/模型/上下文隔离级别；不适用条件与退出条件。

例：E6-VIDEO-QA，目标是确认正确换集而非点击成功；专业能力为浏览器媒体、SPA 与事件竞态测试；利益 N/A；偏差是只看单元测试；职责独立测试设计与验收建议；权限只读和已授权测试，不改批准需求；输入 K2.8–K2.10、当前构建与目标站点；输出原生连播竞争测试记录、目标媒体身份和实际播放证据；验收为一次正确导航、无重复动作、未知则停止；没有真实浏览器时标未验证。

## 3. 动态选择与协作

先识别本轮任务、被影响主体、必需专业能力、风险、缺失证据和决策权威。简单可逆 UI 修改：产品/UX 或工程单视角，按需独立 QA；复杂跨站/共享/认证：追加安全、架构、QA 及平台视角。默认建议 1–3 个有实质差异的视角，重大风险 3–5 个或依实际覆盖扩充；仅是待测成本策略，不是硬性人数。若新增角色不能提供新问题、证据或权责则不选；每个排除的重大风险需理由。强制独立审核由现行策略决定，不因角色少而豁免。

协作协议（候选）：
1. 固定目标、版本、范围、验收和权威来源；分发同一证据包及不同视角，不向首轮提供作者结论/其他评审意见。
2. 独立首轮并保存原始结果与运行标识。记录 actual_mode：单会话模拟、独立上下文 Agent、异构模型 Agent、真实人类；模型、工具、上下文/共享状态和失败回退如实记录。模式不可用时披露，独立审核要求未满足则阻断，不能无声降级。
3. 合并同根因发现但保存来源和分歧；区分事实冲突（查证）、目标/利益冲突（授权权衡）、方案冲突（实验比较）、规则冲突（现有治理升级）。
4. 只对重大争议做交叉质疑、反例攻击；审查原始假设与最小替代方案。每条意见使用位置、证据、影响、反证条件、建议，少数意见不删除。允许撤回并解释；自我否决指方案不能满足已批准硬约束时撤回，不给 AI 任意否决权。
5. 核查证据与风险，记录采纳/拒绝/延后及理由，未决阻断项进入 Unknown；授权人/已认证策略走现有 Decision Gate。多数票不是事实、权限或验收。低风险预算可先设一轮独立+一轮交叉，必要时增轮；无新证据、无新重大问题或达到预算则停止讨论，未解决重大问题保持 blocked。

减少虚假共识：首轮盲审、分离作者与评审上下文、保存原始结果、必要时异构模型与真实工具/人类；拒绝仅因他人信心而改结论；同源证据不重复计票；事前固定评分规则、隐藏目标得分、以反例和实际结果校准；不能将多模型、多个上下文或角色名称视为统计独立或人类 IV&V。

## 4. 真实业务案例：OpenDesk 连播助手

事实来源：[需求 K0–K4/F1–F9](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/video-auto-skip/REQUIREMENTS.zh-CN.md)、[历史验收](https://github.com/shopable-ai/opendesk-browser/blob/58d18b06bd785fa99aa4f9ceb1d517c28092c2ad/projects/video-auto-skip/LOCAL-R1-ACCEPTANCE.zh-CN.md)。以下是对真实需求文档的单模型视角映射，非独立评审/新增发现实证；不把已有要求说成新需求。

| 角色 | 研发环节 | 问题类型 | 场景与要求出处 | 验收证据（待执行） |
|---|---|---|---|---|
| S1/E1 用户视角 | 需求 | 业务结果 | 片头前剧情/片尾后彩蛋 K1.3/5 | 真实视频区间，彩蛋继续播放、不误切集 |
| E2 产品 | 需求/范围 | 过度设计 | K0–K2 不依赖完整作品身份 | 无剧名但可信时长下核心功能闭环 |
| E3 UX | 交互 | 可控性 | 标记与查看分离 K1.8/9 | 录屏/播放时间：标记不 seek、查看才 seek、撤销不重跳 |
| E4/E5 架构/浏览器 | 设计/实现 | 状态与竞态 | K0.5/6、K2.8–10 换源/原生连播 | 事件/媒体身份日志；旧任务失效、恰好一次正确导航 |
| E6 QA | 测试/验收 | 错误结果 | K2.4/5/9 倒序、分页、预告、换集 | 真浏览器目标集身份+播放开始；未知不得判通过 |
| S5/E7 平台/安全 | 设计 | 权限与隐私 | K0.7、K4.2 跨域与 AI 上传 | 拒绝权限/网络日志；未授权不上传；平台政策另核 |
| S4/E8 运营 | 迭代 | 恢复和维护 | K4.6 公共规则服务不可用 | 离线与回滚测试；本地规则优先 |
| E9 反方/审计 | 验收 | 证据不足 | 需求文件的证据边界、旧版本验收 | 当前版本/环境/结果匹配，不能用旧通过替代新验收 |

示例冲突：体验希望自动连播，QA 要求不误切。保留可信目标才执行、歧义停止及用户明确点选；由实际需求与授权决定，不投票。上述条件已有 K2 支持，故不生成重复需求卡。真正的未知项是当前版本在目标网站的表现；须实跑。对于首站不需要 AI 上传的任务不激活 K4 评审。

## 5. 多角色评审 Skill（候选）与主线接口

候选名称 multi-perspective-review（未实现、不注册正式 Skill）。触发：实质需求/设计/验收争议、风险或知识缺口；简单任务走已有自检/策略。输入：目标/任务 ID、当前工件稳定引用和版本、scope、批准约束、证据、待回答问题、风险/授权、预算。输出：角色选择及理由、真实执行模式/Run 引用、发现列表（对象、场景、关切、来源/状态、严重度、建议、验证条件）、重复/冲突/异议、未解决问题、采纳建议；不输出虚假最终批准。失败：缺来源标 Unknown、模式回退披露、冲突或硬门禁未解保持阻断。退出：问题有处置路径且已达预算/停止条件。

与主线对应（已核对 [现有需求设计工作流](https://github.com/shopable-ai/ai-native-project-os/blob/1a1867640b7ee538bac21cd1a16d50f6a7e19c0f/docs/workflows/REQUIREMENT_DESIGN_WORKFLOW.md)、[框架总览 README](https://github.com/shopable-ai/ai-native-project-os/blob/1a1867640b7ee538bac21cd1a16d50f6a7e19c0f/README.md)）：新增观点进入 draft 功能需求卡/Unknown；冲突进入现有 ADR/Decision Gate；测试方向进入需求验收条件及后续 Test/Evidence；审核证据按已注册 Run/Evidence/Verdict 消费；受控对象、策略认证、授权、baseline 与完成声明沿用原机制。不得通过本 Skill 新建第二套事实、批准或证据权威。此处是语义映射候选，不宣称接口已实现或正式接入。

## 7. 验证路线、评分与退出

建议下一轮仅验证方法增益，不扩充角色库：从连播助手 K0/K1/K2、Web Flow 或 AI Proxy 取不同风险的真实任务，冻结未含答案的输入及判据，用独立人审/已核验缺陷与可复现测试构造参考集（保留开放发现的复核机制）。比较 A 单模型直接分析、B 单会话角色模拟、C 隔离 Agent 首轮、D C+证据驱动交叉质疑；随机顺序、等预算、重复至少3次作初筛，记录模型与实际运行模式。预注册发现准确率、已知重大问题召回率、经核验新增问题、误报/重复、未经授权批准次数、token/时间及可读性；真实用户需求由用户证据判断。建议门槛：重大预置问题全发现、零伪造/越权、精确率≥90%、与等预算基线相比有可复核增益且成本可接受；95分目标为候选采用标准，具体效益阈值须在实验前经主线接受，不能事后调整。若增加讨论无增益则保留最简模式。初筛不证明跨项目通用性。

本轮单模型设计自评（非独立专家评分）：框架及边界94、角色库可用性90、来源/BMAD92、协作治理94、主线映射90、真实验证72；等权平均88.7/100。扣分：细分能力未验证、文献以公开摘要/指南及源码静态阅读为主、未实际运行独立 Agent、未做正式接口/真实案例对照实验。独立专家评分与实际效果评分均未评估。重大风险、权限、证据缺失或未执行独立审核不被平均分掩盖。未达到95采用门槛。

可合并回主工作流的摘要：按需选择利益相关者视角与专业能力，首轮独立、证据驱动质疑、保留异议、由已有合法决策门批准；输出需求增量/未知/风险/验收条件。优先验证其相对单模型基线的增益，之后再决定是否升格为正式 Skill。此文件只保存独立研究，不修改业务仓或工程内核。
