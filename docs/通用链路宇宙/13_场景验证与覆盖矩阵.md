## 一、测试方法

每个场景统一检查：

> **触发与输入 → 最小正常路径 → 基础链映射 → 横向控制 → 输出与证据 → 信息不足 → 资源不足 → 质量失败／方案失败 → 风险事件 → 需求／目标错误 → 返回位置 → 停止条件 → 生命周期出口**

本文件属于结构回归测试，不代替真实运行。状态分为：

- **结构通过**：能够用现有链解释正常、失败、异常和退出路径；
- **部分验证**：有合理路径，但真实效果、阈值、角色或工具仍需现场确定；
- **失败**：出现无法由现有链表达的重要状态转化；
- **不适用**：该失败类型在当前场景没有合理意义。

## 三、场景 1：个人一周计划与健康维护

### 目标与输入

- 输入：一周固定承诺、待办、健康状态、睡眠和精力、必要医疗建议、可支配时间。
- 输出：可执行的一周重点、最低健康行动、缓冲时段、复查点和调整规则。
- 强度：通常轻量；出现疾病、伤痛、用药或重大风险时提高为严格并转专业支持。

### 正常路径

> 记录本周信号 C01 → 按生活价值排序 C03 → 设置少量结果和健康底线 C04／C05 → 安排时间精力 C06／C07 → 每日执行 C09〔最小记录 C10＋状态监测 C11〕→ 周中纠偏 C13 → 周末评价 C15 → 维护、更新或暂停 C30

### 失败与返回

| 测试 | 触发信号 | 返回与处置 | 期望证据 |
| --- | --- | --- | --- |
| 信息不足 | 不知道时间花到哪里、身体状态不清 | C10 最小记录；必要时专业评估 | 关键时间与状态记录 |
| 资源不足 | 时间、睡眠或精力不能支持全部目标 | C03 降优先；C07 缩减、替代、留恢复 | 明确不做项和新安排 |
| 质量失败 | 动作完成但健康结果恶化 | C15 判断效果；C21 分析原因；C13 调整 | 症状、行为与结果变化 |
| 风险事件 | 伤痛、严重不适或危险信号 | 立即停止原计划，进入 C29 和专业支持 | 安全状态、求助与处置记录 |
| 目标错误 | 计划持续损害睡眠、关系或基本生活 | 返回 C03／C04 重判价值和目标 | 修改或取消目标的理由 |
| 停止条件 | 继续执行的风险高于预期收益 | 暂停、终止或转专业处理 | 停止原因和复查条件 |
| 生命周期 | 形成稳定习惯或目标结束 | C30 维护、更新、暂停或归档 | 维护周期和下次复查 |

### 反方检查

没有必要把休息、娱乐和关系全部量化；只记录会帮助安全、选择和调整的少量信号。结构测试通过，真实健康阈值必须由本人状态和合格专业意见确定。

## 四、场景 2：普通工作任务从接收到验收

### 目标与输入

- 输入：请求、背景、使用者、期限、现有标准、权限和依赖。
- 输出：被有权接收者接受的成果、移交记录和已关闭或明确负责的遗留项。
- 强度：普通工作采用标准档；对外承诺、高金额或不可逆事项提高为严格档。

### 正常路径

> 澄清场景和真实需要 C02 → 明确目标 C04 与完成标准 C05 → 制定任务依赖和检查点 C06 → 配置资源权限 C07 → 执行 C09〔记录 C10＋沟通 C25＋进度 C11＋质量 C12〕→ 自检提交 → 验证、确认、验收 C14 → 反馈分流 C16 → 收尾或维护 C30

### 失败与返回

| 测试 | 触发信号 | 返回与处置 |
| --- | --- | --- |
| 信息不足 | 接收者、用途或完成标准不清 | 返回 C02／C05；不得靠猜测承诺 |
| 资源不足 | 权限、资料、人员或时间未到位 | C07 补齐、缩范围、改期或升级 |
| 质量失败 | 自检或接收检查发现缺陷 | C12 隔离缺陷，返回 C09 返工复检 |
| 风险事件 | 数据泄露、安全或重大客户影响 | 切换 C29，停止普通执行路径 |
| 需求错误 | 成果符合文字要求但不满足真实用途 | 从 C14 确认失败返回 C02／C04 |
| 停止条件 | 需求失效、成本超过价值或无权继续 | C03／C22 决定暂停、终止或转交 |
| 生命周期 | 验收后仍需维护或交接 | C30 明确责任、版本和复查时间 |

### 接口检查

C05 的输出必须包含 C12 和 C14 能使用的标准与证据；C09 的输出必须包含成果、版本、自检和遗留项。满足接口后结构测试通过。

## 五、场景 3：软件需求从用户问题到上线运营

### 目标与输入

- 输入：用户问题、行为数据、市场与业务背景、现有系统、约束和未知项。
- 输出：可追溯的软件版本、测试与发布证据、运行状态、用户效果和商业结果。
- 强度：通常标准或严格；生产数据、支付、隐私、安全和核心业务必须严格。

### 正常路径

> 捕捉用户信号 C01 → 还原场景 C02 → 定义问题 C20 → 研究证据 C23 → 生成并选择方案 C22 → 建立目标范围 C04 和验收标准 C05 → 计划架构任务依赖 C06 → AI与工程协同实现 C09 → 测试与质量控制 C12 → 发布检查与验收 C14 → 监测用户和运行效果 C11／C15 → 反馈迭代 C16／C13 → 维护更新下线 C30

### 需求—实现—测试追溯

> 来源／事实／未知 → 经人确认的需求 → 场景与业务链 → 能力与功能要求 → 规格和验收标准 → 实现版本 → 测试证据 → 发布决定 → 运行和价值证据

AI 生成的候选解释、规格或代码不得自动越过业务确认、审查、测试和发布授权。

### 失败与返回

| 测试 | 触发信号 | 返回与处置 |
| --- | --- | --- |
| 信息不足 | 用户问题、数据或系统约束证据不足 | C23 补证，标注未知；可逆时先小试 |
| 资源不足 | 容量、权限、技能、预算或依赖不足 | C07 补齐、降范围、延后或换方案 |
| 质量失败 | 测试、安全或数据一致性不通过 | C12 阻断发布，返回实现或规格 |
| 风险事件 | 发布造成故障、泄露或严重错误 | C29 隔离、回退、恢复并调查 |
| 需求／目标错误 | 功能正确但用户不用或无业务价值 | 返回 C02／C03／C04，而非继续堆功能 |
| 停止条件 | 无法达到安全、价值或经济门槛 | C22／C30 暂停开发、转向或下线 |
| 生命周期 | 继续、维护、迁移、暂停、交接或淘汰 | C30 处理代码、数据、依赖、用户和责任 |

结构测试通过；架构、安全、性能、隐私、服务目标和回退阈值必须在具体产品 L4 工作流中定义。

## 六、场景 4：AI 重度软件 OPC 从机会到现金回收

### 正常路径

> 发现细分机会 C01 → 澄清目标用户和付费场景 C02 → 价值排序 C03 → AI辅助研究并核查 C23 → 选择定位和最小方案 C22 → 设目标、价格与验证标准 C04／C05 → 快速实现交付版本 C09／C12 → 获客成交与承诺确认 C25 → 履约验收 C14 → 回款、成本和客户效果评估 C15 → 反馈迭代 C16 → 经验资产化 C19 → 维护、扩大、外包、公司化或退出 C30

### 关键并行控制

- 现金：获客、交付、应收、模型与平台成本不能只看收入。
- AI质量：关键事实、代码、安全、客户承诺和最终验收由人负责。
- 隐私与版权：客户数据、训练材料、生成内容和第三方资产需有合法边界。
- 个人容量：时间、注意力和健康是硬约束，不把过载伪装成增长。

### 失败与返回

| 测试 | 返回与处置 |
| --- | --- |
| 没有付费证据 | 返回 C02／C03／C22，缩小验证，不先扩大建设 |
| 获客成本或交付成本过高 | C15 重算单位经济，C13 改定价、渠道、范围或自动化方式 |
| AI输出质量不稳 | C12 增加代表性测试、独立核查和人工关口 |
| 单一平台、模型或客户中断 | C28 预警与替代；发生后 C29 恢复和止损 |
| 客户需求不适配 | C02 重澄清；必要时拒绝成交或终止交付 |
| 现金或个人负荷触底 | 停止非关键投入，C30 缩减、暂停、合作或退出 |

结构测试通过；真实通过仍需付费、毛利、现金周期、客户结果、留存和创始人负荷数据。

## 七、场景 5：项目经验转成公司流程并被采用

### 正常路径

> 汇总项目事实 C17 → 复盘原因和适用边界 C18 → 形成候选方法 C19 → 选择公司需要和试点场景 C03／C22 → 设计角色、流程、模板、工具和版本 C27 → 培训与练习 C24 → 小范围运行 C09〔记录＋质量＋沟通〕→ 监测采用和结果 C11／C15 → 修订、发布、扩大或撤回 C30

### 采用验证

不能以“文档已发布、培训已完成”作为成功。至少检查：

- 不同合格人员能否脱离原作者执行；
- 输出质量和成本是否仍在可接受范围；
- 权限、资源、激励和考核是否支持采用；
- 新场景差异是否落在已声明适用边界；
- 使用者能否反馈、申请例外和推动版本更新。

### 失败与返回

| 测试 | 返回与处置 |
| --- | --- |
| 经验证据不足 | 返回 C18／C19，保留为候选实践而非标准 |
| 人员没有时间、能力或权限 | C07／C24／C26 补资源、训练和授权 |
| 质量在新人员或场景下降 | C12 阻断扩大，C21 分析差异 |
| 激励与流程冲突 | 返回 C27 的组织采用设计，调整权责和激励 |
| 原目标或机制错误 | 撤回标准，返回 C03／C22，不强迫执行 |
| 停止条件 | 采用成本长期高于收益或副作用不可接受 | C30 暂停、退回、替代或淘汰 |

结构测试通过；真实通过需要跨人员复现、采用率、错误率、处理时间和净价值数据。

## 八、场景 6：生产故障的止损、恢复和防复发

### 正常事件路径

> 告警与人工信号 C01 → 验证并分级 → 切换异常响应 C29〔保护人员资产证据 → 隔离止损 → 通知指挥 → 诊断 → 修复／回退／替代 → 验证 → 逐步恢复〕→ 原因分析 C21 → 永久纠正 C13／C12 → 事件复盘 C18 → 沉淀监控、预案和工具 C19 → 风险复审 C28 → 维护更新 C30

### 关口

1. 异常一旦确认，不继续停留在“发生概率”讨论。
2. 恢复最低可接受服务优先于完整根因调查，但不能破坏证据。
3. 技术恢复不等于事件关闭，还需处理数据、客户、责任和补偿。
4. 防复发措施必须验证，不能只登记待办。

### 失败与返回

| 测试 | 返回与处置 |
| --- | --- |
| 影响和证据不清 | 保持安全降级，补监控和现场证据，不盲目操作 |
| 权限或专家资源不足 | 升级指挥和授权，调用替代或外部支持 |
| 修复验证失败 | 保持隔离，回退或切换替代路径 |
| 原方案持续扩大损失 | 停止原计划，按安全和业务连续性重新决策 |
| 无法恢复 | C22／C30 启动替代、灾难恢复、终止或退役 |

结构测试通过；真实 L4 必须定义事件等级、服务目标、通知时限、数据完整性、回退和恢复阈值。

## 九、场景 7：产品或流程的暂停、交接、淘汰和重启

### 统一路径

> 收集效果、成本、风险和依赖 C15 → 比较继续／维护／更新／暂停／交接／归档／淘汰 C22 → 执行生命周期处置 C30〔沟通 C25＋协作 C26＋风险 C28〕→ 验证资料、权限、数据、责任和依赖状态 → 记录复查或保留期限

### 四种分支

| 分支 | 必做事项 | 完成证据 |
| --- | --- | --- |
| 暂停 | 保存状态版本、处理安全和客户影响、设复查日期与触发器 | 可恢复资产、责任人、复查条件 |
| 交接 | 整理状态、资料、权限、关系、风险和未决项；接收者演练 | 接收确认、能力缺口关闭、责任转移 |
| 淘汰 | 识别用户依赖、设计替代迁移、通知、停用和安全处置 | 依赖迁移、访问关闭、必要记录保留 |
| 重启 | 重新核查价值、完整性、时效、权限、依赖、安全和容量 | 新基线、测试证据、重新批准 |

### 失败与返回

- 不知道谁仍在使用：补追溯、资产和相关方调查，不能直接淘汰。
- 接收者没有能力或权限：返回资源、培训和授权，交接未完成。
- 数据或隐私保留冲突：进入合规安全审查并由有权者决定。
- 暂停没有复查条件：不允许标记为完成，补责任与复查门。
- 重启对象过时或不安全：返回更新、迁移或维持淘汰状态。

结构测试通过；具体保留期、审批权、用户通知和数据处置依赖适用法规和组织政策。

## 十、场景 8：复杂项目从模糊目标到交付

### 目标与输入

- 输入：模糊想法、外部要求或待解决问题，现有背景、限制、已有资源和已知未知。
- 输出：价值成立且被验收的项目成果，以及清楚的经验、剩余问题和生命周期决定。

### 正常路径

> 澄清真实需要 C02 → 判断价值 C03 → 建目标 C04 与完成标准 C05 → 调查现状与差距 → 目标拆解＋问题拆解 → C23 搜已有解法、案例、失败和实践经验 → 生成结构不同的方案 → C22 比较并选择，必要时先验证关键未知 → C06 拆阶段成果、任务和依赖 → C07 配资源 → C09 分阶段执行〔C10＋C11＋C12＋C25＋C28〕→ C13 按偏差纠正 → C14 验收 → C15 评估真实效果与价值 → C18／C19 复盘沉淀 → C30 延续或退出

### 关键测试

| 测试 | 返回与处置 |
| --- | --- |
| 目标只是模糊口号 | 回 C02／C04／C05，补真实用途、边界和完成标准 |
| 目标拆成大量动作但没有阶段成果 | 回目标拆解／C06，先定义交付物和依赖 |
| 问题太大、不知道从哪研究 | 回 C20／C23，拆子问题和关键未知 |
| 默认从零做但已有成熟方案 | C23 补已有解法调查，再回 C22 比较采用／改造／自建 |
| 多方案只是同一方案改措辞 | 重新生成不同机制、资源结构或交付方式的候选 |
| 关键未知没有验证 | 做最小补证／试验后再投入大规模执行 |
| 执行持续延期 | 判断是任务、计划、资源、方案还是目标层问题，返回最近根因层 |
| 做完但真实用途未满足 | 从 C14 确认失败返回 C02／C04／C22 |
| 剩余价值低于继续成本 | C15／C22／C30 缩小、暂停、转向或终止 |

结构测试通过。这个场景证明“目标建立、目标拆解、问题拆解、已有解法、多方案、失败研究、验证和阶段评估”需要显著 L3 入口，但仍可由现有 C 链组合表达。

## 十一、场景 9：文章／单书从筛选到掌握迁移

### 正常路径

> 明确当前问题或能力目标 → C03 判断是否值得读 → C23 预读、提取主张机制条件证据 → 对照旧知，标记重复／新增／冲突／未知 → C24 主动回想、练习和变式辨别 → C09 在真实问题／项目中应用 → C15 评估是否真正掌握和迁移 → C19 沉淀有效知识 → C30 更新、复查或归档

### 关键测试

| 测试 | 返回与处置 |
| --- | --- |
| 文章与当前目标无关 | 尽早退出，不为了“读完”继续投入 |
| 来源或证据可疑 | C23 追原始来源、交叉核查，保留未知 |
| 与旧知大量重复 | 跳过重复部分，只保留新证据、新边界或反例 |
| 看懂但合上后说不出来 | C24 返回主动回想和间隔复习 |
| 能复述但不会解决实际问题 | C24／C09 增加练习和真实应用 |
| 一次会做但换场景失败 | 返回适用条件、变式练习和迁移测试 |
| 书中内容过时 | C23 更新来源，C30 标记过时并重新核查 |

结构测试通过；真实验证需要延迟回想、独立应用和新情境迁移数据，而不是用“读过、收藏、做了笔记”代替掌握。

## 十二、场景 10：大量资料去重并形成知识差额

### 正常路径

> C20 明确研究问题和知识地图 → 建已有知识与掌握基线 → C23 盘点文件、版本和来源 → 解析并保留原始位置 → 按文件／文本／近似候选／语义候选逐层缩小 → 判断命题相同、包含、扩展、支持、冲突或无关 → 判断是否增加新机制、条件、证据、反例或更新 → 与 C24 掌握状态比较 → 生成高价值未掌握队列 → 定向学习与真实应用 → C15 抽样评估去重质量和学习效果 → C19 建代表项与来源关系 → C30 增量更新

### 关键测试

| 测试 | 返回与处置 |
| --- | --- |
| 文件版本和来源混乱 | 先补盘点、稳定标识和原始定位 |
| OCR／解析质量差 | 标记待核查，不进入高置信合并 |
| 向量相似但命题不同 | 只保留为候选，进入命题关系判断，不直接删除 |
| 主题相同但有新证据／边界／反例 | 保留增量并挂到代表知识节点 |
| 错误合并被抽样发现 | 回退关系、调整规则／模型并重新计算 |
| 重复漏检太多 | 增加文字近似或语义候选召回，再人工校准 |
| 笔记存在但本人不会应用 | C24 标为未掌握／不确定，进入学习队列 |
| 人工复核成本超过收益 | 收紧处理范围，优先当前问题和高价值知识差额 |

结构测试通过；具体哈希、MinHash、SimHash、向量模型、聚类、阈值和数据库属于 L4 实现，不能提升为基础链。

## 十四、新基础链必要性判定

十个基准场景中的关键转化均能映射到 C01—C30 或已登记的扩展动作；新增项目、阅读和知识增量场景暴露的是**L3 场景入口不足**，而不是新的 L2 状态转化。

因此本轮决定：

- 不新增第 31 条核心链；
- 正式新增两个高频 L3 场景宇宙：项目／复杂任务、阅读学习／知识研究；
- 目标拆解和问题拆解继续作为显著扩展动作和场景子链，先用更多跨领域案例验证其独立性；
- OCR、哈希、语义模型、Agent 参数等继续留在 L4；
- 后续若真实测试出现现有 C 链无法表达、且跨领域高频复现的新状态转化，再重新启动准入审计。
