# 通用链路宇宙：优化路线与遗漏清单

## 二、本轮已经修正的问题

《02_通用基础链路库》已由“直接进入30张长卡”调整为：

> **标准卡说明 → 核心主闭环 → 四类按需调用链 → 30条编号速查 → 按卡点选链 → 30条完整标准卡 → 扩展链 → 准入规则**

这解决了“细节完整但需要长时间翻页”的问题，也明确了30条链不是必须从 C01 顺序执行到 C30。

## 三、仍需优先补齐的内容

### 3.1 检索与阅读层

1. 增加术语表，统一“目标、标准、要求、成果、效果、价值”等高频概念。
2. 增加编号与别名索引，避免不同文件对同一链使用不同名称。
3. 为领域文件增加“调用哪些基础链”的映射表。
4. 为基础链增加上游、下游和常见组合的反向链接。
5. 为长文件增加顶部速览、按卡点选链和局部目录。

### 3.2 L4执行层

当前标准卡适合描述通用机制，但真实工作流还应按需增加：

- 前置条件与不适用条件；
- 角色、责任人、批准人和决策权；
- 输入来源、输出产物和证据位置；
- 时限、服务水平、预算与容量；
- 指标、阈值、容差和升级条件；
- 工具、模板、检查表和自动化接口；
- 依赖、版本、变更和回退方案；
- 安全、隐私、合规和数据保留规则；
- 停止条件、暂停条件和重启条件。

这些内容通常不应塞入30条通用基础链，而应进入统一的 L4 工作流模板及具体场景。

### 3.3 横向控制与专业边界

| 候选缺口 | 建议位置 | 处理原则 |
| --- | --- | --- |
| 安全、隐私、数据治理 | 09横向控制＋软件／行业包 | 属于贯穿控制，不宜只在AI文件出现 |
| 知识产权、合同、采购、供应商 | OPC／公司／行业包 | 主要由交易结构、法规和行业决定 |
| 单位经济、现金转换、容量与负载 | OPC／公司／软件运营 | 属于经营与运行约束，不是人人必经基础链 |
| 业务连续性、韧性、灾难恢复 | 09异常与生命周期 | 从单次异常恢复扩展到长期生存能力 |
| 利益相关方、激励、权力和价值分配 | 公司／协作／决策模块 | 步骤正确不代表相关方愿意采用 |
| 实验设计、因果判断和不确定性 | 研究、决策、评估扩展链 | 避免把相关性、主观反馈当作效果证据 |
| 配置、资产、依赖和退役数据处置 | 软件／公司／生命周期 | 防止对象退出后遗留依赖、权限和数据 |
| 可访问性、包容性、可持续性和外部影响 | 价值标准＋行业包 | 根据影响等级与法规选择强度 |

### 3.4 验证层

当前最需要的不是继续自评，而是建立可重复测试：

1. 同一场景由不同人选链，结果是否基本一致。
2. 前链输出是否真的足够作为后链输入。
3. 删除某条链后，是否出现无法解释的状态转化。
4. 合并两条链后，是否丢失不同的完成标准或返回路径。
5. 低风险任务能否在一分钟内选出最小闭环。
6. 高风险任务能否自动增加证据、权限、预案、合规和验收。
7. 失败、异常、暂停、交接和淘汰是否都有可执行出口。
8. 链路运行是否产生有用成果，而不是只产生更多文档。

## 四、不建议升级为新基础链的内容

以下差异通常应作为扩展链、组合链、领域链或 L4 配置，而不是新增核心 L2：

- 只是对象不同，例如学习计划、项目计划、旅行计划；
- 只是角色不同，例如个人决策、经理决策、董事会决策；
- 只是工具不同，例如手工记录、表格记录、AI自动记录；
- 只是风险等级不同，例如普通发布和医疗系统发布；
- 只是行业法规、表单、阈值或术语不同；
- 由三条以上基础链组合而成，例如项目管理、产品创造、公司转化。

只有出现新的输入、输出、核心转化、完成标准和失败返回，才考虑增加核心基础链。

## 六、优化优先级

### P0：立即完成

- 30条核心链顶部速览与按卡点选链；
- 术语、编号和文件引用一致性检查；
- 基础链字段完整性和重复性检查；
- 建立可直接复制使用的持续优化母提示词。

### P1：使体系可执行

- 建立L4工作流模板和核心表单；
- 为生活、工作、OPC、公司和软件各补三个代表性场景；
- 建立正常路径、失败返回、异常旁路和结束状态测试。

### P2：使体系可验证

- 建立覆盖矩阵、输入输出契约和回归测试；
- 用真实任务记录耗时、错误、返工、价值和采用情况；
- 根据证据合并、降级、修订或淘汰链路。

### P3：扩展行业

- 先完成软件IT行业包；
- 再按用户价值和真实案例选择第二行业；
- 只有跨多个行业稳定复现的机制，才提升到通用层。

## 七、下一轮验收标准

1. 所有文件只有一个一级标题，重要内容均在顶部。
2. 30条核心链编号唯一，标准字段齐全，没有同义重复。
3. 所有相对链接有效，不存在孤立文件和失效引用。
4. 每个领域至少有正常、失败、异常、交接或退出场景。
5. 最小闭环可以在一分钟内选择，复杂流程可以追溯到证据和责任。
6. 通用层不被AI、软件或公司术语绑架；技术模式和行业差异保持下沉。
7. 所有新增内容说明层级、理由、影响文件和回退方式。
8. 没有为了“看起来完整”而增加无法验证的链路。

## 八、停止与收敛条件

当新增内容主要只是同义词、行业名词或工具差异；场景测试不再发现新的状态转化；继续增加结构的维护成本高于检索与执行收益时，停止扩充通用层，转向具体场景、模板和实测改进。
