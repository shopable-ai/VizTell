# 通用基础链路库

> **本文件最重要的内容**：三十条核心链不是名称清单，而是具有“解决问题、输入、步骤、输出、完成标准、返回路径、调用关系和应用场景”的可执行模块。其余链先作为扩展链保留，只有高频使用时再升级为完整卡。

## 一、标准卡字段

每条核心链统一包含：解决、输入、核心步骤、输出、完成标准、返回、可调用、应用。L4具体工作流再增加角色、时限、工具、阈值、证据、权限和法规。

## 二、三十条核心基础链速览

> **先看本节，再按编号查阅完整卡。** 三十条链不是要求依次运行的固定长流程，而是一个“主闭环＋按需调用库”。普通事项只使用最短闭环；问题复杂、多人协作、高风险或长期运行时，再增加相应链路。

### 2.1 核心主闭环

> **触发识别 C01 → 需求澄清 C02 → 价值排序 C03 → 目标设定 C04 → 标准设定 C05 → 计划制定 C06 → 资源配置 C07 → 风险预案 C08 → 任务执行 C09〔记录 C10＋监测 C11＋质量 C12〕→ 纠偏调整 C13 → 提交验收 C14 → 评估判断 C15 → 反馈处理 C16 → 总结提炼 C17 → 复盘改进 C18 → 经验沉淀 C19 → 维护、更新或退出 C30**

### 2.2 四类按需调用链

- 遇到不清楚的问题：**问题定义 C20 → 原因分析 C21 → 决策选择 C22**。
- 遇到信息或能力缺口：**信息处理 C23 → 个人学习 C24 → 返回当前任务**。
- 遇到多人或组织转化：**沟通闭环 C25 → 分工协作 C26 → 组织转化 C27**。
- 遇到风险、事故或生命周期变化：**风险管理 C28 → 异常恢复 C29 → 维护更新退出 C30**。

### 2.4 如何快速选链

| 当前卡点 | 优先查看 |
| --- | --- |
| 不知道是否值得做 | C01—C03 |
| 知道要做，但目标或完成标准不清 | C04—C05 |
| 目标清楚，但不知道怎样推进 | C06—C08 |
| 正在执行，需要留痕、检查和纠偏 | C09—C13 |
| 已有成果，需要判断是否真正完成 | C14—C16 |
| 希望下次做得更好并能够复用 | C17—C19 |

| 信息不足或能力不足 | C23—C24 |
| 涉及沟通、多人协作或公司采用 | C25—C27 |
| 涉及高风险、异常、维护、更新或退出 | C28—C30 |

## 三、三十条核心基础链标准卡

### C01 触发识别链

**核心步骤**：接收信号 → 记录现象 → 辨别需求／问题／机会／变化／任务 → 核验真实性 → 估计影响 → 响应／观察／忽略

- 解决：模糊信号是否值得进入处理系统。
- 输入：感受、诉求、数据变化、外部事件、例行任务或异常。
- 输出：已分类、已核验并带去向的触发事项。
- 完成标准：类型、可信度、影响和下一去向明确。
- 返回：证据不足进入观察或取证；分类错误重新辨别。
- 可调用：证据核查、价值排序、需求澄清、问题定义、异常响应。
- 应用：个人愿望、用户反馈、市场变化、系统告警、政策变化。

### C02 需求澄清链

**核心步骤**：识别相关方 → 收集诉求 → 还原使用场景 → 区分手段与目的 → 识别冲突约束 → 表述真实需要 → 确认理解

- 解决：把含混、表面或互相冲突的诉求转成可承接需求。
- 输入：愿望、抱怨、请求、访谈、需求草案。
- 输出：包含对象、场景、价值、约束和确认人的需求说明。
- 完成标准：相关方能一致复述“谁在什么场景需要什么结果、为什么”。
- 返回：出现新相关方、新证据或冲突时返回收集澄清。
- 可调用：表达确认、范围界定、价值排序。
- 应用：个人目标、软件需求、客户委托、组织改革。

### C03 价值排序链

**核心步骤**：明确事项 → 估计收益 → 估计成本风险 → 判断必要性时效 → 比较替代和机会成本 → 排优先 → 立项／延后／委派／放弃

- 解决：有限时间和资源应投向什么。
- 输入：候选需求、问题、机会、任务或改进项。
- 输出：带理由的优先级和处置决定。
- 完成标准：决定者、评价维度、排序和下一动作明确。
- 返回：价值、成本、风险、资源或时效实质变化时重评。
- 可调用：证据核查、风险管理、决策选择。
- 应用：个人待办、产品路线、项目组合、公司投资。

### C04 目标设定链

**核心步骤**：承接已选事项 → 初识现状约束 → 描述期望结果 → 划定范围 → 设置指标期限 → 检查价值可行一致 → 明确责任 → 确认承诺

- 解决：把方向、愿望或责任转成可以规划和评价的目标。
- 输入：已通过价值门的事项、上位目标和关键约束。
- 输出：结果、范围、指标、期限和责任明确的目标。
- 完成标准：可以据此生成计划，并能判断最终是否达成。
- 返回：不可行返回范围、指标、期限或资源；价值失效返回价值排序。
- 可调用：现状初判、范围界定、标准设定、表达确认。
- 应用：健康、学习、任务、项目、组织目标。

### C05 标准设定链

**核心步骤**：明确成果与用途 → 选择评价维度 → 定义指标阈值 → 规定证据和测量方式 → 说明容差例外 → 指定判定人 → 确认标准

- 解决：事前明确怎样算完成、合格、成功或安全。
- 输入：目标、需求、质量要求、风险边界。
- 输出：可测量、可取证、可解释的标准。
- 完成标准：不同评价者基于同一证据能够得到基本一致判断。
- 返回：无法测量时修改指标证据；环境变化时修订并保留版本。
- 可调用：数据采集、证据管理、版本更新。
- 应用：验收标准、学习考核、服务质量、健康指标、风险阈值。

### C06 计划制定链

**核心步骤**：读取目标范围标准方案 → 拆解成果任务 → 分析依赖 → 排定优先 → 估算时间资源 → 分配责任 → 设置里程碑检查点 → 识别风险变更 → 形成基线

- 解决：把目标和方案转成可协调、可监测的行动安排。
- 输入：目标、范围、标准、选定方案和约束。
- 输出：任务、依赖、时序、责任、资源、检查点和风险明确的计划。
- 完成标准：近期任务可启动，关键依赖和缺口已有处置。
- 返回：目标变化回目标；资源冲突回配置；执行偏差触发重排或变更。
- 可调用：目标拆解、资源配置、责任授权、风险预案。
- 应用：周计划、学习计划、项目计划、运营计划、应急计划。

### C07 资源配置链

**核心步骤**：读取任务需要 → 盘点时间精力人员资金信息工具 → 识别缺口 → 获取调配替代 → 按优先分配 → 解决冲突 → 确认可用

- 解决：为计划提供足够且可以实际调用的资源。
- 输入：任务负荷、资源存量、预算和约束。
- 输出：带责任和时限的资源安排。
- 完成标准：关键资源到位；缺口有替代、缩减或升级决定。
- 返回：资源失效、任务变化或过载时重新盘点分配。
- 可调用：价值排序、预算管理、冲突协商、风险管理。
- 应用：个人时间精力、项目人员预算、生产设备、数据权限。

### C08 风险预案链

**核心步骤**：识别潜在风险 → 描述触发条件 → 评估概率影响 → 排定等级 → 选择应对 → 设置预警责任 → 准备应急动作 → 演练复查

- 解决：在不确定事件发生前降低发生概率或影响。
- 输入：目标、方案、计划、环境约束和历史事件。
- 输出：风险清单、等级、责任人、预警条件和预案。
- 完成标准：高风险都有策略、触发器和责任人，剩余风险获知情接受。
- 返回：环境、方案或暴露程度变化时重新评估。
- 可调用：证据管理、决策选择、异常响应。
- 应用：健康计划、财务决策、软件上线、公司运营。

### C09 任务执行链

**核心步骤**：接收任务 → 确认结果标准权限 → 核对前置条件 → 推进行动 → 处理阻碍 →〔记录过程＋同步进展〕→ 自检 → 提交

- 解决：把已定义任务转成可检查成果。
- 输入：任务、标准、资源、权限和期限。
- 输出：成果、过程记录、遗留问题和提交说明。
- 完成标准：成果已提交且通过提交前自检；是否最终完成由验收决定。
- 返回：要求不清回澄清；条件不足回准备；偏差进纠偏；异常进恢复。
- 可调用：过程记录、沟通协作、进度监测、质量控制、异常响应。
- 应用：日常待办、学习练习、内容制作、开发功能、运营作业。

### C10 过程记录链

**核心步骤**：明确记录目的 → 定义最小记录项 → 人工或自动采集 → 标注时间来源责任 → 关联任务版本 → 校验完整 → 分类保存 → 提供检索

- 解决：让过程可见、可追溯、可评估和可复盘。
- 输入：事件、行为、状态、决定、产出和异常。
- 输出：有来源、时间、上下文和对象关联的过程记录。
- 完成标准：关键事实可检索、可解释，并连接到对应对象和版本。
- 返回：缺失错误时补录修正；负担过高时缩减为最小必要集合。
- 可调用：记录管理、证据管理、追溯管理。
- 应用：习惯日志、实验日志、任务状态、会议纪要、系统日志。

### C11 进度监测链

**核心步骤**：读取目标计划和阈值 → 采集实际状态 → 比较范围进度成本里程碑 → 识别偏差趋势 → 判断影响 → 预警升级 → 触发处置

- 解决：在结果失败前发现进度和负荷偏差。
- 输入：计划基线、过程记录、完成量和资源状态。
- 输出：当前状态、偏差、趋势、影响和处置触发。
- 完成标准：重要偏差及时进入有权处理者的队列。
- 返回：数据不可靠回记录采集；基线失效回计划或变更。
- 可调用：过程记录、评估判断、纠偏调整、沟通协作。
- 应用：个人计划、学习进度、项目控制、经营监控。

### C12 质量控制链

**核心步骤**：读取质量标准 → 设置控制点 → 选择检查对象方法 → 执行检测 → 记录缺陷证据 → 判定等级 → 返工／让步／放行 → 复检

- 解决：防止缺陷流入下游并判断产物是否符合质量要求。
- 输入：被检对象、质量标准、检测方法。
- 输出：质量结论、缺陷清单和处置决定。
- 完成标准：阻断缺陷关闭或经授权接受，检查证据可追溯。
- 返回：缺陷回执行；标准不合理回标准；系统缺陷进原因分析。
- 可调用：标准设定、证据管理、原因分析、纠偏调整。
- 应用：文档校对、软件测试、产品检验、流程审计。

### C13 纠偏调整链

**核心步骤**：确认偏差 → 判断偏差层级 → 定位可控原因 → 选择最小有效调整 → 评估连带影响 → 实施 → 再次检查 → 保留／回退／升级

- 解决：在不无谓推翻全部工作的前提下恢复可接受轨道。
- 输入：进度、质量、成本、风险、资源或目标偏差。
- 输出：已验证调整，或升级重规划的决定。
- 完成标准：偏差回到容许范围，或已移交更高层处理。
- 返回：动作无效回原因方案；根因位于目标计划时返回相应阶段。
- 可调用：原因分析、决策选择、计划制定、质量控制。
- 应用：习惯调整、学习纠错、任务重排、项目变更、运营纠偏。

### C14 提交验收链

**核心步骤**：整理成果证据 → 核对交付清单 → 正式提交 → 接收方检查 → 验证要求 → 确认用途 → 处理缺陷异议 → 接受／拒收／条件接受 → 移交责任

- 解决：把“执行者认为做完”转成“接收者确认完成和接管”。
- 输入：成果、交付清单、要求、使用情境、标准和权限。
- 输出：验证结论、确认结论、验收决定和移交记录。
- 完成标准：接收方明确确认，遗留项有责任期限，资料权限责任已转移。
- 返回：规格不符回执行质量；用途不符回需求方案；标准争议回澄清设标。
- 可调用：质量控制、评估判断、沟通协作、完成收尾。
- 应用：任务交付、采购收货、软件上线、项目移交、学习成果评审。

### C15 评估判断链

**核心步骤**：明确对象用途 → 读取有效标准 → 收集足够证据 → 测量结果影响 → 对照差距 → 表达不确定性 → 形成结论 → 提出建议

- 解决：依据证据判断表现、效果、价值或是否达标。
- 输入：评估问题、标准、结果数据和过程证据。
- 输出：带证据、限制、置信度和建议的判断。
- 完成标准：结论可追溯到标准证据，并能支持下一决定。
- 返回：证据不足回收集；标准失效回设标；因果不明回原因验证。
- 可调用：证据管理、原因分析、决策选择、效果价值。
- 应用：结果评价、绩效、方案评审、健康检查、投资复核。

### C16 反馈处理链

**核心步骤**：接收反馈 → 确认来源语境 → 核验事实可信度 → 分类聚合 → 定位影响对象 → 判断价值优先 → 回复 → 转入观察／纠偏／问题解决／改进

- 解决：把意见、数据回传和用户反应转成可处理事项。
- 输入：评价、抱怨、建议、行为数据、监测结果。
- 输出：已核验、分类、排序并分派去向的反馈项。
- 完成标准：反馈者得到适当回应，内部责任和下一动作明确。
- 返回：事实不清回核验；重复项聚合；暂不处理进入观察池并设复查条件。
- 可调用：触发识别、价值排序、问题定义、持续改进。
- 应用：自我反馈、教师反馈、用户反馈、员工建议、质量告警。

### C17 总结提炼链

**核心步骤**：汇集材料 → 回顾事实 → 筛选重点 → 归纳结果 → 区分事实解释 → 提炼规律边界 → 压缩表达 → 保存传播

- 解决：把大量材料压缩成准确、易理解和可传播的核心内容。
- 输入：记录、数据、成果、讨论和文献。
- 输出：摘要、结论、要点、模型或简报。
- 完成标准：保留关键事实和边界，目标读者能快速获得所需信息。
- 返回：出现失真、遗漏或冲突时返回材料核查。
- 可调用：证据核查、知识加工、表达确认。
- 应用：日记总结、读书摘要、项目报告、管理简报。

### C18 复盘改进链

**核心步骤**：还原目标假设标准 → 重建关键过程 → 对照结果 → 识别成功失败意外 → 分析直接系统原因 → 提炼经验边界 → 制定改进试验 → 指定责任时间

- 解决：解释为什么得到这一结果，并改变下一次行动。
- 输入：目标、计划、记录、结果和相关方观点。
- 输出：原因判断、经验边界、改进任务和验证安排。
- 完成标准：至少一项可验证改变进入计划；不把运气误认成方法。
- 返回：事实不全回记录取证；原因不明进假设验证；措施无效再复盘。
- 可调用：原因分析、假设验证、经验沉淀、计划制定。
- 应用：日周复盘、学习复盘、项目复盘、事故复盘、经营复盘。

### C19 经验沉淀链

**核心步骤**：收集成功失败经验 → 区分规律偶然 → 提炼条件原则步骤例外 → 选择清单模板流程工具 → 试用验证 → 发布复用 → 收集效果 → 更新版本

- 解决：把一次经历转成跨时间、跨人员复用的资产。
- 输入：经过复盘的经验、证据和改进结果。
- 输出：方法、清单、模板、规则、课程、流程或工具。
- 完成标准：另一人在适用条件下能正确使用并得到可接受结果。
- 返回：不可复现回提炼验证；环境变化进入更新或淘汰。
- 可调用：总结提炼、流程标准化、培训上岗、版本更新。
- 应用：个人方法库、团队实践、公司流程、软件工具化。

### C20 问题定义链

**核心步骤**：发现偏差障碍 → 分离事实判断 → 描述当前状态 → 描述期望状态 → 界定对象范围 → 评估影响 → 排除伪问题 → 形成问题陈述

- 解决：避免用症状、预设方案或情绪代替真实问题。
- 输入：异常、抱怨、失败、冲突、目标偏差。
- 输出：包含对象、现状、期望、差距、影响和边界的问题陈述。
- 完成标准：可以据此收集相关事实、分析原因，而不再争论问题含义。
- 返回：边界过大进问题拆解；事实变化重新定义。
- 可调用：证据管理、范围界定、表达确认。
- 应用：生活障碍、学习卡点、软件缺陷、经营问题、组织冲突。

### C21 原因分析链

**核心步骤**：收集可靠事实 → 建立事件顺序 → 区分症状相关因果 → 生成多个原因假设 → 寻找支持反证 → 识别可干预原因 → 说明置信度

- 解决：找到能解释主要事实并可被行动改变的原因。
- 输入：清楚的问题、时间线、数据和现场信息。
- 输出：按证据和可干预性排序的原因模型。
- 完成标准：关键原因解释主要事实、经受反证并能导出可验证措施。
- 返回：证据不足回收集；解释难分进假设验证。
- 可调用：数据采集、问题拆解、假设验证。
- 应用：行为原因、学习错误、故障诊断、质量问题、事故调查。

### C22 决策选择链

**核心步骤**：明确事项与决策权 → 确认目标硬约束 → 建立比较标准 → 生成选项 → 收集关键证据 → 比较收益成本风险可逆性 → 检查偏差 → 选择／试验 → 记录理由复查条件

- 解决：在多个可能行动之间作出可解释、可复查的取舍。
- 输入：决策问题、候选方案、证据、偏好和约束。
- 输出：被授权的决定、理由、假设、剩余风险和复查条件。
- 完成标准：选择可进入执行，决定权、关键假设和退出条件明确。
- 返回：无合格方案回生成；证据价值高于等待成本时补证；假设不稳先试验。
- 可调用：方案生成、证据管理、风险管理、假设验证。
- 应用：消费、职业、技术选型、项目方案、公司战略。

### C23 信息处理链

**核心步骤**：明确问题 → 找资料 → 筛选 → 分层 → 阅读解析 → 拆解提取 → 统一术语 → 归类去重 → 对比核实 → 处理冲突 → 补充遗漏 → 综合建模

- 解决：把分散资料转成结构化、可靠、可使用的知识。
- 输入：问题、检索结果、文献、记录、数据和观点。
- 输出：来源可追溯、冲突已标注、结构明确的知识模型。
- 完成标准：能回答核心问题，重要主张有证据，未知争议被显式标注。
- 返回：模型缺口回检索；来源冲突回核查；术语混乱回统一；新证据触发更新。
- 可调用：信息检索、筛选、证据核查、知识加工、知识建模。
- 应用：研究、读书、市场调查、软件调研、组织知识库。

### C24 个人学习链

**核心步骤**：明确表现目标 → 接触可靠知识 → 理解含义 → 联系旧知 → 组织结构 → 记忆编码 → 主动回想 → 间隔复习 → 刻意练习 → 场景运用 → 反馈纠错 → 形成能力

- 解决：把外部知识转成能理解、记住、调用和迁移的能力。
- 输入：学习目标、可靠知识、已有基础、练习环境和反馈来源。
- 输出：在目标场景中稳定完成任务的能力及证据。
- 完成标准：不仅能复述，还能在变式场景独立应用并达标。
- 返回：理解错误回解释联系；遗忘回回想复习；操作错误回针对练习；迁移失败回条件分析。
- 可调用：理解建构、记忆巩固、练习反馈、迁移应用、能力评估。
- 应用：陌生领域、职业技能、健康动作、软件工具、管理能力。

### C25 沟通闭环链

**核心步骤**：明确目的对象 → 组织必要信息 → 选择方式时机 → 清楚表达 → 接收回应 → 倾听追问 → 复述确认 → 记录共识 → 跟进行动

- 解决：让“已经说过”变成“正确理解并形成一致行动”。
- 输入：事实、意图、请求、决定或反馈。
- 输出：被确认的理解、共识、分歧和后续动作。
- 完成标准：关键双方能一致复述结果、责任和时限。
- 返回：理解不一致回表达澄清；事实冲突回证据；利益冲突进协商。
- 可调用：证据核查、请求回应、冲突协商、过程记录。
- 应用：家庭沟通、任务交接、会议、客户沟通、跨部门协作。

### C26 分工协作链

**核心步骤**：明确共同成果 → 拆分工作包 → 匹配责任能力 → 约定接口依赖 → 配置权限资源 → 同步进展 → 处理阻塞冲突 → 合并成果 → 共同验收

- 解决：把多人行动转成一致、可衔接的整体成果。
- 输入：共同目标、成员能力、任务依赖和资源。
- 输出：清晰分工、协作接口、同步机制和合并成果。
- 完成标准：责任无空白无重复，接口可衔接，整体成果通过验收。
- 返回：责任冲突回分工；接口失配回依赖；资源不足回配置；关系冲突进协商。
- 可调用：目标拆解、责任授权、沟通闭环、冲突协商、提交验收。
- 应用：家庭事务、学习小组、软件团队、项目群、组织运营。

### C27 组织转化链

**核心步骤**：识别可复用经验 → 收集证据 → 复盘提炼 → 显性表达 → 统一术语标准 → 设计流程角色 → 模板工具化 → 试点 → 培训采用 → 监督质量 → 评估效果 → 修订发布 → 版本维护

- 解决：把个人或单项目经验变成组织可重复执行的能力。
- 输入：已验证经验、过程记录、结果数据和组织需要。
- 输出：流程、标准、模板、工具、培训和维护责任组成的组织能力。
- 完成标准：不同合格人员脱离原作者后仍能稳定得到可接受结果。
- 返回：不可复现回经验验证；执行困难回流程培训；采用率低回权限激励支持；环境变化进更新。
- 可调用：复盘改进、经验沉淀、流程标准化、培训上岗、组织采用、版本更新。
- 应用：最佳实践、交付标准、质量体系、客服话术、研发流程。

### C28 风险管理链

**核心步骤**：建立情境目标 → 识别威胁机会 → 描述原因触发 → 分析概率影响关联 → 评价等级承受度 → 选择应对 → 指定责任资源 → 实施 → 监测复审 → 关闭／转事件

- 解决：管理尚未发生但可能影响目标的不确定性。
- 输入：目标、环境、假设、资产、脆弱性和历史数据。
- 输出：动态风险记录、等级、策略、责任、触发器和剩余风险决定。
- 完成标准：高风险可见、有人负责、可触发行动，剩余风险获授权接受。
- 返回：新风险加入识别；等级变化重评；风险发生转异常响应。
- 可调用：证据管理、决策选择、风险预案、进度监测。
- 应用：健康、出行、消费、财务、项目、上线、公司经营。

### C29 异常恢复链

**核心步骤**：发现验证异常 → 判断等级安全边界 → 保护人员资产证据 → 控制影响 → 通知指挥 → 诊断 → 临时绕行／修复／回退 → 验证恢复 → 逐步恢复 → 加强监测 → 事后调查

- 解决：异常、故障或中断后先稳定局面，再恢复可接受状态。
- 输入：告警、故障、失败事件、影响信息和预案。
- 输出：受控影响、恢复状态、处置记录和调查入口。
- 完成标准：核心功能恢复或安全降级，影响不再扩大，责任人确认状态。
- 返回：恢复失败回隔离诊断或替代方案；不可恢复进止损退出。
- 可调用：沟通闭环、故障恢复、决策选择、事件调查。
- 应用：身体不适、行程中断、数据丢失、软件故障、运营事故。

### C30 维护更新退出链

**核心步骤**：定义有效状态与复查周期 → 检查使用效果 → 识别退化过时 → 评估维护替换成本 → 决定维护／更新／扩大／暂停／交接／归档／淘汰 → 执行迁移 → 验证状态 → 记录版本复查

- 解决：防止成果、知识、习惯、流程和系统在完成后静态老化。
- 输入：已投入使用的对象、状态数据、环境变化和维护成本。
- 输出：有效对象、新版本、迁移结果，或有序暂停归档淘汰状态。
- 完成标准：对象处置、依赖迁移、后续责任和复查时间明确。
- 返回：更新失败回退旧版；归档出现新需求进重新启用；替代不足回决策。
- 可调用：状态维护、版本更新、扩大迁移、交接转移、暂停恢复、归档淘汰、重新启用。
- 应用：个人习惯、知识笔记、软件版本、设备、制度、组织流程。

### 定向与目标

## 五、基础链准入规则

新增一条L2基础链前必须回答：

1. 它的输入和输出是否与已有链相同？
2. 核心转化机制是否真正不同？
3. 完成标准和失败返回是否不同？
4. 差异是否只是行业、对象、角色、工具或时限？
5. 它是否只是已有链中的一个节点或三条以上链的组合？

前三项没有结构性差异时不新增L2；对象差异下沉L3/L4；由多条基础链组成时定义为组合链。
