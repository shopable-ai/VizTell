## 一、标准卡字段与共同运行协议

每条核心链统一包含：解决、输入、核心步骤、输出、完成标准、返回、可调用、应用。L4 具体工作流再增加角色、时限、工具、阈值、证据、权限和法规。

### 1.1 核心链与扩展链的关系

- **C01—C30 核心链**：跨生活、学习、工作、项目和组织场景高频复现的稳定运行包，编号和正式名称保持兼容。
- **扩展基础链**：具有独立输入、输出或判断，但频率、范围或成熟度尚不足以占用核心编号；在第四节以单行链登记。
- **十四个转化主题**：只负责把核心链和扩展链放进易检索视图，不建立第二份定义。
- **L3／L4**：L3 组合多个基础链形成场景链；L4 再加入真实角色、工具、时间、阈值、权限、证据和法规。

### 1.2 所有链共同遵守的正式协议

| 协议项 | 必须回答的问题 | 最小输出 |
| --- | --- | --- |
| 触发 | 什么信号、事件、时间或阈值启动；谁可以启动 | 可识别触发器与登记入口 |
| 前置与输入 | 输入来自哪里、版本是否有效、缺失时能否继续 | 已确认输入或补齐／停止决定 |
| 转化与判断 | 本链把什么状态变成什么状态；在哪些节点作判断 | 核心步骤、关口与判定标准 |
| 责任与权限 | 谁执行、谁负责结果、谁决定例外、谁接收 | 责任人、决策权和升级对象 |
| 证据 | 哪些事实、来源、记录和版本支持结论 | 可追溯的最小证据集 |
| 分支与返回 | 信息不足、资源不足、质量失败、目标失效时去哪里 | 明确返回点、旁路与升级路径 |
| 完成与退出 | 怎样算完成；何时暂停、终止、回退或转交 | 完成状态和生命周期去向 |
| 版本与复查 | 环境变化后由谁更新；旧版如何迁移或淘汰 | 版本、有效期、复查条件 |

L2 卡描述跨领域最小协议；任何高风险或多人场景，都必须在 L4 将这些字段具体化，不能只复制链路名称。

### 1.3 AI／软件时代的三种运行模式

同一条基础链保持相同的语义目标，但可按规模、成本、风险和工具条件选择不同运行模式。

| 模式 | 主要执行方式 | 适用情形 | 人的主要职责 |
| --- | --- | --- | --- |
| **M0 人工模式** | 人完成检索、判断、记录、学习和执行 | 低频、小规模、无工具或需要亲自掌握 | 理解、判断、执行、验证 |
| **M1 AI 辅助模式** | AI 承担搜索、摘要、比较、分类、草拟，人保留关键判断 | 中等规模、知识工作、研究与项目推进 | 定义用途、审查证据、选择与验收 |
| **M2 AI 原生模式** | AI／Agent／软件持续处理大规模输入，人主要处理异常、高价值、高风险和授权节点 | 高频、大规模、持续监测、知识库与自动工作流 | 设定边界、处理例外、关键决策、监督结果 |

AI／软件模式优先采用统一的增量母式：

> **读取可用状态／上下文 → 低成本初筛 → 批量处理 → 识别差额／变化／异常 → 判断价值与处理成本 → 分流 → 深处理高价值部分 → 验证 → 更新状态**

该母式不要求必须存在明确目标；有目标时使用目标，无明确目标时使用当前任务、问题、角色、兴趣、长期方向、历史关注、已有知识、风险等可用上下文，并保留探索入口。


## 二、三十条核心基础链速览

> **先看本节，再按编号查阅完整卡。** 三十条链不是要求依次运行的固定长流程，而是一个“主闭环＋按需调用库”。普通事项只使用最短闭环；问题复杂、多人协作、高风险或长期运行时，再增加相应链路。

### 2.1 核心主闭环

> **触发识别 C01 → 需求澄清 C02 → 价值排序 C03 → 目标设定 C04 → 标准设定 C05 → 计划制定 C06 → 资源配置 C07 → 风险预案 C08 → 任务执行 C09〔记录 C10＋监测 C11＋沟通 C25＋质量 C12＋风险 C28＋按需挂接合规／变更／版本控制〕→ 纠偏调整 C13 → 提交验收 C14 → 评估判断 C15 → 反馈处理 C16 → 总结提炼 C17 → 复盘改进 C18 → 经验沉淀 C19 → 维护、更新或退出 C30**

### 2.2 四类按需调用链

- 遇到不清楚的问题：**问题定义 C20 → 信息处理 C23 → 原因分析 C21 → 决策选择 C22**。
- 遇到大量信息、知识或能力缺口：**信息注意力分流 → 信息处理 C23 → 知识增量与价值分流 →〔个人学习 C24／知识消费路由〕→ 返回当前任务**。
- 遇到多人或组织转化：**沟通闭环 C25 → 分工协作 C26 → 组织转化 C27**。
- 遇到风险、事故或生命周期变化：**风险管理 C28 → 异常恢复 C29 → 维护更新退出 C30**。

| C29 | [异常恢复链](#c29-异常恢复链) / Incident Recovery | 发现验证异常 → 判断等级安全边界 → 保护人员资产证据 → 控制影响 → 通知指挥 → 诊断 → 临时绕行／修复／回退 → 验证恢复 → 逐步恢复 → 加强监测 → 事后调查 | 告警、风险事件化、重大失败 → C21、C18、C30、重入母链 |
| C30 | [维护更新退出链](#c30-维护更新退出链) / Maintenance, Update & Exit | 定义有效状态与复查周期 → 检查使用效果 → 识别退化过时 → 评估维护替换成本 → 决定维护／更新／扩大／暂停／交接／归档／淘汰 → 执行迁移 → 验证状态 → 记录版本复查 | C14、C15、C18、C19、C22 → 维护／更新／扩大／暂停／交接／归档／淘汰／重启 |

### 2.7 AI 原生信息与知识系统高密度总览

> **总装配链**：信息／信号出现 →〔人工遇见／被动信息自动采集〕→ 主动信息发现 → 注意力分流 →〔按需主动研究〕→ C23 信息处理〔原子化＋关系判定＋增量价值分流〕→ 知识消费路由 →〔C24 人工学习／Wiki／RAG／AI Skill／Workflow／SOP／未来知识池〕→ 验证 → 使用 → 反馈 → C30 增量维护；主动信息路由决定立即提醒、任务时注入、周期简报、条件触发、静默更新或授权后的低风险自动动作。

| 一级系统 | 主要模块 | 核心产出 |
| --- | --- | --- |
| **A 信息入口与注意力** | 被动采集、主动发现、注意力筛选、上下文匹配、价值排序 | 值得进一步处理的信息和变化 |
| **B 知识加工与增量** | 基线、原子化、语义关系、增量、时域分流 | 标准知识单元、关系和有效增量 |
| **C 人类阅读与学习** | 阅读调度、掌握状态、理解、记忆、练习、迁移 | 阅读计划和个人能力状态 |
| **D AI 知识与能力** | 上下文、RAG、Skill、Workflow | 可检索知识和可测试执行能力 |
| **E 知识基础设施** | Raw Source、标准知识、Wiki、知识图谱、混合检索 | 可浏览、可关联、可追溯的长期知识系统 |

**知识落点边界**：

| 落点 | 主要用途 | 典型完成状态 |
| --- | --- | --- |
| **Raw Source 原始资料** | 回溯原文、重新解析、证据核验 | 来源、时间、版本和原文可追溯 |
| **Canonical Knowledge 标准知识** | 保存去重后的概念、命题、机制、证据、边界和关系 | 知识原子稳定、来源和关系明确 |
| **Wiki／知识图谱** | 人和 Agent 浏览主题、实体、时间线和关系 | 可导航、可关联、可追溯 |
| **RAG／检索层** | AI 在任务发生时找到最小充分知识 | 召回准确、上下文受预算控制、来源可核验 |
| **AI Skill** | AI 重复执行稳定方法 | 触发、输入、步骤、判断、工具、输出、异常和测试明确 |

| **未来知识池** | 当前不占注意力，需求或条件出现时重新激活 | 可检索、带触发条件和复查状态 |

### 2.8 统一状态体系

| 对象 | 建议状态 |
| --- | --- |
| **资料状态** | 未处理 → 已采集 → 已解析 → 已提取 → 已入知识模型 → 已核查／待核查 → 更新／过时／归档 |
| **知识状态** | 待验证 → 已验证 → 有争议 → 过时 → 被替代 → 归档／重新激活 |
| **个人掌握状态** | 未见 → 见过 → 理解 → 可回忆 → 可辨别 → 可应用 → 可迁移 → 熟练 |
| **AI 能力状态** | 未索引 → 可检索 → RAG 可用 → 已 Skill 化 → 测试通过 → Workflow 可用 → 退化／弃用 |
| **需求状态** | 当前 → 近期 → 中期 → 长期 → 条件触发 → 探索 → 暂无需求 |
| **来源状态** | 未核验 → 二手线索 → 一手来源 → 多源交叉 → 高可信／争议／失效 |

状态变化本身可以触发重新评分。例如未来知识池中的内容，在项目进入对应阶段、风险变化或新证据出现后，应重新进入价值分流，而不是永久沉睡。

### 2.9 主动信息系统协议

> **系统监测入口**：信息源登记／授权 → 被动信息自动采集 → 主动信息发现 → 主动信息路由 →〔立即提醒／任务注入／周期简报／条件触发／静默更新／低风险授权动作／丢弃〕→ 反馈学习。
>
> **人工偶遇入口**：信息出现 → 信息注意力分流 → C23／暂存／探索／忽略。

**注意力防火墙**：

| 级别 | 默认处理 |
| --- | --- |
| **P0 立即打断** | 安全、重大损失、关键截止、重大异常或高时效机会 |
| **P1 当前任务注入** | 与正在执行任务直接相关但无需单独打断 |
| **P2 日报／短周期简报** | 有价值但不紧急的变化 |
| **P3 周报／探索池** | 趋势、前沿、未知机会和中长期价值 |
| **P4 静默更新** | 只更新 Wiki／RAG／知识关系／监测状态 |
| **P5 丢弃** | 低价值重复、噪声、不可验证或无保留价值的信息 |

注意力预算至少区分：**当前任务预算＋近期学习预算＋探索预算＋风险通道**。

**主动信息卡最小字段**：

> **发生了什么 → 相对已有状态新在哪里 → 为什么与你有关 → 影响／紧迫程度 → 可信度／来源 → 建议动作 → 是否需要人工读原文 → 关联任务／项目／知识／Skill／Workflow → 下一复查条件**

### 2.10 大规模增量处理跨链协议

| 链 | AI 原生增量处理重点 |
| --- | --- |
| **C09 任务执行** | 可重复部分交给 Skill／Workflow，人保留高风险、异常和授权关口 |
| **C10 过程记录** | 优先记录状态变化、关键决定、证据、异常、失败和恢复点，不把所有中间输出永久保存 |
| **C16 反馈处理** | 大量反馈先聚类、匹配已知问题、累计频率和趋势，只升级新问题、异常和状态变化 |
| **C17 总结提炼** | 优先总结新增、变化、异常、决定和待办，而不是重复全量复述 |

## 三、三十条核心基础链标准卡

### C01 触发识别链

**核心步骤**：接收信号 → 记录现象 → 辨别需求／问题／机会／变化／任务 → 核验真实性 → 估计影响 → 响应／观察／忽略

- 解决：模糊信号是否值得进入处理系统。
- 输入：感受、诉求、数据变化、外部事件、例行任务或异常。
- 输出：已分类、已核验并带去向的触发事项。
- 完成标准：类型、可信度、影响和下一去向明确。
- 返回：证据不足进入观察或取证；分类错误重新辨别。
- 可调用：证据核查、价值排序、需求澄清、问题定义、异常响应。
- 应用：个人愿望、用户反馈、市场变化、系统告警、政策变化。

### C02 需求澄清链

**核心步骤**：识别相关方 → 收集诉求 → 还原使用场景 → 区分手段与目的 → 识别冲突约束 → 表述真实需要 → 确认理解

- 解决：把含混、表面或互相冲突的诉求转成可承接需求。
- 输入：愿望、抱怨、请求、访谈、需求草案。
- 输出：包含对象、场景、价值、约束和确认人的需求说明。
- 完成标准：相关方能一致复述“谁在什么场景需要什么结果、为什么”。
- 返回：出现新相关方、新证据或冲突时返回收集澄清。
- 可调用：表达确认、范围界定、价值排序。
- 应用：个人目标、软件需求、客户委托、组织改革。

### C03 价值排序链

**核心步骤**：明确事项 → 估计收益 → 估计成本风险 → 判断必要性时效 → 比较替代和机会成本 → 排优先 → 立项／延后／委派／放弃

- 解决：有限时间和资源应投向什么。
- 输入：候选需求、问题、机会、任务或改进项。
- 输出：带理由的优先级和处置决定。
- 完成标准：决定者、评价维度、排序和下一动作明确。
- 返回：价值、成本、风险、资源或时效实质变化时重评。
- 可调用：证据核查、风险管理、决策选择。
- 应用：个人待办、产品路线、项目组合、公司投资。

### C04 目标设定链

**核心步骤**：承接已选事项 → 初识现状约束 → 描述期望结果 → 划定范围 → 设置指标期限 → 检查价值可行一致 → 明确责任 → 确认承诺

- 解决：把方向、愿望或责任转成可以规划和评价的目标。
- 输入：已通过价值门的事项、上位目标和关键约束。
- 输出：结果、范围、指标、期限和责任明确的目标。
- 完成标准：可以据此生成计划，并能判断最终是否达成。
- 返回：不可行返回范围、指标、期限或资源；价值失效返回价值排序。
- 可调用：现状初判、范围界定、标准设定、表达确认。
- 应用：健康、学习、任务、项目、组织目标。

### C05 标准设定链

**核心步骤**：明确成果与用途 → 选择评价维度 → 定义指标阈值 → 规定证据和测量方式 → 说明容差例外 → 指定判定人 → 确认标准

- 解决：事前明确怎样算完成、合格、成功或安全。
- 输入：目标、需求、质量要求、风险边界。
- 输出：可测量、可取证、可解释的标准。
- 完成标准：不同评价者基于同一证据能够得到基本一致判断。
- 返回：无法测量时修改指标证据；环境变化时修订并保留版本。
- 可调用：数据采集、证据管理、版本更新。
- 应用：验收标准、学习考核、服务质量、健康指标、风险阈值。

### C06 计划制定链

**核心步骤**：读取目标范围标准方案 → 拆解成果任务 → 分析依赖 → 排定优先 → 估算时间资源 → 分配责任 → 设置里程碑检查点 → 识别风险变更 → 形成基线

- 解决：把目标和方案转成可协调、可监测的行动安排。
- 输入：目标、范围、标准、选定方案和约束。
- 输出：任务、依赖、时序、责任、资源、检查点和风险明确的计划。
- 完成标准：近期任务可启动，关键依赖和缺口已有处置。
- 返回：目标变化回目标；资源冲突回配置；执行偏差触发重排或变更。
- 可调用：目标拆解、资源配置、责任授权、风险预案。
- 应用：周计划、学习计划、项目计划、运营计划、应急计划。

### C07 资源配置链

**核心步骤**：读取任务需要 → 盘点时间精力人员资金信息工具 → 识别缺口 → 获取调配替代 → 按优先分配 → 解决冲突 → 确认可用

- 解决：为计划提供足够且可以实际调用的资源。
- 输入：任务负荷、资源存量、预算和约束。
- 输出：带责任和时限的资源安排。
- 完成标准：关键资源到位；缺口有替代、缩减或升级决定。
- 返回：资源失效、任务变化或过载时重新盘点分配。
- 可调用：价值排序、预算管理、冲突协商、风险管理。
- 应用：个人时间精力、项目人员预算、生产设备、数据权限。

### C08 风险预案链

**核心步骤**：识别潜在风险 → 描述触发条件 → 评估概率影响 → 排定等级 → 选择应对 → 设置预警责任 → 准备应急动作 → 演练复查

- 解决：在不确定事件发生前降低发生概率或影响。
- 输入：目标、方案、计划、环境约束和历史事件。
- 输出：风险清单、等级、责任人、预警条件和预案。
- 完成标准：高风险都有策略、触发器和责任人，剩余风险获知情接受。
- 返回：环境、方案或暴露程度变化时重新评估。
- 可调用：证据管理、决策选择、异常响应。
- 应用：健康计划、财务决策、软件上线、公司运营。

### C09 任务执行链

**核心步骤**：接收任务 → 确认结果标准权限 → 核对前置条件 → 推进行动 → 处理阻碍 →〔记录 C10＋监测 C11＋沟通 C25＋质量 C12＋风险 C28〕→ 自检 → 提交

- 解决：把已定义任务转成可检查成果。
- 输入：任务、标准、资源、权限和期限。
- 输出：成果、过程记录、遗留问题和提交说明。
- 完成标准：成果已提交且通过提交前自检；是否最终完成由验收决定。
- 返回：要求不清回澄清；条件不足回准备；偏差进纠偏；异常进恢复。
- 可调用：过程记录、进度监测、沟通闭环、质量控制、风险管理、合规伦理审查、变更控制、异常响应。
- 应用：日常待办、学习练习、内容制作、开发功能、运营作业。

### C10 过程记录链

**核心步骤**：明确记录目的 → 定义最小记录项 → 人工或自动采集 → 标注时间来源责任 → 关联任务版本 → 校验完整 → 分类保存 → 提供检索

- 解决：让过程可见、可追溯、可评估和可复盘。
- 输入：事件、行为、状态、决定、产出和异常。
- 输出：有来源、时间、上下文和对象关联的过程记录。
- 完成标准：关键事实可检索、可解释，并连接到对应对象和版本。
- 返回：缺失错误时补录修正；负担过高时缩减为最小必要集合。
- 可调用：记录管理、证据管理、追溯管理。
- 应用：习惯日志、实验日志、任务状态、会议纪要、系统日志。

### C11 进度监测链

**核心步骤**：读取目标计划和阈值 → 采集实际状态 → 比较范围进度成本里程碑 → 识别偏差趋势 → 判断影响 → 预警升级 → 触发处置

- 解决：在结果失败前发现进度和负荷偏差。
- 输入：计划基线、过程记录、完成量和资源状态。
- 输出：当前状态、偏差、趋势、影响和处置触发。
- 完成标准：重要偏差及时进入有权处理者的队列。
- 返回：数据不可靠回记录采集；基线失效回计划或变更。
- 可调用：过程记录、评估判断、纠偏调整、沟通协作。
- 应用：个人计划、学习进度、项目控制、经营监控。

### C12 质量控制链

**核心步骤**：读取质量标准 → 设置控制点 → 选择检查对象方法 → 执行检测 → 记录缺陷证据 → 判定等级 → 返工／让步／放行 → 复检

- 解决：防止缺陷流入下游并判断产物是否符合质量要求。
- 输入：被检对象、质量标准、检测方法。
- 输出：质量结论、缺陷清单和处置决定。
- 完成标准：阻断缺陷关闭或经授权接受，检查证据可追溯。
- 返回：缺陷回执行；标准不合理回标准；系统缺陷进原因分析。
- 可调用：标准设定、证据管理、原因分析、纠偏调整。
- 应用：文档校对、软件测试、产品检验、流程审计。

### C13 纠偏调整链

**核心步骤**：确认偏差 → 判断偏差层级 → 定位可控原因 → 选择最小有效调整 → 评估连带影响 → 实施 → 再次检查 → 保留／回退／升级

- 解决：在不无谓推翻全部工作的前提下恢复可接受轨道。
- 输入：进度、质量、成本、风险、资源或目标偏差。
- 输出：已验证调整，或升级重规划的决定。
- 完成标准：偏差回到容许范围，或已移交更高层处理。
- 返回：动作无效回原因方案；根因位于目标计划时返回相应阶段。
- 可调用：原因分析、决策选择、计划制定、质量控制。
- 应用：习惯调整、学习纠错、任务重排、项目变更、运营纠偏。

### C14 提交验收链

**核心步骤**：整理成果证据 → 核对交付清单 → 正式提交 → 接收方检查 → 验证要求 → 确认用途 → 处理缺陷异议 → 接受／拒收／条件接受 → 移交责任

- 解决：把“执行者认为做完”转成“接收者确认完成和接管”。
- 输入：成果、交付清单、要求、使用情境、标准和权限。
- 输出：验证结论、确认结论、验收决定和移交记录。
- 完成标准：接收方明确确认，遗留项有责任期限，资料权限责任已转移。
- 返回：规格不符回执行质量；用途不符回需求方案；标准争议回澄清设标。
- 可调用：质量控制、评估判断、沟通协作、完成收尾。
- 应用：任务交付、采购收货、软件上线、项目移交、学习成果评审。

### C15 评估判断链

**核心步骤**：明确对象用途 → 读取有效标准 → 收集足够证据 → 测量结果影响 → 对照差距 → 表达不确定性 → 形成结论 → 提出建议

- 解决：依据证据判断表现、效果、价值或是否达标。
- 输入：评估问题、标准、结果数据和过程证据。
- 输出：带证据、限制、置信度和建议的判断。
- 完成标准：结论可追溯到标准证据，并能支持下一决定。
- 返回：证据不足回收集；标准失效回设标；因果不明回原因验证。
- 可调用：证据管理、原因分析、决策选择、效果价值。
- 应用：结果评价、绩效、方案评审、健康检查、投资复核。

### C16 反馈处理链

**核心步骤**：接收反馈 → 确认来源语境 → 核验事实可信度 → 分类聚合 → 定位影响对象 → 判断价值优先 → 回复 → 转入观察／纠偏／问题解决／改进

- 解决：把意见、数据回传和用户反应转成可处理事项。
- 输入：评价、抱怨、建议、行为数据、监测结果。
- 输出：已核验、分类、排序并分派去向的反馈项。
- 完成标准：反馈者得到适当回应，内部责任和下一动作明确。
- 返回：事实不清回核验；重复项聚合；暂不处理进入观察池并设复查条件。
- 可调用：触发识别、价值排序、问题定义、持续改进。
- 应用：自我反馈、教师反馈、用户反馈、员工建议、质量告警。

### C17 总结提炼链

**核心步骤**：汇集材料 → 回顾事实 → 筛选重点 → 归纳结果 → 区分事实解释 → 提炼规律边界 → 压缩表达 → 保存传播

- 解决：把大量材料压缩成准确、易理解和可传播的核心内容。
- 输入：记录、数据、成果、讨论和文献。
- 输出：摘要、结论、要点、模型或简报。
- 完成标准：保留关键事实和边界，目标读者能快速获得所需信息。
- 返回：出现失真、遗漏或冲突时返回材料核查。
- 可调用：证据核查、知识加工、表达确认。
- 应用：日记总结、读书摘要、项目报告、管理简报。

### C18 复盘改进链

**核心步骤**：还原目标假设标准 → 重建关键过程 → 对照结果 → 识别成功失败意外 → 分析直接系统原因 → 提炼经验边界 → 制定改进试验 → 指定责任时间

- 解决：解释为什么得到这一结果，并改变下一次行动。
- 输入：目标、计划、记录、结果和相关方观点。
- 输出：原因判断、经验边界、改进任务和验证安排。
- 完成标准：至少一项可验证改变进入计划；不把运气误认成方法。
- 返回：事实不全回记录取证；原因不明进假设验证；措施无效再复盘。
- 可调用：原因分析、假设验证、经验沉淀、计划制定。
- 应用：日周复盘、学习复盘、项目复盘、事故复盘、经营复盘。

### C19 经验沉淀链

**核心步骤**：收集成功失败经验 → 区分规律偶然 → 提炼条件原则步骤例外 → 选择清单模板流程工具 → 试用验证 → 发布复用 → 收集效果 → 更新版本

- 解决：把一次经历转成跨时间、跨人员复用的资产。
- 输入：经过复盘的经验、证据和改进结果。
- 输出：方法、清单、模板、规则、课程、流程或工具。
- 完成标准：另一人在适用条件下能正确使用并得到可接受结果。
- 返回：不可复现回提炼验证；环境变化进入更新或淘汰。
- 可调用：总结提炼、流程标准化、培训上岗、版本更新。
- 应用：个人方法库、团队实践、公司流程、软件工具化。

### C20 问题定义链

**核心步骤**：发现偏差障碍 → 分离事实判断 → 描述当前状态 → 描述期望状态 → 界定对象范围 → 评估影响 → 排除伪问题 → 形成问题陈述

- 解决：避免用症状、预设方案或情绪代替真实问题。
- 输入：异常、抱怨、失败、冲突、目标偏差。
- 输出：包含对象、现状、期望、差距、影响和边界的问题陈述。
- 完成标准：可以据此收集相关事实、分析原因，而不再争论问题含义。
- 返回：边界过大进问题拆解；事实变化重新定义。
- 可调用：证据管理、范围界定、表达确认。
- 应用：生活障碍、学习卡点、软件缺陷、经营问题、组织冲突。

### C21 原因分析链

**核心步骤**：收集可靠事实 → 建立事件顺序 → 区分症状相关因果 → 生成多个原因假设 → 寻找支持反证 → 识别可干预原因 → 说明置信度

- 解决：找到能解释主要事实并可被行动改变的原因。
- 输入：清楚的问题、时间线、数据和现场信息。
- 输出：按证据和可干预性排序的原因模型。
- 完成标准：关键原因解释主要事实、经受反证并能导出可验证措施。
- 返回：证据不足回收集；解释难分进假设验证。
- 可调用：数据采集、问题拆解、假设验证。
- 应用：行为原因、学习错误、故障诊断、质量问题、事故调查。

### C22 决策选择链

**核心步骤**：明确事项与决策权 → 确认目标硬约束 → 建立比较标准 → 生成选项 → 收集关键证据 → 比较收益成本风险可逆性 → 检查偏差 → 选择／试验 → 记录理由复查条件

- 解决：在多个可能行动之间作出可解释、可复查的取舍。
- 输入：决策问题、候选方案、证据、偏好和约束。
- 输出：被授权的决定、理由、假设、剩余风险和复查条件。
- 完成标准：选择可进入执行，决定权、关键假设和退出条件明确。
- 返回：无合格方案回生成；证据价值高于等待成本时补证；假设不稳先试验。
- 可调用：方案生成、证据管理、风险管理、假设验证。
- 应用：消费、职业、技术选型、项目方案、公司战略。

### C23 信息处理链

**核心步骤**：明确问题／用途／探索方向 → 读取可用知识基线 → 获取筛选资料 → 解析拆解 → 统一术语主题 → 与已有知识比较 → 判定重复／改写／支持／补充／冲突／反例／新证据／新边界／替代／新结论 → 压缩低值重复 → 核实高价值增量 → 补缺解冲突 → 综合建模并更新知识状态

- 解决：把分散信息转成结构化、可靠、可增量维护和可按需使用的知识，同时降低重复资料持续增长后的处理成本。
- 输入：问题、用途或探索方向，检索结果、文献、记录、数据、观点，以及可获得的已有知识基线。
- 输出：来源可追溯、关系明确、冲突和未知显式标注的知识模型，以及相对已有知识真正新增、变化或需要重新验证的部分。
- 完成标准：核心问题或探索方向得到足够覆盖；重要主张有证据；重复、补充、反例、冲突、边界和版本关系可区分；新增知识已进入合适下游。
- 返回：模型缺口回检索；来源冲突回证据核查；术语混乱回统一；关系不确定回原文；需求变化或新证据触发局部重评而非全量重做。
- 可调用：信息注意力分流、信息检索、信息筛选、证据管理、追溯管理、知识原子化与关系判定、知识增量与价值分流、知识建模、知识消费路由、知识增量维护。
- 应用：单篇文章、第 21 本同类书、批量书库、市场调查、软件调研、竞品分析、新闻流、用户反馈、组织知识库和 AI 长期知识系统。

### C24 个人学习链

**核心步骤**：明确表现目标 → 读取个人掌握基线 → 识别能力缺口 → 区分必须内化／随用随查／可委托 AI → 理解联系旧知 → 记忆回想 → 刻意练习 → 场景独立运用 → 反馈纠错 → 更新掌握状态 → 形成可迁移能力

- 解决：把真正需要由人掌握的知识转成能理解、记住、独立调用和迁移的能力，并把人的有限学习时间集中到高价值能力缺口。
- 输入：表现目标、可靠知识、个人已有掌握状态、阅读调度结果、练习环境和反馈来源。
- 输出：知识状态〔未见／见过／理解／可回忆／可应用／可迁移／熟练〕及真实场景中的能力证据。
- 完成标准：需要内化的知识能在代表性和变式场景独立应用并达标；只需检索或可委托 AI 的内容有可靠调用路径，不占用不必要记忆成本。
- 返回：理解错误回解释联系；遗忘回回想复习；操作错误回针对练习；迁移失败回条件分析；目标变化时重评哪些内容需要内化。
- 可调用：阅读调度、掌握状态管理、理解建构、记忆巩固、练习反馈、迁移应用、能力评估、知识消费路由。
- 应用：陌生领域、职业技能、判断框架、健康动作、软件工具、管理能力，以及 AI 辅助环境下的人类核心能力建设。

### C25 沟通闭环链

**核心步骤**：明确目的对象 → 组织必要信息 → 选择方式时机 → 清楚表达 → 接收回应 → 倾听追问 → 复述确认 → 记录共识 → 跟进行动

- 解决：让“已经说过”变成“正确理解并形成一致行动”。
- 输入：事实、意图、请求、决定或反馈。
- 输出：被确认的理解、共识、分歧和后续动作。
- 完成标准：关键双方能一致复述结果、责任和时限。
- 返回：理解不一致回表达澄清；事实冲突回证据；利益冲突进协商。
- 可调用：证据核查、请求回应、冲突协商、过程记录。
- 应用：家庭沟通、任务交接、会议、客户沟通、跨部门协作。

### C26 分工协作链

**核心步骤**：明确共同成果 → 拆分工作包 → 匹配责任能力 → 约定接口依赖 → 配置权限资源 → 同步进展 → 处理阻塞冲突 → 合并成果 → 共同验收

- 解决：把多人行动转成一致、可衔接的整体成果。
- 输入：共同目标、成员能力、任务依赖和资源。
- 输出：清晰分工、协作接口、同步机制和合并成果。
- 完成标准：责任无空白无重复，接口可衔接，整体成果通过验收。
- 返回：责任冲突回分工；接口失配回依赖；资源不足回配置；关系冲突进协商。
- 可调用：目标拆解、责任授权、沟通闭环、冲突协商、提交验收。
- 应用：家庭事务、学习小组、软件团队、项目群、组织运营。

### C27 组织转化链

**核心步骤**：选择经验证经验或变更目标 → 识别组织需要、受影响者与现状 → 明确赞助、决策权和采用标准 → 设计目标状态、角色流程、制度激励、模板工具及迁移回退 → 沟通参与 → 试点 → 培训支持 → 分批采用 → 监测使用质量效果 → 处理阻力例外 → 修订固化／撤回 → 版本维护

- 解决：把个人或单项目能力，以及已经决定的组织变更，转成脱离原作者后仍能被组织采用和持续运行的能力。
- 输入：已验证经验或变更决定、过程与结果证据、组织需要、相关方、现行权责流程和约束。
- 输出：获得授权并被实际采用的目标状态，以及配套流程、角色、制度、模板、工具、培训、迁移和维护安排。
- 完成标准：不同合格人员能在真实场景稳定执行；采用率、质量、成本和效果达到标准；权责、激励、例外、回退和维护责任明确。
- 返回：证据不足回 C18／C19；目标或赞助失效回 C03／C22；执行困难回流程培训；阻力来自权责激励时返回变更设计；副作用不可接受时撤回或 C30 退出。
- 可调用：复盘改进、经验沉淀、流程标准化、工具化自动化、培训上岗、组织采用、组织变更落地、沟通闭环、分工协作、版本更新。
- 应用：最佳实践、交付标准、质量体系、客服话术、研发流程、组织改革、制度迁移和 AI 工作方式落地。

### C28 风险管理链

**核心步骤**：建立情境目标 → 识别威胁机会 → 描述原因触发 → 分析概率影响关联 → 评价等级承受度 → 选择应对 → 指定责任资源 → 实施 → 监测复审 → 关闭／转事件

- 解决：管理尚未发生但可能影响目标的不确定性。
- 输入：目标、环境、假设、资产、脆弱性和历史数据。
- 输出：动态风险记录、等级、策略、责任、触发器和剩余风险决定。
- 完成标准：高风险可见、有人负责、可触发行动，剩余风险获授权接受。
- 返回：新风险加入识别；等级变化重评；风险发生转异常响应。
- 可调用：证据管理、决策选择、风险预案、进度监测。
- 应用：健康、出行、消费、财务、项目、上线、公司经营。

### C29 异常恢复链

**核心步骤**：发现验证异常 → 判断等级安全边界 → 保护人员资产证据 → 控制影响 → 通知指挥 → 诊断 → 临时绕行／修复／回退 → 验证恢复 → 逐步恢复 → 加强监测 → 事后调查

- 解决：异常、故障或中断后先稳定局面，再恢复可接受状态。
- 输入：告警、故障、失败事件、影响信息和预案。
- 输出：受控影响、恢复状态、处置记录和调查入口。
- 完成标准：核心功能恢复或安全降级，影响不再扩大，责任人确认状态。
- 返回：恢复失败回隔离诊断或替代方案；不可恢复进止损退出。
- 可调用：沟通闭环、故障恢复、决策选择、事件调查。
- 应用：身体不适、行程中断、数据丢失、软件故障、运营事故。

### C30 维护更新退出链

**核心步骤**：定义有效状态与复查周期 → 检查使用效果 → 识别退化过时 → 评估维护替换成本 → 决定维护／更新／扩大／暂停／交接／归档／淘汰 → 执行迁移 → 验证状态 → 记录版本复查

- 解决：防止成果、知识、习惯、流程和系统在完成后静态老化。
- 输入：已投入使用的对象、状态数据、环境变化和维护成本。
- 输出：有效对象、新版本、迁移结果，或有序暂停归档淘汰状态。
- 完成标准：对象处置、依赖迁移、后续责任和复查时间明确。
- 返回：更新失败回退旧版；归档出现新需求进重新启用；替代不足回决策。
- 可调用：状态维护、版本更新、扩大迁移、交接转移、暂停恢复、归档淘汰、重新启用。
- 应用：个人习惯、知识笔记、软件版本、设备、制度、组织流程。

## 四、扩展基础链紧凑库

> 本节解决“核心 30 条之外是否缺链”的问题。以下链具有独立用途，但暂不占用 C 编号；它们是 C01—C30 的拆分链、伴随链或低频专用链。名称首次正式登记在本节，详细落地字段由 L4 工作流补齐。核心链已经覆盖的“风险预案 C08”和“质量控制 C12”不再重复登记。

### T01 触发与登记

- **现状初判链**：明确目的 → 收集关键事实 → 识别硬约束 → 判断能否继续 → 形成初始说明。
- **机会识别链**：观察变化 → 发现未满足价值 → 识别受益者 → 判断窗口与能力 → 形成机会假设 → 探索／等待／放弃。

### T02 需求、价值与边界

- **范围界定链**：明确对象 → 列出包含与排除 → 识别接口约束假设 → 处理争议 → 建立范围基线。
- **现状差距链**：描述目标状态 → 统一口径 → 收集当前证据 → 对照差距 → 识别障碍 → 排定关键差距。

### T03 目标与判据

- **目标拆解链**：划分成果 → 分解子目标 → 建立依赖 → 分配责任 → 设置里程碑 → 校验完整。
- **阶段决断链**：汇总阶段证据 → 评估剩余价值成本风险 → 比较继续／扩大／调整／暂停／转交／终止 → 授权决定 → 记录复查条件。

### T04 计划、资源与就绪

- **预算管理链**：估算收入成本 → 分配额度 → 保留缓冲 → 批准支出 → 记录实际 → 比较偏差 → 调整。
- **时间注意力链**：盘点承诺精力 → 匹配任务强度 → 安排时段缓冲 → 减少切换 → 观察负荷 → 重排。
- **责任授权链**：明确成果 → 选择负责人 → 说明权责边界 → 配资源权限 → 约定报告升级 → 确认接手。
- **执行准备链**：确认任务 → 检查前置 → 补能力权限 → 准备环境工具数据 → 演练检查 → 启动／补齐／暂停。

### T05 风险、证据与合规

- **证据管理链**：明确待证主张 → 收集证据 → 记录来源方法语境 → 评价可信度 → 关联主张 → 保留反证未知 → 受控存取。
- **追溯管理链**：定义追溯对象 → 建立来源—决定—版本—结果关系 → 分配稳定标识 → 校验断点 → 支持正反向查询。
- **合规伦理审查链**：识别规则与受影响者 → 检查合法正当公平 → 评估隐私安全伤害 → 增加控制 → 授权决定 → 留证复查。

### T06 信息与知识

- **被动信息自动采集链**：登记信息源与授权范围 → 定义采集对象、频率、时间窗、保留期和失败策略 → 定时／事件触发采集 → 清洗解析 → 标注来源、时间、版本和对象 → 完全／近似去重与聚类 → 记录采集状态 → 送入待发现池。
- **主动信息发现链**：读取新输入＋历史状态基线 → 按主题／事件／实体聚类 → 比较时间线、版本、频率和关系 → 识别新增／变化／异常／机会／风险／冲突／弱信号 → 初核来源可信度 → 估计潜在影响和领先时间价值 → 形成候选主动信息 → 进入主动信息路由／C23。
- **信息注意力分流链**：信息出现 → 快速识别主题来源 → 判断相关性、重要性、新颖度、可信度、紧迫性、潜在价值与处理成本 → 对照可用个人／项目上下文 → 忽略／扫读／暂存／探索／深入处理。
- **信息检索链**：明确问题／探索方向 → 规划关键词与范围 → 选择来源 → 搜索采集 → 扩展线索 → 记录出处 → 判断充分。
- **主动研究雷达链**：选择目标／领域／项目／公司／文章／关键词作为种子 → 提取关键问题与知识缺口 → 生成关键词、主题、来源、人物、公司与项目图谱 → 追溯一手公开来源 → 扩展论文／代码／文档／访谈／招聘／Beta 等线索 → 识别弱信号与方向变化 → 评估覆盖度、边际信息价值、时间和预算 → 继续／停止／转持续观察 → 更新研究地图与队列。
- **信息筛选链**：汇总资料 → 初筛相关性 → 判断质量时效 → 分层排序 → 排除低值重复 → 保留理由。
- **数据采集链**：定义问题指标 → 选择来源方法 → 采集样本 → 校验质量 → 清洗标注 → 保存交付。
- **知识原子化与关系判定链**：解析材料 → 提取概念／事实／命题／机制／方法／证据／案例／反例／边界 → 统一术语 → 召回已有知识 → 判定重复／改写／支持／补充／冲突／反例／替代／新证据／新边界／新结论 → 合并或建关系。
- **知识增量与价值分流链**：读取知识基线 → 提取真正新增／变化／冲突部分 → 评价当前、近期、未来、条件触发与探索价值＋注意力成本 → 立即处理／随用随查／近期／未来／观察／归档／跳过。
- **阅读调度链**：读取材料结构＋已有知识覆盖＋价值时域 → 估计阅读收益与成本 → 标记人工精读／略读／AI 代读／随用随查／未来再读／跳过 → 生成阅读顺序和重点 → 随需求变化重排。
- **知识加工链**：阅读／解析 → 拆解提取 → 统一术语 → 归类关系 → 对比冲突 → 压缩表达 → 保留来源边界。
- **知识建模链**：识别概念 → 建立分类与关系 → 解释机制 → 补充证据、例证、反例和边界 → 标注争议版本 → 发布更新。
- **知识消费路由链**：识别知识类型与用途 → 判断使用主体〔人／AI／Agent／组织〕、频率、实时性、风险与复用需求 → 选择〔个人学习／临时上下文／Wiki／RAG／AI Skill／Workflow／SOP／未来知识池〕→ 转入对应加工与验证链。
- **知识索引与 RAG 链**：确定查询／消费端 → 建全文、语义、元数据和关系索引 → 查询理解 → 混合召回 → 重排 → 上下文预算与压缩 → 组装来源和最小充分上下文 → 回答／执行 → 检查引用、召回遗漏和错误命中 → 调整索引／切分／重排策略。
- **知识增量维护链**：检测新资料、需求或环境变化 → 召回受影响知识／Wiki／索引／Skill／Workflow → 判定新增／补充／冲突／替代／过时 → 局部更新标准知识和关系 → 重建受影响索引／页面 → 必要时回归测试 Skill／Workflow → 发布／回退 → 记录版本和重新激活条件。
- **主动信息路由链**：候选信息 → 匹配当前任务、问题、角色、兴趣、长期方向、历史关注、风险和未来触发条件 → 判断影响、紧迫性、行动性、领先性与打断成本 → 立即提醒／任务时注入／周期简报／条件触发／静默更新／授权后的低风险自动动作／丢弃 → 收集实际使用反馈。
- **试错情报链**：明确待避免的失败成本 → 搜索相似项目与实践者 → 追溯一手公开信息 → 重建假设、用户、产品、技术、商业模式和团队的尝试／失败／转向时间线 → 聚合招聘、代码、论文、文档、Beta、访谈等弱信号 → 提取失败原因、约束、反例和有效条件 → 与自身条件比较 → 避坑项／前置验证项／风险项／可借鉴项／持续观察项。

### T07 问题、方案与验证

- **问题拆解链**：选择维度 → 分解子问题 → 检查重叠遗漏 → 标注依赖 → 确定关键问题。
- **假设验证链**：提出假设 → 定义可检验预测 → 设计验证 → 收集结果 → 排除替代解释 → 接受／修正／否定。
- **方案生成链**：明确目标约束 → 寻找机制先例 → 生成多方案 → 补保底与退出方案 → 筛除不可行项。
- **概念设计链**：理解需求 → 提出核心概念 → 描述场景 → 设计结构机制 → 明确取舍 → 形成方案。
- **原型试验链**：选择关键假设 → 制作最小原型 → 设计测试 → 收集行为反馈 → 判断 → 修改／推进／停止。

### T08 创造、生产与发布

- **创意形成链**：收集问题素材 → 发散联想 → 重组变异 → 生成构想 → 初筛价值可行性 → 保留候选。
- **生产完善链**：确认规格 → 组织资源 → 制作初版 → 编辑校验 → 修复缺陷 → 质量复核 → 形成成品。
- **发布迭代链**：确认上线与回退条件 → 发布 → 确认可达可用 → 监测反馈 → 排定改进 → 更新版本。

### T09 执行控制与变更

- **记录管理链**：盘点记录 → 分类命名 → 设置位置权限保留期 → 建立索引 → 备份保护 → 定期清理迁移。
- **状态预警链**：选择领先指标 → 定义阈值趋势组合 → 持续观察 → 过滤噪声 → 分级通知 → 确认响应 → 调整规则。
- **变更控制链**：提出变更 → 说明原因范围 → 评估价值影响风险 → 批准／拒绝 → 更新基线版本 → 通知迁移 → 验证回退。

### T10 验证、移交与收尾

- **验证确认链**：明确规定要求与真实用途 → 设计证据 → 验证符合要求 → 确认满足情境 → 处理差异 → 形成双重结论。
- **完成收尾链**：确认验收 → 关闭遗留 → 结清资源责任 → 通知相关方 → 归档证据 → 正式结束。

### T11 沟通、协商与关系

- **表达确认链**：明确目的对象 → 组织事实意图请求 → 选择方式时机 → 表达 → 接收回应 → 复述确认 → 记录共识。
- **倾听理解链**：创造可表达条件 → 完整倾听 → 区分事实情绪判断需要 → 追问 → 复述 → 请对方确认。
- **请求回应链**：说明情境需要 → 提出具体请求 → 明确责任期限边界 → 对方评估 → 接受／拒绝／反建议 → 确认动作。
- **冲突协商链**：暂停对抗 → 分离人与问题 → 澄清事实立场利益底线 → 生成选项 → 比较交换 → 协议／升级。
- **会议决议链**：明确目的 → 准备议题证据 → 邀请必要角色 → 限时讨论 → 决定 → 指定责任期限 → 记录跟进。
- **授权监督链**：定义成果边界 → 选择承接者 → 配权力资源 → 约定检查升级 → 放手执行 → 监督例外 → 验收调整。
- **关系维护链**：识别目标期望 → 保持真实互动 → 履行承诺互惠 → 尊重边界 → 修复破损 → 定期重评。

### T12 评估、学习与改进

- **效果价值链**：定义预期变化 → 建立基线对照 → 测量结果副作用 → 分析贡献 → 比较成本风险分配 → 决定延续。
- **持续改进链**：建立基线 → 选择瓶颈 → 提出小改动 → 试验测量 → 比较净效果 → 标准化／撤回 → 下一轮。
- **掌握状态管理链**：明确表现目标 → 评估已有掌握 → 标记未见／见过／理解／可回忆／可应用／可迁移／熟练 → 识别能力缺口 → 选择内化／随用随查／AI 委托 → 训练或配置调用路径 → 根据真实表现更新状态。
- **理解建构链**：激活旧知 → 接触信息 → 解释含义机制 → 建联系结构 → 生成例子反例 → 自我解释检查。
- **记忆巩固链**：选择关键内容 → 深度编码 → 主动回想 → 间隔复习 → 交错辨别 → 根据遗忘调整。
- **练习反馈链**：定义表现目标 → 拆技能 → 设计递进练习 → 独立作答／操作 → 获得反馈 → 针对错误再练。
- **迁移应用链**：识别原理适用条件 → 比较新旧情境 → 选择策略 → 独立运用 → 检查结果 → 修正边界。
- **能力评估链**：定义真实任务标准 → 设计代表性测评 → 独立完成 → 收集表现证据 → 诊断缺口 → 训练／认证。
- **习惯形成链**：选择行为 → 绑定情境 → 降低启动难度 → 改造环境 → 重复记录反馈 → 处理遗漏 → 稳定重评。
- **状态调节链**：觉察状态 → 识别诱因需要 → 降低过载危险 → 休息／小行动／求助 → 观察恢复 → 调整环境。

### T13 沉淀、组织与复制

- **流程标准化链**：选择稳定做法 → 定义输入输出角色控制 → 编写标准 → 跨人试运行 → 修订批准 → 版本发布。
- **工具化自动化链**：识别重复规则 → 判断自动化边界 → 设计人机分工 → 实现测试 → 监测错误 → 回退维护。
- **AI 能力封装链**：选择稳定知识／方法 → 定义触发条件、输入、步骤、判断规则、工具、输出和异常 → 配置示例与证据 → 构造正常／边界／异常测试 → 执行验证 → 修复回归 → 发布 Skill 版本。
- **工作流编排链**：读取目标与可用 Skill／工具 → 定义状态、步骤、依赖、分支、权限、检查点、人工关口、失败回退与完成条件 → 小范围运行 → 验证整体结果 → 发布／调整 Workflow。
- **培训上岗链**：定义岗位表现 → 设计学习练习 → 示范辅导 → 独立实操 → 评估授权 → 跟踪补训。
- **组织采用链**：识别采用对象 → 对齐价值权责激励 → 配置流程工具支持 → 试点 → 收集阻力 → 扩散／撤回。
- **组织变更落地链**：明确理由与目标状态 → 识别受影响者 → 建立赞助决策权 → 设计过渡迁移回退 → 沟通参与 → 培训支持 → 分批采用 → 监测稳定。
- **扩大复制链**：验证可复制单元 → 检查容量差异 → 标准化接口 → 分批扩大 → 监测质量边际收益 → 调整上限。

### T14 异常与生命周期

- **故障恢复链**：确认恢复目标 → 隔离诊断 → 修复／回退／替代 → 验证数据功能 → 逐步恢复 → 加强监测。
- **失败重启链**：确认失败与停止状态 → 保护证据资产 → 复核价值根因条件 → 修正关键前提 → 从干净基线小范围重启 → 监测。
- **事件调查链**：保护证据 → 重建时间线 → 分析技术与系统因素 → 确认影响责任 → 提整改建议 → 跟踪验证。
- **状态维护链**：定义健康状态 → 设置周期 → 保养修补 → 验证状态 → 记录成本问题 → 继续／更新。
- **版本更新链**：收集变化 → 判断兼容影响 → 设计新版本迁移回退 → 验证 → 批准发布 → 监测采用 → 淘汰旧版。
- **扩大迁移链**：明确目标环境规模 → 盘点依赖差异 → 设计转换映射 → 分批迁移 → 验证完整可用 → 切换回退。
- **交接转移链**：盘点状态资料权限关系风险 → 选择接收者 → 讲解演练 → 补能力权限 → 接收确认 → 转移责任。
- **暂停恢复链**：决定暂停 → 保存安全状态版本 → 处理影响依赖 → 指定责任复查触发 → 重新核验 → 恢复／退出。
- **归档保留链**：确认不再活跃使用 → 整理版本元数据 → 设置权限保留期 → 安全存放 → 验证检索 → 到期处置。
- **过时淘汰链**：识别过时风险 → 调查依赖用户 → 选择替代迁移 → 通知停用 → 安全处置 → 验证无遗留。
- **重新启用链**：提出重启需要 → 复核价值时效完整权限依赖 → 补更新测试 → 重新批准 → 小范围启用 → 监测稳定。


## 五、基础链准入规则

新增一条L2基础链前必须回答：

1. 它的输入和输出是否与已有链相同？
2. 核心转化机制是否真正不同？
3. 完成标准和失败返回是否不同？
4. 差异是否只是行业、对象、角色、工具或时限？
5. 它是否只是已有链中的一个节点或三条以上链的组合？

前三项没有结构性差异时不新增L2；对象差异下沉L3/L4；由多条基础链组成时定义为组合链。
