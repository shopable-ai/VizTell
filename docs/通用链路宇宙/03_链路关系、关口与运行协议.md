# 链路关系、关口与运行协议

> **核心运行原则**：前链输出必须满足后链输入；控制链与执行并行；反馈按根因分级返回；异常优先旁路；所有循环必须有停止条件；完成后仍要决定维护、扩大、交接或退出。

## 一、三个运行平面

- **主工作面**：触发／需求／问题 → 目标方案 → 计划准备 → 执行创造 → 成果交付。
- **控制面**：记录、证据、监测、沟通、质量、风险、合规、变更、权限。
- **学习治理面**：评估、总结、复盘、学习、沉淀、标准化、版本、归档退出。

## 二、九种关系

| 关系 | 表达 | 使用条件 |
| --- | --- | --- |
| 顺序 | `A → B` | A的输出是B的合法输入 |
| 并行 | `A →〔B＋C＋D〕→ E` | 多链共享时间轴并在E汇合 |
| 条件 | `判断 → 路径甲／乙／丙` | 根据关口结果选择不同路线 |
| 循环 | `执行 → 检查 → 调整 → 再执行` | 有明确改进目标和停止条件 |
| 调用 | `母链 →〈调用子链〉→ 返回母链` | 子链有独立输入输出 |
| 阶段门 | `阶段成果 → 授权评审` | 高成本、不可逆、跨责任边界 |
| 升级 | `超出权限／风险阈值 → 上移` | 当前角色不能合法处理 |
| 旁路 | `重大异常 → 应急恢复 → 重入主链` | 安全和止损优先于原计划 |
| 递归 | `组织目标 → 部门 → 团队 → 个人` | 同一链作用于不同层级对象 |

## 三、典型并行束

**执行控制束**：执行任务 →〔记录事实＋监测进度＋沟通接口＋检查质量＋跟踪风险合规〕→ 汇总状态 → 继续／纠偏／暂停

**方案研究束**：明确决策 →〔收集证据＋生成方案＋评估风险＋征求相关方意见〕→ 汇总候选 → 比较选择

**产品实现束**：确认规格 →〔设计＋开发＋内容＋运营准备＋合规检查〕→ 集成验证 → 发布

**组织落地束**：发布方法 →〔培训＋工具配置＋权限开通＋激励调整＋现场支持〕→ 就绪检查 → 采用运行

并行汇合必须满足：必要输出齐全、接口一致、冲突已解决、整合责任人明确。

## 四、十二个统一关口

1. 价值门：值得、正当、及时吗？
2. 清晰门：事项、对象、相关方和边界清楚吗？
3. 目标门：结果、标准、证据和责任明确吗？
4. 证据门：信息足以支持当前决定吗？
5. 方案门：有可接受方案、保底和退出方案吗？
6. 就绪门：资源、能力、权限、风险和合规允许开始吗？
7. 执行门：应继续、纠偏、变更、升级、暂停还是停止？
8. 验证门：成果是否符合规定要求？
9. 确认门：成果是否满足真实用途？
10. 验收门：有权者是否接受并接管成果、资料、权限和责任？
11. 价值实现门：实际效果相对成本、风险和副作用是否值得？
12. 延续门：进入继续、扩大、维护、更新、暂停、交接、归档还是淘汰？

## 五、分级返回

| 偏差 | 返回位置 | 处置 |
| --- | --- | --- |
| 动作错误、熟练度不足 | 执行／练习 | 重做、纠错、补练 |
| 质量缺陷 | 生产／质量控制 | 隔离、返工、复检 |
| 时间资源依赖失效 | 计划／资源 | 重排、补资源、缩范围 |
| 权责不匹配 | 授权／治理 | 重授权、升级、转交 |
| 假设失败 | 假设／方案 | 修改机制、换方案、停止 |
| 方案无效 | 方案／决策 | 生成替代、重新选择 |
| 标准失真 | 标准设定 | 重定义指标、阈值、证据 |
| 目标错误 | 目标／价值 | 调整范围期限、取消目标 |
| 需求误解 | 需求澄清 | 重新还原场景和价值 |
| 环境突变 | 触发定向 | 重判整个事项 |
| 风险已发生 | 异常响应 | 安全止损、恢复调查 |
| 对象过时 | 更新／淘汰 | 迁移依赖、归档停用 |

采用“最小充分返回”：能在执行层修复不重开目标；根因在目标层也不能靠加班掩盖方向错误。

## 六、十二条组合纪律

1. 输出对接：前链输出必须满足后链输入。
2. 最小闭环：至少包含定向、行动、检查和处置。
3. 先门后投入：先过价值与可行性门。
4. 标准前置：目标、成功标准和证据尽量同时定义。
5. 风险适配：流程强度与风险、不可逆性、人数和承诺相匹配。
6. 控制并行：记录、监测、沟通、质量、风险和合规挂接执行。
7. 并行有汇合：明确接口、同步点和整合责任。
8. 事件切换：风险发生后立即从风险管理切换异常响应。
9. 反馈分流：先核验，再进入观察、纠偏、问题解决或改进。
10. 循环有界：规定预算、期限、次数、升级点和停止条件。
11. 经验需验证：跨人员或跨场景复现后才能标准化。
12. 生命周期完整：创建长期资产时同时定义维护、版本、归档和淘汰。
