# 链路关系、关口与运行协议

> **核心原则**：链路宇宙不是把步骤堆成一条长流水线，而是让不同状态转化可以顺序、并行、分支、返回、循环和退出。复杂任务的关键不是增加更多控制字段，而是确保“目标—研究—方案—执行—评价”之间真的能衔接。

## 一、三个运行平面

- **主工作面**：触发／需求／问题 → 目标与标准 → 研究和方案 → 计划 → 执行 → 成果。
- **控制面**：按需要挂接记录、监测、沟通、质量、风险、合规和变更。
- **学习与生命周期面**：评估、反馈、总结、复盘、沉淀、维护、扩大、迁移和退出。

三个平面并不要求每件小事都完整展开。低风险事项可以极简；复杂项目才展开更多链路。

## 二、九种基本关系

| 关系 | 表达 | 什么时候使用 |
| --- | --- | --- |
| 顺序 | `A → B` | A 的输出是 B 的有效输入 |
| 并行 | `A →〔B＋C〕→ D` | 多项活动可以同时推进，最后需要汇合 |
| 条件 | `判断 → 甲／乙／丙` | 不同条件进入不同路径 |
| 循环 | `执行 → 检查 → 调整 → 再执行` | 有新结果可以用于改进下一轮 |
| 调用 | `母链 →〈子链〉→ 返回` | 中途临时需要另一种独立转化 |
| 返回 | `发现根因 → 返回上游` | 下游问题来自上游错误 |
| 阶段门 | `阶段成果 → 判断 → 继续／返回／停止` | 下一步投入明显增加或方向可能改变 |
| 旁路 | `异常 → 止损恢复 → 重入主链` | 正常流程已经不适合处理当前事件 |
| 递归 | `大目标 → 子目标 → 更小目标` | 同一种链在不同层级重复使用 |

## 三、几个容易遗漏的组合束

### 1. 目标与拆解束

> 明确价值 → 设目标和完成标准 → 看现状和差距 → 拆阶段成果 → 拆子问题和依赖 → 判断哪些必须先解决

目标拆解不是单纯列任务。任务应该来自成果和问题，而不是为了“看起来有计划”而罗列。

### 2. 方案研究束

> 明确要解决什么 →〔找事实＋找已有产品／工具／项目／方法＋找成功案例＋找失败案例＋必要时咨询实践者〕→ 形成候选方案 → 标记未知和假设 → 决定补证、试验或直接比较

这一束解决的是“不要默认自己从零发明解决方案”。

### 3. 多方案比较束

> 多个结构不同的方案 → 明确必须条件 → 比较预期效果、所需资源、时间、难度、长期负担、风险、可逆性和机会成本 → 找关键未知 → 必要时先试 → 选择／组合／暂缓／放弃

比较维度按场景选择，不要求所有事情都使用统一打分表，更不能制造虚假的精确分数。

### 4. 失败预演束

> 假设方案失败 → 倒推可能原因 → 查历史失败和反例 → 识别早期信号 → 判断能否规避、缓解、转移或接受 → 必要时修改方案

失败研究服务于更好的决定，不是为了无限寻找风险。

### 5. 执行控制束

> 执行 →〔必要记录＋进度监测＋沟通＋质量检查＋风险观察〕→ 汇总实际状态 → 继续／纠偏／返回上层／暂停

### 6. 经验借力束

> 识别高试错成本或高隐性经验问题 → 找真正做过的人 → 收集经验、边界和失败条件 → 与其他事实交叉核对 → 吸收到方案或试验 → 观察实际结果

咨询结果是输入，不自动成为事实、标准或最终决定。

## 四、十二个通用关口

1. **价值门**：值得处理吗？现在值得吗？
2. **清晰门**：对象、场景、问题或需求是否足够清楚？
3. **目标门**：要达到什么状态，怎样算完成？
4. **现状门**：对当前状态、差距和限制了解得足够吗？
5. **研究门**：是否已经知道足够的信息、已有解法和关键未知？
6. **方案门**：是否存在至少一个可接受方案，是否需要更多方案或试验？
7. **决策门**：为什么选择这个方案，哪些假设仍然存在？
8. **就绪门**：近期行动所需资源、责任和关键前置是否具备？
9. **执行门**：继续、调整、返回上游、暂停还是停止？
10. **验收门**：成果是否符合要求、满足用途并被正确接收？
11. **价值实现门**：实际效果相对投入、风险和副作用是否值得？
12. **延续门**：继续、扩大、维护、迁移、暂停、交接、归档还是淘汰？

关口是判断问题，不是额外审批表。低风险事项可以由同一人快速判断；高风险事项才需要正式证据和授权。

## 五、分级返回

| 发现的问题 | 优先返回 | 典型处理 |
| --- | --- | --- |
| 动作做错 | 执行 | 修正动作、补练、重做 |
| 质量不合格 | 质量／执行 | 隔离、返工、复检 |
| 任务顺序或依赖不对 | 计划 | 重排任务和检查点 |
| 资源不足 | 资源／优先级 | 补资源、缩范围、延后或放弃低优先项 |
| 关键事实不足 | 研究 | 补资料、核查来源、咨询或小试 |
| 假设失败 | 方案／研究 | 改假设、换方案或停止 |
| 方案不合适 | 决策 | 重新生成或比较方案 |
| 完成标准失真 | 标准 | 重定义标准和证据 |
| 目标本身错误 | 目标／价值 | 改目标、转向或终止 |
| 需求理解错误 | 需求澄清 | 重新还原真实场景 |
| 环境发生重大变化 | 触发与定向 | 重新判断整件事 |
| 风险已经发生 | 异常恢复 | 先安全、止损和恢复，再调查 |

采用“最小充分返回”：能在最近一层修好就不要推翻全部；根因在上游时也不要用更多下游动作掩盖方向错误。

## 六、十二条组合纪律

1. **先结果后动作**：先知道要产生什么，再决定做什么。
2. **先理解后拆任务**：需求、目标或问题不清时，不批量制造任务。
3. **大任务先拆成果和问题**：不是只拆动作。
4. **先看已有解法**：复杂问题默认检查外部已有知识、产品、工具、项目、服务和经验。
5. **多方案要有真实差异**：不能只是改措辞形成伪方案。
6. **关键未知优先验证**：只验证会显著改变决定的未知。
7. **研究有停止点**：信息足以支持当前决定时可以保留剩余未知；具体时间和费用限制属于具体工作流配置，不是通用链本体。
8. **执行控制按需挂接**：风险越低，控制越轻；不把所有生活和工作强制工程化。
9. **反馈按根因返回**：动作、计划、方案、目标和需求是不同返回层。
10. **异常切换路径**：已经发生的严重事件优先恢复，不继续按普通计划推进。
11. **评估贯穿前中后**：立项、方案、执行、验收和长期效果都可能触发评估。
12. **生命周期完整**：长期对象创建时就要允许未来维护、更新、迁移、暂停、交接和退出。

## 七、链路卡运行模板

> **触发**：什么情况进入本链  
> **输入**：必须已经知道或具备什么  
> **状态转化**：本链把什么状态变成什么状态  
> **核心步骤**：A → B → C  
> **判断关口**：什么情况下继续、返回、切换或停止  
> **输出**：交给下一链的结果  
> **完成标准**：怎样算这条链结束  
> **典型返回**：失败时回哪里  
> **常见组合**：通常与哪些链一起出现

角色、软件、参数、预算、审批表和具体阈值只有在真实 L4 工作流确有需要时再补充，不作为通用链卡的默认组成。
