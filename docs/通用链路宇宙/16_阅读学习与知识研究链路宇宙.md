# 阅读学习与知识研究链路宇宙

> **核心主链**：**信息／信号进入〔人工遇见＋被动自动采集〕→ 主动发现新增／变化／异常／机会／风险 → 注意力分流 → 明确问题／用途／探索方向 → 读取已有知识与需求状态 → 搜索／主动研究 → 原子化与关系判定 → 提取高价值知识增量 → 按当前／近期／未来／条件触发／探索价值分流 →〔人工阅读学习／Wiki／RAG／AI Skill／Workflow／SOP／未来知识池〕→ 验证使用 → 更新知识、掌握、AI 能力与需求状态 → 持续监测、增量维护、归档或淘汰**。

## 一、本文件的职责与边界

本文件承担阅读、学习、研究、大量资料知识增量、主动信息和主动研究的 **L3 场景组合**。C23 信息处理链和 C24 个人学习链仍是 L2 的正式定义；本文件说明它们与信息采集、主动发现、Wiki／RAG、AI Skill、Workflow、主动研究雷达和试错情报怎样组合。

同一份信息需要区分至少四类状态：

- **外部知识状态**：资料是否已解析、原子化、核验、结构化、更新或过时；
- **个人掌握状态**：人是否理解、能回忆、能应用和迁移；
- **AI 能力状态**：知识是否可检索、可进入 RAG、已封装 Skill、已通过测试或已进入 Workflow；
- **需求状态**：当前、近期、中期、长期、条件触发、探索或暂无需求。

M0 人工、M1 AI 辅助、M2 AI 原生三种模式共享相同语义链。OCR、哈希、MinHash、SimHash、Embedding、具体向量数据库、抓取器和阈值属于 L4 工具配置；本文件描述的是输入、状态转化、判断、分流、验证和更新机制。

## 二、AI 原生信息与知识体系：八个一级系统

| 一级系统 | 主要解决的问题 |
| --- | --- |
| **A 信息入口与注意力** | 每天大量消息、新闻、文章、视频和工具变化中，哪些值得进入后续处理 |
| **B 知识加工与增量** | 大量同类资料中，什么是重复、改写、证据、边界、冲突、替代和真正新知识 |
| **C 人类阅读与学习** | 人应该精读什么、略读什么、什么时候练习，怎样形成真实能力 |
| **D AI 知识与能力** | 哪些知识应进入上下文、RAG、Skill 或 Workflow，怎样验证 AI 真正可用 |
| **E 知识基础设施** | Raw Source、标准知识、Wiki、知识图谱、索引和 RAG 怎样分层协作 |
| **F 主动信息与主动研究** | AI 怎样持续接收外部变化、主动发现价值信息，并从种子信息向外扩展研究 |
| **G 前沿、弱信号与试错情报** | 怎样提前发现项目方向变化、未发布尝试、失败经验和可避免的重复试错 |
| **H 验证与生命周期** | 知识、来源、Skill 和 Workflow 怎样验证、更新、替代、归档和重新激活 |

## 三、七种主要入口场景

### 1. 偶然看到一条信息

> **信息出现 → 快速识别主题和来源 → 判断相关性、重要性、新颖度、可信度、紧迫性、潜在价值和处理成本 → 忽略／扫读／暂存／探索／深入处理**

这个入口不要求先存在明确目标。可使用当前任务、问题、角色、兴趣、长期方向、历史关注、已有知识和风险等可用上下文；同时保留探索入口，避免只看已经知道自己需要什么的信息。

### 2. 被动信息自动监测

> **登记信息源和权限 → 设定范围、频率、保留期与失败处理 → 自动采集 → 清洗解析 → 标注来源／时间／版本 → 去重聚类 → 进入待发现池 → 与历史状态持续比较**

适用于 RSS、邮件、网页、新闻、GitHub、论文、产品文档、招聘、价格、版本、公司动态和其他授权数据源。目标不是把所有内容推给人，而是把世界变化稳定送入后续“主动信息发现”。

### 3. 一篇文章

> **判断是否值得进入 → 扫描结构 → 提取主张、机制、条件、证据、例子和反例 → 对照已有知识 → 判断重复／新增／冲突／过时／未知 → 决定忽略／收藏／核查／深读／学习／应用／归档**

### 4. 单本书

> **是否值得读 → 预读结构 → 映射已有知识 → 划分人工精读／略读／AI 代读／随用随查／未来再读／跳过 → 提取知识单元 → 与旧知和同类资料比较 → 学习真正需要内化的部分 → 更新知识和掌握状态**

阅读强度由知识差额、需求时域和注意力成本决定，不由页数决定。

### 5. 围绕问题的多资料研究

> **定义研究问题 → 建知识基线 → 搜不同来源 → 分层证据 → 提取主张和条件 → 对比来源 → 处理冲突与未知 → 建解释模型 → 找反例和边界 → 形成阶段结论 → 根据边际信息价值继续／停止／转观察**

### 6. 本地大量资料／书库

> **盘点文件和版本 → 解析并保留来源定位 → 切分知识单元 → 完全重复检测 → 近似／语义候选召回 → 命题关系判断 → 知识增量判断 → 价值时域分流 → 生成阅读／RAG／Skill 队列 → 抽样复核 → 新资料增量更新**

重点是识别真正新增的机制、条件、证据、反例、时效信息和个人未掌握部分。

### 7. 领域／项目／公司主动研究

> **选择目标、领域、项目、公司、文章或高价值关键词作为种子 → 提取关键问题和知识缺口 → 生成关键词、主题、来源、人物、公司和项目图谱 → 追溯一手公开来源 → 扩展论文、代码、文档、访谈、招聘、Beta 等线索 → 重建时间线和弱信号 → 评估边际信息价值、覆盖度与预算 → 继续／停止／转持续观察**

这个场景把“用户主动搜索”升级为“AI 主动研究雷达”。

## 四、主动信息系统

### 4.1 被动信息自动采集链

> **登记信息源与授权范围 → 定义采集对象、频率、时间窗、保留期和失败策略 → 定时／事件触发采集 → 清洗解析 → 标注来源、时间、版本和对象 → 完全／近似去重与聚类 → 记录采集状态 → 送入待发现池**

**输出**：带来源、时间、版本和主题归属的标准化新输入流。

**完成标准**：高价值来源能稳定进入系统；重复和采集故障可识别；采集行为不越过授权、隐私与合规边界。

### 4.2 主动信息发现链

> **读取新输入＋历史状态基线 → 按主题／事件／实体聚类 → 比较时间线、版本、频率和关系 → 识别新增／变化／异常／机会／风险／冲突／弱信号 → 初步核验来源可信度 → 估计潜在影响和领先时间价值 → 形成候选主动信息 → 进入主动信息路由／C23**

**输出**不是“今天抓到了多少消息”，而是“哪些状态发生了值得关注的变化”。

### 4.3 主动信息路由链

> **候选主动信息 → 匹配当前任务、问题、角色、兴趣、长期方向、历史关注、风险和未来触发条件 → 判断价值、紧迫性、行动性、领先性和打断成本 → 立即提醒／任务时注入／周期简报／条件触发／静默更新／低风险自动动作／丢弃 → 收集实际使用反馈**

### 4.4 注意力防火墙

| 级别 | 默认处理 |
| --- | --- |
| **P0 立即打断** | 安全、重大损失、关键截止、重大异常或高时效机会 |
| **P1 当前任务注入** | 与正在执行的任务直接相关，但无需单独打断 |
| **P2 日报／短周期简报** | 有价值但不紧急的信息和变化 |
| **P3 周报／探索池** | 趋势、前沿、未知机会和中长期价值 |
| **P4 静默更新** | 只更新 Wiki／RAG／知识关系／监测状态，不占人的注意力 |
| **P5 丢弃** | 低价值重复、噪声、不可验证或无保留价值的信息 |

注意力预算至少分为：**当前任务预算＋近期学习预算＋探索预算＋风险通道**。探索预算独立存在，防止系统只强化既有兴趣和目标。

### 4.5 主动信息卡

高价值主动信息优先输出为统一决策入口：

> **发生了什么 → 相对已有状态新在哪里 → 为什么与你有关 → 影响和紧迫程度 → 可信度／来源 → 建议动作 → 是否需要人工阅读原文 → 关联任务／项目／知识／Skill／Workflow → 下一复查条件**

低风险且已有授权的变化可自动进入静默更新、验证或维护动作；高风险、不可逆、费用、外部发送、权限变更等动作进入人工关口。

## 五、文章进入链

### 5.1 快速筛选

> **为什么看到它 → 与可用上下文是否相关 → 作者／来源是否值得初步信任 → 是否存在明确主张、证据、新颖性或潜在影响 → 是否值得继续投入 → 忽略／稍后／探索／深读**

### 5.2 内容提取

将重要内容尽量整理为：

> **概念／对象 → 核心主张 → 作用机制 → 成立条件 → 适用范围 → 证据 → 例子／反例 → 结论／行动含义**

### 5.3 与旧知比较

> **找到对应旧知识 → 判断重复／改写／包含／扩展／支持／冲突／替代／无关 → 检查新机制、新边界、新证据、新反例和新时效信息 → 更新知识模型**

### 5.4 去向决定

- 没有价值增量：忽略或仅累计来源／频率；
- 有新证据：挂到原知识节点；
- 有新边界或反例：修改适用条件；
- 有冲突：进入核查；
- 有真正新知识：进入价值时域和消费路由；
- 暂时无法判断：进入待核查；
- 当前不需要但未来有价值：进入未来知识池并设置条件触发。

## 六、单本书 T0—T7 阶段链

### T0：选择与调度

> **当前／近期／未来需求＋探索价值 → 书的主题、作者、版本和证据质量 → 与已有知识重叠预估 → 阅读收益与注意力成本 → 人工精读／略读／AI 代读／随用随查／未来再读／跳过**

### T1：预读

> **目录 → 序言 → 结论 → 索引／摘要 → 核心问题 → 作者整体结构 → 形成阅读地图**

### T2：映射已有知识

> **章节主题 → 对照已有知识和掌握状态 → 已知／不确定／未知／需更新 → 必读／选读／AI 代读／跳过 → 设章节问题**

### T3：章节阅读与提取

> **带问题阅读／AI 解析 → 找主张、机制、条件、证据、例子和反例 → 形成知识单元 → 保留原始定位**

### T4：比较与增量判断

> **与旧知／同类书比较 → 重复／改写／扩展／支持／冲突／替代／新增 → 检查时效和适用边界 → 更新知识模型**

### T5：人的主动回想与练习

> **选择必须内化内容 → 合上资料 → 回想核心结构 → 解释原因机制 → 辨别相似概念 → 解决练习／案例 → 暴露理解和记忆缺口 → 返回补学**

### T6：真实迁移

> **选择真实问题／项目 → 判断何时适用 → 独立使用方法 → 观察结果 → 获取反馈 → 修正理解和边界**

### T7：延迟复查与生命周期

> **间隔一段时间／触发新需求 → 再次回想／应用／检索 → 检查遗忘、过时、新证据和替代关系 → 保留／更新／重新学习／重新激活／归档／淘汰**

## 七、四种阅读与使用模式

### 筛选式阅读

> **预读 → 定位新内容 → 只读高价值部分 → 更新知识关系 → 结束**

### 问题式阅读

> **问题 → 所需证据／机制 → 定位相关章节 → 提取 → 对比 → 支持决定／行动 → 停止**

### 能力式阅读

> **表现目标 → 理解 → 回想 → 练习 → 反馈 → 真实应用 → 迁移 → 延迟验证**

### AI 使用式处理

> **确定任务 → 检索相关知识 → 组装最小充分上下文 → 调用规则／Skill／工具 → 验证结果 → 更新调用与能力状态**

一本书或资料集可以同时采用多种模式；“人是否要学”和“AI 是否要能用”是两条不同路线。

## 八、多资料去重与知识增量链

### 8.1 建立基线

> **研究问题／知识地图／探索方向 → 已有知识节点和版本 → 已验证／争议／过时／被替代 → 个人掌握与 AI 可用状态 → 形成当前基线**

### 8.2 资料盘点与解析

> **盘点文件 → 识别版本／格式／语言／质量 → 解析或 OCR → 保留文件、页码、章节和原始位置 → 切成章节／段落／命题级单元 → 建稳定标识**

### 8.3 七层判断

1. **文件完全重复**；
2. **文本完全重复**；
3. **文字近似重复**；
4. **语义相似候选**；
5. **命题关系**：重复、改写、包含、扩展、支持、冲突、反例、替代或无关；
6. **知识增量**：新机制、新条件、新范围、新证据、新反例、新版本或新时效信息；
7. **消费差额**：人是否需要内化、AI 是否需要检索／Skill 化、组织是否需要 SOP 化。

语义相似只负责召回候选，不直接授权删除、合并或替代。

### 8.4 代表项和来源关系

> **选最完整、最清楚或最权威的标准知识项 → 其他来源挂支持／反例／边界／冲突／替代关系 → 保留原始来源定位 → 维护来源独立性和可信度**

### 8.5 生成差额队列

> **知识模型 − 已有状态 → 待核查／新增／变化／冲突知识 → 按需求时域、潜在影响、基础依赖、使用频率和注意力成本排序 → 生成阅读／RAG／Skill／观察队列**

## 九、知识基础设施：从原始资料到 AI 能力

| 层级 | 核心对象 | 主要作用 |
| --- | --- | --- |
| **L0 Raw Source 原始资料层** | PDF、EPUB、Markdown、网页、视频字幕、代码、邮件、日志、原始数据 | 原文回溯、重新解析、证据核验 |
| **L1 Canonical Knowledge 标准知识层** | 去重后的概念、命题、机制、方法、证据、案例、反例、边界、版本 | 形成稳定知识资产和关系基线 |
| **L2 Wiki／知识图谱层** | 主题页、实体、关系、时间线、来源、项目／人物／公司图谱 | 人和 Agent 浏览整体结构、追踪关系和演化 |
| **L3 检索／RAG 层** | 全文、语义、元数据、关系索引、重排和上下文预算 | 在任务发生时找到最小充分知识并保留来源 |
| **L4 Skill／Workflow 层** | Skill、工具、规则、状态机、分支、权限、测试 | 把稳定知识升级为可重复执行能力 |

### 9.1 知识索引与 RAG 链

> **确定查询／消费端 → 建全文、语义、元数据和关系索引 → 查询理解 → 混合召回 → 重排 → 上下文预算与压缩 → 组装来源和最小充分上下文 → 回答／执行 → 检查引用、召回遗漏和错误命中 → 调整索引／切分／重排策略**

RAG 的完成标准不是“向量库里已经有数据”，而是代表性查询能稳定召回正确知识、遗漏和错误命中可测、最终结果可回到来源。

### 9.2 知识增量维护链

> **检测新资料、需求或环境变化 → 召回受影响知识／Wiki／索引／Skill／Workflow → 判定新增／补充／冲突／替代／过时 → 局部更新标准知识和关系 → 重建受影响索引／页面 → 必要时回归测试 Skill／Workflow → 发布／回退 → 记录版本和重新激活条件**

## 十、统一状态体系

| 对象 | 建议状态 |
| --- | --- |
| **资料状态** | 未处理 → 已采集 → 已解析 → 已提取 → 已入知识模型 → 已核查／待核查 → 更新／过时／归档 |
| **知识状态** | 待验证 → 已验证 → 有争议 → 过时 → 被替代 → 归档／重新激活 |
| **个人掌握状态** | 未见 → 见过 → 理解 → 可回忆 → 可辨别 → 可应用 → 可迁移 → 熟练 |
| **AI 能力状态** | 未索引 → 可检索 → RAG 可用 → 已 Skill 化 → 测试通过 → Workflow 可用 → 退化／弃用 |
| **需求状态** | 当前 → 近期 → 中期 → 长期 → 条件触发 → 探索 → 暂无需求 |
| **来源状态** | 未核验 → 二手线索 → 一手来源 → 多源交叉 → 高可信／争议／失效 |

状态变化是增量更新和主动信息触发的重要输入。例如“未来知识池”中的内容在项目进入对应阶段后应重新评分，而不是永久沉睡。

## 十一、主动研究、弱信号与试错情报

### 11.1 主动研究雷达

> **种子目标／文章／项目／公司 → 关键问题和知识缺口 → 高价值关键词 → 来源／人物／公司／项目图谱 → 一手来源追溯 → 扩展论文、代码、招聘、产品文档、Beta、访谈和社区线索 → 弱信号聚合 → 更新研究地图 → 评估覆盖度、边际信息价值、时间和预算 → 继续／停止／观察**

### 11.2 来源追溯

> **二手信息 → 找引用对象 → 找原作者／原项目 → 找原始数据、代码、论文、文档或访谈 → 记录来源链、时间和独立性 → 多源交叉验证 → 更新可信度**

二手来源主要承担发现、解释和关联；事实核验优先回到一手公开来源或独立证据。

### 11.3 弱信号

重点关注正式产品和市场共识形成前已经公开出现的变化，例如：

> **招聘变化／GitHub commit 和 issue／论文与专利／技术博客／创始人和员工访谈／产品文档变化／Beta／合作伙伴／定价／社区反馈／停更／方向切换**

弱信号需要按时间线和实体关系聚合，单一信号不直接等于结论。

### 11.4 试错情报链

> **明确待避免的失败成本 → 找相似项目与实践者 → 重建假设、用户、产品、技术、商业模式和团队的尝试／转向时间线 → 提取失败原因、限制、反例、有效条件和后续调整 → 与自身条件比较 → 形成避坑项／前置验证项／风险项／可借鉴项／持续观察项 → 随新证据更新**

试错情报的价值在于把别人已经支付的时间、资金和机会成本转成自己的前置验证与避坑资产。

## 十二、评估、停止与跨链增量协议

### 12.1 核心评估指标

- 单位注意力和计算成本获得的高价值信息增量；
- 重复候选中的错误合并、漏检和来源丢失；
- 真正知识新增、新证据、新边界、新反例和冲突发现率；
- 主动信息的命中率、打断成本和后续行动价值；
- 阅读后的回想、辨别、应用和迁移表现；
- RAG 的召回正确性、遗漏、来源可追溯性和上下文成本；
- Skill／Workflow 的正常、边界、异常和回归测试通过情况；
- 新资料进入后能否低成本局部更新。

### 12.2 研究停止条件

- 已足以支持当前决定、行动或能力目标；
- 新增搜索主要产生重复或不改变模型／选择；
- 关键来源已收敛且新增独立证据的边际价值很低；
- 当前瓶颈转为练习、执行、反馈或实验，而不是知识缺口；
- 继续搜索的时间、注意力或计算成本超过预期新增价值；
- 达到预设覆盖度、预算或时间窗，转持续观察而非无限研究。

### 12.3 大规模增量处理的跨链协议

| 链 | AI 原生增量处理重点 |
| --- | --- |
| **C09 任务执行** | 可重复部分交给 Skill／Workflow，人保留高风险、异常和授权关口 |
| **C10 过程记录** | 优先记录状态变化、关键决定、证据、异常、失败和恢复点，而不是永久保存所有中间废话 |
| **C16 反馈处理** | 大量反馈先聚类、匹配已知问题、累计频率和趋势，只把新问题、异常和状态变化升级处理 |
| **C17 总结提炼** | 优先总结新增、变化、异常、决定和待办，而不是重复全量复述 |
| **C19 经验沉淀** | 与已有方法库比较，只沉淀新的机制、边界、失败模式、模板或验证证据 |
| **C22 决策选择** | 对 AI 生成的大量方案先按底层机制聚类去重，再比较真正独立路线 |
| **C23 信息处理** | 读取知识基线，只深处理高价值增量、冲突、新证据、新边界和替代关系 |
| **C30 维护更新** | 环境变化后识别受影响的知识／Wiki／RAG／Skill／Workflow，局部更新、回归验证和回退 |

## 十三、层级与去重决定

本文件不新增 C31 等核心编号：

- C23 负责信息变成可靠、结构化、可增量维护的知识；
- C24 只负责人需要真正形成的理解、记忆、练习和迁移能力；
- 被动信息自动采集、主动信息发现、信息注意力分流、阅读调度、知识消费路由、主动研究雷达、RAG、知识增量维护和试错情报作为扩展链或 L3 组合；
- AI Skill／Workflow 由 T13 的 AI 能力封装、工作流编排和 C09 执行连接；
- 效果判断用 C15，经验资产化用 C19，更新归档淘汰用 C30；
- 具体爬虫、数据库、模型、阈值和自动化平台属于 L4。

只有出现现有 C 链无法表达的新跨领域状态转化时，才重新启动核心编号准入审计。
