# 通用总链与 Level 1—3 总地图

> **本文件最重要的内容**：通用链路宇宙的重点是“状态怎样变化、链怎样组合和返回”，不是把某一种软件、Agent 或项目管理方法写成通用流程。L0 管完整生命周期，L1 用于定位功能，L2 保存稳定状态转化，L3 负责场景组合，L4 才放具体工具和参数。

## 一、一分钟找到入口

| 当前情境 | 推荐入口 |
| --- | --- |
| 一个普通待办 | 需求／结果 → 完成条件 → 执行 → 检查 → 结束 |
| 不知道事情值不值得做 | C01 触发 → C02 需求 → C03 价值排序 |
| 有目标但事情很大 | C04 目标 → C05 标准 → 目标拆解 → C06 计划；详见项目与复杂任务场景链 |
| 问题复杂、原因不清 | C20 问题定义 → 问题拆解 → C23 信息处理 → C21 原因分析 → C22 决策选择 |
| 有多种解决方式 | C23 搜集已有解法和证据 → 生成结构不同的方案 → C22 比较选择 → 必要时小试 |
| 不懂、不会或资料太多 | C23 信息处理 → C24 个人学习 → 返回真实任务；详见阅读学习场景链 |
| 多人一起完成 | C25 沟通 → C26 分工协作 → C09 执行 → C14 验收 |
| 风险已发生 | C29 异常恢复；不要继续停留在“风险可能发生”的讨论里 |
| 对象长期存在 | C30 维护、更新、迁移、暂停、交接、归档、淘汰或重启 |

## 二、三版通用总链

### 1. 八节点记忆版

> **感知 → 定向 → 规划 → 行动 → 检查 → 调整 → 学习 → 更新**

### 2. 二十节点紧凑版

> **发现信号 → 明确需要／问题／机会／任务 → 判断价值 → 排定优先 → 界定边界 → 初识现状 → 设定目标与标准 → 分析差距 → 拆解目标／问题 → 查找信息与已有解法 → 形成多方案 → 核实证据与失败条件 → 验证关键假设 → 比较并决策 → 制定计划与配置资源 → 执行〔记录＋监测＋沟通＋质量＋风险〕→ 纠偏／变更／恢复 → 提交验收 → 评估效果与价值 → 总结复盘并进入维护／扩大／迁移／暂停／交接／归档／淘汰／重启**

### 3. 完整生命周期版

> **感知需求／问题／机会／变化／任务 → 登记并判断是否值得处理 → 识别对象、相关方和真实使用场景 → 明确目标、边界、成功标准与不做事项 → 了解当前状态、关键差距、限制与未知 → 分解目标、成果和问题 → 搜集事实、知识、现有产品、工具、项目、案例、服务和实践经验 → 区分事实、观点、假设与未知 → 生成结构不同的候选方案，包括保底、替代和不做方案 → 主动寻找失败案例、限制条件和反例 → 必要时向有经验者咨询或用最小试验补足关键未知 → 比较预期效果、所需资源、时间、难度、长期负担、风险、可逆性和机会成本 → 作出决定并记录关键理由 → 将目标和方案拆为阶段成果、任务、依赖与检查点 → 配置必要时间、人员、资金、信息、工具、能力与责任 → 执行并同步记录、监测、沟通、质量和风险 → 发现偏差后判断是动作、计划、方案、目标还是需求层问题 → 返回最近的根因层纠正 → 形成成果并提交 → 验证是否符合要求 → 确认是否满足真实用途 → 由有权者验收和接管 → 评价实际效果、成本、副作用和净价值 → 总结发生了什么 → 复盘为什么 → 提炼可复用经验 → 继续、维护、扩大、迁移、暂停、交接、归档、淘汰或重新启用**

完整生命周期不是强制每次走完所有节点。简单、低风险、可逆事项可直接走最小闭环；复杂度上升时再展开中间链路。

## 三、复杂任务／项目通用组合链

这是一条高频 L3 组合，不新增 C31：

> **判断价值 → 明确目标和完成标准 → 了解现状与差距 → 拆目标／拆问题 → 找已有解法 → 生成多个方案 → 查失败与反例 → 必要时咨询实践者 → 验证最关键未知 → 比较方案 → 选择 → 拆成果与任务 → 排依赖优先级 → 配资源 → 执行 → 阶段检查 → 按根因返回 → 验收 → 效果价值评估 → 复盘沉淀 → 延续或退出**

其中几个经常被漏掉的环节：

- **目标建立**：模糊想法不能直接变成任务；先确认真实需要、价值、结果、边界和完成标准。
- **目标拆解**：先拆阶段成果、子目标和交付物，再拆任务、依赖和里程碑。
- **问题拆解**：分清事实、症状、原因假设、子问题和关键未知，再决定研究顺序。
- **找已有解法**：先确认是否已有成熟产品、开源项目、工具、服务、标准、案例或现成方法，避免默认从零开始。
- **咨询实践者**：当试错昂贵、信息难公开取得或隐性经验很重要时，用交流或咨询降低未知；咨询结果仍需结合证据判断。
- **失败研究**：不仅搜“怎么成功”，还搜为什么失败、隐藏成本、边界、反例和退出困难。
- **小试验证**：优先测试会改变方案选择的关键未知，而不是先把整个方案做完。
- **多维评估**：效果、成本、时间、学习难度、长期维护、风险、可逆性和机会成本按场景选择，不要求所有事项都做复杂评分表。

完整拆解见 [15_项目与复杂任务链路宇宙.md](15_项目与复杂任务链路宇宙.md)。

## 四、Level 0—4 分层

| 层级 | 职责 | 典型内容 | 不应承担 |
| --- | --- | --- | --- |
| L0 通用生命周期 | 描述从触发到退出的完整状态变化 | 八节点、二十节点、完整生命周期 | 工具、角色、算法细节 |
| L1 功能系统 | 帮助判断当前处于哪类活动 | 十一类运行系统 | 固定阶段顺序 |
| L2 基础链 | 完成一种稳定、跨领域复用的状态转化 | C01—C30 | 因对象、行业或工具不同而重复造链 |
| L3 场景组合链 | 把多个基础链组合成常见情境 | 项目推进、学习、决策、故障、经营 | 重新定义 C 链 |
| L4 具体工作流 | 落实到真实环境 | 人员、工具、期限、权限、表单、行业规则 | 冒充通用规律 |

## 五、十一类运行系统总地图

### L1-01 感知与定向

- C01 触发识别：信号 → 有去向的事项。
- C02 需求澄清：含混诉求 → 被确认的真实需要。
- C03 价值排序：候选事项 → 优先、延后、委派或放弃决定。
- C04 目标设定：已选事项 → 可承诺目标。
- C05 标准设定：期望成果 → 可判断的完成标准。

典型 L3：生活事项、用户需求、工作请求、机会筛选、项目立项。

### L1-02 研究与认识

- C20 问题定义：症状／偏差 → 清楚的问题。
- C23 信息处理：分散资料 → 可使用的知识模型。
- C21 原因分析：事实与现象 → 原因模型。

常用扩展动作：现状调查、问题拆解、信息检索、证据核查、已有解法搜索、案例比较、失败案例调查。

典型 L3：陌生问题研究、市场调查、多书阅读、故障诊断、经营分析。文章、单书和大量资料的完整组合见 [16_阅读学习与知识研究链路宇宙.md](16_阅读学习与知识研究链路宇宙.md)。

### L1-03 选择与验证

- C22 决策选择：多个可行动选项 → 被选择的方案和复查条件。

常用扩展动作：方案生成、假设验证、原型试验、阶段决断、专家咨询、反例检查。

典型 L3：消费决策、职业选择、产品方案、技术选型、项目路线选择。

### L1-04 计划与配置

- C06 计划制定：目标和方案 → 可启动的任务、依赖和检查点。
- C07 资源配置：需要 → 可用资源安排。
- C08 风险预案：潜在风险 → 触发器和预案。

常用扩展动作：目标拆解、成果拆解、优先级安排、时间注意力安排。

### L1-05 执行与创造

- C09 任务执行：任务 → 可提交成果。
- C12 质量控制：产物 → 质量结论和处置。
- C13 纠偏调整：偏差 → 恢复基线或升级决定。
- C14 提交验收：执行者成果 → 被接收和移交的成果。

### L1-06 沟通与协作

- C25 沟通闭环：信息／请求 → 被确认的理解和行动。
- C26 分工协作：共同目标 → 协同完成的整体成果。
- C27 组织转化：经验证经验／变更 → 被组织持续采用的能力。

### L1-07 记录与保障

- C10 过程记录：发生的事实 → 可追溯记录。
- C11 进度监测：运行状态 → 偏差和预警。
- C28 风险管理：尚未发生的不确定性 → 动态风险处置。
- C29 异常恢复：已发生重大异常 → 恢复状态和后续调查。

记录、监测、质量、风险、合规和版本属于可并行控制，不要求低风险生活事项全部启用。

### L1-08 评估与改进

- C15 评估判断：结果和证据 → 判断。
- C16 反馈处理：反馈 → 已分类并有去向的事项。
- C17 总结提炼：材料和经历 → 核心事实与结论。
- C18 复盘改进：结果 → 原因、经验和下一次改变。

### L1-09 学习与能力

- C24 个人学习：外部知识 → 能独立理解、回想、应用和迁移的能力。

典型 L3：文章学习、单书学习、问题式学习、能力式学习和项目中边做边学。详见 [16_阅读学习与知识研究链路宇宙.md](16_阅读学习与知识研究链路宇宙.md)。

### L1-10 沉淀与复制

- C19 经验沉淀：经验证经验 → 可复用方法、模板、流程或工具。
- C27 组织转化：可复用经验 → 多人可持续采用。

### L1-11 运维与退出

- C30 维护更新退出：在用对象 → 维护、更新、扩大、迁移、暂停、交接、归档、淘汰或重启状态。

## 六、高频返回关系

> **动作不对 → C09／C13**  
> **质量不对 → C12 → C09**  
> **任务计划不对 → C06**  
> **资源不够 → C07／C03**  
> **关键假设错 → 研究／验证 → C22**  
> **方案本身不合适 → C22**  
> **目标错误 → C04／C03**  
> **需求理解错误 → C02**  
> **环境已经变化 → C01 重新定向**

采用“最小充分返回”：能在最近层修好就不重新开整个流程；根因在上层时也不能靠下层继续加动作掩盖。

## 七、不要进入通用层的内容

以下内容可以重要，但通常只是 L4 实现配置：

- 某个 Agent 的 token、单轮费用、最大尝试次数或模型参数；
- 某个软件框架、数据库、编程语言或云厂商；
- 某个公司的审批表、职位名称和内部 SLA；
- 某个算法的固定阈值；
- 只适用于单一行业的法规或专有术语。

它们可以作为具体工作流的输入和约束，但不能因为“很具体”就提升为通用链路。
