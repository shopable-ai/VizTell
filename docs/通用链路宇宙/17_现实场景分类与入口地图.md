# 现实场景分类与入口地图

> **本页结论**：现实场景不是另一套基础链，也不是“生活／工作／软件／公司”等领域目录的同义词。现实场景层负责回答：**用户现在发生了什么、应该从哪条链进入、接下来通常组合哪些链。**

> **五维场景坐标**：**现实场景 = 主场景类型 × 发生领域 × 主体规模 × 复杂度／风险 × 生命周期阶段**。

> **使用主链**：**自然语言描述 → 识别主场景入口 → 标记必要的次场景 → 确定领域、主体、复杂度和生命周期 → 映射 C01—C30 入口 → 调用对应 L3 场景组合 → 按结果返回、继续或退出**。

## 一、场景分类的核心规则

1. **主场景按“当前状态和当前问题”分类**，而不是按行业、工具或对象分类。
2. **领域是第二维度**。同一个“问题场景”可以发生在健康、学习、工作、公司或软件中。
3. **一个现实事件可以同时具有多个场景标签，但只选一个主入口**。例如“项目延期”主入口是偏差场景，同时带项目场景标签。
4. **场景代码 `S01—S15` 只是导航编号，不是新的基础链编号**，不能与 C01—C30 混用。
5. **简单场景只走最小闭环**；只有复杂度、风险、参与者或生命周期要求上升时才展开更多链。
6. **领域、主体、复杂度和生命周期不产生新的基础链**，它们只改变入口、组合强度、证据和控制要求。

### 场景入口选择原则

当一句话同时命中多个场景时，优先选择**当前最需要改变的状态**作为主入口：

> **发生了什么 → 现在卡在哪里 → 下一步必须得到什么结果 → 选择主场景入口**

例如：

- “我有个 AI 软件想法，不知道值不值得做” → 主场景 S03 机会／想法，次场景 S10 项目；
- “项目已经延期两周” → 主场景 S12 偏差／改进，次场景 S10 项目；
- “系统已经宕机” → 主场景 S13 异常／恢复，不从普通项目计划重新开始；
- “功能做完了但用户不用” → 主场景 S14 价值评估，失败后可能返回 S02／S04／S06。

## 四、第三维：主体规模

| 主体 ID | 规模 | 典型变化 |
| --- | --- | --- |
| P01 | 个人 | 决策权简单，重点是价值、能力、时间和自我反馈 |
| P02 | 两人／关系 | 增加双向理解、边界、承诺和协商 |
| P03 | 小团队 | 增加分工、接口、依赖和合并验收 |
| P04 | 跨团队 | 增加决策权、升级、版本、冲突和协调成本 |
| P05 | 组织 | 增加治理、制度、激励、采用和长期维护 |
| P06 | 跨组织／生态 | 增加合同、利益分配、外部规则、供应和退出安排 |

主体规模改变沟通、协作和治理强度，但不改变基础链本体。

## 五、第四维：复杂度与风险

| 等级 | 典型特征 | 建议展开程度 |
| --- | --- | --- |
| R01 轻量 | 低风险、个人、短时、可逆 | 结果 → 下一动作 → 执行 → 检查 |
| R02 标准 | 普通工作、购买、学习目标、重复事项 | 目标标准 → 计划 → 执行 → 检查 → 验收／评估 |
| R03 复杂 | 多阶段、多未知、多依赖、多方案或多人 | 展开研究、拆解、方案、验证、资源、返回和阶段门 |
| R04 高风险 | 人身、法律、隐私、重大金额、生产、不可逆或高外部影响 | 增强专业判断、证据、授权、预案、独立检查和退出方案 |

复杂度不是“流程越多越专业”。正确原则是：**风险和未知越高，才增加必要链路与控制。**

| L01 | 发现／启动前 | S01／S02／S03／S05 |
| L02 | 定义／创建／准备 | S04／S06／S07／S10 |
| L03 | 执行／使用 | S09／S10／S11 |
| L04 | 监测／反馈／改进 | S12／S14 |
| L05 | 稳定维护 | S15 |

## 七、现实场景的标准标注格式

采用下面的轻量格式即可：

> **场景：S__ 主场景〔＋S__ 次场景〕｜领域：D__｜主体：P__｜复杂度：R__｜生命周期：L__｜推荐入口：C__／场景文件**

示例：

| 现实描述 | 场景坐标 | 推荐入口 |
| --- | --- | --- |
| 我有一个 AI 软件想法，不知道要不要做 | S03＋S10｜D04＋D06｜P01｜R03｜L01 | C01→C03→C23→C22→15 项目场景 |
| 老板让我周五交报告 | S02＋S09｜D03｜P01/P03｜R02｜L02 | C02→C04→C05→C09→C14 |
| 项目连续延期 | S12＋S10｜D03/D07｜P03｜R03｜L03 | C11→C13；按根因回 C06／C07／C22／C04 |
| 这本书值不值得读 | S07｜D02｜P01｜R01｜L01 | C23→16 阅读学习场景 |
| 我知道原理但不会实际操作 | S08｜D02/D03｜P01｜R02｜L02 | C24→练习→C09→C15 |
| 系统已经宕机 | S13｜D06｜P03/P05｜R04｜L03 | C29→恢复→C21→C18→C30 |
| 产品已经稳定，要不要迁移平台 | S06＋S15｜D06｜P03/P05｜R03｜L05/L06 | C15→C22→C30 |
| 用户说功能虽然做完但不好用 | S12＋S14｜D06｜P03｜R03｜L04 | C16→C14/C15；用途失败回 C02／C04／C22 |

## 八、场景到深度场景宇宙的路由

- 命中 **S10 项目／复杂任务**：优先进入 [15_项目与复杂任务链路宇宙.md](15_项目与复杂任务链路宇宙.md)。
- 命中 **S07 信息／研究** 或 **S08 学习／能力**：优先检查 [16_阅读学习与知识研究链路宇宙.md](16_阅读学习与知识研究链路宇宙.md)。
- 发生在生活、工作、OPC、公司、软件 IT 领域：再叠加 04—08 对应领域文件。
- 命中 S13 或 S15：同时检查 [09_支撑控制、异常与生命周期.md](09_支撑控制、异常与生命周期.md)。
- 只需单个稳定状态转化时：直接进入 [02_通用基础链路库.md](02_通用基础链路库.md)，无需打开大型场景文件。

## 九、场景分类的完成标准

一次现实场景分类只要能够回答下面六个问题即可：

1. 当前最主要的状态是什么？
2. 现在真正需要解决的问题是什么？
3. 从哪条基础链或哪个 L3 场景进入最短？
4. 哪些次场景必须并行或随后调用？
5. 如果失败，最可能返回哪一层？
6. 当前生命周期出口是什么？
