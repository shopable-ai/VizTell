# 来源、证据与可信度

> 研究“这条信息从哪里来、证据是什么、证据是否独立、能否被验证，以及当前应处于什么知识状态”。避免把“某书写过”“专家说过”“很多网页都写过”自动升级为事实。

---

# 一、L2 二级维度

- **信息载体**：书籍、论文、文章、网页、视频、课程、播客、访谈、报告、数据库、代码、案例、个人经验、原始记录。
- **来源层级**：一手、二手、三手/聚合、来源不明。
- **来源角色**：原始观察者、研究者、作者、转述者、编辑者、机构、平台、模型生成者。
- **来源专业度**：普通作者、从业者、领域专家、专业机构、学术研究机构、官方/原始发布者。
- **来源独立性**：独立来源、同源转述、共同上游来源、互相引用、疑似复制、数据重合。
- **证据类型**：原始数据、实验、观察研究、系统综述、标准/规范、审计记录、案例、专家意见、个人经验、无明确证据。
- **证据直接性**：直接支持目标 Claim、间接支持、仅支持相关前提、关联但不支持因果。
- **证据强度**：强、中等、初步、弱、仅案例/经验、无明确证据。
- **方法质量**：研究设计、样本、测量、统计/推理、对照、偏差控制、复现、外部效度。
- **科学状态**：科学共识、主流支持、研究中、争议中、假说、证据不足、不可证伪/不可验证、已被反驳、疑似伪科学。
- **可验证性**：直接验证、重复验证、交叉验证、间接验证、暂不可验证。
- **来源忠实度**：二手内容是否准确保留原始 Claim、条件、范围与不确定性。
- **利益与偏差**：商业利益、立场利益、选择性引用、幸存者偏差、营销包装、叙事夸张。
- **可信状态**：高、中、低、未知或结构化 epistemic state；必须由多个维度联合产生。

---

# 二、Source Quality 与 Claim Quality 分离

高质量来源并不保证其中每个 Claim 都正确；低知名度来源也可能引用强一手证据。

因此至少分开：

```text
source_quality
claim_epistemic_state
evidence_quality
provenance_quality
```

禁止：

> 作者头衔很高 → Claim 自动高可信。

---

# 三、Claim 默认先是 Claim，不默认是 Fact

一个来源中的陈述进入系统时，建议先记录：

```yaml
claim:
  statement: "..."
  source_ref: S-...
  evidence_refs: []
  epistemic_status: unverified
```

只有完成相应验证后，才可能进入：

- supported；
- strongly_supported；
- verified_for_scope；

而不是在 Atom 提取阶段就直接标记“事实”。

---

# 四、来源数量与独立证据数量分离

必须至少同时观察：

- raw source count；
- primary source count；
- independent evidence group count。

十篇文章引用同一研究，不等于十份独立证据。

必要时建立：

```yaml
evidence_lineage:
  evidence_id: E-...
  primary_source: S-...
  derived_sources: []
  independence_group: EG-...
  data_overlap: unknown
  method_family: "..."
```

---

# 五、L3：来源独立性

优先展开：

- 是否共享同一 primary source；
- 是否共享作者/机构；
- 是否共享数据集；
- 是否互相引用；
- 是否存在发布时间依赖；
- 文本是否高度复制；
- 是否属于同一商业/组织利益链；
- 是否独立复现；
- 是否仅换媒体渠道重复发布。

---

# 六、L3：证据质量

不同领域需要不同 Evidence Profile，但通用层至少保留：

- target claim；
- evidence type；
- directness；
- independence；
- sample/data quality；
- measurement quality；
- method validity；
- bias risk；
- replication；
- external validity；
- counterevidence；
- uncertainty；
- applicability to current scope。

不在通用层强制一个跨所有领域的统一证据等级公式。

---

# 七、L3：来源忠实度

二手来源常见损失：

- 删除原始条件；
- 把相关性写成因果；
- 把概率性结论写成必然；
- 删除样本范围；
- 删除作者的不确定性；
- 只保留有传播性的结论；
- 引用标题而未读原研究。

因此二手来源可以高质量地帮助**发现**知识，但 Claim 的证据最好继续回到 primary source。

---

# 八、Epistemic State 候选

建议状态而非单一数值：

- `unverified_claim`
- `weak_evidence`
- `preliminary_support`
- `supported`
- `strongly_supported`
- `consensus_supported`
- `contested`
- `falsified`
- `not_verifiable`
- `obsolete`
- `unknown`

状态应带 scope 和 time，避免“某范围内支持”被扩张为永恒真理。

---

# 九、伪科学/弱证据识别不是关键词过滤

高风险信号包括但不限于：

- 不可证伪却宣称普遍正确；
- 只提供成功案例；
- 结论远强于证据；
- 反复依赖权威身份而无可核证据；
- 选择性展示支持案例；
- 关键条件不断事后修改；
- 缺乏可重复验证路径。

但这些只是**核查触发器**，不能仅凭风格直接判定伪科学。

---

# 十、关键区分

- 多来源重复 ≠ 多份独立证据。
- 专家观点 ≠ 已验证事实。
- 经验有效 ≠ 普遍因果规律。
- Case ≠ 机制证据。
- 相关性 ≠ 因果性。
- 来源专业度 ≠ 方法质量。
- 来源知名度 ≠ Claim 正确率。
- JSON Schema 校验成功 ≠ 知识正确。
- provenance 完整 ≠ 证据充分，但 provenance 不完整会降低可验证性。

---

# 十一、与其他文件的边界

- Atom/Canonical 结构见 `16`；

- 当前主体价值见 `05`；
- 时间和过时见 `08`；
- 高风险使用 Gate 见 `10`；
- Synthetic Evidence Benchmark 见 `22`。
