# 标准用户问题与专业问题映射

> 状态：正式上游标准化桥梁 / V2
>
> 本文件连接 `01A_用户旅程、需求与高频问题现象宇宙.md` 与 `01_需求宇宙.md`。
>
> 核心链路：**用户原话 → 标准用户问题（SUP）→ 主 P-L2 → 关联 P-L2 / P-L1。**
>
> 本文件只做问题标准化、语义去重、主归属/关联归属和覆盖审计，不设计产品功能或工程实现。

## 一、三层表达与事实源边界

```text
01A 用户原话 / 阶段 / 场景
↓
01B 标准用户问题 SUP（本文件）
↓
01 canonical P-L1 / P-L2
↓
20 Capability
↓
19 Implementation
```

- 用户原话、真实场景与旅程阶段由 `01A` 保存；本文件不重复保存大段原话。
- SUP 把大量近似用户表达归一成稳定、人工可读的问题。
- `主映射` 表示该 SUP 最主要是哪一种失败机制；优先只有一个 canonical P-L2。
- `关联映射` 表示同一现实问题还会牵连哪些邻近机制，但不因此复制新的 SUP 或 P-L2。
- 一个问题可出现在多个旅程阶段；阶段是“什么时候发生”，不是“问题是什么”。
- 旧 P-L2 迁移别名只在 `01_需求宇宙.md` 的迁移表中保留；本文件新映射只使用 canonical ID。

## 二、去重、拆分与主映射规则

1. 核心困难相同，只是措辞、案例、资料规模或旅程阶段不同 → 合并为一个 SUP。
2. 同一 SUP 可跨单书、多书、项目、长期研究、AI 参与等场景，不因场景变化复制身份。
3. “想不起来”“想起来但不会用”“已经正确调用但执行失败”根因不同 → 拆分。
4. 一句话同时含多个独立失败机制时，允许多个 SUP；不能用一个超大 SUP 强行覆盖所有机制。
5. 主映射判断问题：**如果只能留下一个机制来解释用户为什么失败，最应该留下哪个？**
6. 关联映射只表达次级机制、后果或依赖，不与主映射争夺身份。
7. RAG / Skill / Workflow / Agent / 软件不是 SUP，也不是 P-L2。
8. false merge、模型成本、路由错误等系统错误不是 SUP；只保留用户可感知后果。

| `COVERED` | 已有 canonical P-L2 可以稳定解释，且主归属可说明 |

| `MISSING` | 当前没有合适 canonical P-L2 |
| `MISPLACED` | 实际属于能力、实现、系统错误或工程成本，不属于用户问题层 |

## 五、本轮映射收敛结果

### 5.1 旧映射已全部切换到 canonical P-L2

以下旧条目不再出现在正式 SUP 主映射中：

- 05 的换表达、换名称、换案例、扩写、转载变体；
- 06 的新机制、新步骤、新方法、细化、新组合等“增量类型”；
- 07 的因果、前置、部分—整体、方法—步骤等“关系类型”；
- 08 的场景、人群、时间等“适用条件类型”；
- 13 的知道、理解、主动提取、判断、应用、熟练等“掌握深度状态”；
- 16 的“停止搜索 / 停止阅读分析”阶段性重复。

它们的迁移别名和 canonical 去向以 `01_需求宇宙.md` 为准。

### 5.2 主归属解决“一个 SUP 映射太多编号”的伪覆盖问题

旧版表中经常出现一个 SUP 同时挂三到十个 P-L2，用户无法知道哪个才是主要问题。

V2 正式改成：

```text
一个 SUP
→ 一个主要失败机制（主映射）
→ 0..n 个关联机制（关联映射）
```

如果未来发现一个 SUP 无法选出合理主映射，优先检查：

1. SUP 是否把多个根因混成一句；
2. P-L2 边界是否仍不清；
3. 是否其实是跨层能力/实现问题。

| 无障碍与特殊认知需求 | MISSING Candidate / Cross-cutting Context | 11 / 13 / 15 的部分问题可承接后果 | 可能是跨问题使用条件，不应只因重要就建一级分类 |

另外：

- 长任务中断与上下文恢复已经由 `13-13` 覆盖，并允许跨 J07/J08/J17/J18；
- 人与 AI 对同一知识的不同消费需求，用户后果归 11/13/15，后台能力归 20；
- 海量知识下人工理解与 AI 调用粒度，用户后果归 11/13/16，调用能力归 20；
- Problem Registry / Problem Graph / 状态机属于 Capability / Governance，不是新 P-L1。
