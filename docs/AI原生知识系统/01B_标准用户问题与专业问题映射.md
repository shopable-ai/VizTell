# 标准用户问题与专业问题映射

> 状态：正式上游标准化桥梁
>
> 本文件连接 `01A_用户旅程、需求与高频问题现象宇宙.md` 与 `01_需求宇宙.md`。
>
> 核心链路：**用户原话 → 标准用户问题（Standard User Problem）→ P-L1 / P-L2。**
>
> 本文件只做问题标准化、语义去重、覆盖审计和轻量优先级，不设计产品功能或工程实现。

# 一、三层表达正式定义

```text
A. 用户原话
↓
B. 标准用户问题 SUP
↓
C. 专业问题 P-L1 / P-L2
```

## A. 用户原话

保留真实语气、情境和人工可读性。

例如：

> “这本书是不是只是把旧东西换了一个名字？”

## B. 标准用户问题

把多个近似表达去重为稳定问题，不夹带解决方案。

例如：

> 用户难以判断新资料是否提供真实知识增量，还是仅对已有知识重新命名、改写或案例包装。

## C. 专业问题

映射稳定专业分类：

- `P-L1-05 知识重复与等价`；
- `P-L1-06 知识增量与补充`。

三层不能互相替代：

- 只有 A：难以稳定统计和去重；
- 只有 B：会失去用户真实感；
- 只有 C：普通用户难以判断问题是否真的存在。

# 二、标准用户问题的去重规则

## 2.1 完全同一问题

以下原话通常应合并：

- “为什么十本书都在讲一样的？”
- “是不是这些书只是重复？”
- “第二本和第一本换了说法而已吧？”

若核心困难都是“无法判断知识是否等价”，可归入同一 SUP。

## 2.2 同一问题不同生命周期阶段

“单本书里同一观点重复十次”和“十本书重复一个观点”共享重复判断问题，但规模、时间成本和用户感受不同。

处理方式：

> 标准问题可共享，`stage / scale` 不应丢失。

## 2.3 表面相似但根因不同

- “我想不起来”可能是记忆提取失败；
- “我想起来但不会用”是应用/迁移失败；
- “我会用但用了没效果”是执行、条件或方法适配问题。

不得合并成一个笼统的“学习效果不好”。

## 2.4 一句话混合多个问题

例如：

> “AI 总结得很快，但我怕漏重点，而且看完感觉懂了，自己却说不出来。”

至少包含：

1. 压缩遗漏风险；
2. AI 结果可信度/来源忠实度；
3. 熟悉感误判为掌握；
4. 主动提取失败。

应拆成多个 SUP。

# 三、覆盖状态定义

| 状态 | 含义 |
| --- | --- |
| `COVERED` | 当前 `01` 已有或本轮新增 P-L2 可以直接解释 |
| `PARTIAL` | 现有分类只能解释一部分，仍有语义边界需要研究 |
| `MISSING` | 当前专业问题宇宙没有合适位置，不应强行映射 |
| `MISPLACED` | 该表达实际更像解决方案、实现或其他下游问题，不应作为用户问题分类 |

> 本文件允许保留 `PARTIAL / MISSING`。覆盖审计的目标是发现真实缺口，不是把所有问题强行塞进现有编号。

# 五、本轮覆盖审计的核心发现

## 5.1 不建议新增新的 P-L1

本轮新增的大量真实用户问题，绝大多数可以通过：

- 扩展 P-L2；
- 一个 SUP 映射多个既有 P-L1；
- 调整少量 P-L1 名称边界；

得到解释。

因此当前结论是：

> **不新增新的 P-L1。**

这比为了“阅读、笔记、记忆、AI”分别创建新的一级空间更稳定，因为这些活动实际上跨越多个专业根因。

## 5.2 最需要补充 P-L2 的四个区域

### P-L1-11 知识整理、多来源综合与压缩

过去对“笔记”过于隐式。

需要明确覆盖：

- 笔记粒度；
- 原文 / 作者观点 / 个人理解分离；
- 笔记长期不可再利用；
- 单书笔记孤岛；
- AI 压缩与结构重组的来源忠实度。

### P-L1-13 理解、记忆、掌握与迁移

过去主要描述掌握深度，缺少用户实际学习失败过程：

- 认知负荷；
- 中断恢复；
- 熟悉感错觉；
- 主动提取失败；
- 复习时机；
- 练习反馈；
- AI 替代思考。

### P-L1-14 知识到判断、决策与行动

过去已经覆盖行动，但应补：

- 什么时候调用某项知识；
- 执行失败原因诊断；
- 现实反馈与原知识不一致；
- 行为改变的持续性。

### P-L1-17 规模、成本与停止条件

过去偏系统处理成本，应进一步显式纳入：

- 人工注意力容量；
- 待读积压；
- 百本后人工浏览不可持续；
- 从逐资料处理转向知识差额处理；
- AI 大规模错误放大。

## 5.3 `P-L1-16` 属于特殊边界

`P-L1-16` 中 Search、RAG、Knowledge Graph、Skill、Workflow、Agent、Software 等问题，不是普通用户阅读生命周期里的上游问题。

本轮不大规模重编号，以避免破坏已有引用，但正式标记为：

> **兼容保留的 Solution-Space Bridge（解决方案空间桥接问题）。**

用户层真正的问题应该先写成：

- “我需要本人学会吗？”
- “我只要随时能查到吗？”
- “这件事是不是经常重复发生？”
- “我需不需要长期保持状态？”

之后才由 `19` 判断最小充分实现载体。

# 六、仍然保留的 PARTIAL / MISSING 候选

## 6.1 PARTIAL：学习动机、焦虑囤积与自我控制

当前可由真实目标、主体价值、规模成本部分解释，但若未来系统要正式承担长期学习行为改变，需要进一步研究：

- 动机；
- 拖延；
- 自我效能；
- 情绪；
- 奖励与习惯维持。

当前不因此新增 P-L1。

## 6.2 PARTIAL：长期行为改变维持

`P-L2-14-14` 可以先描述“短期改变但难持续”，但如果未来目标从知识系统扩展到完整行为干预系统，还需要独立用行为科学重新审计边界。

## 6.3 MISSING 候选：团队 / 组织共同学习与知识协作

当前 `01A` 主要以个人用户为主。

未来可能需要研究：

- 多人对同一知识理解不一致；
- 团队知识是否真的共享；
- 专家离开后的知识流失；
- 多角色的证据和权限差异；
- 组织知识与个人知识冲突。

当前先进入候选池，不在本轮新增 P-L1。

## 6.4 MISSING 候选：无障碍与特殊认知需求

例如视觉、阅读障碍、注意力障碍等特殊用户旅程。本轮没有足够依据扩展为正式问题分类，后续如产品目标覆盖此类用户，应单独研究。

# 七、轻量问题优先级原则

标准用户问题只使用人工可判断的粗粒度标签：

- 频率：高 / 中 / 低；
- 痛感：强 / 中 / 弱；
- 时间浪费：高 / 中 / 低；
- 错误风险：高 / 中 / 低；
- 当前价值：高 / 中 / 低；
- 规模：单书 / 多书 / 领域 / 百本 / 海量 / 长期。

不建立统一数学公式。

首批优先关注：

1. 不知道真正需要什么知识；
2. 资料太多，不知道先看什么；
3. 读懂局部但没有整体结构；
4. 抓不住真正重点；
5. 笔记很多但以后不用；
6. 不知道观点是否可靠；
7. 不知道条件与边界；
8. 多书重复与真增量难判断；
9. 看过但需要时想不起来；
10. 知道但不会迁移和行动；
11. 执行失败后无法诊断原因；
12. AI 偏离原意、过度压缩或制造“已经懂了”的错觉；
13. 海量以后注意力与重复处理不可持续；
14. 旧知识失效而用户仍在使用。

# 八、与 Requirement Pattern 的关系

`15_需求模式与场景矩阵.md` 与本文件不是重复关系。

```text
用户原话
→ Standard User Problem（本文件）
→ P-L1 / P-L2（01）
```

回答：

> “用户遇到的是什么问题？”

而 Requirement Pattern 回答：

> “这次任务属于什么稳定需求模式，会组合触发哪些问题？”

一个现实任务可以同时：

- 命中多个 SUP；
- 命中多个 P-L1 / P-L2；
- 命中一个或多个 Requirement Pattern。

三者不是互斥分类。

# 九、正式边界

本文件完成后，后续任何能力、功能或实现建议都应该能够向上追踪：

```text
用户原话
→ SUP
→ P-L1 / P-L2
→ 后续才进入 Capability
```

如果一个候选功能找不到对应 SUP 或稳定 P-L2，应优先怀疑：

> 它可能是技术驱动的过早工程化，而不是被真实用户问题驱动。

本轮到此停止，不继续设计 Skill、Workflow、Agent、软件、数据库或 Schema。
