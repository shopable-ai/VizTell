# 需求宇宙：专业问题分类与 P-L1 / P-L2 事实源

> 本文件是 AI 原生知识系统的**专业问题宇宙（Problem Taxonomy）事实源**。
>
> 它不再承担“用户原话大全”职责。用户什么时候遇到什么问题、会怎样描述，由 `01A_用户旅程、需求与高频问题现象宇宙.md` 承载；大量用户原话如何形成稳定标准用户问题并映射到本文件，由 `01B_标准用户问题与专业问题映射.md` 承载。
>
> 本文件**不预设** ES、RAG、Skill、Wiki、知识图谱、Agent 等解决方案，也不把知识工程内部问题误当成用户最终需求。

---

# 一、核心定位

AI 原生知识系统的上游正式采用：

```text
人的真实目标
→ 用户需求
→ 用户旅程与真实场景（01A）
→ 用户原话问题
→ 标准用户问题（01B）
→ 专业问题 P-L1 / P-L2（本文件）
→ 后续才进入能力、产品与实现
```

本文件回答：

> **大量具体用户问题，从专业问题空间看，属于哪些稳定、可复用、跨场景的问题类别？**

关键原则：

1. **用户需求在前，知识处理在后。**
2. **问题 ≠ 功能。** 问题空间追求覆盖，解决空间追求优先级。
3. **一个标准用户问题可以同时映射多个 P-L1 / P-L2。**
4. **一个旅程阶段也可以出现多个不同专业问题。**
5. **阅读、笔记、记忆、行动等用户活动不必机械各自变成一个 P-L1。** 若现有专业根因组合足以解释，优先补 P-L2。
6. **不因为已有编号强行维持错误边界。** 但若可通过语义修正而不需要大规模重编号，优先保持兼容。
7. **P-L1-16 是特殊的下游桥接分类。** Search / RAG / Skill / Workflow / Agent / Software 的选择不属于普通用户问题本身。
8. **真实用户问题事实源以 `01A` 为准，标准化覆盖关系以 `01B` 为准。**

# 二、编号规则

为避免与 `00_总览与核心框架.md` 中已经存在的 `L1-01 ~ L1-12` 核心评价空间冲突，本文件的问题宇宙独立编号：

- `P-L1-xx`：Problem Space 一级专业问题空间；
- `P-L2-xx-yy`：对应一级空间下的二级稳定问题维度。

这里的 `P-L1 / P-L2` 是**专业问题 Taxonomy**，不是用户原话，也不是知识本体评价轴。

## 3.1 本轮一级空间审计结论

本轮从 `01A / 01B` 的用户旅程和 90+ 个标准用户问题反向审计后：

> **当前不新增 P-L1。**

原因不是“现有分类不能改”，而是本轮新增问题主要可以通过：

- 扩充 P-L2；
- 一个 SUP 映射多个 P-L1；
- 修正 P-L1 名称边界；

得到更稳定解释。

未来若出现团队 / 组织共同学习、特殊无障碍认知需求等大规模独立问题簇，再重新判断是否需要新 P-L1。

# 四、P-L2 二级问题维度

## P-L1-01 用户需求与真实问题

- `P-L2-01-01` 原始需求模糊
- `P-L2-01-02` 问题定义错误
- `P-L2-01-03` 多个问题混杂
- `P-L2-01-04` 表面问题与根因不同
- `P-L2-01-05` 目标不明确
- `P-L2-01-06` 范围过大或过小
- `P-L2-01-07` 成功标准不清
- `P-L2-01-08` 需求随研究、执行或环境变化

## P-L1-02 知识需求识别

- `P-L2-02-01` 不知道需要知道什么
- `P-L2-02-02` 已知与未知不清
- `P-L2-02-03` 前置知识缺失
- `P-L2-02-04` 核心知识与辅助知识混杂
- `P-L2-02-05` 理论、方法、案例、数据需求混杂
- `P-L2-02-06` 信息需求与能力需求混杂
- `P-L2-02-07` 当前需求与未来需求混杂
- `P-L2-02-08` 所需知识深度不明确
- `P-L2-02-09` 不知道当前真正需要的是答案、解释、判断标准、方法、案例、练习还是反馈

## P-L1-03 来源发现与资料获取

- `P-L2-03-01` 不知道去哪里找
- `P-L2-03-02` 来源类型选择错误
- `P-L2-03-03` 搜索结果过多
- `P-L2-03-04` 搜索结果不足
- `P-L2-03-05` 用户词汇与专业概念不一致
- `P-L2-03-06` 重要资料难以发现
- `P-L2-03-07` 一手资料与二手资料混杂
- `P-L2-03-08` 资料获取成本过高或不可访问

## P-L1-04 资料筛选、阅读优先级与处理深度

- `P-L2-04-01` 标题相关但正文无关
- `P-L2-04-02` 一份资料只有部分内容有价值
- `P-L2-04-03` 热门不等于高质量
- `P-L2-04-04` 权威不等于适合当前需求
- `P-L2-04-05` 高质量但低相关
- `P-L2-04-06` 低质量资料可能包含独特增量
- `P-L2-04-07` 阅读／处理成本与收益不匹配
- `P-L2-04-08` 不知道先读什么、后读什么
- `P-L2-04-09` 不知道资料应该浏览、局部阅读还是深读
- `P-L2-04-10` 收藏、待读与候选资料持续积压但优先级不清
- `P-L2-04-11` 不同资料类型需要不同处理深度却被统一处理
- `P-L2-04-12` 不知道何时应该跳过低价值章节、段落或重复内容

## P-L1-05 知识重复与等价

- `P-L2-05-01` 多个来源反复讲相同原则
- `P-L2-05-02` 同一知识只是换一种表达
- `P-L2-05-03` 同一模型使用不同名称
- `P-L2-05-04` 相同原理只是换了案例
- `P-L2-05-05` 内容大量扩写但没有实质新增
- `P-L2-05-06` 摘要、改写、转载造成伪新增
- `P-L2-05-07` 名称相同但实际含义不同
- `P-L2-05-08` 部分重复、部分新增，难以整体判断

## P-L1-06 知识增量与补充

- `P-L2-06-01` 增加新概念
- `P-L2-06-02` 增加新机制
- `P-L2-06-03` 增加新原因或解释
- `P-L2-06-04` 增加新步骤
- `P-L2-06-05` 增加新方法
- `P-L2-06-06` 增加适用条件
- `P-L2-06-07` 增加边界、限制或例外
- `P-L2-06-08` 增加案例、反例或证据
- `P-L2-06-09` 对已有知识进行有效细化
- `P-L2-06-10` 形成新的组合、模型或知识结构

## P-L1-07 知识关系与结构

- `P-L2-07-01` 上位—下位关系不清
- `P-L2-07-02` 部分—整体关系不清
- `P-L2-07-03` 原因—结果关系不清
- `P-L2-07-04` 前提—结论关系不清
- `P-L2-07-05` 问题—方法关系不清
- `P-L2-07-06` 方法—步骤关系不清
- `P-L2-07-07` 原理—应用关系不清
- `P-L2-07-08` 理论—案例关系不清
- `P-L2-07-09` 依赖与前置关系不清
- `P-L2-07-10` 替代、补充与组合关系不清
- `P-L2-07-11` 作者显式目录结构与实际讨论的知识结构不一致
- `P-L2-07-12` 局部内容可理解，但跨章节／跨资料无法形成整体结构

## P-L1-08 冲突、条件与边界

- `P-L2-08-01` 多个来源结论直接冲突
- `P-L2-08-02` 表面冲突但成立条件不同
- `P-L2-08-03` 场景不同导致结论不同
- `P-L2-08-04` 人群／主体不同导致结论不同
- `P-L2-08-05` 时间不同导致结论不同
- `P-L2-08-06` 隐含前提没有显式表达
- `P-L2-08-07` 方法存在适用边界
- `P-L2-08-08` 例外情况被忽略
- `P-L2-08-09` 反例削弱或推翻原结论
- `P-L2-08-10` 当前证据不足以判定谁正确

## P-L1-09 来源、证据与可信度

- `P-L2-09-01` 找不到原始来源
- `P-L2-09-02` 大量来源实际来自同一个源头
- `P-L2-09-03` 多次转述造成信息失真
- `P-L2-09-04` 作者观点被误当成事实
- `P-L2-09-05` 个别案例被误当成普遍规律
- `P-L2-09-06` 相关性被误认为因果
- `P-L2-09-07` 单一证据被过度推广
- `P-L2-09-08` 不同来源的证据质量差异巨大
- `P-L2-09-09` 专家或研究之间存在真实争议
- `P-L2-09-10` 新证据改变或推翻旧判断
- `P-L2-09-11` AI 或二次解释引入原始来源未支持的内容
- `P-L2-09-12` 引用／出处存在但与实际主张不匹配
- `P-L2-09-13` 流畅表达、权威身份或确定语气造成过度信任
- `P-L2-09-14` 原始事实、作者观点、用户理解与 AI 推断被混合表达

## P-L1-10 时间、版本与知识失效

- `P-L2-10-01` 内容已经过时
- `P-L2-10-02` 新版本替代旧版本
- `P-L2-10-03` 新旧版本只是修订而非替代
- `P-L2-10-04` 规则、政策、技术或环境发生变化
- `P-L2-10-05` 结论只在特定时期有效
- `P-L2-10-06` 失效知识仍在大量传播
- `P-L2-10-07` 无法确定当前有效版本
- `P-L2-10-08` 知识更新后影响范围不清

## P-L1-11 知识整理、多来源综合与压缩

- `P-L2-11-01` 大量资料知识密度低
- `P-L2-11-02` 核心原则被大量案例和叙述淹没
- `P-L2-11-03` 多来源难以形成统一结构
- `P-L2-11-04` 不同作者使用不同术语体系
- `P-L2-11-05` 不知道哪些内容应该保留
- `P-L2-11-06` 压缩时丢失重要条件、边界或证据
- `P-L2-11-07` 摘要看似正确但无法支持判断或行动
- `P-L2-11-08` 信息很多但没有形成可理解模型
- `P-L2-11-09` 不知道当前仍缺哪些关键知识
- `P-L2-11-10` 不知道什么时候已经研究充分
- `P-L2-11-11` 笔记／记录粒度过细或过粗，后续难以再使用
- `P-L2-11-12` 原文、作者观点、个人理解和后续推断混在同一记录中
- `P-L2-11-13` 笔记或整理结果长期不可检索、不可理解或从未再次使用
- `P-L2-11-14` 单资料／单书笔记形成孤岛，跨资料无法关联
- `P-L2-11-15` 摘要或结构重组破坏作者原意、原始结构或来源可追溯性
- `P-L2-11-16` AI 压缩遗漏关键差异、条件或边界，但用户难以及时发现

- `P-L2-12-04` 长期高价值但投入成本高
- `P-L2-12-05` 通用知识与场景知识价值不同

- `P-L2-12-07` 知识价值随目标和阶段变化

- `P-L2-13-05` 需要能够实际应用
- `P-L2-13-06` 需要反复练习形成技能

- `P-L2-13-10` 不知道应该学习到什么深度

## P-L1-16 能力化与实现载体选择（下游桥接）

- `P-L2-16-01` 直接全文检索是否已经足够
- `P-L2-16-02` 是否需要语义检索
- `P-L2-16-03` 是否需要混合检索
- `P-L2-16-04` 是否需要 RAG
- `P-L2-16-05` 是否需要知识图谱或关系层
- `P-L2-16-06` 是否需要 Skill
- `P-L2-16-07` 是否需要 Workflow
- `P-L2-16-08` 是否需要 Agent
- `P-L2-16-09` 是否值得独立软件化
- `P-L2-16-10` 是否应直接连接现有工具、平台或服务

> **边界修正：**本节保留编号用于兼容 `15 / 19 / 20 / 22` 等既有文档，但它不是 `01A` 用户旅程中的一级用户问题。标准用户问题原则上先映射 `P-L1-01 ~ 15 / 17 / 18`；只有在问题与能力已经明确后，才进入本节和 `19` 做最小充分实现判断。

## P-L1-17 规模、注意力、成本与停止条件

- `P-L2-17-01` 资料数量持续增长甚至近乎无限
- `P-L2-17-02` 全量深度处理成本过高
- `P-L2-17-03` 大量新材料没有实质知识增量
- `P-L2-17-04` 重复计算和重复阅读浪费资源
- `P-L2-17-05` 高成本模型或人工审核使用过度
- `P-L2-17-06` 不知道何时粗筛、何时深处理
- `P-L2-17-07` 边际知识增量持续下降
- `P-L2-17-08` 不知道何时停止搜索
- `P-L2-17-09` 不知道何时停止阅读／分析
- `P-L2-17-10` 不知道何时应该重新启动研究
- `P-L2-17-11` 信息、阅读与决策负荷超过人工注意力容量
- `P-L2-17-12` 收藏、待读、待整理资料持续积压并失去控制
- `P-L2-17-13` 规模扩大后人工浏览、定位和重新找到已有知识不可持续
- `P-L2-17-14` 不知道何时应从逐资料处理转向按主题、问题或知识差额处理
- `P-L2-17-15` AI 大规模处理会同步放大错误判断、无效计算和错误传播

## P-L1-18 反馈、评测与持续演化

- `P-L2-18-01` 不知道结果是否真正解决用户问题
- `P-L2-18-02` 系统判断错误但难以及时发现
- `P-L2-18-03` 重复／等价判断错误
- `P-L2-18-04` 增量判断错误
- `P-L2-18-05` 来源／证据／可信度判断错误
- `P-L2-18-06` 学习与掌握建议错误
- `P-L2-18-07` 人机分工判断错误
- `P-L2-18-08` 能力化／实现路由判断错误
- `P-L2-18-09` 用户目标改变后旧决策仍被沿用
- `P-L2-18-10` 新知识进入后已有结论未被重新评估
- `P-L2-18-11` 用户实践反馈与已有知识、条件或结论无法有效衔接
- `P-L2-18-12` 过去判断的依据、变化过程和失败原因无法恢复

# 五、专业问题主链与非线性关系

这些 P-L1 不是简单平行分类，也不是所有场景都必须逐步执行。

纯用户问题主链更接近：

```text
P-L1-01 真实问题
→ P-L1-02 需要什么知识
→ P-L1-03 找到资料
→ P-L1-04 选择资料与处理深度
→ P-L1-05 判断重复
→ P-L1-06 识别新增
→ P-L1-07 建立关系与结构
→ P-L1-08 处理冲突、条件与边界
→ P-L1-09 判断来源、证据与可信度
→ P-L1-10 处理时间与版本
→ P-L1-11 整理、综合与压缩
→ P-L1-12 判断主体价值
→ P-L1-13 决定理解、记忆、练习和掌握深度
→ P-L1-14 转化为判断、决策与行动
→ P-L1-15 决定人 / AI / 工具 / 服务分工
→ P-L1-17 控制规模、注意力、成本与停止条件
→ P-L1-18 用结果反馈并持续演化
```

`P-L1-16` 是从问题与能力进入实现世界时的侧向桥梁：

```text
已明确问题
→ 已明确所需能力
→ P-L1-16 / 19 判断最小充分实现载体
```

不同用户任务可以从不同位置进入，也可以跳过不适用环节。

# 六、问题现象到系统能力的推导原则

本文件的用途不是把每个问题直接变成一个软件功能，而是建立可追踪关系：

```text
01A 用户原话
→ 01B Standard User Problem
→ 本文件 P-L1 / P-L2
→ 需要作出的判断
→ 通用系统能力
→ 是否值得产品化
→ 最小充分实现方式
→ Benchmark
```

例如：

```text
用户原话：
“第十一本书我只想看前十本没有告诉我的内容。”
↓
SUP-060 / SUP-063
↓
P-L1-05 知识重复与等价
P-L1-06 知识增量与补充
P-L1-17 规模、注意力、成本与停止条件
↓
后续才判断需要什么能力
```

因此：

> **问题清单可以成为未来能力清单和功能清单的上游，但问题不能直接等于功能。**

# 七、需求属性维度

P-L1 / P-L2 解决“会遇到什么专业问题”。一条具体 Requirement 还需要通过需求属性描述，原有维度继续保留：

- **目标用途**：当前解题、辅助决策、任务推进、项目推进、系统学习、能力形成、研究、探索未知、长期发展、未来备用。
- **时间时机**：立即、近期、当前阶段、下一阶段、未来、条件触发、暂无需求。
- **需求范围**：单点问题、主题、领域、项目、多领域、全局知识体系。
- **需求主体**：个人、AI、人+AI、团队、组织。
- **掌握深度**：知道存在、理解、辨别、判断、应用、迁移、熟练。
- **期望结果**：答案、判断、决策、方案、行动、能力、知识体系、可调用能力、持续更新。
- **先验优先程度**：必须、重要、一般、低优先、暂缓、忽略。
- **需求周期**：一次性、短期持续、阶段持续、长期持续、周期复查。
- **触发来源**：问题、任务、项目、计划、目标、外部变化、兴趣探索、系统主动发现。

一条真实需求通常由多个属性组合，而不是落入一个互斥类别。

例如“半年后可能进入某领域，现在不用学”可以表示为：

- 目标用途：未来项目准备；
- 时间时机：未来／条件触发；
- 先验优先程度：暂缓；
- 掌握深度：未确定；
- 当前动作：不占用人工注意力。

因此“延迟学习”不是一级问题空间，而是多个需求属性和后续路由决策的组合状态。

# 八、本轮覆盖审计结论

## 8.1 已补强但不新增 P-L1 的区域

本轮新增 P-L2 主要集中在：

- 学习动机 / 焦虑囤积：`PARTIAL`；

- 无障碍与特殊认知需求：`MISSING` 候选。

这些问题需要独立研究，不因为发现一个候选就立即新增 P-L1。

- 继续设计 Workflow、Agent、页面、数据库或 API。

后续正确顺序应是：

```text
01A / 01B / 01 稳定

→ Problem → Capability
→ Benchmark
→ 最后才进入实现路由
```
