# 需求宇宙：用户问题、知识支持问题与问题现象总地图

> 本文件描述 AI 原生知识系统的**上游问题空间**：用户为什么需要知识，以及系统在帮助用户理解、学习、决策、解决问题和完成任务时会遇到哪些普遍问题。
>
> 本文件**不预设** ES、RAG、Skill、Wiki、知识图谱、Agent 等解决方案，也不把知识工程内部问题误当成用户最终需求。

---

# 一、核心定位

AI 原生知识系统的出发点不是：

> 如何整理十万本书？

而是：

> **当用户为了理解、学习、判断、决策、解决问题或完成任务而需要调用大量知识时，系统需要帮助用户解决什么问题？**

因此采用以下上游链路：

```text
真实用户需求 / 现实问题
→ 当前任务与决策
→ 知识需求
→ 知识获取与综合过程中出现的问题现象
→ 系统能力
→ 产品功能
→ 技术实现
→ Benchmark / 结果验证
```

关键原则：

1. **用户需求在前，知识处理在后。**
2. **问题 ≠ 功能。** 问题应尽量完整发现，功能只实现高价值部分。
3. **知识重复、去重、证据血缘等属于系统中间问题，不是用户最终目的。**
4. **书籍、论文、网页等只是知识来源容器。**
5. **当前先建立 P-L1 / P-L2 问题骨架，不急于展开 L3、Schema 或技术实现。**
6. **问题空间追求覆盖率，解决空间追求优先级。**

# 二、编号规则

为避免与 `00_总览与核心框架.md` 中已经存在的 `L1-01 ~ L1-12` 核心评价空间冲突，本文件的问题现象宇宙独立编号：

- `P-L1-xx`：Problem Space 一级问题空间；
- `P-L2-xx-yy`：对应一级空间下的二级问题维度／高频问题现象。

这里的 `P-L1 / P-L2` 是**用户任务链上的问题地图**，不是知识本体的评价轴。

# 五、18 个一级空间的主链关系

这 18 个一级空间不是简单平行分类，更接近用户真实任务中的连续问题链：

```text
P-L1-01 真实问题
→ P-L1-02 需要什么知识
→ P-L1-03 找到资料
→ P-L1-04 选择资料
→ P-L1-05 判断重复
→ P-L1-06 识别新增
→ P-L1-07 建立关系
→ P-L1-08 处理冲突、条件与边界
→ P-L1-09 判断来源、证据与可信度
→ P-L1-10 处理时间与版本
→ P-L1-11 综合与压缩
→ P-L1-12 判断主体价值
→ P-L1-13 决定学习与掌握深度
→ P-L1-14 转化为决策与行动
→ P-L1-15 决定人 / AI / 工具 / 服务分工
→ P-L1-16 决定能力化方式
→ P-L1-17 控制规模、成本与停止条件
→ P-L1-18 用结果反馈并持续演化
```

该链不是强制所有场景逐步执行。不同用户任务可以从不同位置进入，也可以跳过不适用环节。

# 六、问题现象到系统能力的推导原则

问题宇宙的用途不是把每个问题直接变成一个软件功能，而是建立可追踪关系：

```text
P-L2 问题现象
→ 需要作出的判断
→ 通用系统能力
→ 是否值得产品化
→ 产品功能
→ 最小充分实现方式
→ Benchmark
```

例如：

```text
P-L2-05-04 相同原理只是换了案例
→ 判断案例是否带来真实增量
→ 知识身份识别 + 案例增量判断
→ 再决定是否需要形成“重复折叠 / 新增高亮”等产品功能
```

因此：

> **问题清单可以成为未来能力清单和功能清单的上游，但问题不能直接等于功能。**

# 七、需求属性维度

前述 P-L1 / P-L2 解决“用户任务链上会遇到什么问题”。一条具体 Requirement 还需要通过以下属性描述，原有需求维度继续保留：

- **目标用途**：当前解题、辅助决策、任务推进、项目推进、系统学习、能力形成、研究、探索未知、长期发展、未来备用。
- **时间时机**：立即、近期、当前阶段、下一阶段、未来、条件触发、暂无需求。
- **需求范围**：单点问题、主题、领域、项目、多领域、全局知识体系。
- **需求主体**：个人、AI、人+AI、团队、组织。
- **掌握深度**：知道存在、理解、辨别、判断、应用、迁移、熟练。
- **期望结果**：答案、判断、决策、方案、行动、能力、知识体系、可调用能力、持续更新。
- **先验优先程度**：必须、重要、一般、低优先、暂缓、忽略。
- **需求周期**：一次性、短期持续、阶段持续、长期持续、周期复查。
- **触发来源**：问题、任务、项目、计划、目标、外部变化、兴趣探索、系统主动发现。

一条真实需求通常由多个属性组合，而不是落入一个互斥类别。

例如“半年后可能进入某领域，现在不用学”可以表示为：

- 目标用途：未来项目准备；
- 时间时机：未来／条件触发；
- 先验优先程度：暂缓；
- 掌握深度：未确定；
- 当前动作：不占用人工注意力。

因此“延迟学习”不是一级问题空间，而是多个需求属性和后续路由决策的组合状态。
