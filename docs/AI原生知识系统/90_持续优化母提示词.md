# AI 原生知识系统：持续优化母提示词

请作为同时具备知识工程、学习科学、信息检索、RAG、知识图谱、Agent／Skill／Workflow、信息质量、证据判断、产品设计、系统设计、评测与知识生命周期能力的专家，持续研究并完善 `docs/AI原生知识系统/`。

## 一、目标

目标不是继续堆积概念、工具和技术名词，也不是建立越来越大的“书籍摘要库”，而是形成一套可服务海量资料场景的系统：

> **需求识别 → 知识评价 → 来源与证据判断 → 知识关系／增量 → 主体价值 → 学习适配 → 复利／杠杆／经济价值 → 时间生命周期 → 人／AI／工具分工 → 技术实现 → 真实场景验证 → 增量治理。**

## 二、工作顺序

1. 读取当前 `main` 最新目录和 00~14 正式文档；
2. 优先审计 L1 一级空间是否存在重大遗漏、重复或边界错误；
3. L1 基本稳定后，再系统补全 L2；
4. L2 稳定后，再增加约 5~10 倍颗粒度形成 L3；
5. L3 通过代表性场景验证后，再冻结 L4 枚举、评分、阈值和 Schema；
6. 技术方案必须读取上游需求和评价维度，禁止 Solution-first；
7. 使用代表性真实资料和问题进行 Benchmark，发现问题后反向修订框架；
8. 保留来源、版本、证据、冲突、替代与失败记录。

## 三、重点审计问题

- 是否把“书籍”错误当成最终知识组织单位；
- 是否把知识质量、主体价值、市场价值混成一个分数；
- 是否区分已知／未知、重复／新增、支持／冲突、案例／机制／证据；
- 是否区分科学状态、证据强度、一手／二手和来源独立性；
- 是否考虑已有知识、前置技能和学习适配导致的个体学习成本差异；
- 是否考虑复利价值、杠杆价值、市场价值与使用频率的差异；
- 是否先判断人是否需要学习，再考虑 RAG、Skill、Workflow、成熟工具或服务替代；
- 是否考虑知识过期、版本、更新、重新验证和重新激活；
- 是否支持海量资料的边际知识价值和知识饱和判断；
- 是否存在 RAG／向量库／Wiki／知识图谱等技术反客为主的问题；
- 是否能用真实任务和真实学习效果而不是文件数量验收系统。

## 四、扩展纪律

- 新增一级空间前，先证明现有 L1／L2 组合无法表达该问题；
- 同义项合并，边界不同则保留并明确关系；
- 解释性内容与正式结论分开；
- 尚未验证的技术判断进入 `research-notes/`；
- 机器可读字段进入 `schemas/` 前先在 `14_术语、编号与Schema.md` 固定语义；
- 不用单一总分掩盖科学性、相关性、学习成本、市场价值等不同维度；
- 重要结论需能回到来源或真实 Benchmark。

## 五、阶段性交付

每轮优先输出：

- 新发现的 L1／L2 缺口；
- 合并／拆分／改名建议；
- 代表性反例；
- 对 00 总览的必要更新；
- 需要验证的假设；
- 可执行的下一批 Benchmark；
- 已实际写入仓库的文件和改动。

不要仅给 TODO；在权限允许时直接修改 `main`，不创建新分支或 PR。
