# 海量知识库场景与工作流

> 面向几十万本乃至更大规模资料库。核心不是“逐本读完”，也不是“先把全部资料加工成知识库”，而是：**从真实用户问题出发，在需要时调用、筛选、综合和验证知识，用最小充分知识支持理解、学习、判断、决策与行动。**
>
> 当前仍处于 V0 框架阶段；本文件描述未来运行链，不代表现在开始处理真实书库。

---

## 一、先区分三层链路

为了避免把知识工程后台流程误当成用户真实工作流，本系统正式区分三层：

1. **用户问题主链**：用户为什么需要知识，最终要得到什么结果；
2. **知识支持链**：为了回答用户问题，系统需要怎样寻找、筛选、比较、综合和判断知识；
3. **后台知识工程链**：为了让上述能力可重复、可追溯、可更新，系统内部怎样表示和治理资料与知识。

三层关系：

```text
用户现实问题
→ 用户任务主链
→ 在需要知识的环节调用“知识支持链”
→ 知识支持链按需调用“后台知识工程链”
→ 返回答案 / 模型 / 方案 / 学习内容 / 决策依据
→ 行动与结果验证
→ 新问题 / 新知识缺口
```

> **前台从问题开始，后台才从 Source 开始。**

---

## 二、第一层：用户问题主链

这是整个 AI 原生知识系统的最高层运行链，也是普通用户首先应该看到的链路。

```text
现实需求 / 问题 / 目标
→ 澄清真正的问题
→ 明确目标、范围与成功标准
→ 判断当前任务 / 决策是什么
→ 判断为了完成任务需要知道什么
→ 识别已知 / 未知 / 误解 / 前置缺口
→ 确定需要研究、查询或学习什么
→ 获取最相关的知识支持
→ 综合、比较、判断
→ 形成答案 / 解释 / 模型 / 方案
→ 判断哪些需要本人掌握，哪些可交给 AI / 工具 / 服务
→ 转化为决策与行动
→ 验证结果
→ 发现新的问题、差距或变化
→ 必要时进入下一轮
```

该链对应 `01_需求宇宙.md` 中的 `P-L1 / P-L2` 问题现象宇宙。

### 2.1 用户任务不等于“读书”

用户真实目标通常是：

- 理解一个陌生领域；
- 解决一个现实问题；
- 比较多个方案；
- 做出高质量决策；
- 推进一个项目；
- 学会一项能力；
- 判断某个观点是否可靠；
- 找到机会、风险或遗漏；
- 把知识转成执行与结果。

书籍、论文、网页、视频、代码、数据只是完成这些任务时可能调用的来源。

## 三、第二层：知识支持链

当用户任务需要外部知识时，系统进入知识支持链。

```text
当前问题 / 知识需求
→ 判断需要什么类型的知识
→ 选择来源类型与检索策略
→ 找到候选资料
→ 判断哪些值得处理
→ 只读取与当前问题相关的部分
→ 提取核心知识
→ 识别重复、改写、换案例和伪新增
→ 识别真正新增的概念、机制、方法、条件、边界、证据和反例
→ 建立知识之间的关系
→ 处理冲突、适用条件和例外
→ 检查来源、证据、独立性和可信度
→ 检查时间、版本与失效
→ 跨来源综合与压缩
→ 找出仍未解决的知识缺口
→ 判断继续研究还是停止
→ 把最小充分知识集返回用户任务
```

这一层回答的不是“数据库里有多少知识”，而是：

> **对于当前问题，我们究竟知道了什么、还缺什么、哪些是重复、哪些是真正新增、哪些可靠、哪些会改变判断？**

### 3.1 “反复讲相同原则”和“只是换案例”属于这里

例如多本资料可能出现：

- 同一原则换一种表达；
- 同一机制换名称；
- 同一原理只更换案例；
- 内容大量扩写但没有实质新增；
- 增加新条件、边界或例外；
- 增加独立证据；
- 增加反例或真实冲突。

系统要做的是判断**知识增量**，而不是简单统计文本相似度。

## 四、第三层：后台知识工程链

只有在需要稳定、规模化、可追溯地支持第二层时，才进入后台知识工程链。

为了人工可读，中文名称作为主名称，英文术语仅作为技术别名。

```text
资料登记（Source Registry）
→ 文件 / 版本识别
→ 保留原文定位
→ 原始片段（Raw Fragment）
→ 知识原子（Knowledge Atom）
→ 标准知识身份（Canonical Knowledge）
→ 知识关系（Relation Assertion）
→ 增量判断（Increment Decision）
→ 来源 / 证据 / 独立性状态
→ 时间 / 版本状态
→ 主体价值与学习差额
→ 人 / AI / 工具消费路由
→ 实现路由
→ 使用、验证与反馈
→ 局部更新 / 影响传播 / 生命周期治理
```

### 4.1 各对象的人话解释

- **资料登记**：知道资料是什么、来自哪里、哪个版本；
- **原始片段**：保留可回到原文的位置；
- **知识原子**：从原文中提取一个可以独立判断的知识单元；
- **标准知识身份**：判断它是不是已有知识，避免不同表达被误当成大量新知识；
- **知识关系**：记录重复、补充、条件、边界、支持、冲突、替代等关系；
- **增量判断**：回答新材料真正增加了什么；
- **证据状态**：回答为什么相信它、证据是否独立；
- **路由**：决定人要不要学，以及系统怎样调用或实现。

> `Canonical Knowledge` 是稳定知识身份，不是“系统宣布它一定为真”。

## 五、三层链路的调用关系

不是每次用户提问都要完整执行三层。

### 场景 A：已有知识足够

```text
用户问题
→ 检索已有知识
→ 形成答案 / 决策支持
→ 验证
```

无需重新处理原始资料。

### 场景 B：已有知识不足

```text
用户问题
→ 发现知识缺口
→ 定向检索新来源
→ 知识支持链
→ 必要的后台增量处理
→ 返回新增知识
→ 更新答案 / 方案
```

### 场景 C：陌生领域

```text
用户目标
→ 问题框定
→ 建立最小领域骨架
→ 找关键知识缺口
→ 优先处理高价值来源
→ 逐轮补全
→ 边际增量下降后停止
```

不是先把整个领域的全部资料处理完。

## 六、主要运行场景

- **当前问题解决**：找到支持当前判断/行动的最小充分知识集；
- **方案比较**：比较方法、条件、证据、成本、风险与适用性；
- **陌生领域进入**：先建立问题和知识骨架，再决定研究深度；
- **项目阶段变化**：重新计算知识需求与优先级；
- **多资料综合**：归并共识、差异、冲突、证据和边界；
- **新资料进入**：只判断与当前知识和需求有关的真实增量；
- **知识更新**：新版本、新证据、外部变化触发局部更新；
- **人工学习**：只把真正需要内化的知识差额送给人；
- **AI 使用**：低频、易检索、可验证知识优先随用随查；
- **能力自动化**：稳定重复任务逐步 Skill / Workflow / Automation 化；
- **产品化**：高频、多用户、长期状态和稳定业务闭环证明后再软件化。

---

## 七、资料处理不是默认全量执行

系统支持三种数据处理模式：

### M0 Metadata-only

只处理：

- 文件名；
- 路径；
- hash；
- 格式；
- 大小；
- 时间等元数据。

不读正文。

### M1 Content-sampling

只读取 Validation Manifest 指定范围，用于特定 Benchmark。

### M2 Full-processing

只对已经授权、明确目的并定义输出边界的数据集做全文处理。

当前 V0 默认不进入 M1/M2。

---

## 八、规模策略：先便宜筛选，再昂贵判断

几十万本级不能全量两两用 LLM 比较。

```text
问题 / 知识需求过滤
→ 元数据与来源筛选
→ 文件/hash/版本快速层
→ 近似文本候选
→ Topic / Entity / Concept 分区
→ Hybrid / Vector Top-K 候选
→ 命题 / 机制 / 条件昂贵裁决
→ 低置信或高影响关系进入人工复核
```

计算资源优先用于最可能改变：

- 用户答案；
- 知识身份；
- 证据状态；
- 决策；
- 学习路线；
- 高风险行动。

---

## 九、研究饱和与停止条件

停止研究不是因为“资料看完”，而是因为继续投入的边际价值已经不足。

重点观察：

- 当前关键问题是否已有足够答案；
- 关键知识缺口是否关闭；
- 新 Canonical Knowledge 率；
- 新机制率；
- 新条件 / 边界率；
- 新独立证据率；
- 新反例 / 冲突率；
- Decision-changing Increment；
- 来源多样性；
- 单位成本边际知识价值；
- 人工复核成本。

当连续多个批次边际价值很低、无高风险未决缺口时，可：

- 停止继续搜索；
- 停止深度阅读；
- 降低处理频率；
- 转入 Monitor；
- 等新触发条件出现后重启。

## 十、人类注意力与能力路由

知识返回用户任务之前，还必须判断最合理的消费方式：

- **立即学习**：当前高价值、必须本人判断、不能依赖延迟检索；
- **阶段学习**：下一阶段明确需要；
- **理解与验收**：AI/工具执行，人负责判断质量和边界；
- **随用随查**：低频、易检索、无需形成长期记忆；
- **未来知识池**：当前价值低但触发条件明确；
- **AI/工具代理**：可靠替代后降低人工学习投入；
- **外部服务**：低频、高专业门槛、采购更经济；
- **忽略/归档**：低价值、低增量且无可预见触发价值。

正式决策见 `18_知识价值、学习投入与消费路由.md`。

---

## 十一、局部更新而非全库重算

新证据、新版本或用户目标变化后：

```text
识别变化
→ 找到受影响问题 / 知识 / 关系
→ 更新对应证据与时间状态
→ 找依赖对象
→ 重算受影响 Routing
→ 找受影响 Skill / Workflow / Agent policy / Learning Material
→ 只运行相关 Benchmark
```

禁止把“一条新资料进入”默认解释成“全库重新处理”。

---

## 十二、人工关口

至少以下操作默认需要更高治理等级：

- 删除唯一来源；
- Canonical merge；
- supersedes / replaces；
- 高风险 Claim 升级为可执行知识；
- 高影响路由改变；
- 自动外部动作；
- 不可逆操作；
- 数据权限变化。

低风险候选召回、索引、聚类可以更高程度自动化。

## 十五、验收原则

本文件合格时，应能让普通使用者先回答：

1. 我到底在解决什么问题？
2. 为什么需要知识？
3. 系统此刻为什么需要查资料？
4. 为什么还需要继续研究，或为什么现在可以停止？
5. 最终系统给我的应该是答案、判断、方案、学习内容还是行动支持？

只有在需要理解内部实现时，才继续看到 Source / Fragment / Atom / Canonical 等后台对象。

> **如果必须先理解 Knowledge Atom 才能理解系统在做什么，说明架构表达仍然站在错误层级。**
