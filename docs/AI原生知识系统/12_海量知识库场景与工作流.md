# 海量知识库场景与工作流

> 面向 20 万本乃至更大规模资料库。核心不是“逐本读完”，而是持续做筛选、增量、价值判断、学习分流与能力化。

## 一、主要场景

- 新资料进入：判断是否值得处理，以及相对已有知识新增什么。
- 当前问题：从海量库中找到足够支持判断／行动的最小知识集。
- 项目阶段变化：重新计算哪些知识变得重要、哪些应暂缓。
- 陌生领域进入：先建立问题／知识地图，再决定学习深度与顺序。
- 多资料综合：对同一问题归并共识、差异、冲突、证据和边界。
- 知识更新：新版本、新证据或外部变化触发局部更新。
- 人工学习：只把需要真正内化的知识差额送给人。
- AI 使用：把低频、易检索、可验证知识交给检索／RAG／Skill／工具。
- 能力自动化：稳定重复任务逐步 Skill 化、Workflow 化或工具替代。

## 二、海量资料主链

> **来源盘点 → 文件／版本识别 → 解析与来源定位 → 候选知识原子化 → 语义候选召回 → 命题关系判断 → 知识增量判断 → 来源／证据评价 → 主体价值评价 → 学习适配评价 → 人／AI／工具分流 → 使用与验证 → 增量更新与生命周期治理**

## 三、书籍只是输入容器

单本书处理只解决：结构识别、章节定位、原始来源、作者模型与书内关系。跨书后应逐步转向标准知识单元，不让“书名”成为最终组织边界。

## 四、人类注意力路由

- **立即学习**：当前高价值、高相关、必须本人掌握。
- **阶段学习**：下一阶段明确会用，提前满足关键前置。
- **随用随查**：低频、易检索、无需形成直觉。
- **未来知识池**：当前价值低但存在明确未来触发条件。
- **AI／工具代理**：可靠替代后降低人工学习投入。
- **忽略／归档**：低价值重复、过时、无独立增量或不满足质量标准。

## 五、知识饱和与停止条件

当新增资料持续主要产生重复、改写和不改变模型的案例时，应降低继续深处理的优先级。重点观察：新增知识率、新增机制率、新增边界率、新增证据率、关键冲突发现率、单位处理成本的边际知识价值。
