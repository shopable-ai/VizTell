# 海量知识库场景与工作流

> 面向几十万本乃至更大规模资料库。核心不是“逐本读完”，而是持续做需求匹配、知识身份归一、增量判断、证据验证、主体价值判断、学习分流和能力化。

当前仍处于 V0 框架阶段；本文件描述未来运行链，不代表现在开始处理真实书库。

---

# 一、主要运行场景

- **新资料进入**：判断是否值得处理，以及相对已有 Canonical Knowledge 新增什么。
- **当前问题**：从海量库中找到支持当前判断/行动的最小充分知识集。
- **项目阶段变化**：重新计算哪些知识变得重要、哪些应暂缓。
- **陌生领域进入**：先建立问题/概念/证据地图，再决定学习和研究深度。
- **多资料综合**：归并共识、差异、冲突、证据和边界。
- **知识更新**：新版本、新证据、外部变化触发局部更新和影响传播。
- **人工学习**：只把真正需要内化的知识差额送给人。
- **AI 使用**：把低频、易检索、可验证知识交给 Search/RAG/Skill/Tool。
- **能力自动化**：稳定重复任务逐步 Skill/Workflow/Automation 化；只有动态开放任务才考虑 Agent。
- **产品化**：高频、多用户、长期状态和稳定业务闭环证明后再软件化。

# 二、海量资料运行主链

```text
Requirement / Trigger
→ Source Registry
→ 文件/版本识别
→ 解析并保留原始定位
→ Raw Fragment
→ Knowledge Atom 提取
→ Candidate Canonical Retrieval
→ Identity / Proposition / Mechanism Adjudication
→ Relation Assertion
→ Increment Decision
→ Evidence / Provenance / Independence Evaluation
→ Subject Utility
→ Learning Gap
→ Capability Ownership
→ Consumption Route
→ Implementation Route
→ Use / Validation
→ Feedback
→ Local Update / Impact Propagation / Lifecycle Governance
```

该主链是逻辑协议；具体工具配置属于 L4。

---

# 三、书籍只是 Source Container

单本书处理只解决：

- 原始来源身份；
- 结构定位；
- 作者表达；
- 候选 Atom；
- 书内关系。

跨资料后，组织中心应逐步转向：

> Canonical Knowledge + Evidence + Relation + Requirement + Routing

而不是书名。

---

# 四、三种数据处理模式

## M0 Metadata-only

只处理：

- 文件名；
- 路径；
- hash；
- 格式；
- 大小；
- 时间等元数据。

不读正文。

## M1 Content-sampling

只读取 Validation Manifest 指定范围，用于特定 Benchmark。

## M2 Full-processing

只对已经授权并定义输出边界的数据集做全文 Atom / Canonical / Relation 处理。

当前 V0 默认不进入 M1/M2。

# 五、计算策略：Cheap Recall → Expensive Adjudication

20 万本级不能全量两两 LLM 比较。

```text
文件/hash/版本快速层
→ 近似文本候选
→ Topic / Entity / Concept 分区
→ Hybrid / Vector Top-K 候选
→ 命题/机制/条件昂贵裁决
→ 低置信或高影响关系进入人工复核
```

计算资源应优先用于最可能改变知识身份、证据或决策的候选。

# 六、人类注意力路由

- **立即学习**：当前高价值、必须本人判断、不能依赖延迟检索。
- **阶段学习**：下一阶段明确需要，提前满足关键前置。
- **理解与验收**：执行可交给 AI/工具，但人必须能判断质量和边界。
- **随用随查**：低频、易检索、无需形成直觉。
- **未来知识池**：当前价值低但有明确触发条件。
- **AI/工具代理**：可靠替代后降低人工学习投入。
- **外部服务**：低频、高专业门槛、采购更经济。
- **忽略/归档**：低价值重复、过时、无独立增量且无未来触发价值。

正式决策见 `18`。

# 七、知识饱和与停止条件

停止全量深处理不是因为“资料看完”，而是因为边际增量持续下降。

重点观察：

- 新 Canonical Node 率；
- 新机制率；
- 新条件/边界率；
- 新独立证据率；
- 新反例/冲突率；
- Decision-changing Increment；
- 单位成本边际知识价值；
- 人工复核成本。

当连续多个批次边际价值低，且来源多样性足够、无高风险未决缺口时，可：

- 暂停深处理；
- 降低更新频率；
- 转 Monitor；
- 等触发条件重启。

---

# 八、局部更新

新证据/新版本进入后：

```text
定位 Canonical / Relation
→ 更新对应 Evidence / Time State
→ 找依赖对象
→ 重算受影响 Routing
→ 找受影响 Skill / Workflow / Agent policy / Learning Material
→ 只运行相关 Benchmark
```

禁止把“有一条新资料”默认解释成“全库重算”。

---

# 九、人工关口

至少以下操作默认需要更高治理等级：

- 删除唯一来源；
- Canonical merge；
- supersedes/replaces；
- 高风险 Claim 升级为可执行知识；
- 高影响路由改变；
- 自动外部动作；
- 不可逆操作；
- 数据权限变化。

低风险候选召回、索引、聚类可以更高程度自动化。
