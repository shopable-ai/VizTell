# references

本目录保存已经经过研究整理、需要长期反复查阅，但**不直接等同于正式规范或唯一事实源**的参考地图、能力矩阵、术语映射和外部方案索引。

与其他目录的分工：

- `research-notes/`：保存某次研究过程、外部证据、开放问题、候选方案和尚未稳定的判断；
- `references/`：保存从研究中整理出的稳定参考地图，便于人工和 AI 后续快速查阅；
- `00~99` 正式文档：保存已经进入体系的正式架构、规则、协议、工作流和治理结论；
- `schemas/`：保存机器可验证的数据结构。

核心原则：

```text
Research 回答“我们发现了什么、依据是什么”
Reference 回答“以后需要反复查什么”
Formal Framework 回答“系统最终决定采用什么”
```

约束：

1. Reference 可以引用外部产品、论文、Skill 和行业术语，但必须能追溯到 research note 或原始来源；
2. 外部产品能力会变化，涉及具体版本、价格、性能和发布时间的信息应优先留在 research note；
3. Reference 中的分类可以是本项目自建 taxonomy，必须明确标记，不能伪装成行业标准；
4. Reference 中的架构如果被正式采用，应在对应正式文档中重新定义，并让正式文档成为稳定事实源；
5. 不要在 Reference 中复制整套正式规范，避免多事实源漂移。
