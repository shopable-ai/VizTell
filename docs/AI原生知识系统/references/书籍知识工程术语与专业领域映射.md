# 书籍知识工程术语与专业领域映射

> 类型：Reference / Terminology Map
>
> 目的：把书籍知识工程中容易混淆的英文术语、专业领域和本项目概念对齐，降低阅读和讨论成本。
>
> 注意：本文件用于“翻译和定位”，正式定义仍以对应正式文档为准。

---

## 1. 上位定位

当前体系不宜只称为：

- 书籍摘要；
- AI 读书；
- 笔记整理；
- 第二大脑；
- Book-to-Skill。

更完整的定位是：

> **书籍知识工程（Book Knowledge Engineering）**

指：把书籍从原始来源，转成可理解、可检索、可归类、可去重、可迁移、可学习、可行动、可由 AI 调用、可验证、可长期更新的知识资产与能力。

若强调端到端过程，可用：

> **Book → Knowledge → Learning / Skill → Action → Feedback Pipeline**

中文解释：

> 书籍 → 知识 → 人类学习 / AI 能力 → 行动 → 反馈更新链。

该名称是本项目的架构命名，不宣称为行业统一标准。

## 3. 容易混淆的知识对象

### 3.1 Summary：摘要

回答：

> 原文主要讲了什么？

特点：压缩内容。

它不自动等于：

- 核心知识；
- 原理；
- 知识原子；
- 行动方案。

---

### 3.2 Distillation：蒸馏

回答：

> 大量内容中真正值得保留的是什么？

它允许主动舍弃：

- 重复；
- 低价值案例；
- 修辞；
- 过长表达；
- 非关键背景。

因此：

```text
Summary = 变短
Distillation = 筛选 + 压缩 + 保留高价值结构
```

---

### 3.3 Knowledge Atom：知识原子

本项目中指一个可独立识别、可回源、可建立关系的最小充分知识单元。

可能包含：

- 主张；
- 类型；
- 条件；
- 边界；
- 来源；
- 证据；
- 关系；
- 时间状态。

正式定义见：

`../16_知识原子、标准知识与关系模型.md`

---

### 3.4 Atomic Note：原子笔记

更偏个人知识管理和 Zettelkasten 的笔记单位。

典型原则：

- 一条笔记一个主要想法；
- 自包含；
- 用自己的话；
- 与其他笔记建立链接。

它可以成为 Knowledge Atom 的人工可读视图，但不等于完整机器知识对象。

---

### 3.5 Canonical Knowledge：标准知识身份

回答：

> 多个来源说的这些内容，实际上是不是同一个知识对象？

它用于处理：

- 同义改写；
- 翻译；
- 不同作者重新命名；
- 相同原则换案例；
- 同一知识的新边界、新证据、新版本。

不要把“向量相似”直接当成 Canonical 等价。

---

### 3.6 Knowledge Delta：知识增量

回答：

> 新资料相比已有知识，真正新增了什么？

可能新增：

- 新机制；
- 新条件；
- 新边界；
- 新证据；
- 新反例；
- 新版本；
- 新应用场景；
- 改变决策的信息。

这比“这本书有多少新句子”更重要。

---

### 3.7 Principle / Strategy / Method / Parameter

建议中文：

| 英文 | 中文 | 例子 |
| --- | --- | --- |
| Principle | 原则 | 持续反馈有助于修正行为 |
| Strategy | 策略 | 每周安排固定反馈时段 |
| Method | 方法 | 使用某套复盘步骤 |
| Parameter | 参数 | 每周日 30 分钟 |

必须避免：

> 把具体参数直接升级成普适原则。

---

### 3.8 Mental Model：心智模型 / 思考模型

指帮助解释、预测或判断一类问题的抽象结构。

不是所有“几步法”都配称 Mental Model，也不是作者所有观点都应该包装成模型。

---

## 4. AI 使用相关术语

### 4.1 Book-to-Skill

中文建议：

> **书籍能力化 / 书籍转 Agent Skill**

它解决：

> 怎样把一本书中的稳定方法、规则、模式和参考资料转成 AI 可重复调用的能力包。

它不是“读完一本书”的同义词。

---

### 4.2 Skill

在 Agent Skills 语境中，更接近：

> 可复用的专业说明、流程和资源包。

典型结构：

```text
SKILL.md
references/
scripts/
assets/
```

不要把：

- 一条知识；
- 一个观点；
- 一段 Prompt；

自动称为 Skill。

---

### 4.3 Workflow

中文：工作流。

表示：

> 多步骤任务按照一定顺序、条件和分支运行。

书籍知识工程整体更适合是 Workflow，而其中部分稳定能力可以拆成 Skill。

---

### 4.4 Agent

中文：智能体 / Agent。

通常意味着系统需要：

- 动态判断；
- 选择工具或路径；
- 观察结果；
- 根据环境继续行动。

不能把“多步骤 Prompt”自动叫 Agent。

正式实现路由见：

`../19_知识到Search-RAG-Skill-Workflow-Agent-软件的能力路由.md`

---

### 4.5 Progressive Disclosure

中文建议优先写：

> **渐进加载（Progressive Disclosure）**

在人机知识系统里直观含义：

```text
先只知道“有什么”
→ 任务匹配时加载核心说明
→ 真正需要时再读具体章节 / reference
```

作用：

- 降低 token；
- 减少上下文污染；
- 允许存在大量 Skill；
- 让复杂知识按需展开。

## 5. 人类学习相关术语

### 5.1 Recognition：识别

看到答案时觉得熟悉。

不能证明会主动提取。

### 5.2 Recall：回忆

没有答案提示时主动提取。

### 5.3 Understanding：理解

能够解释含义和关系。

### 5.4 Judgment：判断

能够判断：

- 是否适用；
- 哪些条件成立；
- 什么情况会失败。

### 5.5 Execution：执行

能够在标准任务中做出来。

### 5.6 Adaptation：适应

情况变化时会调整方法。

### 5.7 Transfer：迁移

在陌生新场景中仍能调用原则解决问题。

正式 H0–H7 层级见：

`../06_学习适配、掌握与迁移.md`

## 6. 三类“视图”必须分开

### 6.1 Source View：来源视图

给回源和审计使用：

- 原章节；
- 原段落；
- 页码；
- 版本；
- 引用。

### 6.2 Human View：人工阅读视图

给人理解和浏览使用：

- 阅读地图；
- 核心知识地图；
- 原则模型；
- 场景；
- 关键行为；
- 练习；
- Wiki / 导航页面。

### 6.3 Machine / Agent View：AI 使用视图

给 AI 检索和执行使用：

- IDs；
- metadata；
- schema；
- embeddings；
- relations；
- references；
- Skill；
- routing；
- minimal context package。

关键原则：

> 同一底层知识可以有多个消费视图，不应该强迫人类直接阅读机器最优的数据结构，也不应该让 AI 每次读取整个人工知识库。

## 7. 术语使用规则

以后文档中优先采用：

```text
中文主称呼（English）
```

例如：

- 渐进加载（Progressive Disclosure）；
- 知识增量（Knowledge Delta）；
- 标准知识身份（Canonical Knowledge）；
- 主动回忆（Active Recall）。

避免只有英文缩写而没有中文解释。

如果一个概念第一次出现，应至少回答：

1. 中文是什么意思；
2. 它解决什么问题；
3. 它不解决什么；
4. 在本项目里对应哪个环节。
