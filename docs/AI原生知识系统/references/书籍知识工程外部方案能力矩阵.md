# 书籍知识工程外部方案能力矩阵

> 类型：Reference / Capability Matrix
>
> 目的：用统一维度比较外部 Skill、产品与知识系统，判断它们分别解决书籍知识工程的哪一段，而不是用“谁功能多”做简单排名。
>
> 数据观察截止：2026-08-26。具体产品能力会变化；版本、价格、发布时间和性能数字应回到 research note 或官方来源复核。

---

## 1. 先定义比较维度

| 维度 | 含义 |
| --- | --- |
| Source Grounding | 能否回到原始来源并保留引用 |
| Structure | 是否恢复 / 利用章节和文档结构 |
| Distillation | 是否主动筛选核心知识而非只缩写 |
| Atomization | 是否形成独立知识单元 |
| Canonical / Dedup | 是否解决跨来源知识身份和去重 |
| Relation / Graph | 是否显式连接知识关系 |
| Critical Audit | 是否处理假设、反例、边界、冲突 |
| Human Learning | 是否帮助人理解和形成掌握 |
| Recall / Mastery | 是否通过练习和状态追踪验证掌握 |
| Action | 是否把知识转成现实行为或决策规则 |
| AI Reuse | 是否让 AI 在未来任务中按需调用 |
| Library Scale | 是否面向整个阅读库 / 知识库 |
| Progressive Loading | 是否避免一次加载全部知识 |
| Eval | 是否测试知识 / Skill 是否真正提升结果 |
| Lifecycle | 是否支持持续更新、版本和反馈 |

评级：

- `✓✓`：核心能力；
- `✓`：明确支持；
- `△`：部分支持 / 可间接实现；
- `×`：不是主要能力或公开能力不足以支持该结论。

此矩阵只用于**能力覆盖比较**，不表示产品质量排名。

## 3. 为什么 Recall 更接近“AI 原生个人知识库”

基于其当前公开能力，Recall 同时覆盖：

```text
保存内容
→ AI 摘要
→ 自动分类 / 标签
→ 自动连接
→ Knowledge Graph
→ 全库 AI Chat
→ Quiz / Spaced Repetition
→ API / MCP
```

因此，相比仅做单文档摘要或单本书问答的产品，它更接近：

> **AI 原生个人知识库 / 自组织知识网络。**

这里的“更接近”是本项目基于能力维度的归类，不是 Recall 官方产品类别声明。

它特别值得参考的部分：

- 自动组织；
- 自动连接；
- 整库聊天；
- 图谱探索；
- 记忆强化；
- 对外 API / MCP。

但不能由此推断它已经解决：

- Canonical Knowledge；
- 命题级去重；
- 证据独立性；
- Knowledge Delta；
- 行为反馈；
- H4–H7 高阶掌握验证。

官方参考：

- https://www.getrecall.ai/
- https://app.getrecall.ai/pricing

## 4. 为什么 Readwise 更接近“阅读库 Agent”

Global Ghostreader 已经从单文档问答扩展到整个阅读库，并支持：

- 全库搜索；
- 有引用的跨文档回答；
- 找相似内容；
- 跨资料连接；
- 标签 / 元数据等操作；
- starter skills；
- MCP / CLI 连接外部 Agent。

因此它更适合被归入：

> **Library Agent / Reading Knowledge Agent**

而不只是“阅读器 + 摘要”。

这条路线对本项目未来“十万级材料怎样被 AI 使用”尤其有参考价值。

官方参考：

- https://readwise.io/reader/update-aug2026
- https://docs.readwise.io/changelog

## 5. 为什么 Book-to-Skill 是独立家族

Book-to-Skill 的核心不是：

> 把书缩短。

而是：

> 把书里稳定的方法、框架、决策规则和反模式包装成 Agent 可重复调用的能力资产。

virgiliojr94/book-to-skill 特别强调：

- `SKILL.md` 只承载核心内容和索引；
- 章节、术语、patterns、cheatsheet 分文件；
- Agent 根据问题按需加载。

Londeren/book-to-skill 则进一步强调：

- Go / No-Go；
- 提取可迁移方法；
- source anchor；
- rejection log；
- no-skill baseline eval。

因此该家族应作为本项目 `19_知识到Search-RAG-Skill-Workflow-Agent-软件的能力路由.md` 下的一种**能力化出口**，而不是所有书默认处理终点。

代表来源：

- https://github.com/virgiliojr94/book-to-skill
- https://github.com/Londeren/claude-plugins/tree/main/plugins/book-to-skill

## 6. 为什么 RemNote 更接近“学习闭环”

RemNote Guided Learn 公开链路可概括为：

```text
资料
→ 小节化
→ 摘要
→ Flashcards
→ Quiz
→ AI Tutor
→ Mastery Tracking
→ 针对薄弱主题继续练习
```

并区分 Recall 与 Application 类型的问题。

这说明它不是简单内容输出，而是在追踪：

> **主体状态有没有改变。**

它与本项目的映射：

| RemNote 能力 | 本项目对应概念 |
| --- | --- |
| baseline knowledge | 当前主体状态 |
| topic mastery | 掌握状态 |
| flashcards | 主动回忆 |
| quiz | 掌握验证 |
| application questions | H3/H4 以上的初步迁移验证 |
| targeted follow-up | Knowledge Gap 定向修复 |

但正式映射仍以 `06_学习适配、掌握与迁移.md` 为准，不能直接用某产品的 100% mastery 替换 H0–H7。

官方参考：

- https://www.remnote.com/feature/learn-any-pdf
- https://help.remnote.com/en/articles/15724936-guided-learn-mode

## 7. 为什么 skill-read-deeper 更接近“多消费模式”

`skill-read-deeper` 把读书拆成 12 个模式，而不是执行一个万能 Prompt。

它证明一个重要架构事实：

> 同一本书，在不同目的下应该采用不同消费视图。

例如：

```text
第一次理解 → Core Argument
章节复习 → Chapter Distiller
准备行动 → Action Plan
长期知识库 → Permanent Notes
批判检查 → Blind Spot / Debate
跨书研究 → Cross-Book Connector
记忆验证 → Recall Test
价值筛选 → 1-Year Impact
```

这支持本项目未来继续区分：

- processing pipeline；
- human consumption view；
- AI consumption view；
- task-specific output。

代表来源：

- https://github.com/mp3wizard/skill-read-deeper

## 8. “当前设计覆盖更广”到底是什么意思

当前书籍知识工程候选方案比普通 Book Summary 多出的主要是以下层次：

```text
摘要 / 重点
        ↓
Knowledge Atom
        ↓
Canonical Knowledge
        ↓
跨书关系 / 去重 / 增量
        ↓
来源 / 证据 / 时间 / 边界
        ↓
主体价值 / 学习差额
        ↓
Human / AI / Tool 路由
        ↓
学习 / Skill / RAG / Agent / 行动
        ↓
Benchmark / 反馈 / 更新
```

因此，更严谨的结论应该表述为：

> **本项目当前目标架构覆盖的知识生命周期维度，比本次抽样的单一 Book Summary / Reading Skill 更广。**

不能表述为：

> “本项目已经比这些产品做得更好。”

后者必须有真实 Benchmark。

## 10. 维护规则

以后出现新的“AI 读书”“Book Skill”“Second Brain”“AI Tutor”产品时：

1. 先按本矩阵的 15 个维度标记能力；
2. 再映射到 `书籍知识工程相关Skill家族地图.md`；
3. 只有出现真正新的问题类别，才扩展 Skill 家族；
4. 具体版本能力写入 research note；
5. 稳定能力分类才进入 Reference；
6. 只有系统决定采用的规则才进入正式 00–23 文档。
