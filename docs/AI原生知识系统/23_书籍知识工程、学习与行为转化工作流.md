# 书籍知识工程、学习与行为转化工作流

> 定位：书籍场景的正式装配文档。
>
> 本文件不重新定义 Knowledge Atom、证据、去重、掌握层级或实现路由，而是把现有正式能力装配成“书籍进入系统后怎样处理、怎样给人学、怎样给 AI 用、怎样进入现实任务和反馈”的场景工作流。
>
> 当前版本首先正式化**架构、阶段职责、分流原则和输出边界**；具体 Prompt、阈值、模型选择和自动化实现仍需真实 Benchmark，不在本文中固化。

---

## 1. 结论先行

书籍不是最终知识单位，也不应该默认被“逐章总结”。

正式目标是：

> **把值得处理的书籍转换成可回源、可判断、可去重、可学习、可迁移、可由 AI 按需调用、可进入现实行动并能根据结果继续更新的知识资产。**

书籍场景的目标架构：

```text
原始书籍 / 文档
        ↓
书籍类型与处理价值判断
        ↓
原书结构恢复 / 阅读地图
        ↓
知识原子化 + 来源锚点
        ↓
语义标准化 / Canonical Resolution
        ↓
跨书关系 + 去重 + Knowledge Delta
        ↓
原则 / 模型 / 机制抽象
        ↓
证据 / 条件 / 边界 / 反例 / 时间审计
        ↓
主体价值与消费路由
        ↓
┌─────────────────────┬─────────────────────┐
│ 人类学习与行动层      │ AI / 工具能力层       │
│                     │                     │
│ 阅读地图              │ Search / RAG         │
│ 核心知识地图          │ Skill                │
│ 主动回忆              │ Workflow             │
│ 场景练习              │ Agent                │
│ 迁移测试              │ Software / Service   │
│ 关键行为              │ 按需上下文            │
└──────────┬──────────┴──────────┬──────────┘
           ↓                     ↓
        现实任务 / 决策 / 行动 / AI 执行
                     ↓
              结果、错误与反馈
                     ↓
          经验回写 / 知识更新 / 再验证
```

这不是要求所有书籍每次执行全部步骤。

正式原则是：

> **先判断价值和目标，再选择最小充分处理深度。**

## 2. 本文件解决什么问题

它主要回答：

1. 一本书进入系统后，先做什么、后做什么；
2. 什么步骤是知识工程，什么步骤是人类学习，什么步骤是 AI 使用；
3. 哪些书值得深度知识化，哪些只需要保存、索引或摘要；
4. 怎样避免“书籍摘要”冒充“知识工程完成”；
5. 怎样把单本书结果并入多书、海量书库而不形成知识孤岛；
6. 怎样把知识进一步变成原则、能力、行为和现实任务；
7. 怎样验证人是否真的掌握、AI 是否真的变强；
8. 怎样把实际结果继续反哺知识系统。

本文不是：

- 单本书摘要模板；
- 固定 12 步必须执行的流水线；
- 一个巨大 `SKILL.md`；
- 某个产品的复刻；
- 已经验证完成的自动化实现。

## 4. 三条链必须分开

### 4.1 用户使用链

用户看到的是：

```text
我为什么要处理这本书
→ 它值不值得投入时间
→ 我需要理解到什么程度
→ 最重要的知识是什么
→ 和我已有知识有什么差别
→ 哪些需要记住 / 会用
→ 哪些交给 AI 随用随查
→ 现在应该做什么
→ 做完结果怎样
```

用户不应该被迫理解：

- embedding；
- Canonical Resolution；
- schema；
- chunking；
- vector threshold；
- Agent runtime。

### 4.2 后台知识工程链

系统内部：

```text
Source
→ Structure
→ Fragment
→ Knowledge Atom
→ Canonical Knowledge
→ Relation
→ Knowledge Delta
→ Evidence / Time
→ Value / Learning Gap
→ Consumption Route
→ Implementation Route
```

### 4.3 能力与行为链

最终消费：

```text
知识
→ 人理解 / 人掌握 / AI 调用 / 工具替代
→ 判断 / 决策 / 执行
→ 现实结果
→ Feedback
→ 更新知识与能力
```

三条链共用底层对象，但不应混成一张对用户可见的工程流程图。

## 5. BK00：先判断是否值得处理

默认动作不是“总结”。

先判断：

- 当前真实问题是什么；
- 这本书与问题相关吗；
- 用户是想浏览、研究、学习、行动还是给 AI 使用；
- 与已有知识重复度可能有多高；
- 是否有独特模型、证据、案例或方法；
- 是否只是低密度表达；
- 是否存在版权、隐私、来源或版本问题；
- 是否值得人工阅读；
- 是否值得进入长期知识库。

可能的合法结果包括：

```text
不处理
仅保存原始来源
只建索引
只做阅读地图
只提取核心结论
深度知识工程
只为 AI 建按需引用
只为当前问题提取局部知识
```

> “拒绝深度处理”是成功路由结果，不是失败。

## 6. BK01：判断书籍类型，而不是默认逐章总结

至少区分：

- 原理型；
- 理论型；
- 方法型；
- 工具型；
- 案例型；
- 经验型；
- 格言 / 观点集合型；
- 故事型；
- 混合型。

类型影响：

- 是否重视章节结构；
- 是否需要提取方法步骤；
- 是否需要大量保留案例；
- 是否适合原则抽象；
- 是否适合行为转化；
- 是否适合生成 Skill；
- 是否值得人工深入学习。

例如：

```text
方法型书
→ 方法、条件、步骤、错误模式优先

理论型书
→ 定义、命题、机制、证据、反例优先

案例型书
→ 案例不是默认删除，而要判断是否提供独特机制、边界或迁移价值

格言型书
→ 不应按章节摘要，应优先语义聚类、重复识别、原则抽象和风险审计
```

---

## 7. BK02：恢复原书结构，建立来源阅读地图

这一阶段的目标不是制造知识结论，而是建立可靠的 Source View。

输出至少包括：

```text
书
→ 大章节
→ 子章节
→ 显式主题
→ 隐含主题（如有）
```

同时保留：

- 原始标题；
- 原始顺序；
- 页码 / 位置；
- 版本；
- 表格 / 图片 / 代码等重要非纯文本结构；
- 可回到来源的位置锚点。

主要人工输出：

> 《原书阅读地图》

注意：

> 阅读地图是 Source View，不是重新语义归类后的知识地图。

---

## 8. BK03：提取知识原子，但不把所有句子知识化

只有对当前目标或长期知识库有价值的内容才进入 Knowledge Atom 候选。

优先识别：

- 事实；
- 命题；
- 概念；
- 定义；
- 原理；
- 机制；
- 模型；
- 方法；
- 决策规则；
- 条件；
- 边界；
- 反例；
- 证据；
- 高价值案例；
- 行为建议。

不默认知识化：

- 纯修辞；
- 情绪表达；
- 重复铺陈；
- 不改变理解的普通例子；
- 无法与来源区分的模型补写。

每个重要知识对象必须能回源。

如果原书没有解释机制：

> 标记“原书未提供机制 / 原理”，而不是由模型补写后伪装成作者结论。

---

## 9. BK04：重新语义归类，建立知识地图

不要把原书目录永久当作知识分类。

原书结构回答：

> 作者怎样讲。

知识地图回答：

> 这些知识实际上属于什么问题和概念。

因此需要：

```text
原始章节
→ Knowledge Atom
→ 主题 / 问题 / 概念聚类
→ 跨章节知识地图
```

典型分类可能包括：

- 沟通；
- 决策；
- 情绪；
- 冲突；
- 风险；
- 学习；
- 工作；
- 人际关系；
- 财富；
- 自我管理；

但分类必须由知识本身决定，不把示例类别固定成全领域本体。

人工主要输出：

> 《核心知识地图》

---

## 10. BK05：从经验、方法和案例中抽象原则 / 模型

目标不是为了“显得高级”而制造模型，而是寻找真正可迁移的结构。

候选抽象链：

```text
具体案例 / 经验
→ 策略
→ 原则
→ 机制
→ 更高层模型
```

重点寻找：

- 多次重复出现的规律；
- 跨场景不变量；
- 条件—结果关系；
- 因果假设；
- 决策规则；
- 边界规则；
- 失败模式。

必须保持层级：

```text
原则 ≠ 策略 ≠ 方法 ≠ 参数
```

例如：

```text
“持续获得反馈”可能是原则
“每周复盘”可能是策略
“按 A-B-C 三步复盘”可能是方法
“每周日 30 分钟”只是参数
```

模型抽象属于高 hallucination 风险阶段，必须保留：

- 来源；
- 推断标记；
- 适用条件；
- 反例；
- 是否为作者显式提出。

## 11. BK06：进入跨书 Canonical、去重与 Knowledge Delta

单本书处理结束后，不能直接把整本结果作为孤立知识包长期堆积。

进入多书知识库时，必须对接 `16` 与 `17`：

```text
语义候选召回
→ 命题 / 机制 / 条件对齐
→ Canonical Resolution
→ 关系裁决
→ Knowledge Delta
→ 证据独立性
```

可能关系至少包括：

- same / equivalent；
- restatement；
- supports；
- extends；
- refines；
- adds_condition；
- adds_boundary；
- contradicts；
- counterexample；
- supersedes；
- example_of。

关键原则：

> 相似度只用于候选召回，不能直接删除、合并或宣布“这本书没有新知识”。

人工最终更关心：

> **这本新书相比我已有知识，到底新增了什么？**

而不是：

> 这本书和旧书的 embedding 有多像。

---

## 12. BK07：来源、证据、条件、边界和时间审计

书中陈述必须区分：

- 作者观点；
- 作者经验；
- 引用事实；
- 外部研究；
- 推测；
- 本项目后续推断。

尤其不能把：

> “作者写在书里”

自动升级为：

> “已被证实的普适规律”。

至少检查：

- provenance；
- 是否可回源；
- 证据类型；
- 多来源是否实际同源；
- 时间与版本；
- 适用范围；
- 条件；
- 边界；
- 反例；
- 冲突。

如果需要外部事实验证，应单独进入外部证据研究链，并清楚区分：

```text
书中主张
vs
外部证据
vs
系统推断
```

## 13. BK08：判断对当前主体到底有什么价值

高质量知识不等于当前需要学习。

正式判断：

```text
知识本身质量
× 当前目标相关性
× 当前已有知识
× 使用频率 / 时效
× 错误代价
× 可被 AI / 工具替代程度
→ 当前消费方式
```

可能结果：

- 人必须掌握；
- 人只需理解；
- 人只需知道存在；
- 随用随查；
- 交给 AI；
- 做成 Skill / Workflow；
- 使用现成软件 / 服务；
- 当前完全不投入。

这一阶段必须对接 `18_知识价值、学习投入与消费路由.md`。

## 14. BK09-H：人类学习路线

如果路由结果是“人应该内化”，才进入完整学习路线。

### 14.1 先确定目标掌握层级

使用 `06` 的 H0–H7：

```text
H0 Unknown
H1 Recognize
H2 Understand
H3 Judge
H4 Execute
H5 Adapt
H6 Transfer
H7 Teach / Design
```

不是每条知识都要学到 H6/H7。

### 14.2 Human View 至少可以产生六类资产

1. 原书阅读地图；
2. 核心知识地图；
3. 核心原则 / 模型；
4. 关键行为清单；
5. 场景练习；
6. 值得保留的知识原子 / 永久笔记视图。

### 14.3 练习必须与层级匹配

```text
H1 → 识别
H2 → 解释
H3 → 正误辨别、条件与边界
H4 → 标准任务执行
H5 → 异常调整
H6 → 陌生场景迁移
H7 → 教学、设计、改进
```

仅 Flashcards / 选择题不能证明 H4–H7。

### 14.4 主动回忆和间隔重复不是默认动作

只有需要长期低延迟提取的知识才值得投入记忆成本。

低频、易查、快速变化的知识可以保持：

> 知道存在 + 能可靠检索。

## 15. BK09-AI：AI / 工具能力路线

如果知识主要由 AI 或工具消费，不应默认复制 Human View。

AI 使用层重点是：

- 可识别的知识 ID；
- metadata；
- provenance；
- relations；
- retrieval；
- minimal sufficient context；
- capability routing；
- evaluation。

实现载体仍由 `19` 判断：

```text
Search
RAG
Knowledge Graph
Skill
Workflow
Agent
Automation
Software
External Service
```

### 15.1 Book-to-Skill 只是一个出口

只有当书中存在：

- 稳定方法；
- 重复可用框架；
- 明确决策规则；
- 可重复操作步骤；
- 值得长期调用的专业模式；

才值得考虑 Skill 化。

### 15.2 Skill 应优先渐进加载

参考 Agent Skills 的 Progressive Disclosure 思路：

```text
Skill metadata
→ SKILL.md 核心规则 / 路由
→ 按任务加载 references / chapters / scripts
```

不要把整本书压进一个巨大 `SKILL.md`。

### 15.3 人工视图和 AI 视图分离

```text
同一底层知识
        ↓
┌───────────────┬────────────────┐
│ Human View    │ Machine View   │
│ Wiki / 地图    │ Schema / IDs   │
│ 解释 / 练习    │ Relations      │
│ 行为清单       │ Retrieval      │
│ 场景案例       │ Skill / RAG    │
└───────────────┴────────────────┘
```

这解决：

- 知识原子过多后人难以阅读；
- 为人工可读而保存的大量解释不应每次进入 AI 上下文；
- AI 最优数据结构不应直接成为人的主要阅读界面。

## 16. BK10：把高价值知识转成关键行为

只有满足以下条件时才行为化：

- 与现实选择或动作相关；
- 用户确实希望改变行为；
- 条件和边界足够清楚；
- 错误行为风险可接受；
- 有可观察反馈。

推荐表示：

```text
触发场景
→ 判断条件
→ 应采取行为
→ 不应采取行为
→ 判断标准
→ 反馈信号
```

或：

```text
IF 情境 X 出现
THEN 执行行为 Y
```

但 IF / THEN 只是表示方式，不自动证明行为正确。

---

## 17. BK11：场景迁移与边界练习

对需要达到 H3 以上的重要原则，优先设计：

- 初级典型场景；
- 中等变化场景；
- 复杂场景；
- 反例；
- 边界案例；
- 信息不完整场景；
- 两个原则冲突的权衡场景。

目标不是复述作者原案例，而是测试：

> **离开原书语境以后，这个原则是否仍然会被正确调用。**

## 18. BK12：现实任务与结果反馈

知识系统不能停在“生成完成”。

进入现实任务后，至少记录：

- 使用了什么知识 / 模型；
- 人还是 AI 执行；
- 任务场景；
- 结果；
- 是否偏离预期；
- 是否出现新边界；
- 是否暴露反例；
- 是否是执行错误；
- 是否是知识错误；
- 是否环境变化；
- 是否需要更新知识。

失败诊断至少区分：

```text
K：Knowledge Error      知识本身错误 / 不适用
J：Judgment Error       条件判断错误
E：Execution Error      执行错误
C：Context Change       环境发生变化
F：Feedback Noise       反馈本身噪声 / 延迟
```

否则系统很容易把一次失败错误归因给“书没用”，或把一次偶然成功当成知识已经被验证。

## 19. BK13：反馈回写与知识生命周期

现实反馈可能触发：

- confidence change；
- 新条件；
- 新边界；
- 新反例；
- 新案例；
- 方法修订；
- Skill 更新；
- 学习状态更新；
- 旧知识降级；
- 新版本替代；
- 重新验证。

因此完整链不是线性终点，而是：

```text
Knowledge
→ Use
→ Result
→ Feedback

```

## 20. 书籍处理深度：正式采用“路由思想”，暂不固化自动阈值

当前可以保留以下处理层级作为操作性分类：

```text
T0 仅保存原文件和元数据
T1 恢复目录 / 阅读地图
T2 提取核心结论
T3 知识原子化
T4 原则 / 模型抽象
T5 学习 / 行为 / 迁移资产
T6 跨书 Canonical、去重、证据和长期知识库
```

但必须注意：

1. T0–T6 不是“数字越高越好”；
2. 不同章节可以采用不同深度；
3. 当前真实任务可以只处理局部；
4. 具体自动评分阈值仍属于候选方案，需要 Benchmark；
5. T6 不是“每本书都必须进入”的默认终点。

## 23. Benchmark：怎样证明不是“高级摘要”

本场景必须对接 `13_评测、Benchmark与质量指标.md`。

至少分四类：

### 23.1 知识正确性

- source attribution accuracy；
- author vs inference separation；
- condition / boundary preservation；
- atom quality；
- principle abstraction error rate；
- Canonical relation accuracy。

### 23.2 多书价值

- duplicate detection precision / recall；
- Knowledge Delta recall；
- false merge rate；
- conflict preservation；
- redundant processing reduction。

### 23.3 人类学习

- delayed recall；
- misconception correction；
- H3 boundary judgment；
- H4 task execution；
- H6 transfer；
- confidence-performance calibration。

### 23.4 AI 使用

至少比较：

```text
Baseline A：模型无书籍资料
Baseline B：原始书籍直接长上下文
Baseline C：普通 RAG
Candidate D：结构化知识 / Book Skill
Candidate E：Canonical Knowledge + 路由
```

比较：

- answer correctness；
- source grounding；
- task success；
- context tokens；
- latency；
- cost；
- hallucination；
- failure recovery。

只有当 Candidate 在真实目标上稳定改善，才能宣布“能力化有效”。

## 25. 当前正式结论

本文件正式确认以下原则：

1. **书籍处理不是摘要任务，而是按目标路由的知识工程场景。**
2. **原书结构、知识结构、人类学习结构和 AI 使用结构必须分开。**
3. **一本到多书后，Knowledge Atom 必须进入 Canonical、关系、去重和增量判断。**
4. **人学与 AI 用是两条不同消费链。**
5. **不是所有重要知识都需要人记忆，也不是所有书都值得 Skill 化。**
6. **Progressive Disclosure / 按需加载是 AI 大规模消费的重要设计原则。**
7. **知识原子多以后，必须同时提供 Human View 与 Machine View。**
8. **行为转化只适用于有明确现实动作、边界和反馈的知识。**
9. **练习必须对应掌握层级，Flashcards 不能证明高阶迁移。**
10. **现实结果必须反馈回知识生命周期，而不是把“提取完成”当终点。**
11. **任何“比普通摘要更强”的判断最终都必须由 Benchmark 证明。**
12. **外部 Skill 和产品用于校准与借鉴，不直接替代本项目正式知识模型。**
