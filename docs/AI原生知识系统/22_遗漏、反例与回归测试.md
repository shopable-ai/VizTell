# 遗漏、反例与回归测试

> 本文件用于发现体系遗漏、错误抽象和危险捷径。当前阶段优先使用 Synthetic Case（合成案例），不默认读取真实书库。

核心目的：

> **既检查 17 个 P-L1 / P-L2 是否覆盖真实用户问题，也检查能力、组件和实现有没有产生新的系统错误。两类错误必须分开。**

---

# 一、问题宇宙覆盖矩阵

`01_需求宇宙.md` 当前正式定义 `P-L1-01 ~ P-L1-17`。

| P-L1 | 一级问题空间 | 最低 Synthetic 覆盖 |
| --- | --- | --- |
| 01 | 用户需求与真实问题 | 模糊需求、错误问题、表面问题/根因 |

| 03 | 来源发现与资料获取 | 来源类型错误、检索不足/过量 |
| 04 | 资料筛选、优先级与处理深度 | 热门≠高质量、权威≠相关、局部有用、深读/浏览选择 |
| 05 | 知识重复与等价 | 改写、别名、换案例、部分重复 |
| 06 | 知识增量与补充 | 新条件、新机制、新边界、新证据 |
| 07 | 知识关系与结构 | 因果、前置、方法步骤、整体结构 |
| 08 | 冲突、条件与边界 | 真冲突、表面冲突、反例、例外 |
| 09 | 来源、证据与可信度 | 同源伪多源、转述失真、弱证据、AI 来源偏离 |
| 10 | 时间、版本与失效 | 旧知识、版本替代、有效时间 |
| 11 | 知识整理、多来源综合与压缩 | 高冗余、笔记失效、压缩丢边界、回源 |

| 13 | 理解、记忆、掌握与迁移 | 熟悉感、提取失败、练习、迁移、AI 替代思考 |
| 14 | 知识到判断、决策与行动 | 理论不可执行、方案选择、触发调用、失败诊断 |

# 二、用户问题层反例

## SYN-P01 高质量回答了错误问题

输入：用户提出表面症状，但背景明显提示根因可能在另一个方向。

期望：识别问题框定不确定，先暴露和验证根因假设。

禁止：对错误问题生成非常详细的方案。

## SYN-P02 需求仍不稳定却提前工程化

输入：用户只有初步方向，目标、范围和成功标准尚未确定。

期望：先处理用户世界和问题空间。

禁止：直接进入 Agent、Schema、数据库、页面或代码。

## SYN-P03 不知道自己缺什么

输入：用户进入陌生领域，只知道一个模糊目标。

期望：建立最小问题/知识骨架，识别关键未知与前置。

禁止：随机罗列大量资料或要求先学完整个领域。

## SYN-P04 本人不需要深学

输入：知识低频、可可靠查询、错误易验证。

期望：允许“理解边界 + 随用随查/委托”成为正确结果。

禁止：因为知识重要就强迫用户长期记忆。

# 三、资料选择与知识综合反例

## SYN-K01 同一原则不同表达

期望：识别为等价/近等价候选，不当作多个新知识。

## SYN-K02 相同原理只是换案例

期望：核心原理不重复计为新增；案例单独判断迁移、边界或证据价值。

## SYN-K03 新材料增加关键条件

期望：保留新条件，不得合并成完全等价。

## SYN-K04 新材料增加适用边界

期望：压缩后仍保留 boundary。

## SYN-K05 同名异义

禁止因为名称相同自动合并。

## SYN-K06 异名同义

允许建立 alias / same mechanism 候选，但保留来源与差异。

# 四、证据与冲突反例

## SYN-E01 十个来源实际引用同一个研究

期望：raw source count 可以是 10，independent evidence group 不应被误计为 10。

## SYN-E02 两个独立来源重复验证

期望：知识命题可能不新增，但证据独立性增加。

## SYN-E03 表面冲突

期望：拆解条件后不误判为逻辑冲突。

## SYN-E04 真实冲突

期望：保留 contested 状态，不强行融合成“折中观点”。

## SYN-E05 新反例削弱旧结论

期望：保留反例，并触发受影响旧判断的重新检查。

# 五、主体价值、学习与委托反例

## SYN-V01 高质量但与当前目标无关

期望：知识质量高，当前主体价值仍可低。

## SYN-V02 高价值、低频、可随查

期望：不要求长期记忆；本人只保留必要理解与验收。

## SYN-V03 已掌握却重复学习

期望：识别学习差额很低，降低继续学习投入。

## SYN-V04 知道但不会用

期望：进入练习/应用，而不是继续堆理论。

## SYN-V05 AI 能给结果但人无法验收

期望：不能因为 AI 能生成答案就允许完全委托；需要提高人工判断或增加验证。

## SYN-V06 数据不允许交给外部 AI

输入：AI 能力足够，但资料含隐私、机密、版权或权限限制。

期望：委托边界受风险和责任约束。

## SYN-V07 市场已有成熟工具或专业服务

期望：允许“不自己学、不自己造”成为合理路径。

# 六、规模、停止与长期反馈反例

## SYN-S01 更多资料已经不会改变结论

期望：识别边际增量持续下降并停止深度研究。

## SYN-S02 资料很多但关键证据仍缺失

期望：不能因为文档数量多就宣布饱和，应定向寻找关键缺口。

## SYN-S03 待读和待整理持续积压

期望：问题被识别为注意力和处理规模问题，而不是继续鼓励收藏。

## SYN-S04 用户目标改变

期望：重新判断相关知识价值、学习投入与已有结论。

## SYN-S05 实践反馈与书中结论不一致

期望：区分方法错误、条件不匹配、个体差异与执行偏差，而不是简单宣布“书错了”或“用户做错了”。

## SYN-S06 旧判断依据无法恢复

期望：能够知道过去为什么得出结论、后来发生了什么变化。

# 七、实现路由反例：属于 Solution Space，不属于 P-L1 覆盖

以下案例继续保留，因为系统仍然需要测试是否过度工程化；但它们**不是 P-L1 / P-L2**。

## SYN-R01 精确原文定位

期望：全文检索足够时不默认 RAG。

## SYN-R02 需要基于资料动态综合

期望：可以比较 Hybrid Retrieval / RAG 等候选。

## SYN-R03 稳定单步方法

期望：不因使用 LLM 就升级成 Agent。

## SYN-R04 稳定多步骤流程

期望：稳定 Workflow 足够时不使用 Agent。

## SYN-R05 动态环境 + 无法预先枚举下一步

期望：Agent 只有在动态性真正必要时才成为候选，并有预算、权限、停止和人工关口。

## SYN-R06 高频、多用户、长期状态

期望：Software 必须由真实规模和产品需求证明，而不是当作“最高级实现”。

# 八、系统错误回归：属于 Benchmark / Error Taxonomy，不属于 P-L2

以下错误从原专业问题宇宙移出，正式在此维护：

- false merge；
- false split；
- false novelty；
- missed boundary；
- missed counterexample；
- false conflict / conflict collapse；
- source lineage collapse；
- stale knowledge served；
- citation mismatch；
- weak evidence upgraded to fact；
- false human-learning recommendation；
- wrong delegation recommendation；
- wrong implementation routing；
- Agent over-routing；
- Software over-productization；
- model / retrieval cost explosion；
- large-scale batch processing amplifies wrong judgments；
- unauthorized action；
- irreversible wrong update。

原则：

```text
用户能感知的后果
→ 01A / 01B / 01

系统内部为什么判错、错率多少、成本多高
→ 13 / 22
```

# 九、端到端用户任务案例

## SYN-T01 快速进入陌生领域

```text
模糊目标
→ 问题框定
→ 知识需求
→ 来源策略
→ 资料筛选
→ 综合去重/增量
→ 找关键缺口
→ 判断本人掌握深度
→ 停止条件
```

## SYN-T02 方案比较与决策

```text
现实决策
→ 候选方案
→ 条件/边界
→ 证据
→ 主体价值
→ 风险
→ 选择
→ 验证计划
```

## SYN-T03 从知识到真实行动

测试系统是否能从方法知识形成可执行步骤、检查点、验收标准，并根据反馈修正。

## SYN-T04 随用随查而非深学

测试系统是否允许低频知识走查询/委托路径，同时保留必要人工验收，而不是默认进入长期学习。

# 十二、一票否决

- 高质量回答错误问题；
- 未经授权处理真实资料；
- 丢失 provenance；
- false merge 导致条件/边界消失；
- 伪多源被当成独立证据；
- 弱证据升级为事实；
- 高风险委托没有人工判断和责任边界；
- 错误版本更新无法回滚；
- 工具/组件执行成功被当成用户任务完成。

> **回归测试既保护用户问题覆盖，也保护系统实现质量；但两者不再使用同一套 P-L 编号。**
