# 遗漏、反例与回归测试

> 本文件维护不依赖真实书库的 Synthetic Benchmark、反例、框架遗漏检查和回归测试。它用于在进入真实资料验证之前证明：核心语义和路由至少能处理人为可控的边界情况。

---

# 1. 回归测试目标

测试对象不是“模型会不会总结”，而是：

- L1/L2/L3 是否能表达问题；
- Knowledge Atom 是否类型正确；
- Canonical Knowledge 是否正确归一；
- Relation Assertion 是否正确；
- Evidence 是否被正确区分；
- Subject Value 与 Knowledge Quality 是否分离；
- Human Learning 与 AI/Tool Route 是否正确；
- Search/RAG/Skill/Workflow/Agent/Software 是否不过度路由；
- 生命周期变化是否局部传播；
- 高风险决策是否进入人工关口。

# 2. Relation / Dedup Synthetic Set

## SYN-R01：纯同义改写

A：`在条件 C 下，方法 M 会提高结果 Y。`

B：`若 C 成立，采用 M 能改善 Y。`

预期：

- `paraphrase_equivalent`；
- 不创建两个 Canonical Claim；
- 两个来源仍分别保留 provenance。

## SYN-R02：新增条件

A：`方法 M 会提高 Y。`

B：`只有条件 C 成立时，方法 M 才提高 Y。`

预期：

- 不能判为完全等价；
- B 至少是 `adds_condition` / `refines`；
- 若 B 证据更强，A 可能需要缩小 scope。

## SYN-R03：新增边界

A：`方法 M 对所有对象有效。`

B：`在对象类型 T2 上，M 不产生效果。`

预期：

- B 是 boundary/counterexample；
- 不得把 B 当作“另一个案例”忽略。

## SYN-R04：同名异义

A：某领域中的 `Model X` 定义为 D1。

B：另一领域中的 `Model X` 定义为 D2。

预期：

- 字符串相同不能合并；
- 建两个 Concept；
- 通过 scope/domain 消歧。

## SYN-R05：异名同义

A：`ABC effect` 定义 D。

B：`XYZ bias` 定义同一 D，机制与条件一致。

预期：

- alias/canonical candidate；
- 不因名称差异制造伪增量。

## SYN-R06：包含关系

A：方法 M 包含步骤 1-5。

B：只描述步骤 2-4。

预期：`contains/is_contained_by`，不是 duplicate。

# 3. Evidence Synthetic Set

## SYN-E01：伪多源

Source A、B、C 都引用原始研究 E1。

预期：

- raw source count = 3；
- primary evidence source count = 1；
- independent evidence group count = 1。

## SYN-E02：真正独立证据

E1 与 E2 使用不同数据、不同团队、独立方法验证相同 Claim。

预期：

- independent evidence group count = 2；
- 可以提高证据覆盖，但不能简单做“2票赞成”。

## SYN-E03：专家观点无数据

权威专家提出 Claim C，但没有公开证据。

预期：

- source expertise 可高；
- evidence strength 不能因此自动高；
- epistemic status 至少保持 opinion/unverified claim。

## SYN-E04：二手文章准确转述强研究

预期：

- 二手来源本身不是 primary evidence；
- 可以作为 discovery/source pointer；
- Claim 的证据应挂到原始研究。

## SYN-E05：案例冒充因果证据

一个成功案例被用来证明普遍因果规律。

预期：

- Case 与 general Claim 分开；
- 不能自动升级为强因果证据。

---

# 4. Conflict Synthetic Set

## SYN-C01：真正冲突

同条件、同对象、同指标、同时间：

- A：M 提高 Y；
- B：M 降低 Y。

预期：`conflicts_with`，进入核查。

## SYN-C02：表面冲突——条件不同

- A：C1 下 M 提高 Y；
- B：C2 下 M 降低 Y。

预期：

- 不属于逻辑冲突；
- 生成条件分层。

## SYN-C03：表面冲突——时间版本不同

旧规则 A 在 2024 有效，新规则 B 自 2026 起替代。

预期：

- temporal/version relation；
- 保留历史有效性；
- 当前查询默认命中新规则。

## SYN-C04：定义冲突

两个来源使用同一术语但定义不同。

预期：先做 Concept disambiguation，再比较 Claim。

# 5. Subject Value Synthetic Set

## SYN-V01：高质量、低主体价值

一项高度可靠、专业且稳定的知识与当前目标/项目无关。

预期：

- epistemic quality 高；
- subject utility 低；
- 不进入当前高优先级学习。

## SYN-V02：简单知识、高当前价值

一个简单检查规则能避免当前项目重大损失。

预期：

- complexity 低；
- current utility / risk value 高；
- 可能进入 Checklist/Workflow 或人类必须掌握。

## SYN-V03：市场价值高、个人价值低

某技能外部支付意愿很高，但主体没有对应目标且可外包。

预期：market value 高；subject learning priority 可低。

## SYN-V04：低频但极高单次价值

十年一次的决策，错误损失极大。

预期：不能因为 frequency 低直接忽略；应提升验证/决策支持要求。

# 6. Learning Fit Synthetic Set

## SYN-L01：已有 80% 前置覆盖

主体已掌握核心概念和相邻技能。

预期：

- knowledge complexity 不变；
- individual learning cost 显著下降；
- 只学习差额。

## SYN-L02：错误旧知识导致负迁移

主体已有强烈但错误的旧模型。

预期：

- overlap 高不能等同“好学”；
- 增加 misconception correction cost。

## SYN-L03：必须形成现场直觉

知识用于低延迟、高频、高风险现场判断。

预期：Reference/RAG 不足；提高 practice_to_fluency。

## SYN-L04：变化太快的细节

某 API 参数每月变化，但可可靠实时检索。

预期：降低长期记忆投入，偏向 Reference/RAG。

---

# 7. Human / AI / Tool Routing Synthetic Set

## SYN-H01：成熟工具完全覆盖

工具稳定、便宜、可验证。

预期：Existing Tool Integration 优先；人只需理解边界和验收。

## SYN-H02：AI 能答但不可验证

LLM 通常给出流畅结果，但错误难检测且代价高。

预期：不能因为“AI capability high”直接自动化；增加 human gate 或外部验证。

## SYN-H03：规则稳定、高频重复

预期：Skill / Workflow / Automation 候选上升。

## SYN-H04：动态环境、多分支、下一步依赖反馈

预期：Agent 候选上升，但需要状态、预算、工具权限和停止条件。

---

# 8. Implementation Routing Synthetic Set

## SYN-I01：精确错误码定位

预期：Full-text Search 优先，RAG 不是必要前提。

## SYN-I02：用户表述与文档措辞差异大

预期：Semantic/Hybrid Search。

## SYN-I03：需要任务时动态综合多个来源并引用

预期：RAG + evidence/citation contract。

## SYN-I04：稳定的五步审批链

预期：Workflow，而不是 Agent。

## SYN-I05：需要持续观察网页状态并根据变化决定下一步

预期：Agent/Automation 组合候选。

## SYN-I06：高频、多用户、长期状态、复杂权限、稳定 UI

预期：Software/Product 化信号强。

## SYN-I07：已有成熟 SaaS 能覆盖 95% 需求

预期：Existing Tool Integration，除非数据/成本/锁定等约束不允许。

---

# 9. Lifecycle Synthetic Set

## SYN-T01：新证据只影响一个 Claim

预期：局部更新，不重跑整个知识库。

## SYN-T02：基础概念版本变化影响多个下游方法

预期：Impact Propagation 找到受影响 Canonical、RAG、Skill、Workflow、学习内容。

## SYN-T03：知识仍有效，但工具实现过时

预期：knowledge lifecycle 与 implementation lifecycle 分离。

## SYN-T04：当前不需要但触发条件明确

预期：Deferred + trigger，不删除。

---

# 10. Risk / Governance Synthetic Set

## SYN-G01：高价值但版权不允许再分发

预期：可保留合法允许的索引/元数据/内部处理状态，但输出和存储动作受许可约束。

## SYN-G02：可自动执行但不可逆

预期：Automation feasibility 高，但必须 human gate。

## SYN-G03：知识已被替代

预期：旧版本进入 historical/superseded，不物理删除 provenance。

## SYN-G04：AI 自动 merge 后人工发现错误

预期：Relation Assertion 可回滚；恢复原 Canonical 边界和来源关系。

# 11. Framework Orthogonality Tests

## ORTH-01

“高专业度”不能自动提高“证据强度”。

## ORTH-02

“知识复杂度”不能自动等于“个体学习成本”。

## ORTH-03

“当前相关性”不能改变“事实真伪”。

## ORTH-04

“AI 能执行”不能自动意味着“允许自动执行”。

## ORTH-05

“版本状态”不能与“语义替代关系”混成同一字段。

## ORTH-06

“系统处理状态”不能与“知识可信状态”混淆。

## ORTH-07

“市场价值”不能覆盖“主体价值”。

## ORTH-08

“技术基础设施”属于 Solution Space，不应反向定义需求。

# 12. Regression Case Schema 候选

```yaml
benchmark_case:
  case_id: SYN-R02
  category: relation
  description: "同主张但新增条件"
  inputs: []
  expected:
    relation_type: adds_condition
    canonical_merge: false
  forbidden:
    - paraphrase_equivalent
    - automatic_delete
  severity_if_failed: high
  rationale: "条件差异会改变适用边界"
  status: active
```

# 13. 验收规则

每次框架、Schema、模型、Prompt 或实现变化后，至少检查：

- 是否出现旧案例回归；
- 是否增加 false merge；
- 是否增加 false conflict；
- 是否把弱证据升级为事实；
- 是否把低主体价值错误推给人工学习；
- 是否出现 Agent/Software 过度路由；
- 是否丢失 provenance；
- 是否能从错误决策回滚。

在合成回归集尚未稳定前，不进入大规模真实书库验证。
