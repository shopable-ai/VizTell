# 遗漏、反例与回归测试

> 本文件用于发现体系遗漏、错误抽象和危险捷径。当前阶段只使用 Synthetic Case（合成案例），不默认读取真实书库。

核心目的：

> **不是证明系统“看起来完整”，而是主动寻找哪些 P-L1 / P-L2 问题没有被能力、协议和 Benchmark 覆盖。**

---

| 03 | 来源发现与资料获取 | 来源类型错误、检索不足/过量 |
| 04 | 资料筛选与阅读优先级 | 热门≠高质量、权威≠相关、局部有用 |
| 05 | 知识重复与等价 | 改写、别名、换案例、部分重复 |
| 06 | 知识增量与补充 | 新条件、新机制、新边界、新证据 |
| 07 | 知识关系与结构 | 因果、前置、方法步骤、替代/补充 |

# 二、用户问题层反例

## SYN-P01 高质量回答了错误问题

输入：用户提出一个表面症状，但背景明显提示根因在另一个方向。

期望：识别问题框定不确定，不直接把表面问题当最终问题，输出需要验证的根因假设。

禁止：对表面问题生成非常详细但方向错误的方案。

## SYN-P02 需求仍不稳定却提前工程化

输入：用户只有初步方向，需求、目标和范围尚未确定。

期望：优先澄清问题、目标和成功标准。

禁止：直接进入 Agent、Schema、数据库、页面和代码实现。

## SYN-P03 不知道自己缺什么

输入：用户要进入陌生领域，只知道一个模糊目标。

期望：建立最小问题/知识骨架，识别关键未知与前置知识。

禁止：随机罗列大量资料或默认要求读完整个书库。

# 三、资料选择与知识综合反例

## SYN-K01 同一原则不同表达
期望：识别为等价/近等价候选，不当作多个独立新知识。

## SYN-K02 相同原理只是换案例
期望：核心原理不重复计为新增；案例单独判断是否带来边界、迁移或证据价值。

禁止：因为案例文本差异大就判定为新原理。

## SYN-K03 新材料增加一个关键条件
期望：`adds_condition`，不得自动合并成完全等价。

## SYN-K04 新材料增加适用边界
期望：保留 boundary，禁止压缩时丢失。

## SYN-K05 同名异义
期望：禁止因为名称相同自动 Canonical merge。

## SYN-K06 异名同义
期望：允许 alias / same mechanism 候选，但仍保留来源。

# 四、证据与冲突反例

## SYN-E01 十个来源实际引用同一个研究
期望：raw source count 可以是 10，但 independent evidence group count 不应被误计为 10。

## SYN-E02 两个独立来源真正重复验证
期望：知识内容可能不新增，但证据独立性增加。

## SYN-E03 表面冲突
期望：拆解条件后不误判为逻辑冲突。

## SYN-E04 真实冲突
期望：保留 contested 状态，不强行融合成“中间观点”。

## SYN-E05 新反例削弱旧结论
期望：保留 counterexample 并触发相关知识重验证。

# 五、主体价值、学习与分工反例

## SYN-V01 高质量但与当前目标无关
期望：知识质量高，但当前 subject utility 低。

## SYN-V02 高价值、低频、可随查
期望：Reference / Search / RAG 候选，不要求深度记忆。

## SYN-V03 已掌握却重复学习
期望：识别 learning gap 很低，降低学习投入。

## SYN-V04 知道但不会用
期望：进入练习/应用，而不是继续提供更多理论材料。

## SYN-V05 AI 能完成但失败不可逆
期望：AI capability 高，但 automation permission 低，必须人工关口。

## SYN-V06 市场已有成熟工具
期望：优先 Existing Tool Integration，而不是自建软件。

# 六、实现路由反例

## SYN-R01 精确原文定位
期望：Full-text Search 足够，不默认 RAG。

## SYN-R02 需要基于资料动态综合
期望：RAG / Hybrid Retrieval 候选。

## SYN-R03 稳定单步方法
期望：Skill 候选，不升级为 Agent。

## SYN-R04 稳定多步骤流程
期望：Workflow 候选，不因使用 LLM 就叫 Agent。

## SYN-R05 动态环境 + 无法预先枚举下一步
期望：Agent 候选，但必须有预算、权限、停止条件和人工关口。

## SYN-R06 高频、多用户、长期状态
期望：Software 候选；若只是一两次使用则不得产品化。

---

# 七、规模、停止与长期演化反例

## SYN-S01 更多资料已经不会改变结论
期望：识别边际增量下降并停止深度研究。

## SYN-S02 资料很多但关键证据仍缺失
期望：不能因为文档数量多就宣布饱和，应定向寻找关键缺口。

## SYN-S03 新版本替代旧版本
期望：正确记录 supersedes/replaces、有效时间和影响对象。

## SYN-S04 用户目标改变
期望：局部重算主体价值、学习和实现路由，不全库重算。

## SYN-S05 旧版本回滚
期望：错误更新可以回滚，provenance 和版本链不丢失。

# 八、端到端用户任务案例

## SYN-T01 快速进入陌生领域

测试链：

```text
模糊目标
→ 问题框定
→ 知识需求
→ 来源策略
→ 资料筛选
→ 综合去重/增量
→ 找关键缺口
→ 学习路线
→ 停止条件
```

禁止：默认扫描全部真实书库；用资料数量代替知识覆盖；输出大量摘要但没有形成领域骨架。

## SYN-T02 方案比较与决策

测试链：

```text
现实决策
→ 候选方案
→ 条件/边界
→ 证据
→ 主体价值
→ 风险
→ 选择
→ 验证计划
```

禁止：只罗列优缺点不做条件判断；用来源数量代替证据独立性；忽略用户约束。

## SYN-T03 从知识到真实行动

测试系统是否能从方法知识形成可执行步骤、检查点、验收标准，并根据反馈修正。

禁止：继续提供更多知识但不推动行动。

# 十一、真实数据 Gate

当前文件所有案例默认是人工构造的合成案例。

只有在对应 P-L1/P-L2 已明确、能力和期望结果已定义、Synthetic Benchmark 已通过、`21_验证计划、样本清单与数据边界.md` 的 Manifest 已建立之后，才允许进入受控真实样本。

禁止为了“找案例”默认扫描 `temp/` 或现有真实书库。

# 十二、一票否决

- 高质量回答错误问题；
- 未经授权处理真实资料；
- 丢失 provenance；
- false merge 导致条件/边界消失；
- 伪多源被当成独立证据；
- 弱证据升级为事实；
- 高风险自动化越权；
- 错误版本更新无法回滚；
- 工具/组件执行成功被当成用户任务完成。

> **回归测试的最终职责不是保护某个技术实现，而是保护“系统真正解决用户问题”的能力。**
