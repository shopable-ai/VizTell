# 遗漏、反例与回归测试

> 本文件用于发现体系遗漏、错误抽象和危险捷径。当前阶段优先使用 Synthetic Case（合成案例），不默认读取真实书库。

核心目的：

> **既检查 17 个 P-L1 / P-L2 是否覆盖真实用户问题，也检查分类边界是否正确，还检查能力、组件和实现有没有产生新的系统错误。三类错误必须分开。**

---

## 一、问题宇宙覆盖矩阵

`01_需求宇宙.md` 当前正式定义 `P-L1-01 ~ P-L1-17`。

| P-L1 | 一级问题空间 | 最低 Synthetic 覆盖 |
| --- | --- | --- |
| 01 | 用户需求与真实问题 | 模糊需求、错误问题、表面问题/根因 |
| 02 | 知识需求识别 | 未知缺口、前置缺失、知识深度 |
| 03 | 来源发现与资料获取 | 来源类型错误、检索不足/过量 |
| 04 | 资料筛选、优先级与处理深度 | 热门≠高质量、权威≠相关、局部有用、深读/浏览选择 |
| 05 | 知识重复与等价 | 改写、别名、换案例、部分重复 |
| 06 | 知识增量与补充 | 新条件、新机制、新边界、新证据 |
| 07 | 知识关系与结构 | 因果、前置、方法步骤、整体结构 |
| 08 | 冲突、条件与边界 | 真冲突、表面冲突、反例、例外 |
| 09 | 来源、证据与可信度 | 同源伪多源、转述失真、弱证据、AI 来源偏离 |
| 10 | 时间、版本与失效 | 旧知识、版本替代、有效时间 |
| 11 | 知识整理、多来源综合与压缩 | 高冗余、笔记失效、压缩丢边界、回源 |
| 12 | 主体价值与优先级 | 高质量低相关、高价值高成本 |
| 13 | 理解、记忆、掌握与迁移 | 熟悉感、提取失败、练习、迁移、AI 替代思考 |
| 14 | 知识到判断、决策与行动 | 理论不可执行、方案选择、触发调用、失败诊断 |
| 15 | 本人掌握、委托与监督边界 | 随查/委托、人工验收、权限责任、能力退化 |
| 16 | 规模、注意力与研究停止 | 过度研究、边际增量下降、注意力超载、停止/重启 |
| 17 | 反馈、修正与长期再判断 | 目标变化、实践反馈、旧判断重查、历史恢复 |

要求：

- 每个 P-L1 至少有一个合成案例；
- 高优先 P-L2 必须有直接案例；
- 高风险 P-L2 必须定义 Forbidden Outcome；
- 完整任务案例应跨多个 P-L1；
- `01B` 的 SUP 必须能够映射到正式 P-L2，或者明确标记 `PARTIAL / MISSING / MISPLACED`；
- 不允许为了得到“100% COVERED”把候选问题强行塞入错误分类。

## 二、P-L2 分类质量 Gate

仅有 Coverage 不够。P-L2 本身还必须通过以下测试。

### 2.1 类型纯度 Gate

每个 P-L2 必须回答一个稳定的问题、困难、失败、缺口、冲突或判断不确定性。

以下表达单独出现时应判定失败：

- “增加新概念”——这是增量类型；
- “需要主动记忆”——这是掌握深度状态；
- “因果关系”——这是关系类型；
- “海量资料”——这是规模属性；
- “需要 RAG”——这是实现选择；
- “false merge”——这是系统错误。

### 2.2 上游支持 Gate

正式 P-L2 至少要满足一个：

- 有 `01A` 用户表达支持；
- 有 `01B` SUP 支持；
- 有明确合成反例证明问题稳定存在。

禁止只因为“从系统架构看应该有”就创建 P-L2。

### 2.3 同级去重 Gate

对同一 P-L1 下任意两个近似 P-L2，应能回答：

> “什么案例只属于 A、不属于 B？”

如果无法给出，优先合并、改写或降级为属性。

### 2.4 相邻 P-L1 边界 Gate

对高混淆边界必须存在至少一个 adversarial case：

- 01 vs 02；
- 03 vs 04；
- 04 vs 16；
- 05 vs 06；
- 06 vs 09；
- 07 vs 11；
- 11 vs 13；
- 08 vs 09；
- 09 vs 17；
- 10 vs 17；
- 12 vs 04；
- 13 vs 14；
- 14 vs 17；
- 15 vs Capability；
- 16 vs 工程成本。

### 2.5 Solution Leakage Gate

如果一个候选问题只能通过下列词汇才成立：

- 向量库；
- RAG；
- Agent；
- Graph DB；
- 缓存；
- token；
- 模型规格；

则默认不属于 P-L2，除非先能改写成无需这些实现词仍然成立的用户问题。

## 三、相邻分类对抗测试

### SYN-B01 05 重复 vs 06 增量

输入 A：第二本书用完全不同故事解释同一原则，没有新增条件、机制、边界或证据。

期望：主归属 `05`，不因为“案例不同”自动进入实质增量。

输入 B：第二本书结论相同，但增加一个会改变使用范围的关键边界。

期望：核心原则可重复，新增边界必须进入 `06`，并与 `08` 建立关联。

禁止：把整份资料整体二分为“重复”或“新增”。

### SYN-B02 07 知识结构 vs 11 外部整理 vs 13 内部理解

输入：系统已经正确识别概念 A → 机制 B → 方法 C 的关系，但生成的笔记仍是一百条平铺卡片，用户看完后也无法解释整体模型。

期望：

- 关系本身正确：`07` 可通过；
- 外部表达不可用：命中 `11`；
- 用户仍未形成内部模型：命中 `13`。

禁止：把三个不同层次都归结为“知识结构不好”。

### SYN-B03 09 新证据判断 vs 17 旧判断重查

输入：出现一项新研究。

期望：

1. `09` 先判断它是否独立、质量如何、是否足以支持/削弱旧主张；
2. 若证据状态真的改变，再由 `17` 判断哪些既有结论、决策和优先级要重看。

禁止：新证据一出现就直接修改所有旧结论。

### SYN-B04 10 版本变化 vs 17 影响传播

输入：一个软件框架从 v3 升级到 v4。

期望：

- `10` 识别哪些规则被替代、哪些只是修订、哪些仍有效；
- `17` 再检查历史项目决策是否受这些变化影响。

禁止：把“版本差异”与“所有下游判断更新”混成同一个 P-L2。

### SYN-B05 13 迁移能力 vs 14 现实行动

输入 A：用户只会在原教材案例中识别某原则，换场景就想不到。

期望：主归属 `13`。

输入 B：用户已经正确识别当前现实场景应使用该原则，但仍无法形成可执行方案。

期望：主归属 `14`。

### SYN-B06 04 局部处理深度 vs 16 规模注意力

输入 A：只有一本 300 页书，用户不知道应浏览还是精读。

期望：主归属 `04`。

输入 B：有 2 万份候选资料，即使每份只花 5 分钟也不可持续，且不知道何时停止。

期望：主归属 `16`。

### SYN-B07 15 人机分工问题 vs 20 系统能力

输入：用户问“高风险领域里 AI 可以帮我，但哪些判断必须我自己保留？”

期望：命中 `15`。

后续系统可以推导人工验收、权限、审计等 Capability，但这些能力不能反向成为新 P-L2。

### SYN-B08 AI 一次拿多少知识

输入：系统一次给模型 300 条低相关知识，重要条件被噪声淹没且成本上升。

期望：

- 用户可感知的错误后果可映射到可信度、综合、行动等 P；
- “上下文选择是否过量”进入 `20` 的 AI Knowledge Consumption；
- 噪声率、遗漏率、成本进入 `13 / 22`。

禁止：创建“P-L2：AI 上下文 token 太多”。

### SYN-B09 Problem Graph / 问题状态机

输入：多个对话反复发现同一问题，希望记录问题状态、依赖与历史。

期望：

- 用户侧重复研究、历史恢复可由 `16-04 / 17-05` 等解释；
- 是否建立 Problem Registry / Graph / State Machine 属于 Capability / Implementation 候选。

禁止：恢复旧 `P-L1-18` 只为了容纳治理结构。

## 四、用户问题层反例

### SYN-P01 高质量回答了错误问题

输入：用户提出表面症状，但背景明显提示根因可能在另一个方向。

期望：识别问题框定不确定，先暴露和验证根因假设。

禁止：对错误问题生成非常详细的方案。

### SYN-P02 需求仍不稳定却提前工程化

输入：用户只有初步方向，目标、范围和成功标准尚未确定。

期望：先处理用户世界和问题空间。

禁止：直接进入 Agent、Schema、数据库、页面或代码。

### SYN-P03 不知道自己缺什么

输入：用户进入陌生领域，只知道一个模糊目标。

期望：建立最小问题/知识骨架，识别关键未知与前置。

禁止：随机罗列大量资料或要求先学完整个领域。

### SYN-P04 本人不需要深学

输入：知识低频、可可靠查询、错误易验证。

期望：允许“理解边界 + 随用随查/委托”成为正确结果。

禁止：因为知识重要就强迫用户长期记忆。

## 五、资料选择与知识综合反例

### SYN-K01 同一原则不同表达

期望：识别为等价/近等价候选，不当作多个新知识。

### SYN-K02 相同原理只是换案例

期望：核心原理不重复计为新增；案例单独判断迁移、边界或证据价值。

### SYN-K03 新材料增加关键条件

期望：保留新条件，不得合并成完全等价。

### SYN-K04 新材料增加适用边界

期望：压缩后仍保留 boundary。

### SYN-K05 同名异义

禁止因为名称相同自动合并。

### SYN-K06 异名同义

允许建立 alias / same mechanism 候选，但保留来源与差异。

### SYN-K07 新独立证据但没有新命题

输入：新研究得出与已有命题相同的结论，但研究来源独立、方法质量较高。

期望：知识命题不必复制；证据增量必须保留。

禁止：因为“结论重复”把独立证据一起删除。

## 六、证据与冲突反例

### SYN-E01 十个来源实际引用同一个研究

期望：raw source count 可以是 10，independent evidence group 不应被误计为 10。

### SYN-E02 两个独立来源重复验证

期望：知识命题可能不新增，但证据独立性增加。

### SYN-E03 表面冲突

期望：拆解条件后不误判为逻辑冲突。

### SYN-E04 真实冲突

期望：保留 contested 状态，不强行融合成“折中观点”。

### SYN-E05 新反例削弱旧结论

期望：保留反例，并触发受影响旧判断的重新检查。

## 七、主体价值、学习与委托反例

### SYN-V01 高质量但与当前目标无关

期望：知识质量高，当前主体价值仍可低。

### SYN-V02 高价值、低频、可随查

期望：不要求长期记忆；本人只保留必要理解与验收。

### SYN-V03 已掌握却重复学习

期望：识别学习差额很低，降低继续学习投入。

### SYN-V04 知道但不会用

期望：进入练习/应用，而不是继续堆理论。

### SYN-V05 AI 能给结果但人无法验收

期望：不能因为 AI 能生成答案就允许完全委托；需要提高人工判断或增加验证。

### SYN-V06 数据不允许交给外部 AI

输入：AI 能力足够，但资料含隐私、机密、版权或权限限制。

期望：委托边界受风险和责任约束。

### SYN-V07 市场已有成熟工具或专业服务

期望：允许“不自己学、不自己造”成为合理路径。

### SYN-V08 熟悉感不等于掌握

输入：用户看到答案时觉得全部会，但无提示时无法回忆，换场景也不会判断。

期望：命中 `13` 的主动提取与迁移问题，而不是继续用重复阅读证明掌握。

## 八、规模、停止与长期反馈反例

### SYN-S01 更多资料已经不会改变结论

期望：识别边际增量持续下降并停止深度研究。

### SYN-S02 资料很多但关键证据仍缺失

期望：不能因为文档数量多就宣布饱和，应定向寻找关键缺口。

### SYN-S03 待读和待整理持续积压

期望：问题被识别为注意力和处理规模问题，而不是继续鼓励收藏。

### SYN-S04 用户目标改变

期望：重新判断相关知识价值、学习投入与已有结论。

### SYN-S05 实践反馈与书中结论不一致

期望：区分方法错误、条件不匹配、个体差异与执行偏差，而不是简单宣布“书错了”或“用户做错了”。

### SYN-S06 旧判断依据无法恢复

期望：能够知道过去为什么得出结论、后来发生了什么变化。

## 九、实现路由反例：属于 Solution Space，不属于 P-L1 覆盖

以下案例继续保留，因为系统仍然需要测试是否过度工程化；但它们**不是 P-L1 / P-L2**。

### SYN-R01 精确原文定位

期望：全文检索足够时不默认 RAG。

### SYN-R02 需要基于资料动态综合

期望：可以比较 Hybrid Retrieval / RAG 等候选。

### SYN-R03 稳定单步方法

期望：不因使用 LLM 就升级成 Agent。

### SYN-R04 稳定多步骤流程

期望：稳定 Workflow 足够时不使用 Agent。

### SYN-R05 动态环境 + 无法预先枚举下一步

期望：Agent 只有在动态性真正必要时才成为候选，并有预算、权限、停止和人工关口。

### SYN-R06 高频、多用户、长期状态

期望：Software 必须由真实规模和产品需求证明，而不是当作“最高级实现”。

## 十、系统错误回归：属于 Benchmark / Error Taxonomy，不属于 P-L2

以下错误正式在此维护：

- false merge；
- false split；
- false novelty；
- missed boundary；
- missed counterexample；
- false conflict / conflict collapse；
- source lineage collapse；
- stale knowledge served；
- citation mismatch；
- weak evidence upgraded to fact；
- false human-learning recommendation；
- wrong delegation recommendation；
- wrong implementation routing；
- Agent over-routing；
- Software over-productization；
- model / retrieval cost explosion；
- large-scale batch processing amplifies wrong judgments；
- unauthorized action；
- irreversible wrong update；
- wrong P-L1 / P-L2 classification；
- state-as-problem：把状态值错误建成 P-L2；
- type-as-problem：把知识类型/关系类型错误建成 P-L2；
- solution leakage：把实现载体重新混入 Problem Space；
- forced coverage：为了 100% COVERED 把 Missing Candidate 强行塞入错误分类。

原则：

```text
用户能感知的后果
→ 01A / 01B / 01

分类放错位置
→ 01 / 22 的 Taxonomy Regression

系统内部为什么判错、错率多少、成本多高
→ 13 / 22
```

## 十一、端到端用户任务案例

### SYN-T01 快速进入陌生领域

```text
模糊目标
→ 问题框定
→ 知识需求
→ 来源策略
→ 资料筛选
→ 综合去重/增量
→ 找关键缺口
→ 判断本人掌握深度
→ 停止条件
```

### SYN-T02 方案比较与决策

```text
现实决策
→ 候选方案
→ 条件/边界
→ 证据
→ 主体价值
→ 风险
→ 选择
→ 验证计划
```

### SYN-T03 从知识到真实行动

测试系统是否能从方法知识形成可执行步骤、检查点、验收标准，并根据反馈修正。

### SYN-T04 随用随查而非深学

测试系统是否允许低频知识走查询/委托路径，同时保留必要人工验收，而不是默认进入长期学习。

### SYN-T05 海量资料但只需最小充分知识

输入：领域内有海量资料，但当前任务只需要回答一个高价值决策问题。

测试：

```text
当前问题
→ 所需知识
→ 高价值资料
→ 去重/增量
→ 关键证据
→ 最小充分知识
→ 停止
```

禁止：以“资料很多”为理由全库深处理或全量塞入 AI 上下文。

## 十二、回归触发器

以下变化应重新跑相关案例：

- P-L1 / P-L2；
- P-L2 准入规则；
- SUP；
- Requirement Pattern；
- Knowledge Atom / Canonical / Relation 语义；
- Evidence taxonomy；
- Learning / Delegation rule；
- Capability map；
- Implementation routing；
- Schema；
- 模型、Prompt、Embedding、Reranker；
- 阈值；
- 时间、版本、权限政策。

当 `01` 的 P-L2 文案或所有权边界改变时，至少重跑 `SYN-B01 ~ SYN-B09`。

## 十三、真实数据 Gate

只有在对应问题、能力和预期结果明确，Synthetic Benchmark 已通过，并建立 `21_验证计划、样本清单与数据边界.md` 规定的 Manifest 后，才允许进入受控真实样本。

---

## 十四、一票否决

- 高质量回答错误问题；
- 未经授权处理真实资料；
- 丢失 provenance；
- false merge 导致条件/边界消失；
- 伪多源被当成独立证据；
- 弱证据升级为事实；
- 高风险委托没有人工判断和责任边界；
- 错误版本更新无法回滚；
- 工具/组件执行成功被当成用户任务完成；
- 把 Capability / Implementation 再次写回 P-L1 / P-L2；
- 为了“完整”消灭所有 PARTIAL / MISSING 候选。

> **回归测试现在同时保护三件事：问题是否覆盖、分类是否放对位置、系统实现是否可靠；三者不再共用同一套编号和评价逻辑。**
