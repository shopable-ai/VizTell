## 一、本轮先给结论

本轮最重要的变化不是“补更多编号”，而是把专业分类转换成普通用户可以理解、机器又可以稳定审计的问题体系。

正式结论：

1. 17 个 P-L1 继续保留，不新增、不合并。
2. 正式采用“一个稳定问题身份 + 一个主归属 + 多个关联归属 + 多阶段 + 多场景/规模标签”。
3. 旧 183 个 P-L2 身份收敛为 **151 个 canonical P-L2 + 32 个迁移别名/降级项**。
4. 本轮最主要的重复来源不是用户问题真的有 32 个消失，而是过去把“变体、类型、关系、状态、阶段”误当成独立问题身份。
5. `01B` 从“一个 SUP 挂很多 P-L2”改成“主映射 + 关联映射”，避免覆盖率看起来很高但用户仍不知道主要问题是什么。
6. 长任务中断与上下文恢复明确保留为一个稳定问题 `13-13`，允许跨 J07/J08/J17/J18 和阅读/项目/长期研究场景。
7. AI 参与默认是场景/主体标签；只有 AI 引入新的失效机制时，才增加关联问题，不因“由 AI 执行”复制同机制 P-L2。
8. `20` 当前 14 个前台通用能力仍可承接收敛后的问题，本轮不需要因为 P-L2 数量变化机械增删 Capability。

## 二、为什么“多标签”不能等于“多身份”

真实用户问题天然不是互斥分类。

例如：

> “每一条知识都看懂，但脑中没有形成整体理解。”

它同时涉及：

- 07：知识关系是否清楚；
- 11：外部整理是否形成可理解结构；
- 13：用户本人是否形成内部模型。

但如果知识关系和外部整理都已经正确，用户本人仍然无法形成整体理解，主失败机制仍然是 `13-11`。

因此正确模型不是：

```text
一个现象
→ 三个同等问题身份
```

而是：

```text
稳定问题身份：13-11
主归属：13
关联：07 / 11
出现阶段：J09 / J16 等
场景：单书 / 多书 / 陌生领域等
```

同样：

> “停两周以后完全接不上。”

可以出现在阅读、项目和长期研究，但只要核心失败机制都是“上下文、进度、关键判断和未决问题无法恢复”，就应该共享 `13-13`，而不是制造三个 P-L2。

## 三、183 → 151 的具体收敛来源

### 3.1 P-L1-05：等价变体不再各占 P-L2

合并 5 个旧身份到 `05-01`：

- 换一种表达；
- 异名同义；
- 相同原理换说明性案例；
- 大量扩写但无实质新增；
- 摘要、改写、转载造成伪新增。

它们本质都是：

> **材料表面不同，但实质知识等价或近等价。**

差异应进入 `equivalence_variant`，不需要五个问题身份。

保留：

- `05-07` 同名异义：这是另一种真实风险——错误合并；
- `05-08` 部分重复、部分新增：它无法被整份资料二分。

### 3.2 P-L1-06：增量类型不再冒充问题

旧：新机制、新原因、新步骤、新方法、细化、新组合……

这些是 `increment_type`。

真正稳定的问题是：

> **新材料看起来不同，但无法判断是否真的增加了新的可用知识。**

因此：

- 一般增量判断统一到 `06-01`；
- 条件/边界类重要增量统一到 `06-06`；
- 案例/反例/证据的增量性质保留 `06-08`，因为它需要区分说明性重复、迁移增量和证据增量。

本组净化 7 个旧身份。

### 3.3 P-L1-07：关系类型不再各占 P-L2

旧：

- 上位—下位；
- 部分—整体；
- 原因—结果；
- 前提—结论；
- 问题—方法；
- 方法—步骤；
- 原理—应用；
- 理论—案例；
- 依赖/前置；
- 替代/补充/组合。

这些是 `relation_type`，不是十个不同用户问题。

真正稳定的问题是：

> **关键知识关系没有被识别清楚，知识仍是一堆孤立碎片。**

因此用 `07-01` 作为 canonical 关系问题，保留 `07-11` 作者目录与实际知识结构不一致、`07-12` 跨章节/跨资料整体结构失败两个独立问题。

本组净化 9 个旧身份。

### 3.4 P-L1-08：适用条件值不再复制问题

旧 `08-03 / 08-04 / 08-05` 分别把：

- 场景；
- 人群/主体；
- 时间

作为不同“表面冲突”问题。

它们本质都是 `applicability_condition`。

只要核心机制是：

> 表面冲突来自成立条件不同，用户没有把条件拆出来，

统一到 `08-02`。

如果是版本/时效失效，则进入 10，而不是继续留在 08。

本组净化 3 个旧身份。

### 3.5 P-L1-10：版本关系归一

`10-02 / 10-03` 原来分别问“是否替代”和“修订/补充/并行/替代”。

它们是同一个稳定判断任务：

> **新旧版本究竟是什么关系？**

统一到 `10-02`；具体关系是 `version_relation` 值。

### 3.6 P-L1-11：AI 压缩不是第二个压缩问题

旧 `11-16`：AI 压缩遗漏关键差异、条件或边界。

与 `11-06` 的核心失败机制相同：

> **压缩/摘要/重组丢失决策相关信息。**

因此统一到 `11-06`。

AI 参与保留为场景标签；如果 AI 同时引入来源未支持内容，再关联 `09-11`；如果用户无法验收，再关联 `15-03`。

### 3.7 P-L1-13：掌握深度值不再各占 P-L2

旧 `13-01 ~ 13-06` 事实上主要在枚举：

- 知道存在；
- 理解；
- 主动提取；
- 独立判断；
- 实际应用；
- 稳定技能。

这些应该是 `mastery_depth`。

真正稳定的问题是：

> **不知道某项知识应该掌握到什么深度，导致过度学习或掌握不足。**

统一为 `13-01`。

已经真实发生的学习失败仍保留独立身份，例如：

- `13-07` 理解但不会用；
- `13-08` 不能迁移；
- `13-14` 熟悉感误判掌握；
- `13-15` 主动提取失败；
- `13-18` 会复述但不会独立判断。

本组净化 5 个旧身份。

### 3.8 P-L1-16：停止搜索/停止阅读不是两个问题身份

旧 `16-06` 和 `16-07` 分别按活动阶段写成：

- 什么时候停止搜索；
- 什么时候停止阅读/分析。

如果真正失败机制都是：

> **信息已经足够支持当前判断，却不知道停止继续获取和处理，**

则应共享 `16-06`。

搜索/阅读/分析是旅程活动标签。

本组净化 1 个旧身份。

## 四、主归属 + 关联归属的判定方法

对一个现实问题依次问：

1. 用户最终失败表现是什么？
2. 哪个机制即使其他邻近机制都正常，仍足以独立造成这个失败？
3. 如果修复这个机制，用户的主要痛点是否会明显改善？
4. 其他 P-L1 是原因、后果、依赖还是同时相关？

例如：

> “AI 总结一本书后漏掉适用条件，我自己也没有发现。”

可拆成：

- 主问题若是压缩产物丢条件：`11-06`；
- AI 加入来源不支持内容时关联 `09-11`；
- 用户缺验收能力时关联 `15-03`。

不同问题机制可以同时存在，但不能因为同时存在就把它们说成一个同义问题。

## 五、用户旅程、场景、规模为什么只做标签

### 5.1 旅程阶段回答“什么时候”

例如 `13-13` 可出现：

- J07 建立阅读地图与重新进入；
- J08 阅读过程；
- J17 项目/行动推进；
- J18 长期调用。

只要失败机制不变，身份不变。

### 5.2 场景回答“在哪里发生”

建议主要标签：

- 单书；
- 多书；
- 陌生领域；
- 项目驱动学习；
- 海量知识；
- AI 参与；
- 长期积累；
- 高风险判断；
- 随用随查；
- 团队协作。

### 5.3 规模只有改变机制时才可能形成新问题

一本书不知道精读还是浏览，主问题是 04。

两万份资料即使每份只看 5 分钟也不可持续，才进入 16。

因此“单书/海量”本身不是 P-L2，但规模可能改变根因。

## 六、问题之间的关系不等于问题类型

正式建议问题关系：

- `causes`
- `caused_by`
- `blocks`
- `special_case_of`
- `overlaps_with`
- `retriggered_by`

例如：

- `02-03 前置知识缺失` 可 `causes` `13-12 认知负荷过高`；
- `10-04 环境/版本变化影响知识对象` 可 `retriggered_by` / 触发 `17-03 旧结论重查`；
- `05-01 重复未识别` 可 `causes` `16-04 重复研究浪费`。

这些关系用来连接稳定问题，不创建新 P-L2。

如果先做 Schema 再想“用户为什么痛”，很容易重新出现：

- 类型就是问题；
- 状态就是问题；
- 阶段就是问题；
- 能力就是问题；
- 系统错误就是问题。

所以当前正确顺序仍然是：

```text

→ 主归属 / 关联归属
→ 阶段 / 场景 / 规模
→ 机器字段
→ Capability
```

## 八、四组仍未强行收敛的缺口

### 8.1 学习动机、焦虑囤积、自我调节

当前 `SUP-012` 仍为 PARTIAL。

01、12、16 可以解释：

- 目标不清；
- 价值排序；
- 积压和停止。

但它们不能完整解释：

> “用户知道继续囤积/继续学习没有价值，却仍然难以自我调节和停止。”

继续研究，不急于新增 P-L1。

### 8.2 长期行为改变与行为维持

`14-14` 暂时保留为 canonical + PARTIAL。

需要后续区分：

- 行动设计；
- 环境与提示；
- 反馈；
- 自我调节；
- 技能熟练；
- 习惯形成；
- 复发/恢复。

### 8.3 团队 / 组织共同学习与知识协作

仍为 MISSING Candidate。

不能只因为“团队重要”就新增 P-L1。下一步应先建立真实问题样本，例如：

- 谁知道什么、谁不知道；
- 如何形成共享理解；
- 个人知识怎样交接；
- 团队观点冲突怎样保留依据；
- 谁有权限修改公共知识；
- 团队判断如何跨人员变化恢复。

### 8.4 无障碍与特殊认知需求

仍为 MISSING Candidate / Cross-cutting Context。

它可能更像跨 11 / 13 / 15 的情境条件，而非天然独立问题域。

例如：

- 信息结构过于复杂导致认知负担；
- 工作记忆、注意、语言理解差异；
- 同一信息需要不同表达方式；
- 人工验收方式必须适配用户能力。

需要真实用户问题后再决定分类位置。

## 十一、外部专业框架校准

外部资料只用于校准方法，不取代仓库事实源。

### 11.1 分类学 / 知识组织：概念可以有多种关系，不要求单一互斥树

ISO 25964 / NISO thesaurus 体系区分概念、层级关系与关联关系，并支持复杂层级/多层级关系。这与本轮“稳定身份 + 主归属 + 关联关系”的方向一致：一个概念不需要因为参与多个关系就复制为多个概念身份。

参考：

- NISO / ISO 25964 overview: https://www.niso.org/schemas/iso25964
- ISO 25964-1: https://www.iso.org/standard/53657.html
- ISO 25964-2: https://www.iso.org/standard/53658.html

### 11.2 自我调节学习：动机、执行监控和反思具有独立过程

Panadero 对自我调节学习模型的综述显示，主流模型通常不只处理“知识是否理解”，还包含前瞻/动机、执行中的监控与调节、反思等过程。

这支持把 `SUP-012` 继续保留为 PARTIAL，而不是简单塞进“价值排序”或“研究停止”。

参考：

- Panadero (2017), A Review of Self-regulated Learning: https://pmc.ncbi.nlm.nih.gov/articles/PMC5408091/

### 11.3 任务中断研究：恢复需要重新建构上下文

任务中断研究通常区分 interruption 后的 resumption lag / context reconstruction。它支持把“中断后接不上”视为一个稳定的上下文恢复问题，而不是只归因于一般记忆差。

参考：

- Task interruption / resumption research: https://pmc.ncbi.nlm.nih.gov/articles/PMC12271330/
- Frontiers task interruption study: https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2021.659451/full

### 11.4 认知无障碍：同一信息结构对不同用户的负担可能不同

W3C Cognitive Accessibility Guidance 强调，记忆、注意、语言、理解、执行功能等差异会改变用户与信息和界面的交互难度。

这支持把无障碍/特殊认知需求作为重要 Cross-cutting Context 继续研究，而不是直接假设现有普通用户路径对所有人等效。

参考：

- W3C Cognitive Accessibility: https://www.w3.org/WAI/cognitive/
- W3C Making Content Usable for People with Cognitive and Learning Disabilities: https://www.w3.org/TR/coga-usable/
