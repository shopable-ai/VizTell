# 书籍知识工程外部 Skill 与产品生态研究

> 状态：Research Note / External Calibration
>
> 日期：2026-08-26
>
> 研究对象：Book-to-Skill、深度阅读 Skill、AI 学习系统、个人知识库、Agent Skills、原子笔记与书库级 Agent。
>
> 目的：校准 `书籍知识工程与行为转化候选方案`，确认哪些能力已有外部实现、哪些只是局部覆盖、哪些仍属于本体系需要继续验证的组合设计。

---

## 1. 结论先行

截至 2026-08-26，网络上已经存在大量与“把书转成可复用知识”相关的 Skill、产品和工作流，但它们大多解决其中一段，而不是完整闭环。

可以观察到两条已经较清楚的路线：

1. **AI 使用路线**：书籍 / 文档 → 结构化提取 → Agent Skill / 检索 → 按需加载 → 问题解决；
2. **人类学习路线**：书籍 / PDF → 摘要 / 重点 → 卡片 / 测验 / 导师 → 掌握度与复习。

本项目当前候选方案试图进一步连接：

```text
来源材料
→ 结构恢复
→ 知识原子
→ 语义归一与去重
→ 原则 / 模型抽象
→ 来源 / 证据 / 边界
→ 人类学习与迁移
→ AI 按需调用
→ 行为与现实任务
→ 结果反馈
→ 知识更新
```

这意味着它不宜继续被定义为“Book Summary Skill”，更接近“书籍知识工程 + 学习工程 + Agent 能力化”的组合系统。

但必须强调：

> “覆盖维度更广”不等于“实际效果已经优于外部产品”。目前只能说本项目的**设计覆盖范围**比普通摘要工具更宽；是否更好，必须通过真实书籍、用户学习结果、AI 任务结果和长期 Benchmark 验证。

---

## 2. 这属于哪些专业范围

目前没有一个单一行业术语完整覆盖本项目。更合理的是视为多个领域交叉：

| 层面 | 专业范围 | 本项目对应问题 |
| --- | --- | --- |
| 来源处理 | Document Intelligence | PDF / EPUB / Markdown 等怎样恢复成可处理结构 |
| 内容理解 | Semantic Analysis | 主题、命题、隐含结构、观点与关系 |
| 知识工程 | Knowledge Engineering | Knowledge Atom、Canonical Knowledge、关系与 Schema |
| 知识压缩 | Knowledge Distillation | 大量表面表达怎样压缩成少量高迁移原则 |
| 模型抽象 | Mental Model / Framework Extraction | 经验 → 策略 → 原则 → 模型 |
| 知识管理 | PKM / Second Brain | 怎样长期保存、查找、连接与更新 |
| Agent 工程 | Agent Skills | 怎样把知识包装成 AI 可重复调用的能力 |
| 上下文工程 | Progressive Disclosure | 如何按需读取而不是一次加载整本书 |
| 学习科学 | Learning Engineering | 怎样理解、回忆、练习、反馈与验证 |
| 迁移 | Transfer of Learning | 能否从原案例迁移到新场景 |
| 行为设计 | Behavior Design | 知识如何转成触发条件、动作和反馈 |
| 批判性阅读 | Critical Reading | 假设、证据、冲突、反例、适用边界 |
| 评测 | Evaluation / Benchmark | 人和 AI 使用之后是否真的变强 |

因此，当前推荐的上位中文名是：

> **书籍知识工程（Book Knowledge Engineering）**

若强调完整闭环，可描述为：

> **Book → Knowledge → Learning / Skill → Action → Feedback Pipeline**

这些名称是本项目的架构命名，不宣称是行业统一标准术语。

## 3. Agent Skills 标准带来的直接启发

Agent Skills 官方规范把 Skill 视为一个可版本化目录，核心入口是 `SKILL.md`，并允许附带 `references/`、`scripts/`、`assets/` 等资源。其关键设计之一是 **Progressive Disclosure（渐进加载）**：Agent 先知道 Skill 的名称和描述，真正需要时才加载完整 Skill，再按任务需要读取参考文件或执行脚本。

这对书籍知识工程非常重要，因为它直接回应：

- 书越来越多后不可能把所有知识放进上下文；
- 一份巨大 `SKILL.md` 会产生上下文浪费；
- 章节、术语、模式、案例、评测应按需加载；
- AI 使用视图与人类浏览视图可以共享底层知识，但不必共享同一种展示结构。

参考：

- Agent Skills Overview: https://agentskills.io/home
- Agent Skills Specification: https://agentskills.io/specification

## 4. 代表性外部方案

### 4.1 virgiliojr94 / book-to-skill

项目：

- https://github.com/virgiliojr94/book-to-skill

定位不是普通摘要，而是把技术书、文件夹或多个来源转换成可供 Agent 按需使用的 Skill。

其公开结构包括：

```text
SKILL.md
chapters/
glossary.md
patterns.md
cheatsheet.md
```

公开说明强调提取：

- frameworks；
- mental models；
- principles；
- techniques；
- anti-patterns；
- decision rules；
- 章节级内容。

章节文件按需加载，不要求每次把整本书放进上下文。项目公开报告在其测试条件下，相比整书直接进入上下文，单次问题可减少约 24×–51× token 使用；该数字属于项目自身测量结果，应在本项目中独立复现后才能作为正式 Benchmark 证据。

**最值得借鉴：**

- Book → Skill 的明确目标；
- 结构提取而不是只做摘要；
- 章节路由；
- 小入口 + 按需参考文件；
- 多来源可合并为统一 Skill。

**当前没有完整解决：**

- 人类掌握状态；
- 跨大量书籍的 Canonical Knowledge 去重；
- 知识价值与主体目标路由；
- 行为长期反馈闭环。

---

### 4.2 Londeren / book-to-skill

项目：

- https://github.com/Londeren/claude-plugins/tree/main/plugins/book-to-skill

该方案更强调“提取可迁移方法，而不是重述书”。其公开流程包括：

```text
Go / No-Go
→ typed extraction
→ validation + rejection log
→ skill assembly
→ eval against no-skill baseline
```

关键特点：

- 先判断来源是否真的含有可重复方法；
- 每个提取单元绑定来源原文；
- 过滤“合格专家本来就知道”的普通知识；
- 保存 rejection log；
- 用 no-skill baseline 比较 Skill 是否产生增益。

**最值得借鉴：**

> “不是提取越多越好”，以及“Skill 生成后必须证明它提高了任务结果”。

这与本项目的知识价值分级、低价值知识过滤和 `13_评测、Benchmark与质量指标.md` 高度相关。

---

### 4.3 mp3wizard / skill-read-deeper

项目：

- https://github.com/mp3wizard/skill-read-deeper

该 Skill 提供 12 个阅读模式：

1. Core Argument Extractor；
2. Chapter Distiller；
3. Action Plan Builder；
4. Permanent Memory Notes；
5. Blind Spot Finder；
6. Personal Relevance Filter；
7. Quote-to-Principle Converter；
8. Teacher Mode；
9. Debate Mode；
10. Cross-Book Connector；
11. Recall Test；
12. 1-Year Impact Selector。

这说明“深度读书”已经自然分解为多个不同消费模式，而不是一份万能摘要。

**最值得借鉴：**

- 行动计划；
- 盲点与反方检查；
- 个人相关性；
- 引文 → 原则；
- 跨书连接；
- 主动回忆；
- 高杠杆知识筛选。

**与本项目的主要差异：**

本项目还需要显式处理知识身份、语义去重、来源独立性、跨书增量、时间版本、AI 能力路由和长期治理。

---

### 4.4 Zettelkasten / Atomic Notes Skill

代表项目：

- https://github.com/ake117/Zettelkasten-Obsidian-Claude-Code-Skill

其主要解决：

```text
来源 / literature notes
→ atomic notes
→ permanent notes
→ links
→ hub notes
→ slip-box validation
```

公开能力包括：

- note classification；
- one idea per note；
- meaningful links；
- hub notes；
- orphan / broken link / stale note validation。

**最值得借鉴：**

- 原子性；
- 单条知识可以独立存在；
- 知识连接和导航；
- 知识库健康检查。

**边界：**

它重点回答“知识如何保存与连接”，而本项目还必须回答“这条知识值不值得保留、是否重复、是否可信、是否需要本人学习、是否应该交给 AI”。

---

### 4.5 RemNote Guided Learn

官方：

- https://www.remnote.com/feature/learn-any-pdf
- https://help.remnote.com/en/articles/15724936-guided-learn-mode

RemNote 当前把 PDF、文档、视频等转换成：

```text
章节 / 小节
→ 摘要
→ Flashcards
→ Quiz
→ AI Tutor
→ Mastery Tracking
→ 针对薄弱主题继续练习
```

其公开功能还区分：

- recall questions；
- application questions；
- multiple choice；
- free response；
- easy / hard；
- topic mastery；
- follow-up questions。

**最值得借鉴：**

- “看过”不等于“掌握”；
- 学习内容要与 mastery state 联动；
- 错误应该追溯到底层 topic；
- 从 Recall 向 Application 升级。

这与本项目 `06_学习适配、掌握与迁移.md` 中 H0–H7 掌握层级可以形成校准关系，但两者不应直接等同。

---

### 4.6 NotebookLM

官方：

- https://support.google.com/notebooklm/answer/16958963

NotebookLM 可以从 notebook sources 生成 Flashcards 和 Quizzes，并允许设置难度和额外指令。

它更接近：

> **Source-grounded Learning Workspace**

可作为“来源有据的问答 / 学习资产生成”的代表，但并不等价于完整长期知识本体、跨书 Canonical Resolution 或行为反馈系统。

---

### 4.7 Recall

官方：

- https://www.getrecall.ai/
- https://app.getrecall.ai/pricing

Recall 当前公开能力包括：

- AI summaries；
- automatic organization / tags；
- AI Chat across saved knowledge；
- automatic connections；
- knowledge graph；
- spaced-repetition quiz；
- API / MCP。

因此在本次样本中，它比单纯摘要产品更接近：

> **AI 原生个人知识库 / 自组织知识网络**

它同时覆盖“保存—分类—连接—检索—复习”多个环节。

但仍不能因此推导它已经解决本项目的：

- 命题级知识身份；
- 严格去重与证据独立性；
- 主体价值路由；
- 书籍原则 → 行为 → 真实结果反馈。

---

### 4.8 Readwise Reader / Global Ghostreader

官方：

- https://readwise.io/reader/update-aug2026
- https://docs.readwise.io/changelog

2026-08 的 Global Ghostreader 已支持跨整个 Reader library 进行有引用的问答，并可执行整理类动作。Readwise 同时提供 starter skills，例如：

- Research a topic；
- Digest my reading；
- Triage my inbox；
- Find similar。

并提供 MCP / CLI 让外部 AI Agent 使用整个阅读库。

这表明阅读产品正在从：

```text
单文档阅读 / 摘要
```

向：

```text
全库检索
→ 跨文档连接
→ Agent 操作
→ 自定义 Skill
```

演进。

**最值得借鉴：**

- library-level agent；
- 全库引用式回答；
- 跨文档连接；
- Skill 与阅读库结合；
- 让外部 Agent 通过 MCP / CLI 使用阅读资产。

## 6. 本项目当前覆盖与外部方案的关系

### 6.1 当前设计覆盖更宽的部分

相较本次抽样的大多数单一 Book Summary / Reading Skill，本项目候选方案显式增加了：

- Knowledge Atom；
- Canonical Knowledge；
- 语义归一；
- 跨书重复 / 补充 / 支持 / 冲突 / 反例关系；
- 来源与证据独立性；
- Knowledge Delta；
- 人类掌握状态；
- Human / AI / Tool 消费路由；
- Search / RAG / Skill / Workflow / Agent 实现路由；
- 行为转化；
- 现实结果反馈；
- 生命周期更新；
- Benchmark。

因此，它更像一个“多 Skill / 多能力的书籍知识工程系统”，而不是单 Skill 摘要器。

### 6.2 当前反而落后的部分

外部成熟方案也暴露出本项目仍需要补强的地方：

1. Progressive Disclosure 的真实上下文成本测量；
2. Skill 生成后的 no-skill baseline；
3. 真正可运行的章节级路由；
4. 人类 mastery 的持续追踪 UI；
5. spaced repetition 的长期调度；
6. 全库级 Agent 的真实交互体验；
7. 大规模检索、延迟与成本 Benchmark；
8. 行为执行后如何采集现实反馈；
9. 人工阅读视图与 AI 机器视图如何共用底层对象。

## 7. 推荐吸收而不是照搬的机制

| 外部机制 | 推荐吸收方式 | 不应直接照搬的原因 |
| --- | --- | --- |
| Progressive Disclosure | 作为 AI 消费层原则 | 仍需与本项目知识身份、权限和检索层结合 |
| Book-to-Skill | 作为一种能力化出口 | 不是所有书都值得变 Skill |
| Go / No-Go | 作为处理深度路由 | 需要扩展到主体价值和知识增量 |
| Rejection Log | 保存低价值 / 被拒绝提取原因 | 需对接本项目生命周期和审计 |
| No-skill Baseline | 加入 Skill Eval | 还需加入人类学习和真实任务结果 |
| 12 Reading Modes | 作为消费模式候选 | 不应把 12 模式误当完整知识工程链 |
| Atomic Notes | 作为人工可读知识视图 | 原子笔记不自动等于 Canonical Knowledge |
| Mastery Tracking | 对接 H0–H7 | 必须避免只用测验分数冒充高阶迁移 |
| Knowledge Graph | 用于连接和探索 | 图关系多不等于知识质量高 |
| Library Agent | 作为海量知识消费入口 | 需经过权限、证据和最小充分上下文治理 |

## 8. 研究后推荐的目标架构

```text
原始书籍 / 文档
        ↓
书籍类型与处理价值判断
        ↓
原书结构恢复 / 阅读地图
        ↓
知识原子化 + 来源锚点
        ↓
语义标准化 / Canonical Resolution
        ↓
跨书关系 + 去重 + Knowledge Delta
        ↓
原则 / 模型 / 机制抽象
        ↓
证据 / 条件 / 边界 / 反例 / 时间审计
        ↓
主体价值与消费路由
        ↓
┌─────────────────────┬─────────────────────┐
│ 人类学习与行动层      │ AI / 工具能力层       │
│                     │                     │
│ 阅读地图              │ Search / RAG         │
│ 核心知识地图          │ Skill                │
│ 主动回忆              │ Workflow             │
│ 场景练习              │ Agent                │
│ 迁移测试              │ Software / Service   │
│ 关键行为              │ 按需上下文            │
└──────────┬──────────┴──────────┬──────────┘
           ↓                     ↓
        现实任务 / 决策 / 行动 / AI 执行
                     ↓
              结果、错误与反馈
                     ↓
          经验回写 / 知识更新 / 再验证
```

这张图应作为“书籍场景的正式目标架构”，而不是外部产品能力清单。正式装配入口见：

`../23_书籍知识工程、学习与行为转化工作流.md`

## 9. 下一阶段需要验证的问题

### 9.1 单本书

- 不同书型是否需要完全不同处理路径？
- 知识原子字段怎样做到最小充分？
- 原则抽象的 hallucination rate 是多少？
- 关键行为生成是否真的有助于现实使用？

### 9.2 多书 / 海量书库

- Knowledge Delta 的准确率如何？
- 多书去重是否能明显减少重复阅读与重复 token？
- 图谱、全文、向量、Canonical Knowledge 各自的最小充分边界是什么？

### 9.3 人类学习

- H2 理解、H3 判断、H4 执行、H6 迁移分别如何验证？
- RemNote 式 mastery tracking 能覆盖哪些层级、不能覆盖哪些？
- spaced repetition 应该用于哪些知识，而不是默认用于所有知识？

### 9.4 AI 使用

- Book Skill 相对原始 PDF + RAG 是否更准确？
- 是否真的降低 token、延迟和人工找资料成本？
- Skill 是否会把作者观点错误升级为通用方法？
- 多 Skill 组合是否产生冲突和上下文污染？

### 9.5 行为与现实结果

- 哪些类型的书值得行为化？
- IF / THEN 是否只是语言改写，还是改善执行？
- 如何采集反馈并区分“知识错”“执行错”“环境变化”？

因此本文只能作为**外部校准与研究证据**，不能替代正式 Benchmark。
