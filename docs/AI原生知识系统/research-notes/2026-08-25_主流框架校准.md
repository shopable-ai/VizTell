# 2026-08-25 主流框架校准：AI 原生知识系统

> 状态：Research Note。用于校准术语、接口与治理边界，不要求把整个系统强制改造成 RDF/OWL 或某一标准产品。

本轮只使用公开正式标准/机构资料进行框架级校准，不使用现有书库作为研究输入。

---

# 1. 校准结论

当前 AI 原生知识系统的方向与主流知识工程实践并不冲突，但不应试图寻找一个“单一标准”覆盖全部问题。

更合理的方式是：

- **知识组织**借鉴 SKOS 的 Concept、preferred/alternative label、broader/narrower/related 等语义；
- **来源与派生追踪**借鉴 W3C PROV 的 Entity / Activity / Agent 与 provenance 关系；
- **机器对象约束**采用 JSON Schema 2020-12；
- **AI 风险治理**参考 NIST AI RMF 与 Generative AI Profile 的生命周期风险管理思路；
- 证据强度、科学状态和领域事实判断仍需按领域建立 Evidence Profile，不能由上述标准替代。

因此仓库采取：

> **内部轻量领域模型 + 标准语义映射 + 可选互操作层**

而不是：

> **为了“标准化”强迫所有知识进入一个本体。**

---

# 2. SKOS：适合概念组织，不适合承载全部知识真值

官方规范：

- W3C SKOS Reference: https://www.w3.org/TR/skos-reference/
- W3C SKOS Primer: https://www.w3.org/TR/skos-primer/

SKOS 面向 thesauri、taxonomies、classification schemes、subject headings 等知识组织系统，适合表达：

- Concept；
- preferred label；
- alternative label；
- notation；
- broader/narrower；
- related；
- concept scheme；
- mapping relation。

对本项目最重要的借鉴：

### 2.1 一个概念多个名称

内部：

- `canonical_label`
- `aliases`

可映射：

- `skos:prefLabel`
- `skos:altLabel`

### 2.2 概念关系与命题关系分离

SKOS 的 broader/narrower/related 适合 Concept 组织，但 Claim 的：

- supports；
- conflicts；
- adds_condition；
- refines；

不是 SKOS 本身要解决的问题。

因此本系统必须继续保留 typed Relation Assertion。

### 2.3 不强制 RDF

当前 Markdown/JSON 模型仍是事实源；只保证 Concept 语义未来可映射 SKOS。

# 3. W3C PROV：适合来源、活动与派生链

官方规范：

- PROV-O: https://www.w3.org/TR/prov-o/

PROV-O 提供可交换 provenance 的通用模型，核心概念包括：

- Entity；
- Activity；
- Agent。

对本项目最重要的是明确：

> “知识是什么”与“这个知识怎么被产生/提取/修订”不是同一个对象。

因此可以建立映射：

| 内部对象 | PROV 校准方向 |
|---|---|
| Source / Raw Fragment / Canonical Knowledge | Entity |
| parse / extract / normalize / merge / adjudicate | Activity |
| human / model / organization / service | Agent |
| derived_from | wasDerivedFrom |
| revision_of | wasRevisionOf |
| primary source relation | hadPrimarySource |
| alternate representation | alternateOf |

具体 RDF 属性不要求立即实现，但内部语义应避免与成熟 provenance 模型冲突。

# 4. JSON Schema 2020-12：机器协议基线

官方规范：

- https://json-schema.org/draft/2020-12
- https://json-schema.org/specification

当前 JSON Schema 官方规范页面仍将 2020-12 列为当前已发布版本。

本项目采用：

```json
"$schema": "https://json-schema.org/draft/2020-12/schema"
```

作为首批 Schema dialect。

用途：

- 对象结构校验；
- required / enum / pattern；
- oneOf / anyOf；
- reusable definitions；
- schema versioning。

JSON Schema 不负责：

- 判断 Claim 是否真实；
- 判断两个知识是否语义等价；
- 判断路线是否合理。

它只保证：

> **机器对象符合已定义的数据合同。**

# 5. NIST AI RMF / Generative AI Profile：用于 AI 风险治理，不用于知识分类

官方资料：

- AI RMF: https://www.nist.gov/itl/ai-risk-management-framework
- AI RMF 1.0: https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10
- Generative AI Profile: https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence

截至 2026-08，NIST 官方页面说明 AI RMF 1.0 正在修订；Generative AI Profile（NIST AI 600-1）于 2024 发布并在 2026 更新页面信息。

因此本项目不把某一版 RMF 字段硬编码进知识本体，而吸收这些长期稳定原则：

- 风险贯穿设计、开发、使用和评估；
- trustworthiness 不能由单一模型能力指标替代；
- AI 输出需要测量、监测和治理；
- 高风险场景需要更强的人类监督和验证；
- 系统变化后需要重新评估风险。

对应本项目：

- `10_风险约束与系统治理.md`；
- Routing Decision 的 human gate；
- Benchmark / regression；
- Agent/Automation 的 permission、stop、rollback；
- AI 能力状态与知识正确性分离。

# 6. 主流框架无法直接替代的项目特有问题

以下问题需要本项目自己的领域模型：

1. 同一知识跨几十万资料的 Canonicalization；
2. 新知识相对个人已有知识的差额；
3. 主体价值与市场价值的分离；
4. Human Learning / RAG / Skill / Workflow / Agent / Software 联合路由；
5. 知识饱和与边际增量；
6. Knowledge → Capability → Implementation 的桥接；
7. “人是否真的需要学”的成本/替代判断。

这些不是 SKOS、PROV、JSON Schema、AI RMF 单独要解决的问题。

# 7. 当前正式映射建议

```text
Knowledge Identity
  ├─ Concept vocabulary → SKOS-compatible semantics
  ├─ Claim/Mechanism/Method → internal typed knowledge model
  ├─ Evidence → internal evidence profile
  └─ Relation Assertion → internal typed relation model

Provenance
  └─ PROV-compatible Entity / Activity / Agent lineage

Machine Contract
  └─ JSON Schema 2020-12

AI Risk & Governance
  └─ NIST AI RMF-aligned lifecycle principles
```

---

# 8. 不采用的错误做法

- 不因为 SKOS 存在就把所有知识降成 taxonomy；
- 不因为 PROV 存在就把 provenance 当真实性证明；
- 不因为 JSON Schema 校验成功就认为知识正确；
- 不因为 NIST AI RMF 存在就照抄一个巨型治理字段表；
- 不为了标准名称提前引入复杂 RDF/OWL 基础设施；
- 不用标准替代真实 Benchmark。
