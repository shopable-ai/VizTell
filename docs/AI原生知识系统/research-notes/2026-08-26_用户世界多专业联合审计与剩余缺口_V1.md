# 一、联合审计结论

## 1.1 当前 18 阶段用户旅程总体成立

当前 J01～J18 已经覆盖：

```text
真实目标
→ 是否需要本人学习
→ 知识缺口
→ 找资料
→ 筛选与优先级
→ 处理深度
→ 阅读地图与重新进入
→ 认知负荷
→ 理解
→ 提取重点
→ 记录与回源
→ 来源 / 证据
→ 条件 / 边界 / 冲突
→ 多来源去重与增量
→ 主体价值
→ 记忆 / 主动回忆 / 练习 / 迁移
→ 决策 / 行动 / 反馈
→ 长期调用 / 更新 / 淘汰
```

当前不建议继续增加 J19、J20。

原因：本轮发现的剩余问题大多是**跨阶段风险**，而不是新的时间阶段。

## 1.2 不新增 P-L1

现有 P-L1-01～18 已经足以承载本轮稳定问题。

继续增加一级分类的主要风险是：

- 把“阅读”“笔记”“记忆”“AI”等活动名称误当根因分类；
- 同一问题同时出现在多个阶段，导致重复计数；
- 专业问题宇宙越来越像目录，而不是稳定 Taxonomy；
- 工程实现重新侵入用户问题层。

因此本轮保持：

> **先补 P-L2、做多对多映射、保留 PARTIAL / MISSING，再考虑新的 P-L1。**

# 二、多专业视角的主要分歧与最终裁决

## 2.1 “做笔记困难”到底是不是核心用户问题？

### 用户研究视角

用户会真实说：

- “我不知道怎么做笔记。”
- “笔记越做越多，最后一次都没打开。”

所以它当然是真实问题现象。

### 学习科学视角

继续追问：

> 用户真正想要的是“做出笔记”，还是理解、记住、能提取、能判断、能用？

如果笔记很多但不能提取和使用，笔记动作本身没有完成最终目标。

### 产品与需求工程视角

进一步质疑：

> 如果未来 AI 可以承担摘录、结构化和回源，人是否仍必须亲自做传统笔记？

### 最终裁决

“不会做笔记”保留在用户原话层，但专业层应拆成：

- 重点选择；
- 粒度；
- 来源分离；
- 跨资料关联；
- 再查找；
- 再理解；
- 再使用；
- 主动提取与掌握。

> **笔记是手段，不是系统最终目标。**

---

## 2.2 “人必须学习”还是“交给 AI”优先？

### 学习科学视角

重要知识需要理解、主动提取、练习、反馈和迁移。

### AI 原生产品视角

大量低频、可检索、变化快的信息，如果强迫人长期记忆，会产生巨大机会成本。

### 认知科学视角

外部工具可以降低当下认知负荷，但过度认知卸载可能改变用户的记忆、监控和独立判断方式，因此不能简单采用“AI 能做 = 人无需理解”。

### 最终裁决

先执行 J02：

```text
这项知识是否需要本人即时判断？
→ 使用频率多高？
→ 查询延迟是否允许？
→ 错误后果多大？
→ 是否需要迁移和直觉？
→ AI / 工具是否可靠、可验证、可监督？
→ 最后才决定本人掌握深度
```

因此：

> **“本人不学习、随用随查或委托 AI”可以是正确结果，不属于学习失败。**

---

## 2.3 Search / RAG / Skill / Workflow / Agent 是不是用户问题？

工程视角容易把“该用什么技术”当成问题分类。

用户视角真正会遇到的通常是：

- “我需要时找不到以前的内容。”
- “每次都要重复做同一件事。”
- “这个任务需要持续跟踪变化。”
- “AI 一次拿太多资料，反而回答得更差。”

至于最终用全文检索、RAG、Skill、Workflow、Agent 或软件，是后续实现决策。

因此现有 `P-L1-16` 只兼容保留为**解决方案空间桥接区**，不再作为新用户问题发现入口。

# 三、本轮反方审计：哪些看起来像新问题，其实不应新增

## 3.1 “需要一个知识图谱”

不是上游需求。

可能对应真实需求：

- “我看不出这些概念之间有什么关系。”
- “我不知道这个结论依赖哪些前提。”
- “旧前提变化后，不知道哪些判断受影响。”

这些已有 P-L1-07、08、10、18 承载。

## 3.2 “需要 RAG”

不是上游需求。

可能对应：

- “需要时找不到知识”；
- “资料太多，无法每次全部读”；
- “希望回答能够回到原始来源”。

是否使用 RAG 属于后置实现。

## 3.3 “需要做笔记”

可能只是实现习惯。

真正需要确认的是：

- 是否为了理解；
- 是否为了以后找回；
- 是否为了记忆；
- 是否为了跨资料综合；
- 是否为了行动；
- 是否只是收藏焦虑。

## 3.4 “所有重要知识都应该学习”

错误。

重要性、本人掌握必要性和消费方式必须分开。

## 3.5 “AI 能处理一百本书，所以用户问题已经解决”

错误。

AI 规模化会同时放大：

- 错误去重；
- 伪增量；
- 来源失真；
- 条件和边界遗漏；
- 错误引用；
- 用户理解错觉；
- 无效处理成本。

处理能力扩大不等于用户结果改善。

# 四、仍值得保留的剩余候选问题簇

以下问题经过本轮交叉审计后，**值得继续观察，但当前不建议立即扩张 P-L1**。

## C-U01 只寻找支持原观点的资料，反方证据没有进入判断

### 用户可能会说

- “我找了很多资料，怎么判断是不是因为我只搜了支持自己观点的？”
- “这个结论看起来证据很多，但反对它的研究我是不是根本没看到？”
- “AI 会不会顺着我的问题一直帮我找支持材料？”

### 为什么它不是“普通来源质量问题”的简单重复

即使每一份资料本身都可靠，用户仍可能因为搜索、选择和解释过程偏向既有信念而得到偏斜的证据集合。

### 当前映射

- P-L1-03 来源发现；
- P-L1-08 冲突、条件与反例；
- P-L1-09 来源、证据与可信度。

### 当前裁决

`PARTIAL / Candidate`。

建议先作为“证据集合是否具有反方覆盖”的用户研究问题继续验证，不立即为了它创建新的 P-L1。

---

## C-U02 看起来能理解，但脱离资料后无法独立解释或产出

### 用户可能会说

- “看着的时候都懂，让我关掉书自己讲就讲不出来。”
- “我能认出正确答案，但让我从零解释这个概念就卡住。”
- “我看了很多内容，却写不出一份自己的结构化说明。”

### 与已有问题的关系

它和以下问题相邻但不完全相同：

- 熟悉感误认为掌握；
- 主动提取失败；
- 能解释但不会判断；
- 缺少练习与反馈。

当前 `P-L2-13-14 / 13-15 / 13-17 / 13-18` 已能组合解释。

### 当前裁决

优先作为新的用户原话 / SUP 候选继续验证，**暂不新增 P-L2**。

如果后续大量真实案例证明“独立生成解释 / 输出”会稳定改变学习路线，再考虑独立 P-L2。

---

## C-U03 AI 能处理，但资料不一定能安全交给 AI

### 用户可能会说

- “AI 能帮我整理，但公司内部资料可以直接发给它吗？”
- “这份内容有版权或隐私限制，我能不能让外部 AI 处理？”
- “不是 AI 会不会做，而是我有没有权限把资料交给它。”

### 与已有问题的关系

- `P-L2-15-04` 已覆盖“风险或权限不允许自动执行”；
- `L1-10 风险与约束` 已覆盖版权、隐私、机密、法律和权限。

但用户层需要警惕：

> “AI 能力归属”与“数据是否允许进入该 AI”是两个不同判断。

### 当前裁决

`PARTIAL / Candidate`。

暂不新增 P-L1；后续若真实任务中高频出现，再判断是否需要明确新的 P-L2，而不是只藏在系统风险层。

---

## C-U04 学习动机、焦虑囤积、拖延与长期坚持

已有 `SUP-012` 与 `SUP-083` 分别标记为 `PARTIAL`。

这类问题真实存在，但它们可能把系统边界从“AI 原生知识系统”扩张到：

- 行为改变；
- 动机科学；
- 自我效能；
- 情绪调节；
- 习惯形成。

### 当前裁决

保留候选，不为了覆盖一切人的学习问题而无限扩大核心知识系统。

---

## C-U05 团队 / 组织共同学习与知识协作

典型问题包括：

- “团队里每个人对同一个概念理解得不一样。”
- “专家离开以后，关键判断依据也一起丢了。”
- “个人笔记有很多，但组织并没有真正形成共享知识。”
- “不同角色看到的证据和允许使用的知识不同。”

### 当前裁决

这是一个真实、可能独立的大问题域，但当前 `01A` 的主旅程以个人知识使用为中心。

因此继续保持 `MISSING Candidate`，未来如果系统正式覆盖团队 / 组织场景，应单独做用户旅程与问题宇宙，不把组织问题硬塞进个人阅读旅程。

# 五、外部专业研究校准

本节用于检查“这些问题是不是只来自专家想象”，不把学术文献直接当成具体用户需求证据。

## 5.1 学习策略：阅读流畅和重复阅读不等于长期掌握

Dunlosky 等对多种学习技术的综述指出，不同学习方法效用差异很大；练习测试、分散练习等证据更强，而单纯重读、划重点等方法的效用更有限或依赖条件。

参考：

- Dunlosky, J. et al. (2013). *Improving Students’ Learning With Effective Learning Techniques*. Psychological Science in the Public Interest. DOI: `10.1177/1529100612453266`。

这支持现有体系把：

```text
阅读 / 标记
≠
真正掌握
```

并把主动提取、练习和反馈独立出来。

## 5.2 主动提取不是“考试附属动作”

Roediger & Karpicke 的实验表明，提取测试不仅测量记忆，也可以改善延迟保持；Karpicke & Blunt 进一步显示，在其研究任务中，主动提取对概念学习的效果优于相应的概念图学习条件。

参考：

- Roediger, H. L. & Karpicke, J. D. (2006). *Test-Enhanced Learning: Taking Memory Tests Improves Long-Term Retention*. DOI: `10.1111/j.1467-9280.2006.01693.x`。
- Karpicke, J. D. & Blunt, J. R. (2011). *Retrieval Practice Produces More Learning Than Elaborative Studying With Concept Mapping*. Science. DOI: `10.1126/science.1199327`。

这支持 `J16` 和 `P-L2-13-14～17` 独立存在，而不是全部归入“做笔记”。

## 5.3 认知负荷是真实学习约束

Sweller 的认知负荷研究指出，有限认知处理能力会影响学习与图式形成。

参考：

- Sweller, J. (1988). *Cognitive Load During Problem Solving: Effects on Learning*. DOI: `10.1207/s15516709cog1202_4`。

这支持：

- J08 认知负荷；
- P-L2-13-12；
- 海量知识不能直接平铺给人。

## 5.4 认知卸载可以有价值，但不应默认“全部交给工具”

Risko & Gilbert 将 Cognitive Offloading 描述为通过外部行为降低内部认知需求，并强调人是否选择卸载受到对自身能力的元认知判断影响。

参考：

- Risko, E. F. & Gilbert, S. J. (2016). *Cognitive Offloading*. Trends in Cognitive Sciences. DOI: `10.1016/j.tics.2016.07.002`。

这支持 J02 的存在：

> “需要本人学到什么程度”应该成为显式判断，而不是默认全部记住，也不是默认全部交给 AI。

## 5.5 只寻找支持材料是独立风险

Nickerson 对 Confirmation Bias 的综述把它描述为以偏向既有信念、期待或假设的方式寻找或解释证据。

参考：

- Nickerson, R. S. (1998). *Confirmation Bias: A Ubiquitous Phenomenon in Many Guises*. DOI: `10.1037/1089-2680.2.2.175`。

这为 C-U01 提供专业依据，但仍不能替代真实用户研究，因此当前只进入候选，不直接晋升 P-L2。

# 七、本轮没有正式晋升的内容，未来怎样处理

后续出现新的用户原话时，必须按下面顺序处理：

```text
新用户原话
→ 是否只是已有 SUP 的新说法？
→ 是否只是同一问题出现在新阶段？
→ 是否其实由多个已有 SUP 组合造成？
→ 是否只是工程实现问题？
→ 是否有真实用户场景和失败后果？
→ 是否跨多个样本稳定存在？
→ 才考虑新增 SUP
→ 再判断是否真的需要新增 P-L2
→ 最后才可能讨论 P-L1
```

禁止：

```text
发现一句新问题
→ 立即新增 P-L2
→ 立即生成能力
→ 立即生成 Agent / 软件功能
```

# 八、停止条件

本轮联合审计在以下位置停止：

```text
用户旅程
→ 用户需求
→ 用户问题现象
→ 用户原话
→ Standard User Problem
→ P-L1 / P-L2
```

当前已经有足够质量作为下一阶段问题优先级与能力推导的上游事实源。

本文件不继续设计：

- Capability；
- RAG；
- Skill；
- Workflow；
- Agent；
- UI；
- 数据库；
- 软件架构；
- 代码。

> **本轮最重要的结果不是“又增加了多少分类”，而是正式确立：先看用户世界，再归一标准问题，再进入专业问题宇宙；任何工程能力都必须在这三层之后。**
