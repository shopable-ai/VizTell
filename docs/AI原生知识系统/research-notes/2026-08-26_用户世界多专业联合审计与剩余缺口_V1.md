## 一、最终重构裁决

### 1.1 18 阶段用户旅程继续成立

当前 J01～J18 已覆盖：

```text
真实目标
→ 是否需要本人学习
→ 知识缺口
→ 找资料
→ 筛选与处理深度
→ 阅读地图与重新进入
→ 认知负荷
→ 理解
→ 提取重点
→ 记录与回源
→ 来源 / 证据
→ 条件 / 边界 / 冲突
→ 多来源去重与增量
→ 主体价值
→ 记忆 / 主动回忆 / 练习 / 迁移
→ 决策 / 行动 / 反馈
→ 长期调用 / 更新 / 淘汰
```

本轮发现的剩余问题大多是跨阶段风险，不构成新的时间阶段，因此暂不增加 J19 / J20。

### 1.2 P-L1 从 18 类重构为 17 类

前一版审计曾提出：

> “为了历史兼容，保留 P-L1-16 为解决方案空间桥接区。”

在进一步确认“当前仍处于框架推理阶段，没有稳定外部接口需要兼容”后，这一折中被正式推翻。

最终裁决：

```text
删除：原 P-L1-16 能力化与实现载体选择
净化并重编号：原 P-L1-17 → 新 P-L1-16 规模、注意力与研究停止
净化并重编号：原 P-L1-18 → 新 P-L1-17 反馈、修正与长期再判断
```

原因：

- Search / RAG / Skill / Workflow / Agent / Software 回答“怎样实现”，不是“用户遇到什么问题”；
- false merge、增量判断错误、路由错误、模型成本等回答“系统哪里失败”，不是用户问题分类；
- 为历史编号保留错误层级，会把临时设计债固化为正式架构。

因此正式原则改为：

> **在框架尚未冻结时，语义正确性优先于编号兼容。**

## 二、多专业视角的主要分歧与裁决

### 2.1 “做笔记困难”是不是核心用户问题？

用户会真实说“我不知道怎么做笔记”，所以它是真实现象；但学习科学和需求工程继续追问：用户真正要的是笔记，还是以后能够理解、找回、判断、记住和使用？

最终裁决：

> “不会做笔记”保留在用户原话层；专业层拆成重点选择、粒度、来源分离、跨资料关联、再查找、再理解、再使用和主动提取。

**笔记是手段，不是最终目标。**

### 2.2 “人必须学习”还是“交给 AI”优先？

学习科学强调理解、主动提取、练习、反馈和迁移；AI 原生视角强调低频、可查询、变化快的知识不值得全部占用长期记忆。

最终裁决由 `P-L1-15 本人掌握、委托与监督边界` 承担：

```text
本人是否必须现场判断？
→ 使用频率？
→ 查询延迟是否允许？
→ 错误后果？
→ 是否需要迁移和直觉？
→ AI / 工具是否可靠、可验证、可监督？
→ 数据和责任是否允许委托？
→ 决定本人掌握深度
```

“本人不深学、随用随查或委托”可以是正确结果。

### 2.3 Search / RAG / Skill / Workflow / Agent 是不是用户问题？

不是。

用户实际会说：

- “我需要时找不到以前的内容。”
- “每次都要重复做同一件事。”
- “AI 拿太多资料反而答得更差。”
- “这个任务需要长期跟踪变化。”

这些先进入用户问题宇宙。最终采用什么实现，直接进入 `19`，不再经过任何 P-L1 桥接编号。

### 2.4 系统判断错误是不是 P-L2？

不是。

例如：

- false merge；
- false novelty；
- 错误路由；
- 模型成本失控；
- 批处理规模化放大错误。

这些进入 `13 / 22`。

但用户能感知的后果仍可进入用户问题层，例如：

- “AI 把重要限制删掉了”；
- “AI 给的引用并不支持结论”；
- “我需要时找不到以前存过的知识”。

## 三、反方审计：哪些看起来像需求，其实不是

### 3.1 “需要一个知识图谱”

不是上游需求。真实问题可能是关系不清、依赖不清、旧前提变化后不知道影响哪些结论。

### 3.2 “需要 RAG”

不是上游需求。真实问题可能是找不到知识、资料太多、需要来源支持。

### 3.3 “需要做笔记”

可能只是实现习惯。需要追问目的究竟是理解、回忆、检索、综合还是行动。

### 3.4 “所有重要知识都应该学习”

错误。知识重要性、本人掌握必要性和最合理消费方式必须分开。

### 3.5 “AI 能处理一百本书，所以问题解决了”

错误。处理规模提升会同时放大来源失真、条件遗漏、错误引用、错误去重和用户理解错觉，因此必须用用户结果和 Benchmark 验证。

## 四、仍值得保留的候选问题簇

### C-U01 只寻找支持原观点的资料，反方证据没有进入判断

用户可能会说：

- “我找了很多资料，但会不会只是因为我只搜了支持自己的？”
- “反对这个结论的研究是不是根本没进入我的候选集？”
- “AI 会不会顺着我的问题一直帮我找支持材料？”

当前映射：P-L1-03、08、09。

裁决：`PARTIAL / Candidate`。先继续验证是否需要独立 P-L2，不新增 P-L1。

### C-U02 看起来理解，但脱离资料后无法独立解释或产出

用户可能会说：

- “看着都懂，关掉书自己讲就讲不出来。”
- “我能认出正确答案，但无法从零解释。”

当前 `13-14 / 13-15 / 13-17 / 13-18` 已能组合解释。

裁决：优先作为新的用户原话 / SUP 候选验证，暂不新增 P-L2。

### C-U03 AI 能处理，但资料不一定允许交给 AI

用户可能会说：

- “公司内部资料可以直接交给外部 AI 吗？”
- “这份内容有隐私或版权限制，能不能让 AI 处理？”

本轮重构后已由 `P-L2-15-04` 明确承载：能力上可委托，不代表数据、权限、责任上允许委托。

### C-U04 学习动机、焦虑囤积、拖延与长期坚持

真实存在，但可能把知识系统扩张到完整行为干预系统。

裁决：继续保留 `PARTIAL`，不为了覆盖全部学习行为而无限扩大核心边界。

### C-U05 团队 / 组织共同学习与知识协作

典型问题：

- 团队对同一概念理解不一致；
- 专家离开后判断依据流失；
- 个人知识很多但组织没有形成共享知识；
- 不同角色看到的证据和权限不同。

裁决：`MISSING Candidate`。如果系统正式覆盖组织场景，应单独做组织用户旅程，不硬塞进个人阅读旅程。

## 五、专业研究校准后的稳定判断

当前可以稳定保留的原则：

1. 阅读流畅和熟悉感不能证明掌握；
2. 主动提取、练习、反馈和迁移属于不同学习环节；
3. 认知负荷过高是独立问题，不等于“不会做笔记”；
4. 外部工具和 AI 可以降低认知成本，但委托会改变人工掌握需求；
5. 大规模知识使用会产生重复、边际增量下降、停止研究和长期再查找问题；
6. 搜索和证据选择过程本身可能偏向已有观点，因此反方覆盖值得继续研究。

## 六、当前停止条件

本轮正式停止在：

```text
用户旅程
→ 用户需求
→ 用户问题现象
→ 用户原话
→ Standard User Problem
→ P-L1 / P-L2
```

不继续在本轮深入：

- Capability 设计；
- RAG；
- Skill；
- Workflow；
- Agent；
- UI；
- 数据库；
- 软件架构。

> **最终裁决：当前没有任何理由为了历史编号保留错误的分类边界。正式 P-L1 应优先追求概念纯度和长期可理解性。**
