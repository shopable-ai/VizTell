# 专业领域、成熟框架与工具来源地图

> 目的：回答“01E 的检查方法从哪些成熟专业领域来”，避免只靠模型自行发明检查清单。

---

## 一、来源选择原则

优先级：

```text
成熟专业领域的经典/权威框架
> 专业机构正式方法或手册
> 大学课程与开放教材
> 高质量综述与专业教材
> 实务组织公开方法
> 通俗书籍
> 自媒体总结
```

但“权威来源”只说明方法来源较可靠，不代表方法可无条件跨领域使用。

## 三、第一批正式锚点框架

### 3.1 Informal Logic

重要贡献：

1. 先把自然语言论证“标准化”：提取 premise / conclusion / inference；
2. 去掉与推理无关的重复、修辞噪声；
3. 补出隐含前提；
4. 再评估前提是否可接受、相关、足够。

重要启示：

> **不要跳过论证结构提取，直接搜索谬误词。**

### 3.2 Argumentation Schemes + Critical Questions

适合把“诉诸专家”“类比”“案例”“因果”等高频论证转成：

```text
模式识别
→ 对应 Critical Questions
→ 缺失前提
→ 反例/例外
→ 风险状态
```

这样可以降低“谬误谬误”。

### 3.3 Toulmin Model

用于提取：

- Claim；
- Data / Grounds；
- Warrant；
- Backing；
- Qualifier；
- Rebuttal。

其价值主要是帮助 AI 暴露“证据为什么能支持结论”这一隐含桥梁。

### 3.4 Cochrane RoB 2 / ROBINS-I

重要启示：

> **研究质量不是总体印象，而应按不同偏倚来源提出 signalling questions。**

并允许：低风险 / 有疑虑 / 高风险，而不是只有对错。

### 3.5 GRADE

把单项研究和整体 evidence body 分开，关注：

- risk of bias；
- inconsistency；
- indirectness；
- imprecision；
- publication bias。

### 3.6 AMSTAR 2

用于系统综述方法学审查。

关键启示：

> 关键缺陷不能被普通加分项平均掉；不推荐把方法学质量压成一个简单总分。

### 3.7 EQUATOR / Reporting Guidelines

CONSORT、STROBE、PRISMA 等主要帮助提高报告透明度和完整性。

必须明确：

> **报告完整 ≠ 研究设计正确 ≠ 偏倚低 ≠ 结论正确。**

### 3.8 ASA p-value Principles

核心检查思想：

- p-value 不是“假设为真的概率”；
- 不应只凭阈值做科学/业务结论；
- 显著性不表示效应大小；
- 显著性不等于实际重要性；
- 推断需要完整报告与上下文。

### 3.9 Harvard CAUSALab / Causal Inference: What If

提供反事实、混杂、选择偏差、DAG 等成熟因果框架。

普通用户层只提炼成检查问题，高级数学和估计方法保留为专业核验路径。

### 3.10 APA 测量与构念效度

强调：对测试/指标的解释必须有证据和理论支持。

重要不变量：

> **再高级的统计分析，也无法自动修复一个错误或失真的测量。**

### 3.11 Calling Bullshit

适合现实世界的数据、科研论文和可视化误导训练；其 misleading axes 与 proportional ink 尤其适合 F12。

### 3.12 SIFT / Civic Online Reasoning

SIFT：

```text
Stop
→ Investigate the source
→ Find better coverage
→ Trace claims / quotes / media to original context
```

Civic Online Reasoning：

1. 谁在背后？
2. 证据是什么？
3. 其他来源怎么说？

适合作为低成本快速核验层。

### 3.13 Full Fact

重要实务思想：

- 检查 Claim，而不是先给人物贴标签；
- 先明确真正说了什么和隐含假设；
- 尽量回到 primary sources；
- 必要时咨询相关专家；
- 公开证据和上下文。

### 3.14 C2PA / Content Credentials

用于验证数字内容 provenance / authenticity 信号。

必须明确：

> provenance 能帮助证明“内容来自哪里、是否被修改”，不能单独证明内容里的现实 Claim 为真。

### 3.15 Structured Analytic Techniques

Key Assumptions Check、Analysis of Competing Hypotheses、Devil's Advocacy 等适合把“认知偏差”转成主动操作：

- 显式列出关键假设；
- 找会迫使假设失效的信息；
- 生成竞争解释；
- 主动搜索不利证据。

## 四、框架引入 Gate

一个成熟框架进入正式工具库前至少回答：

1. 它原来解决什么问题？
2. 原始专业领域是什么？
3. 适用对象是什么？
4. 是否是理论、方法、检查表还是评分工具？
5. 是否需要专业训练？
6. 哪些字段可转成普通用户问题？
7. 哪些步骤可被 AI 自动执行？
8. 哪些裁决必须保留专业上下文？
9. 是否存在已知局限或误用？
10. 引入后与现有 F 是否重复？

禁止因为某框架“有名”就整套照搬。
