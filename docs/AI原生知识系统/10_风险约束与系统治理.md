# 风险约束与系统治理

> 为保持现有目录编号稳定，本文件同时承载两个逻辑一级空间，但二者必须明确分开：
>
> - **L1-10 风险与约束**：回答“能不能做、风险多大、有哪些边界”。
> - **L1-11 系统状态与治理**：回答“系统怎样处理、记录、发布、更新、回滚与退出”。

高价值、高相关、高自动化并不意味着可以无条件使用。

---

# 一、L1-10：风险与约束

## 1.1 L2 风险维度

- **版权与许可**：复制、索引、训练、展示、再分发、衍生使用范围。
- **隐私与机密**：个人数据、商业秘密、组织权限、最小访问范围。
- **法律与监管**：地域法律、行业规则、记录与审计要求。
- **安全风险**：危险知识、滥用风险、不可逆操作、权限升级。
- **伦理风险**：操控、歧视、不公平、侵犯主体自主性。
- **偏差风险**：来源偏差、样本偏差、文化偏差、模型偏差、选择性证据。
- **误导风险**：伪科学、错误因果、过度概括、权威错觉、过时结论。
- **错误代价**：低损失、可逆损失、高损失、不可逆/重大后果。
- **责任风险**：谁承担专业、业务、法律或组织责任。
- **自动化风险**：模型能力是否超过可治理、可验证和可恢复的边界。

---

# 二、风险与知识质量不能混为一个字段

例如：

- 一个知识可能证据很强，但版权不允许再分发；
- 一个结论可能主体价值极高，但证据不足；
- 一个自动化任务可能准确率很高，但失败不可逆；
- 一个低可信主张可能仍值得作为“待验证风险信号”保存。

因此至少分开：

```text
epistemic state
≠ risk state
≠ permission state
≠ execution authorization
```

# 三、风险 Gate

典型 Gate：

## G-R1 Evidence Gate

高风险任务使用的关键 Claim 必须达到相应证据门槛或进入人工/专业验证。

## G-R2 Permission Gate

模型能执行 ≠ 有权限执行。

## G-R3 Irreversibility Gate

不可逆、高费用、外部发送、权限变更、删除等动作需要更强人审。

## G-R4 Accountability Gate

需要专业主体承担责任时，不能把“AI 完成”当作责任转移。

## G-R5 Data Boundary Gate

真实知识资产读取、处理、导出和派生必须符合明确的数据使用范围；见 `21_验证计划、样本清单与数据边界.md`。

# 五、治理能力

至少包括：

- **Identity & Versioning**：对象和版本身份稳定；
- **Access Control**：谁能读取、修改、执行；
- **Audit Log**：关键读取、修改、合并、执行可追溯；
- **Change Review**：高影响变化进入复核；
- **Rollback**：错误 merge、错误路由、错误版本可恢复；
- **Retention**：保留、归档、删除和法律保留策略；
- **Impact Propagation**：变化能找到受影响对象；
- **Human Gate**：高风险和低置信决策可人工接管；
- **Incident Handling**：错误知识、错误自动化、数据泄露等异常处置；
- **Responsibility**：关键对象和流程有责任主体。

---

# 六、知识治理的关键不变量

1. **来源不丢失**：Canonical merge 后仍能回到 Raw Source。
2. **历史不覆盖**：新版本替代旧版本时保留历史有效期和修订链。
3. **关系可回滚**：Relation Assertion 是独立对象，不直接物理融合后失去恢复能力。
4. **状态不串线**：已解析 ≠ 已验证；已向量化 ≠ 可用；Skill 跑通一次 ≠ 已批准。
5. **高风险不靠总分自动放行**：必须有规则化 Gate。
6. **反馈可反向更新**：使用失败能够回到知识、关系、路由或能力对象。
7. **删除和合并可解释**：必须保留决策原因与证据。

# 七、时间与版本治理

系统至少应区分：

- source published time；
- source ingested time；
- knowledge valid time；
- verified time；
- relation adjudicated time；
- route computed time；
- implementation version time。

详细时间模型见 `08_时间、版本与知识生命周期.md`。

# 八、AI 风险治理校准

AI/LLM 相关治理采用生命周期风险思想，而不是把“模型准确率”当作全部风险。

需要持续管理：

- 输入数据风险；
- 来源与版权；
- 幻觉/错误归因；
- 自动合并错误；
- 过期知识；
- 工具调用权限；
- 自动执行副作用；
- 人工过度依赖；
- 能力退化；
- 模型/Prompt/工具更新后的回归风险。

主流框架校准记录见 `research-notes/2026-08-25_主流框架校准.md`。

# 九、L3 优先展开

## 风险侧

- 错误影响半径；
- 错误可逆性；
- 数据敏感等级；
- 许可范围；
- 专业责任等级；
- 人工关口等级；
- 自动化上限；
- 风险重评触发器。

## 治理侧

- 审计日志完整率；
- provenance 完整率；
- rollback 成功率；
- 过期发现时延；
- 影响传播召回率；
- 人工接管成功率；
- 未授权操作率；
- 状态一致性错误率。
