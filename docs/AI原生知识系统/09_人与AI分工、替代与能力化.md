# 人与 AI 分工、替代与能力归属

> 面对任何有价值知识，不默认“人去学习”，而是先判断：**谁需要拥有这项能力、承担什么责任、掌握到什么程度，以及哪些部分可以被 AI、工具或外部服务可靠替代。**

本文件属于 Problem / Evaluation Space。

Search、RAG、Skill、Workflow、Agent、Software 的具体实现选择不在本文件决定，见 `19_知识到Search-RAG-Skill-Workflow-Agent-软件的能力路由.md`。

---

## 一、L2 二级维度

- **人类掌握必要性**：必须内化、需形成判断能力、理解即可、知道存在即可、无需掌握。
- **人工消费模式**：系统学习、阶段学习、练习到熟练、随用随查、检查清单、专家咨询。
- **AI 可承担层级**：不可用、可辅助检索、可总结、可判断候选、可规划候选、可执行候选。
- **工具替代成熟度**：无工具、部分替代、成熟工具可完成、商品化服务可完成。
- **服务替代**：内部专家、外部专家、外包服务、平台服务。
- **任务确定性**：规则稳定、部分分支、开放不确定。
- **可验证性**：结果易验证、抽样可验证、需专家验证、难验证。
- **错误可逆性**：可自动恢复、可人工恢复、高成本恢复、不可逆。
- **责任归属**：AI 辅助、人最终负责、双重审核、专业主体负责。
- **监督需求**：无特殊监督、抽样复核、关键节点人审、全程强监督。
- **异常接管**：AI 自恢复、切换工具、降级人工、暂停执行、外部升级。
- **能力退化风险**：长期委托后是否损害人的关键判断与应急能力。

## 二、先判断 Capability Ownership，再判断 Implementation

统一决策顺序：

```text
知识/技能有价值吗
→ 当前任务需要谁作最终判断
→ 人需要掌握到什么深度
→ 哪些部分允许延迟检索
→ AI/工具是否能稳定完成
→ 输出是否可验证
→ 错误是否可发现和恢复
→ 谁承担最终责任
→ 决定 Human / AI / Tool / Service 的能力归属
→ 再进入 19 选择最小充分实现载体
```

这避免：

> “AI 能回答” → “应该 Agent 化”

或：

> “知识很重要” → “人必须全部内化”。

## 三、人必须掌握的典型信号

以下因素会提高人工内化必要性：

- 高频核心判断；
- 低延迟现场判断；
- 高错误代价；
- 需要形成直觉、模式识别或身体技能；
- 需要跨情境迁移；
- 需要即时沟通、协商、教学或领导；
- 外部工具不可用或不稳定；
- 属于大量后续学习的关键前置；
- 属于职业/身份核心能力；
- 人必须承担最终专业责任。

典型目标：

- `UNDERSTAND_AND_JUDGE`
- `EXECUTE`
- `PRACTICE_TO_FLUENCY`
- `TRANSFER`

---

## 四、人无需深学的典型信号

以下因素会降低人工深度学习必要性：

- 低频；
- 任务发生时允许查询；
- 知识稳定、易检索；
- 内容变化快，长期记忆很快过期；
- 有成熟可靠工具；
- AI 输出容易验证；
- 任务程序化；
- 学习成本高但真实使用概率低；
- 外部专业服务更经济；
- 不需要形成个人直觉或迁移能力。

可能的能力归属：

- Reference；
- AI-assisted；
- Tool delegated；
- External Service；
- Deferred。

## 五、AI “能做”至少拆成五层

不能用一个 `ai_capability = high` 表达。

至少分别判断：

1. **Access**：能否访问正确数据/工具；
2. **Reasoning**：是否具备完成任务的模型能力；
3. **Reliability**：能否稳定重复而非偶尔成功；
4. **Verifiability**：结果能否被系统或人检查；
5. **Governability**：权限、停止、审计、恢复和责任是否可控。

只有这些维度共同满足，才可能进入更高自动化。

## 六、成本不能只算“学习时间”

### 人类成本

- 理解；
- 记忆；
- 练习；
- 反馈；
- 迁移；
- 维护；
- 能力退化恢复。

### AI/系统成本

- Prompt/规则设计；
- 知识准备；
- 工具集成；
- 评测；
- 验证；
- 人工审核；
- 异常恢复；
- 运行成本；
- 模型/工具更新维护。

### 外部服务成本

- 采购；
- 响应时延；
- 交接；
- 责任边界；
- 供应商锁定；
- 数据与隐私成本。

## 七、L3 优先展开

- 人工目标掌握层级；
- 查询延迟容忍；
- AI 稳定成功率；
- 输出可验证性；
- 人工审核成本；
- 错误发现概率；
- 错误恢复成本；
- 工具成熟度；
- 外部服务可用性；
- 任务确定性；
- 责任不可外包程度；
- 能力退化风险；
- 人机交接成本。

## 八、与实现路由的接口

本文件最终输出一个能力归属状态，例如：

```yaml
capability_ownership:
  human_required_level: judge
  ai_delegation_allowed: true
  tool_substitution_maturity: medium
  external_service_option: false
  verification_required: high
  human_final_accountability: true
  automation_ceiling: human_gated
```

然后 `19` 再决定：

> Search / RAG / Skill / Tool / Workflow / Agent / Automation / Software / Existing Tool Integration

不能把这两步合并成一个模糊的“AI 能力化”。
