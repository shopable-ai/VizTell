# 跨宇宙因素与关系索引（R2）

> **唯一职责**：提供跨宇宙候选变量的稳定身份、最小定义、去重与研究路由；不接管领域正文、案例事实、证据卡或最终结果。稳定入口是本文件；全局分类见 [全局地图](00_知识宇宙目录与跨域关联.md)，排序见 [候选与研究优先级](01_全局宇宙候选与研究优先级.md)，实际研究见 [多维推理与节点续研协议](思维与方法宇宙/03_跨宇宙多维推理与节点续研协议.md)。  
> **版本状态**：`R2 / candidate-index / 2026-11-22`。本版包含 71 个候选变量，以及单独的机制、动态、指标入口。数量来自当前构念区分，不是覆盖目标、成熟度或因果证明。没有据此建立新的“元因素宇宙”目录。

## 1. 本轮决定：先建立因素总索引

“资源、信息、制度、时间”等词横跨多个对象类型。把它们全部放进一个元因素宇宙，会形成第二套专业定义并把不同证据标准混在一起。本版采用**联邦因素索引**：身份在这里登记，专业含义由原宇宙或外部正式 Owner 维护，具体影响由限定问题的研究记录核验。

本文件提供的是**候选元因素族及其可操作变量**。一个变量只有在至少两个不同领域的研究中保持可比较定义、边界和测量，并经原 Owner 复核后，才可标为“已核验可跨域复用”。广泛出现、名字抽象、图中连接多，均不满足这一条件。

### 1.1 同一个词先分角色

| 对象 | 本文件怎样处理 | 不能直接推出 |
| --- | --- | --- |
| Factor | 可在指定分析中作为解释变量的状态或差异；例如需求紧迫度 | 改变它一定改变结果 |
| Resource | 在指定主体、权限和时段下可调用的存量；例如可用现金 | 名义拥有即实际可用 |
| Capability | 在指定任务、标准、负载和支持条件下能兑现的能力 | 职位、年限或一次成功等于能力 |
| Condition | 对象所处的背景、约束或暴露；例如决策权限 | 条件是可由本人操纵的原因 |
| Mechanism | 变量通过什么过程关联结果；单列 `VZM-*` | 画箭头即完成因果识别 |
| Dynamics | 周期、演化、阶段和状态转移；单列 `VZD-*` | 时间序列有波动即存在固定周期 |
| Outcome | 当前问题要评价的结果，由该结果 Owner 维护 | 未说明时点/因果角色就把同一观测值循环用于定义原因和结果；中介和滞后反馈可有不同角色 |
| Indicator | 构念的可观测代理或计算量；单列 `VZI-*` | 代理指标等于构念或目标价值 |
| Probability | 对明确事件、参考类和期限的模型估计 | “概率”本身是一种致因因素 |

`Factor / Resource / Capability / Condition` 是本表变量的单一 `primary_type`。一项构念可以在别的研究中承担结果或中介角色，但要注明时点和研究角色，不因此复制新 ID，也不在一个加总模型中重复计入。

## 2. Owner、字段与状态合同

### 2.1 职责各自唯一

| 职责 | 本轮位置与权限 |
| --- | --- |
| `identity_owner` | 本文件：拥有 `VZF-*` 身份、短定义、别名、路由和弃用映射。短定义用于辨别对象，不替代专业权威正文。 |

| `outcome_owner` | 根据当前问题选择；研究B的产品采用与经济回报必须分别定义结果，不能让同一因果记录拥有两个模糊终点。 |
| `risk_owner` / `resource_owner` | 由具体研究分别绑定；缺失时不得晋级行动权限。风险处置不会被平均研究分覆盖。 |
| `run_owner` | 在既有领域正文或研究记录中维护研究状态、预算、停止/重开条件；这里仅回写稳定增量与链接。 |

**候选的共同缺省字段**：`registry_status=candidate`、`evidence_status=not_assessed`、`evidence_scope=coverage_only`、`action_permission=research_only`、`last_reviewed=2026-11-22`、`review_trigger=定义冲突/新反证/Owner迁移/研究排序或行动条件变化`。以下各行均继承这些字段；表中的方向、时间和风险是**待检验命题或要排查的误用**，不是已发现的平均效应。

本文件的 `VZF-*` 是**索引身份**，不是对现有商业 Atom、营销 D 域、Canonical Knowledge ID 的替代。后续找到正式专业 ID 时登记映射；不得改名吞并、重编号或重复维护原正文。

## 3. 候选变量总表

### 阅读约定

- “方向”均相对于具体结果，默认 `±/Unknown`；表述“可能提高/降低”仅定义待检假设，不能用作行动依据。
- 时间是研究观察窗建议，不是经过估计的效应持续期。
- `A/B/C` 分别指互联网注意力竞争、软件交付后采用/回报不足、假设性跨维创业问题；唯一案例/证据Owner为 [路由样例与R2验收](03_全局路由样例与R2验收.md)，稳定ID分别是 `VZCASE-A-META-2022`、`VZCASE-B-STADIA-2022`、`VZCASE-C-HYPOTHETICAL`。关联只说明该问题应召回哪些候选，不表示真实案例证据已证明每一变量的效应。`—` 表示三例没有覆盖，不能为追求映射而强塞。
- 所有应用列给出的是**需要产出的观察或判断材料**，不是处方。自然、生物等行保留全局覆盖缺口，不假装三例已验证它们。

### 5.2 最小关系登记与现有Schema边界

### 5.3 作用命题必须把上下文写在边上

例如“退出成本增加使依赖更强”不能作为本表普遍结论。研究包装层至少写：

| 字段 | 要回答什么 |
| --- | --- |
| `research_question` | 哪个主体在何种安排中，退出成本变化是否改变哪种依赖结果？ |
| `relation_id / claim_id` | 连接哪条结构关联或候选主张；不可把关联直接升级成因果 |
| `condition / comparator` | 替代方案、权限、损失承担和约束是否相同？ |
| `mechanism / competing_explanations` | 是否经过替代受限、风险规避等中间环节？还有哪些解释？ |
| `direction / time_scale` | 正、负、非线性或Unknown；起效与观察窗口是什么？ |
| `evidence / counterevidence` | 当前来源实际支持哪一部分，哪些对照会削弱判断？ |
| `outcome / risk / owner` | 结果、风险、事实分别由谁裁决？ |
| `decision_change / stop` | 哪项观察会改变行动、排序或停止条件？ |

## 7. 从登记到持续深化

1. 从全局地图选一个会改变真实判断的节点，查本表及原Owner，先去重再分配新ID。
2. 固定结果、主体、比较对象、时间窗和风险门；从表中取少量变量，说明为什么排除其他变量。
3. 把变量关系写成可区分的候选机制；调用既有 [链路垂直深挖与审计框架](通用链路宇宙/19_链路垂直深挖与审计框架.md)，不再建立一套深挖目录。
4. 恢复旧证据、反例、Unknown与停止条件；搜证据并记录访问层级，形成条件化结论。
5. 仅在定义/别名/Owner/状态/研究路由发生增量时更新本表。事实、证据、专业结论与具体运行日志留在相应Owner。
6. 新证据冲突、Owner迁移、ID弃用、结果反转、风险变化时重开；只有同义复述或更多相同来源时不算研究进展。
7. 下游引用受影响时回归检查：A/B/C路由、原语义Owner、状态权限、指标边界、旧ID解析。结构通过不代表因果通过。

本轮没有把71条候选都展开为研究卡；也没有把发现优先级转成个人建议、专业行动或自动执行权限。
