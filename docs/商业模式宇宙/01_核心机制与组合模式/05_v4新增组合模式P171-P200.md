# 商业模式宇宙 v4：新增组合模式 P171-P200

> 本文件是 `../08_机器数据与Schema/patterns_v4_extension_P171-P200.jsonl` 的人类阅读镜像，用来补齐与 `03_v3新增组合模式P131-P170.md` 对称的阅读入口。
>
> **机器事实源仍以 JSONL 为准。** 本文件不创建新 ID，也不改变 P171-P200 的公式；新增或修改组合模式时必须同步更新机器文件与本阅读版。

## 一、定位

v4 的 30 个组合模式不是再增加一批“营销名字”，而是把以下横向系统组合成可执行结构：

> **商品角色 × 价格架构 × Offer Graph × Context Router × Basket/Cohort Economics × U19 条件经济 × 增量实验**

它们与 P001-P170 是增量关系，而不是替代关系。

特别是：

- `P171` 不重复 `P033 Loss Leader → Backend`；它增加资格围栏、Attach 测量、Cohort Economics 与滥用防护。
- `P198-P200` 更接近决策/核算/路由模式，用于约束 Skill，而不是具体行业故事。
- 同一项目可以同时使用多个 Pattern，不要求互斥分类。

| P174 | Sample → Trust → Full-size → Replenishment | 低成本样品 PR05 → 建立质量信任 PR08 → 正装 Core → 消耗周期补货 PR22 → 用 sample-to-paid 与 repeat 回收采样成本 |

| P178 | Anchor + Decoy + Target Tier | 目标 Tier + 真实 Anchor + 可解释 Comparison/Decoy → 改变选择集 → 受控实验验证目标 Tier 增量选择与利润，失败则移除 |

| P191 | Bundle Anchor → Cross-category Basket Optimization | 高感知 Bundle Driver → 搭配互补品形成套餐 → 优化总篮贡献而非逐 SKU 毛利 → 用 incrementality/cannibalization 测试套餐是否真实增量 |
| P192 | Unbundle Entry → Paid Add-ons → Premium Rebundle | 拆低首次门槛 → 用户只买最小核心 → 高价值功能 Add-on → 重度用户升级到重新打包 Premium → 比较 ARPU 与复杂度成本 |

| P194 | Paid Pilot → B2B Land-and-Expand | 小范围付费 Pilot 筛选真实项目 → 明确验收与价值证明 → Core 合同 → 席位/区域/模块/用量扩张 → 避免无限免费 PoC |
| P195 | Supplier-funded Entry SKU → Backend Profit | 供应商返点/MDF/free goods 改变入口 SKU 净成本 → 允许更强前端优惠 → 客户篮子/后端获利 → 必须把供应商条件、clawback 和资格写入 Net Effective Economics |
| P196 | Enterprise Gift → Recipient Acquisition | 企业付款购买礼赠/福利 → 收件人体验商品 → 合法转化为直接关系 → 个人复购/会员/推荐 → 同时计算 B2B 订单与 recipient cohort 价值 |
| P197 | Lifecycle Trigger → Next-best Offer | 结婚/搬家/育儿/续约/设备老化等生命周期事件 → 匹配下一阶段 PR26 产品 → 复用既有信任 → 延长 LTV 并设置敏感数据/隐私边界 |
| P198 | Promotion Budget as CAC | 把入口折扣 + 免费商品 + 券 + 配送补贴 + 直接履约成本统一视为增量获客投资 → 除以合格新增客户 → 与其他渠道 CAC 和 payback 比较 |
| P199 | True Cohort Contribution Waterfall | 前端收入 − COGS − 履约 − 配送 − 损耗 − 促销 + Attach/Backend/会员/复购/Cross-sell/返点等贡献 − CAC − 服务 − 退款 − 欺诈 = True Cohort Contribution |
| P200 | Contextual Offer Portfolio Router | 用户状态 × 时间 × 季节 × 地点 × 天气 × 事件 × 生命周期 × 库存 × 容量 → 生成 3~7 个候选 Offer Architecture → 经济/风险/品牌/渠道过滤 → 排序并用最小实验更新路由 |

## 三、使用纪律

调用 P171-P200 时至少继续检查：

1. 对应的 `PR01-PR40` 商品角色是否明确；
2. 价格机制是否映射到 U10，并经过 U19 Net Effective Economics；
3. 转化链是否以 Offer Graph 的节点和条件边表示；
4. 是否区分 Front-end、Basket、True Cohort Contribution；
5. 是否存在真实的 Attach/Backend/Repeat/Referral/Conditional Economics；
6. 是否考虑库存、容量、品牌、渠道、欺诈与合规约束；
7. 是否通过 control/holdout 或其他合理方法检验增量；
8. 是否设置 pass / kill / scale condition。
