# 商业模式宇宙 v4：缺口审计与研究来源

> 本文件记录 v4 为什么新增“商品角色 × 价格架构 × Offer 转化 × Context Router × Cohort Economics”，并把公开研究与机制推断分开。

## 一、对 v3 的缺口审计

### 已经覆盖，v4 不重复新增

v2/v3 已存在：

- `U04-A05 免费入口`、`U04-A06 低价爆品`、`U04-A07 高频刚需入口`；
- `U10-A22 Freemium`、`A24 Add-on`、`A25 Bundle`、`A26 Unbundle`、`A28 Cross-subsidy`、`A30 Credits`、`A31 Minimum Commitment`；
- `P023 Freemium`、`P028 Razor & Blade`、`P030 Add-on`、`P031 Bundle`、`P033 Loss Leader → Backend`、`P088 High-Frequency Wedge`；
- U19 + `P101-P130` 的返点、MDF、credits、free goods、净价瀑布、门槛优化；
- U21 的 Revenue/Contribution/Cohort Economics；
- U22 的 Breakage、Utilization、Spoilage、Yield Management；
- U25 的 Float/Working Capital；
- U26 的 Minimum Commitment、Auto-renew、Price Escalator、退出权；
- P135 Breakage、P137 Yield Management、P170 Economic Truth Waterfall 等。

因此“再新增 Loss Leader/Freemium/Breakage/返点”属于重复。

### v3 真正缺少

1. **商品角色 taxonomy**：Traffic/Hook/Loss Leader/Hero/Anchor/Decoy/Profit/Retention 等没有稳定、可多标签的机器对象。
2. **价格梯度与价格围栏**：首单、锚定、Decoy、地域、渠道、季节、场景、条件门槛等不完整。
3. **Offer 不是图**：已有 pattern 召回，但缺少 `Offer Node → conditional edge → next Offer` 的转化图。
4. **Context Router**：季节/天气/地点/生命周期/库存/容量没有共同进入“选哪个入口商品”的路由逻辑。
5. **促销经济未被强制 Cohort 化**：虽有 CAC/LTV/Contribution，但缺少统一的 Front-end → Basket → True Cohort Contribution 公式与促销 CAC。
6. **Incrementality 实验门不足**：容易把兑换、相关购买或自然回流误认为促销因果。
7. **商品角色与风险没有强绑定**：高端品牌稀释、渠道价冲突、需求前置、促销容量冲击等需要显式原子。

结论：v4 选择 **0 个新 L1，27 个缺失原子，40 个横向商品角色标签，30 个新 Offer Architecture 组合模式**。

# 二、公开研究校准：Loss Leader 与购物篮

## Source Fact A：低价促销不是自动利润机器

Walters & MacKenzie（Journal of Marketing Research, 1988）使用两个大型超市数据研究 loss leaders、店内特价与双倍优惠券。摘要报告：多数 loss-leader 促销对门店利润没有影响；那些影响利润的案例主要通过**门店客流**起作用，而不是促销 SKU 自身销售。

来源：
`https://journals.sagepub.com/doi/10.1177/002224378802500105`

### v4 机制推断

> “低价 → 流量 → 利润”必须拆成多个可验证边，不能以领取量或促销 SKU 销量直接证明模式成立。

## Source Fact B：购物篮能力会改变 Loss Leader 的可承受价格

*Pricing Best Sellers and Traffic Generators: The Role of Asymmetric Cross-selling* 研究多产品零售商的 cross-selling，指出 loss-leader/traffic-generator 的折扣能力与典型购物篮规模、跨售能力相关；更强的 cross-selling 能力可以支持更深的入口折扣。

来源：
`https://www.sciencedirect.com/science/article/pii/S109499681730052X`

### v4 机制推断

> 候选引流品必须联动 `Basket Size + Attach Rate + Incremental Basket Contribution`，而不是只比较入口商品成本。

## Source Fact C：跨品类定价会相互影响

Journal of Retailing 的 cross-category pass-through 研究发现，价格削减可能伴随其他品类的价格变化，说明零售利润决策需要跨品类观察。

来源：
`https://www.sciencedirect.com/science/article/pii/S0022435913000055`

### v4 机制推断

> SKU 毛利最优 ≠ 购物篮/门店利润最优；但“其他品类涨价补贴”也可能带来消费者和竞争风险，不能机械复制。

# 三、公开研究校准：季节、场景与天气

## Source Fact D：需求峰值期间某些零售品价格反而下降

Chevalier、Kashyap、Rossi（American Economic Review, 2003）基于超市扫描数据发现，某些商品在季节需求峰值期间价格平均下降，主要来自零售毛利下降；结果与 loss-leader 竞争模型一致。

来源：
`https://pubs.aeaweb.org/doi/10.1257/000282803321455142`

### v4 机制推断

> “需求最强时一定涨价”不是通用规则。高需求时令品也可能被用作 Traffic/Seasonal Hook，但必须看整个购物篮和竞争结构。

## Source Fact E：天气会同时改变季节品的需求、库存与价格决策

Fu（2014）研究 weather-sensitive seasonal demand 下的联合订货与定价；Gao 等（Production and Operations Management, 2012）研究 weather-conditional rebates，显示条件促销可以同时影响提前销售、库存持有和预期利润。

来源：
`https://onlinelibrary.wiley.com/doi/10.1155/2014/105098`

`https://onlinelibrary.wiley.com/doi/full/10.1111/j.1937-5956.2011.01298.x`

### v4 机制推断

> Weather-triggered Offer 不只是营销文案问题，还应同时读取库存、易腐性、提前销售和履约成本。

# 四、公开研究校准：价格选择架构

## Source Fact F：Decoy/Attraction Effect 有条件成立

Journal of Consumer Research 的近期研究继续验证 choice-set context/decoy 对选择的影响，同时也显示 effect 会随刺激表达、决策情境和机制条件变化，并非任何三档价格都必然产生同样结果。

来源：
`https://academic.oup.com/jcr/article-abstract/50/1/211/7036340`

`https://academic.oup.com/jcr/article-abstract/50/3/492/6935792`

### v4 机制推断

> `U10-A39 Decoy` 被注册为**可测试价格机制**，而不是“加一个更差套餐就一定提高利润”的确定规则。

---

# 五、公开研究校准：真实净价

## Source Fact G：发票价之外存在大量价格泄漏/利益

McKinsey 的 pocket price waterfall 框架强调，交易实际保留价格需要从 list/invoice 继续扣除或考虑 volume bonus、cash discount、co-op advertising、MDF、freight、payment terms、off-invoice promotions 等。

来源：
`https://www.mckinsey.com/capabilities/growth-marketing-and-sales/our-insights/the-power-of-pricing`

### v4 机制推断

> v4 不另造返点模型，而是在每个 Offer 上强制引用 U19 的 `Net Effective Economics`，把 supplier-funded entry offer 与真实净成本连接。

# 六、公开研究校准：AI/SaaS/API 价格架构

## Source Fact H：现代 usage billing 已经支持多种混合结构

Stripe Billing 文档将 recurring/usage pricing 区分为 flat rate、per-seat、tiered、usage-based，并列出 fixed fee + overage、pay-as-you-go、credit burndown。其 LLM token billing 文档进一步列出 credit packs/top-ups、included usage、pure usage 与 hybrid models。

来源：
`https://docs.stripe.com/billing/subscriptions/design-an-integration`

`https://docs.stripe.com/billing/token-billing`

`https://docs.stripe.com/billing/subscriptions/usage-based/billing-credits`

### v4 机制推断

> AI/API 的 Offer Architecture 应同时表示 `Entry Credits → Usage → Top-up/Overage → Commit/Upgrade`，而不是把 pricing 简化成“订阅 vs 按量”二选一。

---

# 七、公开研究校准：Breakage 与未使用权益

## Source Fact I：礼卡/未使用权利存在独立的会计判断

KPMG Revenue Recognition Handbook 的 gift-card/breakage 示例说明，在实体无法可靠估计 breakage 时，不应凭空确认预期 breakage；兑换历史和重大收入转回风险会影响会计处理。

来源：
`https://kpmg.com/kpmg-us/content/dam/kpmg/frv/pdf/2023/handbook-revenue-recognition.pdf`

### v4 机制推断

> Breakage 是经济变量而不是“免费利润”。Skill 必须区分预测与已实现、会计与现金、以及当地未认领财产/消费者保护等规则。

# 八、竞争与合规校准

Chen & Rey（American Economic Review, 2012）说明 loss leading 也可能产生竞争与市场结构效应，并不能只从单店促销 ROI 看待。

来源：
`https://www.aeaweb.org/articles?id=10.1257%2Faer.102.7.3462`

因此 v4 将：

- below-cost pricing；
- 渠道价格冲突；
- 价格歧视/围栏；
- 高端品牌稀释；
- 未披露利益；

纳入风险门，而不是把所有能提高短期转化的机制都标记为推荐。

---

# 九、证据边界

以上公开研究用于**校准机制是否值得进入宇宙**，不意味着任何具体项目的参数已被验证。

具体项目仍必须获得自身：

- SKU 成本；
- 订单与购物篮；
- 渠道价格；
- 供应商合同/返点；
- 库存/损耗；
- 促销历史；
- 用户 cohort；
- 会员/复购；
- 履约成本；
- 地区法律/合同；

再进入 E3-E5 证据等级。
