# 完整性与反方审计清单

> 本清单同时检查**商业知识完整性**与**仓库结构完整性**。目录重构后不能只确认“文件看起来还在”，还要确认入口、ID、加载顺序、引用和机器资产仍然可解析。

## 一、仓库结构完整性审计

- 是否仍只有一个人类总入口：`../README.md`？
- `00_当前有效版本与加载入口.md` 的路径是否与 main 实际目录一致？
- `MANIFEST.md` 是否覆盖当前全部功能层和关键文件？
- U01-U27、P001-P200、PR01-PR40 的稳定 ID 是否未被重排？
- v2/v3/v4 是否仍采用增量关系，而不是互相覆盖？
- `08_机器数据与Schema/` 中 atoms、patterns、registry、product roles、Schema、Validation 是否齐全？
- Skill 是否加载当前目录中的真实文件，而不是已迁移的旧文件名？
- Markdown 内部引用是否仍指向现存路径？
- 旧目录迁移到新目录后，关键 blob/tree SHA 是否出现非预期变化？
- 人类阅读版与机器事实源是否都有明确主从关系，避免双事实源漂移？
- 专题文件是否进入 `09_专题商业模式/`，没有在根目录再次形成平行入口？
- 研究来源与历史快照是否留在 `90_研究来源与参考/`，没有被误当当前事实源？
- `01_核心机制与组合模式/05_v4新增组合模式P171-P200.md` 与 `06_机会来源_差异捕获与商业模式变换算子.md` 是否各自只有一个当前入口，没有并发迁移副本？

结构调整后的机器校验基线见：

> `../08_机器数据与Schema/validation_v4.json`

## 二、商业知识完整性审计

- 是否遗漏参与者？
- 是否遗漏非付款受益者？
- 是否遗漏非货币资源？
- 是否遗漏第三方付款、补贴和多方支付？
- 是否遗漏资金流、账期、预付和资本结构？
- 是否遗漏风险、责任和治理权？
- 是否遗漏价值链位置变化？
- 是否遗漏行业特殊约束？
- 是否遗漏商业模式迁移？
- 是否遗漏 U19 返点、后台利益和 Net Effective Economics？
- 是否把 Front-end、Basket、True Cohort Contribution 分开？
- 是否遗漏商品角色、价格架构、Offer Graph 与 Context Router？
- 是否遗漏库存、容量、Breakage、公共激励、合同和劳动力经济？

### 机会发现专项

对任何“新机会、套利、共享、轻资产、免费、返利、先订单后供给”等想法，必须继续检查：

- 是否扫描了 **O1-O11**：需求价值、资源/容量、价格成本规模、信息/搜索/信任、时间/地域/渠道、资金/流动性/信用、风险、交易/协调、技术/标准化、生态/网络、制度/合规？
- 识别出的“差异/摩擦/错配”是否真正转成了客户可感知价值，而不是只写“有差价”？
- 是否使用 **T1-T12** 明确改变了参与方、权利、颗粒度、资产边界、供给时序、中介治理、收入定价、采购成本、现金资本、风险信任、产品/平台迁移或生命周期中的某些结构？
- 是否回到 U01-U27/L2 atom 正式表达候选方案，而不是建立第二套概念库？
- 是否核算真实净经济，而不是只看标价、名义毛利或表面 GMV？
- 是否判断了持久性：S1 结构价值、S2 可重复差异、S3 临时套利、S4 漏洞/违规依赖？
- 是否通过 A-D 风险门，并为 B/C 类补齐授权、合同、平台规则、牌照或监管事实？

## 三、正交性审计

- 是否把 SaaS、订阅、按席位、PLG 放在同一抽象层级？
- 是否存在大量同义词重复？
- 是否把渠道战术误当商业模式？
- 是否把案例名称当成模式类型？
- 是否把 Product、Product Role、Pricing Mechanism、Offer、Pattern、Business Model 混成同一个对象？
- 是否把 Opportunity Source、Transformation Operator、Atom、Pattern、Strategy、Tactic、Case 平铺在同一层？
- 是否把价格差、信息差、地域差、时间差直接命名为“商业模式”，而没有说明价值转换和交易结构？
- 是否为了一个横向问题机械新增 U28+，而没有先检查现有 U01-U27？

## 四、反方审计

- 需求是否真实？
- 谁愿意付钱，为什么？
- 是否存在绕开平台或脱媒？
- 单位经济是否可能为负？
- 规模扩大后成本是否反而增加？
- 网络效应是否真实而非口号？
- 护城河是否可持续？
- 供应商为何愿意参与？
- 监管、合规、信用或履约风险由谁承担？
- 低价/免费入口是否只是在补贴原本会购买的人？
- 是否存在促销滥用、品牌稀释、渠道冲突、需求前置或容量冲击？
- 机会是否只依赖暂时不透明、平台漏洞、合同漏洞、地域限制或未授权内容？如果差异明天消失，业务是否还能成立？
- 所谓“轻资产”是否只是把资产风险换成供应商依赖、质量、履约、平台规则或合同风险？
- 所谓“规模返点”是否是正式合同收益，还是未披露利益冲突/秘密回扣？
- 所谓“共享”是否基于合法使用权/许可，还是超授权账户共享？
- 所谓“信息交易”是否有版权、IP、数据、访问权或转售授权？
- 哪条证据可以直接推翻当前商业模式假设？

## 五、结构修改后的强制回读

每次移动、拆分、合并或重命名目录后至少重新读取并核对：

```text
README.md
→ MANIFEST.md
→ 00_导航与总览/00_当前有效版本与加载入口.md
→ 00_导航与总览/11_知识层级与分类规范.md
→ 00_导航与总览/12_阅读与使用路径.md
→ 01_核心机制与组合模式/06_机会来源_差异捕获与商业模式变换算子.md
→ 07_元数据知识图谱与Skill/02_v4_Skill机器加载与Offer决策协议.md
→ 08_机器数据与Schema/validation_v4.json
→ 08_机器数据与Schema/business_model_signature_v4.schema.json
```

如果发生以下任一情况，不得宣称结构调整完成：

- 必需文件 404；
- 旧路径仍作为当前加载入口；
- Schema/Validation/Skill 的路径与 README 不一致；
- 关键 ID 重排；
- 机器文件数量或范围与当前版本口径不一致；
- 文件已移动但内部引用未更新；
- 机会来源/变换算子与正式 atom/pattern 形成双事实源；
- 只验证 commit 成功，没有回读 main。
