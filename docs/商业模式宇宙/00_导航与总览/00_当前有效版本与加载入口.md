## 7. 维护纪律

任何目录、机器协议或运行时调整后，必须同步检查 README、MANIFEST、本文件、阅读路径、Skill 内引用、Validation、runtime Router/Protocol/Benchmark，并重新读取 GitHub `main`。

真实项目输出不好时，先定位：

```text
项目理解
→ 商业问题
→ 市场研究
→ 成功/失败机制
→ 利润池
→ 上下游
→ 候选多样性
→ 经济性
→ 排序
→ 行动
→ P20 状态继承
→ 最后才判断本体知识缺口
```

只有最后确认“现有体系真的无法表达反复出现、跨项目可迁移的机制”，才优先扩 Atom / Pattern / Schema。
