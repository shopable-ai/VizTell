# 商业模式宇宙：当前有效版本与加载入口

## 1. 当前有效版本

### v4 本体

- v2 基线：U01-U19、500 个原子机制、P001-P130 共 130 个组合模式。
- v3 增量：U20-U27 共 149 个原子机制；P131-P170 共 40 个组合模式。
- v4 增量：不新增一级域；在既有 U01-U27 中增加 27 个跨域原子、PR01-PR40 共 40 个商品角色、P171-P200 共 30 个组合模式，并新增 v4 Schema、Validation 与 Offer 决策 Skill 协议。
- 当前合并本体视图：**U01-U27、676 个原子机制、200 个组合模式、40 个商品角色**。

`../01_核心机制与组合模式/06_机会来源_差异捕获与商业模式变换算子.md` 是横向机会发现与模式重构镜头：解释“为什么存在机会、怎样重构现有模式”，但不新增 U28、不新增 atom ID、不改变 P001-P200。

### runtime-v1 横向运行时

本轮在 v4 之上新增：

- Task Router；
- 8 个核心任务族 + Cross-cutting Flags；
- 最小充分上下文与渐进检索策略；
- Real Data / Evidence / External Research Gate；
- 端到端 Commercial Reasoning Workflow；
- Trace / Observability；
- A-E Benchmark；
- Retrieval/Module Ablation；
- Error Taxonomy；
- Regression；
- Knowledge Feedback / Lifecycle。

**runtime-v1 不是 v5 本体。** 它不新增 U、Atom、Pattern 或 Product Role ID，只定义“如何使用、测试和维护 v4”。

## 5. 当前第一阶段 Benchmark

### T01 电子书 Seed Case

输入：

> “基于这本电子书/PDF，研究适合的电商销售与后端商业模式。”

重点测：专题 + 通用宇宙 + Product Role/Offer + Value Chain + True Cohort 是否能组合。

### T02 AI API Canary

输入：

> “按调用计费的 AI API 怎样设计免费额度、commit、overage、渠道和企业后端，避免增长越快亏得越多？”

重点测：跨电子书场景、变量推理成本、Usage/Commit、企业合同和负毛利防线。

A-E 五组最终答案质量必须真实运行后再报告；`benchmark_harness` 的确定性分数只表示 Router/Context/Preservation 是否正确，禁止冒充商业决策质量。

## 7. 冲突优先级

1. 当前版本数字、Schema、Validation 与加载路径以本文件和根 `README.md` 为准；
2. v4 本体/Registry/Schema/Skill 决定稳定知识对象；
3. runtime-v1 决定如何路由、检索、执行和评测，但不得覆写本体稳定事实；
4. v2/v3 文件保留基线与增量语义；
5. 历史目录不作为当前事实源。

任何目录、机器协议或运行时再次调整后，必须同步检查 README、MANIFEST、知识层级、阅读路径、Skill 内部引用、Validation 的 `load_rule/required_current_files`、runtime Router/Protocol/Benchmark，并重新读取 GitHub `main`，不能只以 commit 成功作为完成标准。
