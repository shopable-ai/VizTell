# 商业模式宇宙：统一结构与迁移映射

## 一、问题诊断

此前目录同时存在：

- `universe-business-model/`：第一轮建设，主题分层清楚，适合人工浏览，但定位是 V0.1 / Level 1 知识系统。
- `商业模式宇宙-带整合/`：第二轮及后续 v3/v4 建设，原子机制、组合模式、返点真实经济性、商品角色、Offer/Cohort 横向系统、JSONL、Schema、Skill 协议完整，但文件平铺，容易与第一套形成“双入口”。

真正的问题不是哪一套应该删除，而是两套承担了不同职责，却被放在同一级作为两个“宇宙”。

## 二、合并原则

1. **一个宇宙，一个顶级入口。**
2. **版本与知识形态分离。** v2/v3/v4 是版本关系；主题地图/原子库/横向系统/机器数据是知识形态关系。
3. **通用机制与专题实例分离。** 电子书等专题进入 `09_专题商业模式/`。
4. **人类可读与机器可读分离。** JSONL/Registry/Schema/Validation 进入 `08_机器数据与Schema/`。
5. **真实经济性单独成层。** U19、U20-U27、隐藏利润与 Cohort Economics 统一进入 `06_真实经济性_返点与治理/`。
6. **横向系统不滥增一级域。** v4 复用 U01-U27，通过增量原子、商品角色和模式连接跨域推理。
7. **旧 ID 不重排。** U01-U27、原子 ID、P001-P200、PR01-PR40 保持已有稳定性。
8. **来源与历史不进入当前推理主链。** 统一进入 `90_研究来源与参考/`。

## 四、为何没有“直接把两套内容揉成一个超长文件”

这种做法会造成：主题地图和原子机制层级被打散；v2/v3/v4 增量关系消失；ID 稳定性难维护；Skill 无法稳定加载；人类阅读与机器检索同时恶化。

因此本次采用的是**目录本体合并 + 唯一入口 + 版本优先级 + 功能层归位**，而不是文本暴力拼接。
