# 阅读与使用路径

> 本文件只使用当前合并后的唯一目录 `docs/商业模式宇宙/`。旧路径 `01_商业模式宇宙/`、`90_参考知识/` 已废弃。

## 1. 快速理解商业模式宇宙

1. `../README.md`：先确认当前有效版本、目录职责和冲突优先级。
2. `00_当前有效版本与加载入口.md`：确认 U01-U27、676 atoms、P001-P200、PR01-PR40 的当前口径。
3. `../01_核心机制与组合模式/00_商业模式宇宙总览与核心结论.md`：理解核心逻辑、27 个设计域和横向系统。
4. `../01_核心机制与组合模式/01_L1-L2原子机制库.md`：查具体原子。
5. `../01_核心机制与组合模式/02_L3经典与组合模式库.md`、`03_v3新增组合模式P131-P170.md`、`04_v4商品角色价格架构Offer转化与场景经济.md`、`05_v4新增组合模式P171-P200.md`：查组合模式与 v4 横向结构。
6. `../01_核心机制与组合模式/06_机会来源_差异捕获与商业模式变换算子.md`：理解机会为什么出现，以及怎样把现有结构变换成候选商业模式。
7. `../06_真实经济性_返点与治理/`：校验返点、条件性收益、Cohort、容量、风险、合同、财资和会计经济真相。

## 2. 为具体项目寻找新的商业模式机会

这是本轮新增的推荐路径：

1. **先找机会来源**：阅读 `../01_核心机制与组合模式/06_机会来源_差异捕获与商业模式变换算子.md`，扫描需求、资源、价格/成本、信息、时间/地域/渠道、资金、风险、交易效率、技术、生态、制度等机会来源。
2. **再做结构变换**：使用同文件 T1-T12 变换算子，尝试改变参与方、付款者、所有权、供给边界、颗粒度、履约时序、收入、现金流、风险与治理。
3. **映射正式原子**：回到 `../01_核心机制与组合模式/01_L1-L2原子机制库.md`，只使用已有 U01-U27/L2 机制正式表达候选方案。
4. **形成组合模式**：查 `02_L3经典与组合模式库.md`、`03_v3新增组合模式P131-P170.md` 与 `05_v4新增组合模式P171-P200.md`，判断候选是已有组合、变体还是新的复合结构。
5. **检查价值链与利润池**：进入 `../02_价值链与利润池/`，确认利润从哪里产生、谁被替代、谁获得新增价值、控制点在哪里。
6. **检查生态与价值交换**：进入 `../03_生态与价值交换/`，确认多方激励、非货币价值、合作方收益和治理是否成立。
7. **核算真实经济性**：进入 `../06_真实经济性_返点与治理/`，把返点、账期、Credits、补贴、退款、风险、容量、现金流纳入净经济。
8. **做失败与反方审计**：进入 `../05_失败模式与迁移/01_失败模式库/`。
9. **设计迁移路径**：进入 `../05_失败模式与迁移/02_商业模式迁移路径/`，将变换算子组合成阶段性迁移，而不是一次性“重做全部模式”。
10. **最后看案例**：进入 `../04_案例与行业地图/`，用案例验证，而不是从单一案例反推宇宙分类。

主链可压缩为：

> **机会来源 → 差异/错配 → 客户价值 → 变换算子 → U01-U27 原子 → Pattern 组合 → 利润池/生态 → 真实经济性 → 风险门 → 迁移与实验。**

## 3. 深入研究某一种模式

1. 在 `../01_核心机制与组合模式/02_L3经典与组合模式库.md`、`03_v3新增组合模式P131-P170.md`、`05_v4新增组合模式P171-P200.md` 中找到 Pattern；机器事实源最终以 `../08_机器数据与Schema/*.jsonl` 为准。
2. 拆解其对应 U01-U27 原子。
3. 检查商品角色、价格架构、Offer Graph 与 Context Router 是否只是横向配置，而不是新的模式分类。
4. 查看 `../04_案例与行业地图/` 中的实例和行业适配。
5. 查看 `../02_价值链与利润池/` 中利润池、成本池和控制点。
6. 查看 `../06_真实经济性_返点与治理/` 中净经济、Cohort、容量与风险。
7. 查看 `../05_失败模式与迁移/` 中失效条件与下一阶段迁移。

## 4. 研究“免费、低价、返点、共享、套利”类想法

不要直接把关键词当商业模式名称。

推荐顺序：

> `06_机会来源_差异捕获与商业模式变换算子` → `U04/U10/U11/U12/U13/U19/U22/U23/U25/U26` → `06_真实经济性_返点与治理` → `05_失败模式与迁移`

重点检查：

- 免费/低价是获客、Offer、定价还是长期交叉补贴？
- 返点是正式合同收益还是未披露利益冲突？
- 共享是官方许可的使用权切分，还是违反许可/账号规则？
- 套利是否给客户创造真实价值，还是只依赖短期信息差/漏洞？
- 规模扩大后利润是否真实改善？
- 如果差异消失，模式是否仍然成立？
