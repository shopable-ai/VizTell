# 阅读与使用路径

> **默认原则：解决真实项目或看懂现实中的赚钱现象，先走人类业务工作流；只有需要查机制、结构化加载、Retriever、Trace 或质量保障时，才进入本体/机器/Benchmark 层。**

---

## 1. 真实商业项目：默认推荐路径

正式入口：

```text
../10_任务工作流与运行时/项目商业推理工作流/
```

阅读/执行顺序：

1. `00_总览_怎样使用项目商业推理工作流.md`：先理解总链、目录和业务/技术边界；
2. `01_P01-P20项目商业推理总工作流.md`：完整地图；每个 P 都说明必做/可跳过、输入、输出、错误和下一步；
3. `02_真实项目与现实输入入口.md`：判断当前输入属于已有项目、功能、灵感、经营问题、真实数据、商业现象、案例还是迁移；
4. 根据决策需要进入 `03-08`，并按需调用 `09_专题商业模式/`、`01-06` 知识资产；
5. `09_项目输入输出模板与快速清单.md`：形成统一候选、经济性、排序、行动和状态账本；
6. 新结果进入 P20，只重跑受影响阶段。

人工主链：

> **项目是什么 → 现在到哪一步 → 当前真正问题 → 高价值未知 → 已有资产 → 用户/付款 → 真实市场 → 成功/失败机制 → 商业知识 → 利润池 → 上下游/相邻机会 → 3-5 套候选 → 商品/收费 → 经济性 → 风险/成立条件 → A-E 评级 → 排序 → 最小验证 → 真实交易 → P20 持续经营。**

旧 `10/03`、`10/05`、`10/06` 仅为历史兼容入口，不再作为第二套业务事实源。

## 2. 不同现实输入从哪里进入

### 已有项目

> `02 已有项目入口 → P02-P07 → P11-P18 → 07 实际交易/P20`

重点：已有用户/付款方、商品/功能、收入成本、未商品化资产、漏利润、后端和企业价值。

### 已有功能/资产

> `02 功能入口 → P06-P07-P11-P14-P15-P18 → 07`

重点：

> **功能 → 用户任务 → 价值/成本强度 → 商品角色 → 套餐/按量 → 价格 → 真实付费。**

### 灵感/想法

> `02 灵感入口 → P01-P05-P07-P13-P19`

先找谁最需要、为什么现在会付钱、当前替代、可以变成哪些结构不同的生意、哪个最便宜验证。

### 具体经营问题

利润低、转化低、复购低、CAC 高等：

> `P04 → P06 → P15-P19`

不要重新讲完整项目历史。

### 已有真实数据

> `P15 → P17 → P18 → P19/P20`

真实数据必须导致方案保留、重排、修改、淘汰或验证“不改变排序”。

## 3. 看到别人的赚钱现象：先逆向拆解

入口：

> `../10_任务工作流与运行时/项目商业推理工作流/08_商业现象逆向拆解工作流.md`

标准链：

```text
观察现象
→ 表面交易能否解释长期盈利
→ 建立 H1-H12 盈利假设
→ 找支持证据
→ 找反证
→ 排除/降权
→ 重建核心/辅助/条件性收入
→ 判断可持续性
→ 最后判断能否迁移
```

**不能默认“低价 = 引流”。** 如果现实证据不足，允许最终结论明确写“真实核心利润来源目前无法确认”。

T04 的实际示例见：

`../10_任务工作流与运行时/项目商业推理工作流/10_真实项目验证_T03_AI_PDF与T04_低价电子书现象_2026-08-25.md`。

## 4. 成功/失败案例怎样使用

入口：`项目商业推理工作流/03_市场研究_成功失败与证据判断.md`。

成功案例不直接输出“照抄会员/订阅/平台”，而先拆：付款方、收入、成本、频率、复购、供给/采购、渠道、现金流、控制点、壁垒、必要条件。

失败案例判断：

> **失败的是模式本身，还是错误用户、价格、渠道、成本、时机、规模、资本或执行条件？**

之后再进入 P10-P18 判断迁移。

## 6. 研究免费、低价、返点、共享、套利类想法

推荐：

> `02 判断现实输入 → 如果是观察现象先 08 → 01/06 机会来源 → 相关 U/Pattern → 06真实经济性 → 05失败/迁移 → P15-P19`

重点：

- 免费/低价到底是获客、价格、Offer 还是长期交叉补贴；
- 返点是否正式可验证、有哪些门槛/上限/Clawback；
- 共享是否符合许可/账号规则；
- 套利是否创造持续客户价值还是只依赖漏洞；
- 规模扩大后利润是否真实改善；
- 条件性收入不能未经验证进入 Base Case。

## 9. 真实项目输出不好时的修复顺序

```text
项目理解错？
→ 商业问题错？
→ 市场研究不足？
→ 成功/失败机制错？
→ 利润池漏了？
→ 上下游漏了？
→ 候选同质？
→ 经济性不够？
→ 排序不好？
→ 行动不具体？
→ P20 没继承状态？
→ 最后才判断商业模式宇宙真的缺知识？
```

只有最后一种反复出现，并且现有体系无法表达跨项目机制时，才优先扩 Atom / Pattern / Schema。
