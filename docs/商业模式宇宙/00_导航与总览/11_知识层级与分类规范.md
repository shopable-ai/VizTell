# 知识层级与分类规范

> 本文件使用当前 `README.md` 与 `00_当前有效版本与加载入口.md` 的口径。旧的“L1=原子、L2=机制、L3=结构”定义已废弃，避免与当前 U01-U27 / atoms / patterns 发生层级冲突。

## 1. 当前唯一层级口径

### L0 核心商业逻辑

> **创造价值 → 交付/交换价值 → 捕获价值 → 强化、更新与退出。**

L0 只描述最抽象的价值逻辑，不承载具体模式 ID。

### L1 设计域（Design Domain）

当前为 **U01-U27 共 27 个一级设计域**。

例如：参与方、价值主张、权利包装、供给、平台、交易治理、定价、收入、成本、现金流、数据/IP、增长、壁垒、风险、条件性收益、所有权、容量、风险池、财资、合同、劳动力等。

L1 回答：**一个完整商业系统必须检查哪些主要设计问题？**

### L2 原子机制（Atom）

当前合并视图共 **676 个原子机制**。

原子是最小可复用商业设计单元，例如：

- 按量计费；
- 供应商账期；
- 租赁；
- 经纪；
- 交叉补贴；
- Escrow；
- 采购返点；
- 共享基础设施。

L2 回答：**每个设计域里有哪些可组合的最小机制？**

### L3 组合模式（Pattern）

当前为 **P001-P200 共 200 个组合模式**。

Pattern 是多个原子的稳定组合，例如：

- Razor & Blade；
- Freemium；
- Marketplace；
- Productized Service；
- Qualified Loss Leader → Basket Profit 等。

L3 回答：**哪些原子组合已经形成可复用的稳定商业模式结构？**

### L4 实例 / 案例（Instance / Case）

真实公司、项目、产品或行业在特定时间点采用的具体组合。

案例可以同时实例化多个 Pattern，不允许强迫一个企业只属于一个类别。

### L5 场景、迁移与重构（Context / Migration）

描述：

- 某一模式在不同场景中的适配；
- 从当前模式迁移到候选模式的路径；
- 不同阶段如何改变权利、供给、收费、资本、风险与生态结构。

本层主要对应 `05_失败模式与迁移/`。

## 2. 横向知识对象：不占用 L1-L5 层级 ID

以下对象用于分析和组合，但**不得机械升级成新的 U 域、atom 或 Pattern**。

### 2.1 Product Role

PR01-PR40。描述某个 Offer 在当前系统中的角色，例如 Traffic、Anchor、Profit、Trust、Reactivation。

**商品角色 ≠ 商业模式。**

### 2.2 Opportunity Source / 机会来源

回答“为什么存在可改善和可捕获的商业空间”。

例如：

- 需求缺口；
- 闲置容量；
- 价格/成本/规模差；
- 搜索与信任成本；
- 时间/地域/渠道差；
- 资金、信用、风险错配；
- 交易与协调低效。

机会来源详见：

`../01_核心机制与组合模式/20_机会来源_差异捕获与商业模式变换算子.md`

**机会来源 ≠ 原子机制。** 它通常解释“为什么值得重构”，而不是“采用了什么商业设计”。

### 2.3 Transformation Operator / 商业模式变换算子

回答“怎样把现有结构改成另一种候选结构”。

例如：

- 所有权 → 使用权；
- 整体 → 切片；
- 先采购 → 先订单；
- 自营资产 → 第三方资产；
- 商品差价 → 佣金；
- 固定费 → 按量/结果；
- 单边付款 → 第三方付款；
- 自担风险 → 风险共享/转移。

变换算子主要属于**发现、设计与迁移语法**，本轮不增加 atom ID。

### 2.4 Strategy / Competition Mechanism

战略回答“选择哪种商业模式与竞争位置”；竞争机制回答“依靠什么获得相对优势”。

例如：成本领先、独家资源、供应保障、网络效应、品牌、标准、生态、规模等。

**竞争战略 ≠ 商业模式。** 某些竞争机制只有在长期改变活动系统时，才成为商业模式结构的一部分。

### 2.5 Tactic / Offer / Promotion

在既定商业模式允许范围内的可调整动作：

- 临时折扣；
- 免费试用；
- 促销；
- 优惠券；
- 销售话术；
- 某次渠道活动。

**战术 ≠ Pattern。**

### 2.6 Risk Case

违反版权、许可、账户规则、平台条款、金融监管、消费者保护或反商业贿赂要求的具体做法，不因“能赚钱”而进入正常分类。

处理方式：

> **高风险案例 → 抽象底层经济机制 → 找合法合同/授权实现 → 再映射到 U01-U27。**

## 3. 分类规则

1. **唯一层级口径。** L1=U01-U27，L2=atoms，L3=patterns；不得再维护第二套 L1/L2/L3 定义。
2. **主归属 + 多标签。** 一个概念可以跨多个 U 域，但只设置一个主定义位置。
3. **同义词不重复建模。** 同义词进入术语映射，避免为不同中文表达创建多个 atom。
4. **案例不能替代定义。** 案例进入 `04_案例与行业地图`，机制定义进入 `01`。
5. **定价、商品角色、模式分开。** `低价`、`Traffic Product`、`Loss Leader` 不能混成同一个对象。
6. **返点进入 U19。** 采购返利、门槛返利、Credits、后台基金等统一进入条件性经济，不另造一套“隐藏利润模式”。
7. **机会来源不直接升格。** 价格差、信息差、地域差、时间差等首先是机会来源，只有形成稳定活动系统时才可能对应 Pattern。
8. **变换算子不直接升格。** “产品→平台”“所有权→使用权”描述迁移方向，不自动成为一个新 atom。
9. **竞争动作不直接升格。** 免费、降价、透明报价、长期合同等必须先判断它是 Offer、定价、治理、战略还是完整模式的一部分。
10. **合法性优先于技巧感。** 若候选结构必须依赖欺骗、未授权访问、盗版、规避安全控制、秘密回扣或虚假交易才能成立，直接退出正常候选集。
11. **多文件引用优于复制。** 横向知识以链接映射现有 U 域，不复制第二套定义。
12. **机器层与人工知识层分离。** 新的人类分析镜头只有在经过稳定性、去重和兼容性审核后，才考虑进入 Registry / Schema / Skill；本轮不自动同步。

## 4. 快速判断：一个新概念放哪里？

> **它在回答“为什么有机会？” → Opportunity Source**  
> **它在回答“怎么把结构改掉？” → Transformation Operator / L5 Migration**  
> **它是最小稳定设计选择？ → L2 Atom**  
> **它是多个原子的稳定组合？ → L3 Pattern**  
> **它是某企业实际做法？ → L4 Case**  
> **它是临时价格/促销/销售动作？ → Tactic / Offer**  
> **它是相对竞争位置与长期优势？ → Strategy / U16 等**  
> **它依赖违规执行？ → Risk Case，不进入正常模式库。**
