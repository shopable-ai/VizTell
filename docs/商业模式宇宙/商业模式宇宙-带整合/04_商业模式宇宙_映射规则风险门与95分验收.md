## 2. 新资料进入宇宙的去重规则

一个新“模式”先判断：

1. 是否只是已有模式换了行业？
2. 是否只是已有模式换了营销文案？
3. 是否只是 L2 原子的不同组合？
4. 是否已有同义模式名？
5. 是否只是“商品角色”而不是新模式？
6. 是否只是价格围栏/情境触发，而不是新 L1？
7. 是否真正改变参与方、价值流、现金流、权利结构、转化结构或风险分配？

只有最后一类明显成立时，才优先考虑新增 Pattern；只有现有 U01-U27 无法容纳、且能跨大量行业解释新现象时才考虑 U28+。

## 4. 基础风险门

以下模式不能只凭“案例故事”直接推荐：

- 长期全额返现；
- 高固定收益承诺；
- 代客理财/资金池；
- 股权/收益权众筹；
- 借贷/BNPL；
- 保险返佣；
- 多层推荐收益；
- 储值/钱包/代收资金；
- 自动投资；
- 高杠杆资产模式。

必须先做：

> **法律监管 → 资金隔离 → 最坏情形现金流 → 用户保护 → 退出机制**

## 8. 返点/后台经济门

分析任何采购、广告、渠道、云、软件、零售或分销项目时必须问：

1. 有没有发票外利益？
2. 有没有达量、增长、份额或产品组合门槛？
3. 是追溯式还是增量式？
4. 能不能跨账号/公司/客户聚合？
5. 有没有 MDF、Co-op、credits、free goods 或服务价值？
6. 谁是最终 beneficiary？
7. 有没有 side letter、principal trading 或 dual rate card？
8. 是否存在 clawback、封顶、期限或申领要求？
9. 折算后的 Net Effective Price 是多少？
10. 是否存在未披露利益、个人回扣、竞争法、反贿赂或会计风险？

一票否决：

- 把个人秘密回扣包装成正常“商业模式优化”；
- 只看报价而忽略后台返利；
- 为冲返点而制造负贡献订单；
- 把未兑现/未满足资格的返点当成确定利润；
- 忽略 clawback 与返还义务。

# 9. v4 商品角色门

每个关键 Offer 必须至少回答：

```text
它是什么产品/服务/权益？
它的 primary_role 是什么PR ID？
是否还有 secondary_roles？
角色对应哪个KPI？
角色什么时候失效/退出？
```

禁止：

- 把“卖得多”同时当流量、信任、利润、留存全部成功；
- 把 Traffic Product 与 Loss Leader 当同义词；
- 把 Anchor/Decoy 当成商品永久属性；
- 为了凑 taxonomy 强制每个 SKU 都使用很多角色。

# 10. v4 低价/免费 Offer 经济门

任何 PR03 Loss Leader、超低价、免费、首单补贴方案，必须同时输出：

```text
Front-end Contribution
Basket Contribution
True Cohort Contribution
Qualified Promo CAC
LTV
Payback
Attach Rate
Backend Conversion
Repeat Rate
Refund/Abuse
Cannibalization
```

并回答：

1. 为什么是这个入口品，不是其他候选？
2. 用户是不是目标用户？
3. 是否只吸引薅羊毛/套利用户？
4. 同篮/后端到底靠什么回收？
5. supplier funding / rebate 是否已经进入真实净成本？
6. 活动是否抢走原本全价订单？
7. 是否只是把未来需求提前？
8. 流量放大后履约成本是否反转？
9. 是否伤害高端价格锚点？
10. 是否触发渠道价保/冲突？

### 一票否决

- 没有可识别后端利润池仍声称“先亏后赚”；
- 只用领取量/促销SKU销量证明活动成功；
- 不计算配送、履约、损耗、客服、算力等增量成本；
- 不计算自然购买/cannibalization；
- 不设置补贴预算上限和 kill condition。

# 11. v4 Incrementality 实验门

优先验证：

> **没有 Offer 时，目标行为本来会发生多少？**

候选方法：

- randomized holdout；
- geo/store matched control；
- switchback；
- difference-in-differences；
- pre/post + 合理对照。

必须记录：

- treatment/control；
- 样本与排除条件；
- 观察窗/归因窗；
- 主指标；
- guardrails；
- pass/kill/scale condition；
- 季节、库存、竞品、并行活动等混杂因素。

无法随机化时必须下调 evidence level，不得用伪精确因果语言。

# 12. v4 Context Router 门

```text
Customer State
+ Lifecycle
+ Time/Season
+ Holiday/Event
+ Location/Weather
+ Inventory
+ Capacity
+ Channel
+ Current Intent
```

并把“需求触发”与“运营触发”分开：

- 需求触发：天气热、节庆、搬家、续约、探病等；
- 运营触发：库存临期、低峰容量、返点门槛、MDF、物流空载等。

禁止把“夏天西瓜好卖”直接泛化为全年固定入口。
