# 商业模式宇宙：映射规则、风险门与 95 分验收

## 1. 当前70个案例在体系中的位置

当前资料应该作为：

> **案例实例库 / Seed Case Library**

而不是分类宇宙。

处理顺序：

```text

→ 标注L2原子
→ 标注L3组合模式
→ 记录成立条件
→ 记录来源陈述

→ 记录风险
→ 生成可迁移问题
```

## 2. 新资料进入宇宙的去重规则

一个新“模式”先判断：

1. 是否只是已有模式换了行业？
2. 是否只是已有模式换了营销文案？
3. 是否只是L2原子的不同组合？
4. 是否已有同义模式名？
5. 是否真正改变了参与方、价值流、现金流、权利结构或风险分配？

只有第5类明显成立时，才优先考虑新增模式节点。

## 4. 风险门

以下模式不能只凭“案例故事”直接推荐：

- 长期全额返现
- 高固定收益承诺
- 代客理财/资金池
- 股权/收益权众筹
- 借贷/BNPL
- 保险返佣
- 多层推荐收益
- 储值/钱包/代收资金
- 自动投资
- 高杠杆资产模式

必须先做：

> **法律监管 → 资金隔离 → 最坏情形现金流 → 用户保护 → 退出机制**

## 5. 95 分验收表

| 维度 | 权重 | 通过标准 |
|---|---:|---|
| 覆盖完整性 | 20 | 传统、数字、平台、供应链、金融、AI、循环均有位置 |
| 正交与去重 | 15 | 行业、原子、组合、实例明确分层 |
| 因果深度 | 15 | 能解释谁付钱、为何成立、利润和现金流来自哪里 |
| 跨行业迁移 | 15 | 能按经济结构而非关键词找类比 |
| 机器可读 | 10 | 有稳定ID、Schema、关系和Skill输入输出 |
| 证据纪律 | 10 | 事实/来源陈述/推断/假设分离 |
| 风险与合规 | 10 | 高风险模式有门控与失败条件 |
| 可扩展性 | 5 | 新模式可挂载而不重构整个体系 |
| **总计** | **100** | **目标 ≥95** |

## 8. 返点/后台经济门

分析任何采购、广告、渠道、云、软件、零售或分销项目时必须问：

1. 有没有发票外利益？
2. 有没有达量、增长、份额或产品组合门槛？
3. 是追溯式还是增量式？
4. 能不能跨账号/公司/客户聚合？
5. 有没有MDF、Co-op、credits、free goods或服务价值？
6. 谁是最终beneficiary？
7. 有没有side letter、principal trading或dual rate card？
8. 是否存在clawback、封顶、期限或申领要求？
9. 折算后的Net Effective Price是多少？
10. 是否存在未披露利益、个人回扣、竞争法、反贿赂或会计风险？

一票否决：

- 把个人秘密回扣包装成正常“商业模式优化”；
- 只看报价而忽略后台返利；
- 为冲返点而制造负贡献订单；
- 把未兑现/未满足资格的返点当成确定利润；
- 忽略clawback与返还义务。
