# 商业模式宇宙：返点、门槛、后台利益与真实净经济性

> 这一层解决：**“报价/发票看到的经济性”和“企业最终真正得到的经济性”不是一回事。**

很多行业的利润空间、渠道动力和采购优势都存在第二层甚至第三层：

> **标价 → 前台折扣 → 后台返点 → 非现金权益 → 基金/credits → 账期价值 → 价差/分成 → 真实净价格**

这部分既包含完全正常的合同商业激励，也包含需要披露、审计甚至禁止的利益冲突。二者必须严格分开。

---

## 一、为什么必须单独建模

### 1. 大客户真实价格经常不是公开价格

公开价通常只回答：

> “单笔买多少钱？”

真实经济性还取决于：

- 一年累计买多少；
- 是否跨过阶梯门槛；
- 是否按集团/多个账户汇总；
- 是否增长超过去年；
- 是否卖厂商战略产品；
- 是否有认证或合作伙伴等级；
- 是否达到市场份额；
- 是否提前承诺未来用量；
- 是否得到现金以外的媒体、credits、MDF、培训、数据、运费、账期等；
- 是否有期末 true-up；
- 后续是否发生 clawback。

所以商业模式 Skill 不能只读取 `price`，必须读取一整套 **conditional economics**。

# 二、真实净价 Price Waterfall

## 2.1 买方视角

```text
公开标价 List Price
- 发票内折扣
- 合同折扣
- 即时促销
= Invoice / Front-end Price

- 数量返点
- 增长返点
- 年终返点
- 合作伙伴奖励
- 采购返点
- Cash rebate
= Cash-adjusted Price

- Free goods 的等值金额
- Media / Cloud / Ad credits
- MDF / Co-op 可兑现价值
- 免费培训/支持/服务的可用价值
- 物流/安装补贴
= Benefit-adjusted Price

± 账期/预付产生的融资价值
+ 必须承担的服务费、平台费、履约费
+ 因返点条件产生的额外运营成本
+ 预计 clawback
= Net Effective Cost / 实际净成本
```

## 2.2 卖方视角

```text
Gross Billings / 名义流水
- 前台折扣
- Cash Rebate
- 年终返点
- Credits
- MDF / Co-op
- Free Goods 成本
- 渠道分成
- Affiliate / Agent Commission
- Price Protection / Chargeback
- 退款 / Clawback
= Net Effective Revenue

- 可变履约成本
- 获客成本
- 服务成本
= Contribution Margin
```

**流水、发票金额、GAAP/IFRS收入、现金收入、经济贡献不是同一个指标。**

# 三、门槛函数：返点必须机器可计算

## 3.1 最低门槛

```text
if eligible_spend < threshold:
    rebate = 0
else:
    rebate = eligible_spend × rate
```

## 3.2 追溯式阶梯

例：

```text
0 - 100万：0%
100万 - 300万：3%
300万以上：6%
```

一旦达到 300 万：

> 如果合同是“追溯式”，可能对全部合格基数按 6% 重算。

这会造成明显的 **threshold cliff**。

## 3.3 增量式阶梯

```text
前100万 × 0%
下一200万 × 3%
300万以上增量 × 6%
```

只有新增部分适用高比例，经济曲线更平滑。

## 3.4 增长返点

```text
growth = current_period / baseline_period - 1

if growth >= target:
    rebate = eligible_spend × growth_rate
```

必须定义：

- 基期是什么；
- 并购/新账户是否排除；
- 退款是否扣减；
- 币种怎样换算；
- 哪些SKU合格。

## 3.5 组合门槛

现实合同经常不是单变量：

```text
Spend >= S
AND Growth >= G
AND Strategic_Product_Mix >= M
AND Certification = True
AND Region in Eligible_Regions
```

所以不能用一个简单 `rebate_rate` 字段。

# 四、返点机制完整分类

## A. 按“触发条件”分类

- 数量/金额
- 增长率
- 市场份额
- 品类份额
- 战略产品占比
- 新客户
- 续约
- 使用量
- 认证/能力
- 推广活动
- 陈列/流量位
- 独家/优先
- 区域拓展
- 提前付款
- 长期承诺
- 服务质量
- 客户成功/结果

## B. 按“结算形式”分类

- 现金
- 银行转账
- Credit note
- Free goods
- 免费媒体库存
- 广告 credits
- 云 credits
- SaaS credits
- MDF
- Co-op fund
- 培训
- 研究/数据
- 物流支持
- 安装/实施
- 延长账期
- 价格保护
- Stock rotation
- Chargeback / Bill-back

## C. 按“可见程度”分类

### V0：公开价
所有用户可见。

### V1：公开门槛价
官网/渠道政策公开，但只有满足资格的人可获得。

### V2：合同价
写入框架合同，外部看不到，但双方明确。

### V3：后台政策
交易先按前台价发生，周期末根据累计数据返还。

### V4：集团聚合利益
单一客户未必直接看到；奖励建立在代理集团、母公司或分销集团总量上。

### V5：非现金隐形利益
free inventory、credits、MDF、服务、数据、账期等，不容易从单价发现。

### V6：未披露代理利益
代理/中介从供应方获得与客户支出相关的利益，但客户未知。
这是**利益冲突风险层**。

### V7：个人级秘密回扣
资金或利益进入采购/销售/代理个人，而不是合同主体。
这是**商业贿赂/欺诈风险层**，不能作为正常商业模式原子来优化。

# 五、广告与媒体行业：为什么尤其容易“看不到”

公开研究已经记录过以下结构：

- 按媒体采购额计算的现金返点；
- 免费媒体库存 credits；
- 与采购量关联的服务协议；
- Value Pots；
- Principal trading；
- Dual rate cards；
- 集团总量带来的后台经济利益。

因此分析广告代理/大广告主时不能只看：

> 媒体刊例价、代理费、表面CPM。

还要问：

```text
谁和媒体签约？
Agency 是 agent 还是 principal？
返点按单客户还是集团总量？
客户是否获得其 proportionate share？
是否存在 free inventory/value pot？
是否存在额外 service agreement？
是否存在不同的 buy rate / sell rate？
实际净媒体成本是多少？
代理的 total economics 是多少？
```

# 六、渠道、软件和云：后台利润层

典型组合：

```text
前台毛利
+ 基础渠道返点
+ Growth Accelerator
+ Strategic Product Accelerator
+ Deal Registration
+ MDF / Co-op
+ Cloud Credits
+ Certification Incentive
+ Renewal Incentive
+ Payment-term value
= Total Partner Economics
```

所以评估“卖某软件/API有没有利润”时，不能只算：

> 厂商给我的公开折扣是多少。

要计算：

> **Total Partner Economics / 总渠道经济性。**

# 七、零售、CPG、分销和制造：净价也可能被多层重构

典型结构：

```text
List Price
- Off-invoice discount
- Volume rebate
- Growth rebate
- Free goods
- Slotting / Display fund
- Performance fund
- Markdown allowance
- Freight allowance
- Chargeback
- Early payment discount
= Net-Net / Net Effective Price
```

“买价”如果只取ERP发票价格，会漏掉后台真实利润。

# 八、返点不是越高越好：门槛陷阱

例：

还差 10 万采购即可多获得 20 万年度返点。

表面看：

> “赶快多买10万”。

但必须计算：

```text
新增返点
- 新增商品真实成本
- 库存持有成本
- 降价清库存损失
- 资金占用
- 退货/过期风险
- 为冲量产生的低质量订单
= Incremental Economic Benefit
```

只有结果 > 0 才值得冲门槛。

因此 Skill 应提供：

> **Threshold Opportunity Calculator**

而不是简单提示“再买一点就能拿返点”。

# 十、Skill 应新增的 5 个能力

## `rebate-extractor`

从合同、价目表、邮件、渠道政策中提取：

> 门槛、比例、基数、周期、资格、结算、clawback。

## `net-price-waterfall`

把所有经济利益统一折算：

> **公开价格 → 实际净价格。**

## `threshold-optimizer`

判断：

> 是否值得冲刺下一档返点。

## `rebate-auditor`

检查：

- 漏领返点；
- 算错基数；
- 过期申领；
- 未计提；
- 重复或互斥激励；
- clawback；
- 集团量未合并。

## `hidden-economics-risk-auditor`

识别：

- 未披露代理利益；
- personal kickback；
- 服务协议掩盖返点；
- 双重价卡；
- principal trading 利益冲突；
- 不合理排他条件；
- 返点驱动的低质量采购。

# 十一、必须加入商业模式分析的新问题

以后分析任何项目时增加：

1. **公开价格之外，还有没有后台价格？**
2. **采购/销售额达到什么门槛后经济性会变化？**
3. **返点是追溯还是增量？**
4. **能否跨账户、跨品类、跨客户聚合？**
5. **现金之外还有哪些 credits / goods / funds / services？**
6. **账期是否构成经济收益？**
7. **谁拿到返点——最终客户、代理公司、渠道公司还是个人？**
8. **返点是否必须返还/分享给委托方？**
9. **代理有没有因为后台奖励改变推荐方向？**
10. **为了冲返点而增加的交易是否仍有正贡献？**
11. **返点会不会被追回？**
12. **合同里是否有审计权和数据权？**
13. **折算所有利益后的净价是多少？**
14. **是否存在合规、竞争、反贿赂或会计风险？**

# 十二、正常返点、利益冲突与回扣必须分开

## 合法/正常商业激励

例如合同化的：

- 数量折扣；
- 达量返点；
- MDF；
- co-op；
- commitment discount；
- free goods；
- early payment discount。

本质上是商业定价和渠道激励。

## 需披露/治理的代理利益

例如：

- 代理因客户采购量获得媒体或供应商额外收入；
- principal trading；
- group-level value pot；
- 双重价卡。

关键问题不是“有无返点”，而是：

> **权利归属、合同约定、披露和利益冲突。**

## 高风险秘密回扣

利益直接流向个人，或者以虚假服务等方式隐藏交易动机。

这种情况不能被当成“提高利润空间”的优化技巧，应进入：

> **anti-bribery / fraud / compliance review。**

# 十三、宇宙中的核心新结论

以前：

> **价格 = 报价。**

现在：

> **价格是一个函数。**

```text
EffectivePrice =
f(
  list_price,
  account_identity,
  volume,
  growth,
  product_mix,
  partner_tier,
  commitment,
  time,
  region,
  aggregation_scope,
  rebates,
  funds,
  credits,
  payment_terms,
  clawbacks,
  disclosure_rules
)
```

因此很多商业机会并不是：

> “找到更便宜的供应商。”

而是：

> **找到更优的交易身份、累计方式、门槛结构、渠道等级、产品组合、结算周期和可合法获取的后台经济利益。**

这才是“商业模式宇宙”在采购、渠道、广告、云、软件和平台领域进一步深入后应该具备的能力。
