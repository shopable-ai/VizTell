# 商业模式宇宙：总览与核心结论（v4 合并视图）

## 0. 定义

**商业模式不是一个行业标签，也不是一个“盈利方式”列表。**

统一定义为：

> **某个组织如何选择参与方和价值主张，组织资源与交易，形成需求与交付，通过商品角色、Offer、定价、收入、成本、现金流和条件性经济捕获价值，并依靠留存、网络效应、复制、控制点、治理与生命周期管理持续存在。**

v4 核心总链：

> **识别参与方与需求 → 设计价值主张 → 选择产品/权利包装 → 分配商品角色 → 获客与分发 → 组织供给 → 建立交易与信任 → 构造价格架构与 Offer 图 → 识别返点/门槛/后台经济 → 捕获收入 → 核算 Front-end/Basket/Cohort 贡献 → 管理成本与现金流 → 留存复购 → Context Router 动态选择下一 Offer → 复制增长 → 建立壁垒 → 风险治理 → 实验验证 → 迭代/迁移/退出**

## 1. 为什么不能只做“100种商业模式”

商业模式是一个**组合空间**。一个真实企业往往同时是：

> SaaS + Freemium + Usage-based + PLG + API + Marketplace + Revenue Share

因此“模式名词表”只能作为参考索引，不能作为宇宙本体。

商业模式宇宙采用六层结构：

- **L0 核心逻辑**：创造价值 → 交付/交换价值 → 捕获价值 → 强化/更新价值。
- **L1 27 个设计域**：v2 U01-U19 + v3 U20-U27；v4 不新增 U28+。
- **L2 原子机制**：最小可复用商业设计单元。
- **L3 组合模式**：多个原子稳定组合形成的模式。
- **L4 实例/案例**：具体公司、项目或行业中的真实实现。
- **L5 场景与迁移**：把现有模式迁移到新项目后的方案与实验。
- **横向系统**：返点/经济真相/治理等 v3 系统 + v4 商品角色、价格架构、Offer 图、Context Router、Cohort Economics。

## 4. v4：五个新的横向系统，而不是 U28+

### 4.1 Product Role System

商品角色使用 `PR01-PR40` 稳定标签。角色是**上下文属性**，不是商品永久属性。

例如：

> 同一西瓜在夏季可以同时是 Seasonal Hook + Traffic Product；在其他季节可能只是普通商品。一个精品礼盒可以是 Core、Profit、Premium、Enterprise Gift 的组合。

### 4.2 Price Architecture System

把“一个价格”升级成：

> **参照/Anchor → 进入/Trial/Intro → Segment/Channel/Geo/Time/Context Fences → Choice Architecture → Meter/Commitment → Net Effective Economics**

### 4.3 Offer Conversion Graph

不要求所有项目都走：

> Free → Entry → Core → Upsell → Subscription

而是用 Offer Node + Conditional Edge 表达分支、回流、唤醒与不同客群路径。

### 4.4 Context Offer Router

> **用户状态 × 时间 × 季节 × 地点 × 天气 × 事件 × 生命周期 × 库存 × 容量 × 渠道 → 候选 Offer → 经济/风险过滤 → 下一最佳 Offer**

### 4.5 Cohort Economics & Incrementality Guardrail

> **Front-end Contribution → Basket Contribution → True Cohort Contribution**

并要求 control/holdout 等实验尽可能区分“相关购买”与“真正增量”。

## 5. 三种知识对象必须分开

### 5.1 原子机制 Atom

单一设计选择，例如：按量计费、供应商账期、托管支付、店中店、用户推荐、数据网络效应、首单价、渠道价。

### 5.2 组合模式 Pattern

多个原子稳定组合，例如：

> **Razor & Blade = 低利润耐用品 + Installed Base + 专有耗材 + 持续复购**

或 v4：

> **Qualified Loss Leader → Basket Profit = 高感知入口 + 资格围栏 + 合格流量 + Attach/Backend + Cohort Contribution + Abuse Guardrail**

### 5.3 商品角色 Product Role

说明某个 Offer 在当前系统里承担的任务，例如 Traffic、Trust、Anchor、Profit、Reactivation。它不是新的商业模式分类。

### 5.4 模式实例 Instance

具体公司的实际组合。实例绝不能被强迫归入唯一分类。

## 7. 核心原则

1. **行业 ≠ 商业模式。**
2. **盈利方式 ≠ 完整商业模式。**
3. **免费/低价不是模式终点，必须知道谁补贴、在哪里回收、多久回收。**
4. **Traffic Product ≠ Loss Leader。** 流量品是角色，Loss Leader 是允许前端贡献为负的经济策略。
5. **商品角色 ≠ 定价机制 ≠ 组合模式。** 三者必须独立建模再组合。
6. **平台不是“做一个App”，必须存在多方交互价值。**
7. **现金流好不等于利润好；利润好也不等于现金流安全。**
8. **账面价格 ≠ 实际净经济价格。** 必须经过 U19 Net Effective Economics。
9. **公司级合同返点 ≠ 个人秘密回扣。** 后者进入反贿赂/欺诈风险。
10. **AI产品不能默认照搬传统SaaS固定席位价。** 推理成本随使用变化，应比较 usage、credits、included usage、overage、commit 等结构。
11. **Breakage 是经济/会计变量，不是通过人为增加兑换摩擦获得“免费利润”的方法。**
12. **季节/天气/事件是 Router 输入，不应机械生成一个永久“季节模式”L1。**
13. **高转化率 ≠ 高增量利润。** 必须看 cannibalization、需求前置、自然回流和 control/holdout。
14. **SKU 毛利 ≠ Basket/Cohort 利润。**
15. **任何候选模式最终回到单位经济、现金流、条件经济、参与方激励、风险和实验。**

## 8. 研究基础

本宇宙综合而非仅从当前案例反推：

- Osterwalder / Strategyzer：Business Model Canvas；
- Teece：价值创造、交付、捕获；
- Gassmann / Frankenberger / Csik：Business Model Navigator；
- Weking 等：商业模式 pattern 层次分类；
- Hagiu & Wright：多边平台组织经济学；
- Bocken 等：可持续商业模式原型；
- McKinsey：Pocket Price Waterfall；
- Journal of Marketing Research / Journal of Interactive Marketing / Journal of Retailing：Loss Leader、流量与 cross-selling；
- Journal of Consumer Research：选择集、Decoy/Attraction Effect 的情境条件；
- American Economic Review：季节性高需求与 Loss Leading、竞争效应；
- Stripe Billing：usage、credits、overage、hybrid pricing 的现实机器化实现；
- KPMG/会计准则材料：gift card/breakage 与收入确认校准。
