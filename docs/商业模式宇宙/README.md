> **唯一总入口。** 原 `universe-business-model/` 与 `商业模式宇宙-带整合/` 已按功能层重新合并，不再并列维护两套“商业模式宇宙”。

## 当前有效版本：v4 合并视图

- L1：**U01-U27，共 27 个一级设计域**；v4 不新增 U28+。
- L2：**676 个原子机制** = v2 500 + v3 149 + v4 27。
- L3：**P001-P200，共 200 个组合模式**。
- 横向商品角色：**PR01-PR40，共 40 个**，不计入 L2 atom。
- U19 返点/条件性收益层及旧 ID 保持稳定；v3/v4 使用 additive registry / extension，不覆盖旧数据。

统一分析主链：

> **参与方与需求 → 价值主张 → 产品/权利包装 → 商品角色 → 获客与渠道 → 供给与交付 → 交易与信任 → 价格架构与 Offer Graph → 返点/条件性经济 → 所有权与治理 → 会计与经济真相 → Front-end/Basket/Cohort 贡献 → 容量/库存/风险/公共激励/财资/合同/劳动力 → 留存复购 → Context Router → 增长复制 → 壁垒与竞争反应 → KPI/增量实验 → 风险治理 → 迁移/退出**

## 为什么必须合并

此前两轮建设形成了两个顶级目录：

1. `universe-business-model/`：主题知识地图、价值链、生态、案例、行业、失败与迁移，适合人工浏览。
2. `商业模式宇宙-带整合/`：原子机制、组合模式、返点/真实经济性、v3/v4 横向系统、JSONL、Schema、Skill，适合结构化推理和机器加载。

它们不是两个互斥版本，而是**同一知识系统的不同功能层**。继续并列会造成入口冲突、版本冲突、重复检索和 Skill 加载歧义。本次重构把两者合成一个本体目录，并保留各自优势。

## 不丢失与后续维护规则

1. 不重排 U01-U27、既有原子 ID、P001-P200、PR01-PR40。
2. 禁止再次创建第二个“商业模式宇宙”顶级目录；新内容必须挂载到现有功能层。
3. 横向问题优先复用现有 U01-U27，不为“商品角色/季节/天气/Offer”机械新增一级域。
4. 商品角色、定价机制、组合模式、实例必须分开建模。
5. 价格分析必须经过 U19 Net Effective Economics；不得另造一套返点体系。
6. 低价/免费入口必须核算 Front-end、Basket、True Cohort Contribution 与 Qualified Promo CAC，并设置增量实验及 kill condition。
7. 新机器对象同时更新 Registry/Schema/Validation/Skill，不把机器文件散落在知识正文目录。
8. 通用机制回流 `01/06`，案例回流 `04`，专题项目留在 `09`。
9. 每次扩展后审计：唯一入口、ID 稳定性、Schema 兼容、加载顺序、证据/假设分离、风险门与退出条件。
10. 每次目录移动后，必须同步更新 README、MANIFEST、Skill 内部引用、Validation 路径，并回读 GitHub `main` 验证。
