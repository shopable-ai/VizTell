# 项目商业推理工作流：总览与使用方法

> 本目录是普通创业者、产品负责人、经营者使用“商业模式宇宙”解决真实商业问题的**默认人工入口**。
>
> 它不要求用户先理解 Atom、Pattern、Schema、Retriever、Runtime、Trace 或 Benchmark。技术运行时继续保留在上一级目录，作为后台能力和质量保障层。

---

## 一、这套工作流最终要解决什么

用户只需要给出下面任意一种现实输入：

- 一个已有项目；
- 一组已有功能或资产；
- 一个产品；
- 一个灵感；
- 一个具体经营问题；
- 一组经营数据；
- 一个观察到的赚钱现象；
- 一个成功或失败案例；
- 一个想迁移到自己项目的商业玩法。

工作流的目标不是“列出很多赚钱方式”，而是持续回答：

> **这个项目到底可能怎样赚钱、当前最值得做什么、为什么、怎样最低成本验证，以及真实结果出来后下一轮怎样继续。**

## 二、普通人一眼能理解的业务总链

```text
项目是什么
→ 现在到哪一步
→ 当前真正要解决什么
→ 最值得补什么信息
→ 现在已经拥有什么
→ 谁在用、谁付钱、为什么付钱
→ 市场现在怎样
→ 别人为什么成功、为什么失败
→ 哪些商业机制值得借鉴
→ 钱在哪里
→ 上下游和相邻机会在哪里
→ 有哪几套结构不同的方案
→ 每套到底卖什么、怎么收费
→ 哪套经济性最好
→ 有什么竞争和风险
→ 哪些已经被市场验证
→ 如果只能先做一个，应该选哪个
→ 怎样最低成本验证
→ 怎样转成真实交易
→ 根据结果继续经营
```

这条链是人工理解入口；更细的 P01-P20 是当前完整地图。

关于“P01-P20 是否应该继续作为 20 个同级业务阶段”的重新审计，以及下一版人工业务问题地图、P01-P20 调整建议和业务→工程映射，见：

该文件当前属于**业务架构审计与下一版设计基准**，不直接替代本目录当前正式执行主干。

## 三、默认阅读与执行路径

```text
00 本总览
↓
01 P01-P20 项目商业推理总工作流
↓
02 判断现实输入类型与最佳入口
↓
按当前商业问题进入 03-08 中必要模块
↓
09 使用统一输入、输出、决策、行动和项目状态模板
↓
P20 读取真实结果并进入下一轮
```

不要求所有项目逐文件、逐阶段机械跑完。

如果用户已经有明确经营数据，可以直接从经济性与排序进入；如果只是看到别人的奇怪赚钱现象，应先进入逆向拆解，而不是先替用户设计一个项目。

`11_业务优先审计_业务问题地图与工程映射.md` 不属于日常项目执行必经路径；它用于下一阶段重构、审计和工程化时阅读。

## 五、业务工作流与后台运行时怎样共存

人工默认路径始终以本目录为首。

上一级目录中的这些文件继续承担后台职责：

- `../00_下一阶段演进与成熟度地图.md`：系统演进；
- `../01_任务路由_检索_上下文与数据门.md`：Router、Retriever、Context、Data Gate；
- `../02_端到端商业推理Workflow与知识生命周期.md`：后台运行协议、Trace、错误分类、知识生命周期；
- `../../08_机器数据与Schema/`：Schema、JSONL、Runtime；
- `../../11_Benchmark与回归/`：Benchmark、Regression。

只有当真实项目输出明显不好，并且诊断为检索、上下文、机器协议或知识覆盖问题时，才回到底层修复。

标准排错顺序：

```text
项目理解错？
→ 商业问题找错？
→ 市场研究不足？
→ 成功/失败机制判断错？
→ 利润池漏了？
→ 上下游漏了？
→ 候选同质？
→ 经济性不足？
→ 排序不好？
→ 行动不具体？
→ P20 没有继承状态？
→ 最后才判断商业模式宇宙是否真的缺知识
```

## 六、默认用户输出不是长报告，而是商业决策面板

详细研究可以很深，但第一屏优先给：

```text
项目一句话判断
当前阶段
当前最重要商业问题
已经确认的关键事实
当前最大未知
市场已经验证什么
市场已经证明哪些方式容易失败
最值得赚钱的 3 个位置
第一推荐
第二推荐及其反超条件
暂时不要做什么
下一步只做哪 1-3 件事
```

之后再按用户需要展开证据、经济性和研究过程。

## 七、完成标准

这套工作流只有在以下事情都能发生时才算有效：

1. 一个现实输入可以快速进入正确阶段，而不是被迫填写完整问卷；
2. 市场研究只追踪会改变决策的信息；
3. 事实、推断、假设和未知明确分开；
4. 能从利润池、上下游和用户后续任务发现项目之外的收入机会；
5. 后台可以广泛发现机会，但用户只看到 3-5 套结构不同方案；
6. 没有数据时仍能用公式、区间、情景、敏感性和 Break-even 推进；
7. 必须明确第一推荐、第二推荐、第三推荐和暂不推荐；
8. 第一推荐能变成可成交的商品、价格、渠道和交付；
9. 每个关键实验有继续、修改、停止、扩大条件；
10. 新数据进入后从 P20 继续，而不是每次从头做一遍商业模式分析。

最终形态应该像：

> **一套真正可运行的 AI 商业项目顾问工作流。**
