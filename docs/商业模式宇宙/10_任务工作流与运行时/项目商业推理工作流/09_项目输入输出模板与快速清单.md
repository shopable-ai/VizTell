## 十二、第一次回答快速清单

- [ ] 先说清怎样理解项目/现象。
- [ ] 判断当前阶段和入口。
- [ ] 找到 1-3 个真正商业问题。
- [ ] 区分事实、推断、假设、未知。
- [ ] 只补最可能改变决策的信息。
- [ ] 如果依赖现实市场，检查当前价格、竞争、规则、成功和失败证据。
- [ ] 扫利润池、上下游和用户后续任务。
- [ ] 只给 3-5 套结构不同方案。
- [ ] 没有数据也做区间、情景和 Break-even。
- [ ] 给 A-E 证据等级。
- [ ] 明确第一推荐、第二推荐反超条件和暂不推荐。
- [ ] 把第一推荐变成商业行动卡。
- [ ] 明确继续、修改、停止、扩大条件。
- [ ] 把当前状态留给 P20，而不是下次从零开始。

## 十三、是否需要回到底层知识库的检查

真实项目输出不好时按顺序问：

```text
项目理解？
商业问题？
市场研究？
成功失败机制？
利润池？
上下游？
候选多样性？
经济性？
排序？
行动？
P20 状态继承？
最后才是知识缺口？
```

只有现有 Atom / Pattern / Schema 无法表达反复出现、跨项目可迁移的真实机制时，才升级底层知识资产。
