# 候选商业方案、商品价格与经济性

> 后台可以发现 20-50 个机会，但进入用户决策前必须收敛成 3-5 套结构真正不同的方案，并把每套方案落到商品、收费与真实经济。

## 一、候选方案必须“结构不同”

不同方案至少在以下一项有根本差异：

- 谁付款；
- 卖什么结果、权利或服务；
- 真正利润池；
- 获客渠道；
- 收费计量；
- 风险由谁承担；
- B2C / B2B；
- 自营 / 伙伴 / 平台；
- 一次性 / 订阅 / 按量 / 结果 / 分成；
- 前端与后端关系；
- 现金流和合同结构。

“9.9 元、19.9 元、29.9 元”不是三套方案。

## 二、每套候选必须回答的完整问题

```text
这个方案是什么？
谁付款？
为什么付款？
卖什么？
用户买到什么结果/权利？
前端入口是什么？
真正利润池是什么？
后端是什么？
获客渠道是什么？
怎样收费？
经济逻辑是什么？
市场有没有验证？
成功证据是什么？
失败证据是什么？
成立条件是什么？
为什么适合当前项目？
为什么可能不适合？
最大假设是什么？
最小验证是什么？
Kill Condition 是什么？
```

## 三、已有功能怎样变成商品

不能直接：

```text
功能 A = 一个价格
功能 B = 一个价格
功能 C = 一个价格
```

应该：

```text
功能
→ 用户任务
→ 价值强度
→ 使用频率
→ 成本强度
→ 对哪类用户最重要
→ 商品角色
→ 套餐/按量/附加项
→ 价格与升级路径
```

典型商品角色可以是：

- 免费入口；
- 低门槛入口商品；
- 核心商品；
- 利润商品；
- 高成本按量项；
- Upsell/Cross-sell；
- 专业版/团队版；
- 企业版；
- 服务/实施/培训后端。

---

## 四、价格设计不是单个数字

至少同时考虑：

```text
免费边界
入口价
核心价
高级价
按量计费
容量/用量限制
年付/Commit
Add-on
团队席位
企业合同
退款/试用
```

价格的任务是匹配价值、成本、用户分层和升级路径，而不是只提高转化率。

高变动成本能力尤其要检查：

> 重度用户是否会因为“无限量套餐”变成负毛利用户。

## 五、没有真实数据也必须算经济性

### 1. 前端贡献（Front-end Contribution）

```text
成交收入
- COGS/采购/版权
- 推理/API/履约
- 支付/平台/渠道
- 退款/客服
- 促销增量成本
= 前端贡献
```

### 2. 订单贡献（Basket Contribution）

```text
前端贡献
+ Add-on
+ Upsell
+ Cross-sell
+ 同次服务
+ 已确认订单级条件收益
= 订单贡献
```

### 3. 用户群真实贡献（True Cohort Contribution）

```text
订单贡献
+ 复购
+ 订阅/会员
+ 后端商品
+ 转介绍/再激活
+ 已确认返点/MDF/Credits
- CAC
- 持续服务成本
- 退款/坏账/滥用
- 融资/Clawback 等
= 用户群真实贡献
```

### 4. 现金流

同时检查：

- 收钱时间；
- 付款时间；
- 应收；
- 预收后的履约义务；
- 库存；
- 账期；
- CapEx；
- Working Capital。

## 六、缺数据时的标准推进法

使用：

```text
公式
→ 合理区间
→ 保守 / 基准 / 乐观
→ 敏感性
→ Break-even
→ 最值得补的数据
```

示例不是固定阈值，而是计算方法：

```text
Break-even 后端转化率
= 入口每用户亏损 / 后端每成交用户净贡献
```

如果入口每用户亏 5 元，后端每成交用户净贡献 100 元，则在忽略其他项时，后端转化率至少约 5% 才能补平入口亏损。真实项目还要加入 CAC、退款、服务等项目后重新计算。

---

## 七、条件性收益的处理

返点、MDF、Credits、平台奖励、邀请收入等按三层处理：

```text
Base：只算已经确认、可获得、与当前规模匹配的收益
Conditional：有明确规则，但尚未达到条件
Speculative：只听说、无合同/规则证据
```

Speculative 不得用来证明方案盈利。
