# 最小验证、实际赚钱与持续经营

> 工作流不能结束在“第一推荐”。必须把商业判断变成真实交易、真实数据和下一轮经营。

## 一、从第一推荐到真实交易

```text
第一推荐
→ 目标用户是谁
→ 到底卖什么
→ 用户买到什么结果/权利
→ 为什么愿意付钱
→ 价格/计费方式
→ 在哪里成交
→ 怎样交付
→ 怎样获得第一批真实交易
→ 收集哪几个最重要数据
→ 继续 / 修改 / 停止 / 扩大
→ P20 更新状态
```

## 三、先做最小可卖商品

优先顺序：

```text
先证明有人愿意真实付钱
→ 再证明可以稳定交付
→ 再证明单位经济成立
→ 再证明可以重复获客
→ 最后扩大功能、团队或投入
```

最小可卖商品可以是单品、专题包、服务套餐、付费试用、按量 API、企业 Workshop、人工完成的知识库实施或其他可交付结果。

不要因为最终想做 SaaS，就必须先开发完整 SaaS。

## 四、只验证最可能改变决策的假设

先问：

> **如果这轮只能知道一个新事实，哪个事实最可能改变第一推荐？**

常见最大假设：

- 需求强度；
- 支付意愿；
- 价格是否成立；
- 渠道能否获得合格用户；
- 入口是否真的带来高价值后端；
- 复购/续费是否存在；
- 企业是否愿意进入采购；
- 推理/履约成本是否吞掉毛利；
- 供应商返点是否真实可得；
- 版权、合同、平台条件是否允许长期做。

## 五、指标优先级

对于商业化验证，通常：

```text
真实付费
> 有购买意向的有效线索
> 进入结账/报价
> 高质量试用
> 注册/下载
> 点击/收藏/点赞/曝光
```

具体业务可不同，但不能用浅层互动替代支付或贡献验证。

## 六、Continue / Change / Kill / Scale

### Continue：继续

例如目标价格有人真实购买、CAC 低于可承受上限、后端转化足以让 Cohort 转正、企业客户持续进入采购流程。

### Change：修改

例如需求强但价格错；愿意购买但渠道 CAC 高；入口成立但后端错；企业愿意谈但交付太重；重度用户价值高但套餐导致负毛利。

Change 的含义是修结构，不是立即判死项目。

### Kill：停止

例如多轮 Offer 优化仍无真实支付；必须依赖不可持续补贴/漏洞；用户价值不足以覆盖 CAC 和履约；关键版权、合同、政策条件无法满足；竞争结构中没有合理利润空间。

### Scale：扩大

只有正贡献结构被验证后才扩大，并明确扩大的是哪一项：高价值用户、有效渠道、某价格档、后端商品、企业行业、供应商合作或自动化交付，而不是笼统“加大投入”。

## 七、不同项目阶段看什么

### 想法/早期验证

真实支付、成交顾虑、价值主张、第一批合格客户。

### 已有产品/用户

付费转化、ARPU/客单、商品组合、使用频率、复购/续费、Upsell/Cross-sell、退款。

### 已有收入/利润优化

Contribution Margin、CAC、CAC Payback、LTV/Cohort Contribution、退款、坏账、履约/推理/客服、渠道净收入和真实返点。

### 企业业务

Qualified Lead、Demo/Workshop → Proposal、Proposal → Contract、合同额、实施成本、销售周期、续约/扩容、支持、账期。

### 平台/Marketplace

供需激活、成交率、GMV、Take Rate、绕平台率、补贴后净贡献、供需密度和复购。

## 八、P20 项目状态账本

每轮至少保留：

```text
当前阶段
当前核心决策
已经确认的事实
已经验证的假设
已经失败的假设
当前候选方案与排序
当前第一方案
最大未知
当前实验
最新经营数据
市场变化
下一步行动
```

新结果进入时：

```text
读取已有结论
→ 加入新数据
→ 哪个事实发生变化
→ 哪个假设被验证/推翻
→ 经济性怎样变化
→ 排序怎样变化
→ 继续 / 修改 / 停止 / 扩大
```

禁止默认重新从 P01 开始。

## 九、下一轮什么时候回跳

- 项目定义错 → P02；
- 阶段变化 → P03；
- 决策问题改变 → P04；
- 新市场事实 → P08-P09；
- 发现新利润池 → P11-P13；
- 新价格/成本数据 → P15；
- 新竞争/规则变化 → P16-P17；
- 候选排序变化 → P18；
- 新实验 → P19；
- 所有新结果最终回到 P20 记录。
