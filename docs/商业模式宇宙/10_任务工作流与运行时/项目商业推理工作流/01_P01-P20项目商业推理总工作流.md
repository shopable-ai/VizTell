# P01-P20 项目商业推理总工作流

> 本文件是项目商业推理工作流的**核心业务地图**。P01-P20 必须稳定保留，但它不是机械流水线；不同现实输入可以从不同阶段进入。

## 一、人工快速理解版

```text
项目是什么
→ 现在到哪一步
→ 当前真正要解决什么
→ 最值得补什么信息
→ 现在已经拥有什么
→ 谁在用、谁付钱、为什么付钱
→ 市场现在怎样
→ 别人为什么成功、为什么失败
→ 哪些商业机制值得借鉴
→ 钱在哪里
→ 上下游和相邻机会在哪里
→ 有哪几套结构不同的方案
→ 每套到底卖什么、怎么收费
→ 哪套经济性最好
→ 有什么竞争和风险
→ 哪些已经被市场验证
→ 如果只能先做一个，应该选哪个
→ 怎样最低成本验证
→ 怎样转成真实交易
→ 根据结果继续经营
```

## 三、P01-P20 统一执行定义

### P01 项目接收

**解决什么问题**：识别用户给的是已有项目、功能/资产、灵感、经营问题、真实数据、别人赚钱现象、成功/失败案例还是待迁移玩法。

**什么时候必须执行**：每次新项目或新对象首次进入时。

**什么时候可以跳过**：同一项目已经有稳定状态账本，且用户只是补充新数据或实验结果。

**输入**：用户描述、已有项目资料、数据、链接、文件、历史状态。

**输出**：输入类型、研究对象、范围、限制、用户真正想做的决策。

**常见错误**：把所有输入都当成“从零设计商业模式”；先让用户填写几十项问卷。

**下一步**：进入 P02；如果是商业现象，先进入 `08_商业现象逆向拆解工作流.md`。

### P02 生意重建

**解决什么问题**：区分表面产品和真正的经济结构。

**什么时候必须执行**：项目定义模糊、表面价格无法解释长期经营、用户只描述功能或产品名称时。

**什么时候可以跳过**：已有清晰的“谁付钱—买什么—为什么买—怎样交付—怎样获客”定义且本轮不发生变化。

**输入**：P01 对象、现有产品/交易/用户行为。

**输出**：一句话生意定义，以及 1-3 个可能的真实商业结构。

**常见错误**：把“卖 PDF”“做 AI”“做平台”当成商业定义；把合理推断写成事实。

**下一步**：P03。

### P03 阶段判断

**解决什么问题**：确认当前最重要的问题由项目阶段决定，而不是由知识库有什么决定。

**必须执行**：新项目、阶段变化、重大数据变化。

**可跳过**：同一轮已经确认阶段。

**输入**：产品完成度、用户、收入、增长、利润、组织与市场信号。

**输出**：想法/需求验证/MVP/已有产品/已有用户/已有收入/增长/利润优化/第二曲线等当前阶段。

**常见错误**：在需求未验证时先优化 LTV；已有收入项目仍只做“有没有需求”的早期研究。

**下一步**：P04。

### P04 商业问题定位

**解决什么问题**：从宽泛主题中选出当前最值得解决的 1-3 个决策问题。

**必须执行**：用户问题宽泛或同时有很多商业问题时。

**可跳过**：用户已经给出明确、可决策的问题，例如“当前 CAC 12 元而毛利 8 元，先改价格还是渠道？”

**输入**：项目阶段、当前表现、用户目标。

**输出**：本轮核心决策、非目标、成功标准。

**常见错误**：把“研究商业模式”当成决策；同时解决十几个问题导致输出无法行动。

**下一步**：P05 或针对性跳到 P06/P15。

### P05 高价值未知识别

**解决什么问题**：找到最可能改变当前推荐的信息缺口。

**必须执行**：重要结论依赖未知事实时。

**可跳过**：已有数据足够使方案优劣明显，或缺失信息不会改变决策。

**输入**：当前问题、已知事实、假设、已有数据。

**输出**：按决策价值排序的 3-7 个未知，以及补齐方式：研究、访谈、数据、实验或无需补。

**常见错误**：为了完整收集信息而阻塞推进；搜大量不会改变决策的背景资料。

**下一步**：P06，并把需要外部验证的项带入 P08。

### P06 当前经营盘点

**解决什么问题**：建立已有业务的真实起点。

**必须执行**：已有项目、已有功能、已有收入、已有资产场景。

**可跳过**：纯灵感阶段没有任何现有经营资产。

**输入**：用户、功能、商品、收入、成本、渠道、转化、退款、复购、数据、品牌、技术、供应商等。

**输出**：Current State；未商品化资产；漏钱点；明显约束。

**常见错误**：只看功能不看用户和收入；忽略渠道费、履约、退款、推理成本和现金流。

**下一步**：P07。

### P07 用户与支付分析

**解决什么问题**：分清使用者、决策者、付款者和受益者，并解释为什么会付钱。

**必须执行**：绝大多数商业决策。

**可跳过**：本轮只是已确认用户群下的局部财务优化，且付款方结构不变。

**输入**：用户群、场景、任务、替代方案、购买行为。

**输出**：用户任务、付款方、支付理由、替代方案、用户分层、可能的高价值群体。

**常见错误**：把“有人用”当成“有人愿意付钱”；只分析用户不分析真正付款者。

**下一步**：P08。

### P08 真实市场研究

**解决什么问题**：找到会改变当前商业决策的现实信息。

**必须执行**：依赖现实竞争、价格、规则、供应、用户行为的关键判断。

**可跳过**：纯内部成本优化且不依赖外部市场变化。

**输入**：P04 决策问题、P05 信息缺口、P07 用户结构。

**输出**：竞品、替代、价格、免费边界、渠道、评论、政策、供应商经济、成功/失败项目及证据。

**常见错误**：做行业百科；只看成功者；用旧价格、旧政策或营销文案代替证据。

**下一步**：P09。

### P09 成功失败机制

**解决什么问题**：判断模式为什么成立、为什么失败、成立依赖什么条件。

**必须执行**：重要候选、案例迁移、看似成熟的商业模式。

**可跳过**：很小的低风险实验可先验证，但后续扩张前必须补。

**输入**：成功案例、失败案例、用户评论、经营信号、外部证据。

**输出**：成功机制、失败机制、条件性成功、不可复制优势、反证。

**常见错误**：看到“会员成功”就复制会员；把一家公司的成功直接当作普遍规律。

**下一步**：P10。

### P10 商业知识调用

**解决什么问题**：用商业模式宇宙补充机制视角，而不是凭记忆列点子。

**必须执行**：候选不足、存在复杂定价/平台/价值链/返点/企业/AI 经济时。

**可跳过**：问题极局部且已有充分机制解释。

**输入**：项目画像、当前问题、市场证据。

**输出**：与当前项目真正相关的 Atom/Pattern/Product Role/价值链/经济机制，转译成业务语言。

**常见错误**：把召回到的对象清单直接给用户；全库加载导致噪声。

**下一步**：P11。

### P11 利润池扫描

**解决什么问题**：找到收入大不等于利润大的位置，以及隐藏/条件性收益。

**必须执行**：商业模式设计、利润低、价值链或后端机会判断。

**可跳过**：仅验证一个已定 Offer 的购买意愿。

**输入**：用户、价值链、价格、渠道、成本、供应商关系、现有商品。

**输出**：直接收入、订阅、复购、后端、企业、软件/AI、服务、Affiliate、授权/API/数据、返点/MDF/Credits、账期等利润池地图。

**常见错误**：把 GMV 当利润；把未经证实的返点算进 Base Case。

**下一步**：P12。

### P12 上下游与相邻机会

**解决什么问题**：从“这个商品怎么赚钱”扩展到“这群用户完成同一任务还会为什么付钱”。

**必须执行**：项目拥有用户/渠道/内容/数据等资产时。

**可跳过**：极早期尚未确认核心用户任务。

**输入**：用户任务、现有商品、价值链、供应商、渠道。

**输出**：上游、下游、横向机会以及前置/同步/后续需求。

**常见错误**：只看同类竞品；把完全不相关的相邻行业硬塞进来。

**下一步**：P13。

### P13 候选商业方案

**解决什么问题**：把后台 20-50 个机会收敛成 3-5 套结构真正不同的方案。

**必须执行**：需要选择商业方向时。

**可跳过**：本轮只是优化已经选定的单一方案。

**输入**：P08-P12 的证据、利润池和机会。

**输出**：3-5 套候选，至少在付款方、商品、收入来源、定价、渠道或风险承担之一有根本差异。

**常见错误**：把不同折扣当不同方案；列 20 个赚钱点让用户自己选。

**下一步**：P14。

### P14 商品与收费设计

**解决什么问题**：让每个候选变成能真正成交的商品结构。

**必须执行**：涉及商业化、Offer、套餐、订阅、按量、前后端设计。

**可跳过**：战略性价值链问题不需要具体商品化时。

**输入**：候选方案、用户任务、支付意愿、成本结构。

**输出**：入口商品、核心商品、利润商品、后端商品、免费边界、价格架构、升级路径。

**常见错误**：功能直接等于收费项；先定价格再找价值；高成本功能无限量打包。

**下一步**：P15。

### P15 经济性分析

**解决什么问题**：判断方案到底赚不赚钱、什么参数最关键。

**必须执行**：进入排序前；已有经营数据场景可直接从这里进入。

**可跳过**：只做最早期支付意愿测试时可以先做粗算，但不得在扩大前跳过。

**输入**：价格、销量/转化、CAC、COGS、渠道费、履约、退款、复购、后端、企业、返点等。

**输出**：Front-end、Basket、Cohort、Cashflow；保守/基准/乐观；Break-even；敏感变量。

**常见错误**：没有数据就停止；反过来伪造精确 LTV；把不确定收入当确定收入。

**下一步**：P16。

### P16 竞争与风险判断

**解决什么问题**：判断方案做成以后会发生什么，以及最容易在哪里死。

**必须执行**：所有重要候选。

**可跳过**：极小、可逆、低成本的探索实验可后补，但扩张前不可省。

**输入**：方案、市场、价值链、经济性。

**输出**：竞争反应、供应商反应、渠道风险、用户绕过、合规、壁垒、最脆弱假设。

**常见错误**：把当前信息差当壁垒；只写风险列表而不判断会不会改变推荐。

**下一步**：P17。

### P17 成立条件与证据评级

**解决什么问题**：把“逻辑听起来不错”与“现实已验证”分开。

**必须执行**：排序前。

**可跳过**：无。

**输入**：事实、案例、反证、经济性、关键条件。

**输出**：A-E 商业验证等级 + 成立条件 + 仍需验证的关键假设。

**常见错误**：伪精确打分；一个案例就给 A；把项目匹配与市场验证混成一个维度。

**下一步**：P18。

### P18 排序与选择

**解决什么问题**：明确现在先做什么以及为什么不做其他看似诱人的方向。

**必须执行**：存在多个候选时。

**可跳过**：本轮只有一个固定方案且只是局部优化。

**输入**：验证等级、项目匹配、利润潜力、难度、资本、获客、风险、可逆性、验证成本。

**输出**：第一推荐、第二推荐及反超条件、第三推荐、暂不推荐。

**常见错误**：所有方案都说“可以”；只按市场规模排序；用 87.4、92.6 伪装确定性。

**下一步**：P19。

### P19 最小行动与验证

**解决什么问题**：用最便宜的真实行动验证最可能改变决策的假设。

**必须执行**：第一推荐仍有关键未知时。

**可跳过**：已有充分真实交易数据，可以直接进入扩大/修改决策。

**输入**：第一推荐、最大假设、预算、可执行渠道。

**输出**：1-3 个实验/行动、关键指标、预算上限、继续/修改/停止/扩大条件。

**常见错误**：把“继续开发产品”当验证；只看点击注册不看真实支付；没有 Kill Condition。

**下一步**：真实执行后进入 P20。

### P20 持续经营与更新

**解决什么问题**：让商业推理从一次性报告变成连续经营系统。

**必须执行**：任何有后续数据、市场变化、实验结果的项目。

**可跳过**：一次性案例研究且明确不继续经营。

**输入**：上轮状态、真实结果、新证据、市场变化。

**输出**：哪些事实变化；哪个假设被验证/推翻；经济性如何变化；排序如何变化；继续/修改/停止/扩大；下一轮最大未知。

**常见错误**：每次重新从零分析；只追加新数据不改变旧结论；失败实验不进入知识反馈。

**下一步**：按变化回跳到 P04、P08、P13、P15、P18 或继续下一轮 P19。

## 四、A-E 商业验证等级

- **A**：市场反复验证 + 当前项目高度匹配。
- **B**：市场已经验证，但依赖明确条件。
- **C**：逻辑合理，但现实证据有限，只适合作为实验。
- **D**：存在大量失败信号或经济结构脆弱。
- **E**：当前条件明显不成立。

默认：A/B 优先；C 进入低成本实验；D/E 默认淘汰，除非项目拥有足以改变条件的独特优势。

## 五、重要原则

1. **P01-P20 是地图，不是流水线。**
2. **事实、推断、假设、未知必须分开。**
3. **市场研究服务于决策，不做背景百科。**
4. **后台可以广扫，前台必须收敛。**
5. **没有数据时使用公式、区间、情景、敏感性、Break-even，而不是停止。**
6. **候选必须结构不同。**
7. **排序必须明确第一推荐与暂不推荐。**
8. **工作流不能停在建议，必须进入真实交易。**
9. **P20 必须继承状态。**
10. **只有当现有体系真的无法表达真实问题时，才扩 Atom / Pattern / Schema。**
