# 项目商业推理工作流：P01-P20 业务主干

> 本文件是面向真实项目和人工阅读的**主工作流**。
>
> `02_端到端商业推理Workflow与知识生命周期.md` 负责后台运行协议；本文件负责回答普通用户真正关心的问题：**拿到一个项目以后，AI 应该怎样一步一步把它变成更好的商业决策。**
>
> P01-P20（也可简写为 P1-P20）是稳定主干，但不是要求每个项目机械从头跑到尾。不同现实输入可以从不同阶段进入，具体见 `05_真实商业项目与商业现象解析.md`。

---

# 一、人工快速理解版

整个项目商业推理工作流可以压缩成：

```text
项目是什么
→ 现在到哪一步
→ 当前真正要解决什么
→ 最值得补什么信息
→ 现在已经拥有什么
→ 谁在用、谁付钱、为什么付钱
→ 市场现在怎样
→ 别人为什么成功、为什么失败
→ 哪些成熟商业机制值得借鉴
→ 钱真正在哪里
→ 上下游和相邻机会在哪里
→ 有哪几种结构不同的方案
→ 每种方案到底卖什么、怎么收费
→ 哪种经济性最好
→ 有什么竞争、风险和成立条件
→ 哪些已经被市场验证
→ 如果只能先做一个，应该选哪个
→ 怎样最低成本验证
→ 根据真实结果继续经营和调整
```

这条链是**业务主干**。

Atom、Pattern、Router、Retriever、Schema、Benchmark 等可以在后台支持，但不能替代这条主干。

# 二、P01-P20 总表

| 阶段 | AI 要回答的业务问题 | 本阶段主要产出 |
|---|---|---|
| **P01 项目接收** | 用户现在给我的到底是什么？ | 输入类型、对象、边界 |
| **P02 生意重建** | 这东西表面是什么，实际上可能是什么生意？ | 一句话项目定义 |
| **P03 阶段判断** | 现在处于想法、验证、增长还是利润优化阶段？ | 当前商业阶段 |
| **P04 商业问题定位** | 当前最值得解决的问题究竟是什么？ | 本轮核心决策 |
| **P05 高价值未知识别** | 哪几个不知道的信息最可能改变判断？ | 关键未知排序 |
| **P06 当前经营盘点** | 现在已经有什么用户、产品、功能、收入、成本、渠道和资产？ | Current State |
| **P07 用户与支付分析** | 谁在用？谁付钱？为什么愿意付钱？ | 用户、付款方、任务、支付理由 |
| **P08 真实市场研究** | 市场上现在已经有哪些解决办法？ | 竞品、替代、价格、渠道、规则 |
| **P09 成功失败机制** | 别人为什么赚到钱？为什么有人做不下去？ | 成功条件、失败原因、反例 |
| **P10 商业知识调用** | 还有哪些成熟商业机制值得拿来思考？ | 商业模式宇宙后台调用结果 |
| **P11 利润池扫描** | 这个项目真正有哪些地方可能赚钱？ | 收入与利润机会地图 |
| **P12 上下游与相邻机会** | 当前产品之外，这群用户还会为什么付钱？ | 上游、下游、横向机会 |
| **P13 候选商业方案** | 有哪些结构真正不同的赚钱方案？ | 3-5 套候选方案 |
| **P14 商品与收费设计** | 每套方案到底卖什么、怎么卖、怎么收费？ | 商品组合、价格、Offer、前后端 |
| **P15 经济性分析** | 哪套方案实际上更赚钱？ | 毛利、CAC、LTV、Cohort、现金流、阈值 |
| **P16 竞争与风险判断** | 如果做成了会发生什么？哪里最容易死？ | 竞争、风险、壁垒、脆弱点 |
| **P17 成立条件与证据评级** | 它是真的被市场验证，还是只是理论漂亮？ | A/B/C/D/E、成立条件 |
| **P18 排序与选择** | 如果只能先做一个，应该做哪个？ | 第一推荐、第二推荐、淘汰项 |
| **P19 最小行动与验证** | 最便宜怎样知道判断对不对？ | 1-3 个行动/实验、阈值、Kill Condition |
| **P20 持续经营与更新** | 新数据出来后，项目下一轮应该怎样变？ | 保留、修改、淘汰、扩大、下一轮问题 |

# 三、P01-P06：先看清项目，而不是先找商业模式

## P01 项目接收

先识别用户给的是：

- 已有项目；
- 已有功能或资产；
- 一个灵感；
- 一个经营问题；
- 一批真实数据；
- 别人的商业现象；
- 一个成功/失败案例；
- 一个希望迁移的商业玩法。

不要把所有输入都当成“从零设计新商业模式”。

## P02 生意重建

必须尝试区分：

> **表面产品** 和 **真正的生意**。

例如：

```text
表面：卖低价电子书
可能的真正生意：
用低门槛知识商品识别某类高意向用户，
再围绕其后续任务销售更高价值的知识、软件、AI、服务或企业方案。
```

如果项目定义错了，后面商业模式会整体偏移。

## P03 阶段判断

至少区分：

```text
想法/灵感
→ 需求验证
→ MVP/原型
→ 已有产品
→ 已有用户
→ 已有收入
→ 增长
→ 利润优化
→ 第二增长曲线/平台化/生态化
```

不同阶段的关键问题不同。

## P04 商业问题定位

主题不是决策。

例如：

```text
主题：还能怎么赚钱？

真正问题可能是：
当前已经有低价入口，但后端商品和用户生命周期价值没有建立，
导致无法判断这个入口是否值得扩大。
```

每轮优先只抓住最影响当前项目的 1-3 个商业问题。

## P05 高价值未知识别

不要先向用户索取几十个字段。

只问：

> **哪个未知信息最可能让第一推荐发生变化？**

信息优先级通常是：

1. 会改变项目定义或目标用户；
2. 会改变方案正负经济性；
3. 会导致方案因版权、政策、合同、平台规则不可行；
4. 会改变市场验证判断；
5. 只增加背景知识、但不改变决策的信息。

优先处理 1-4。

## P06 当前经营盘点

已有项目至少盘点：

```text
用户
付款方
核心场景
已有功能/商品
价格
收入
成本
毛利
渠道
转化
退款
复购
后端
已有数据
已有品牌/流量/内容/技术/供应商等资产
```

已有项目的第一任务通常不是“再想一个商业模式”，而是看**现有资产怎样重新组合成更好的生意**。

# 四、P07-P12：理解市场、用户和“钱在哪里”

## P07 用户与支付分析

至少分清：

```text
谁使用
谁决策
谁付款
谁受益
用户要完成什么任务
为什么现在愿意付钱
不付钱时怎样替代
```

不要把“有使用需求”直接等同于“有支付意愿”。

## P08 真实市场研究

只要项目依赖现实市场，应主动研究与决策直接相关的：

- 当前竞品与替代方案；
- 市场常见价格；
- 免费与付费边界；
- 用户评论与真实痛点；
- 渠道；
- 平台政策；
- 供应商/基础设施价格；
- 佣金、返点、MDF、Credits 等条件性收益；
- 新进入者、转型、关闭、降价；
- 上下游公司和战略变化。

市场研究不是背景资料，而是后续方案的**证据层**。

## P09 成功失败机制

重要候选尽量同时找：

### 成功证据

- 持续收费；
- 多年运营；
- 续费/复购；
- 多家公司采用；
- 经济性或商业持续性信号。

### 失败证据

- 关闭/转型；
- 用户拒绝付费；
- CAC 过高；
- 毛利过低；
- 免费转付费失败；
- 补贴停止后崩溃；
- 用户或供应商绕平台；
- 企业销售周期过长；
- 合规/版权/平台规则不可持续。

### 条件性成功

必须回答：

```text
什么用户成立？
什么价格成立？
什么频率成立？
什么渠道成立？
什么成本成立？
什么规模成立？
什么地区/平台成立？
什么项目阶段成立？
```

## P10 商业知识调用

商业模式宇宙在这里作为后台能力，帮助避免只凭经验回答。

可以调用：

- 参与方与付款方；
- 商品角色；
- 定价；
- 渠道；
- 收入；
- 成本；
- 价值链；
- 平台；
- 条件性经济；
- Cohort；
- 企业采购；
- 数据与 AI；
- 风险与迁移；
- Atom / Pattern / Product Role / Offer 等。

但用户最终看到的是商业结论，不是知识对象清单。

## P11 利润池扫描

后台广泛扫描，前台严格筛选。

至少检查：

```text
直接销售
订阅/会员
按量/套餐/升级
Add-on / Upsell / Cross-sell
复购/耗材
软件/AI
服务/咨询/实施/培训
企业采购
授权/白标/API/数据
广告/Affiliate/分销
平台抽佣/Marketplace
供应商返点/MDF/Credits
预付/储值/Commit/容量
现金流/账期
生命周期延伸
```

真正问题不是“还能列出多少赚钱方式”，而是：

> **哪些利润池与当前用户、能力、渠道和阶段真正匹配。**

## P12 上下游与相邻机会

每个项目固定问一次：

> **这个项目获得了怎样的一群用户？这群用户为了完成同一个任务，还需要什么？**

扫描：

```text
上游：供应商、内容、数据、模型、API、采购、代理、白标、规模议价、返点

下游：后续商品、软件、AI、服务、咨询、培训、实施、企业采购、Marketplace

横向：相邻用户、相邻商品、相邻场景、相邻渠道、相邻行业
```

# 五、P13-P18：从“很多可能性”收敛成商业决策

## P13 候选商业方案

最终只保留 **3-5 套结构明显不同**的方案。

候选之间至少在一项上有根本差异：

- 谁付款；
- 卖什么；
- 真正利润池；
- 获客方式；
- 收费计量；
- 风险由谁承担；
- B2C / B2B；
- 自营 / 伙伴 / 平台；
- 一次性 / 订阅 / 按量 / 结果 / 分成。

禁止用“小改价格”伪装成不同方案。

## P14 商品与收费设计

每套候选至少讲清：

```text
前端入口是什么
核心商品是什么
利润商品是什么
后端商品是什么
谁付钱
付多少钱/按什么计量
用户怎样从前端进入后端
什么内容免费、什么收费
```

已有功能项目尤其要完成：

> **功能 → 用户价值 → 商品 → 商品组合 → 收费方式。**

## P15 经济性分析

没有真实数据也不能停止。

至少建立：

```text
收入
- COGS/采购/版权/推理/履约
- 平台/支付/渠道
- 退款/客服/支持
- 获客
= 当前贡献

再加入：
复购 + 订阅 + 后端 + Affiliate + 企业线索 + 已确认返点等
= True Cohort Contribution
```

缺数据时使用：

```text
保守 / 基准 / 乐观
+ Break-even
+ 最敏感变量
```

不要伪造精确 LTV。

## P16 竞争与风险判断

必须问：

- 竞争对手会怎样反应？
- 客户会不会绕过？
- 供应商会不会涨价或绕过？
- 渠道会不会改变规则？
- 规模扩大后单位经济会变好还是变差？
- 当前优势是壁垒还是短期红利？
- 哪个假设一旦错误，整个模式就失效？

## P17 成立条件与证据评级

默认：

```text
A：市场已经大量验证 + 当前项目高度匹配
B：市场已经验证，但依赖明确条件
C：理论合理，现实证据有限，只适合实验
D：失败信号较多或经济结构脆弱，默认不优先
E：当前条件明显不成立，淘汰
```

避免 87.3、92.6 之类伪精确评分。

## P18 排序与选择

最终必须回答：

1. **第一推荐是什么，为什么？**
2. 第二推荐在什么条件下会超过第一？
3. 第三推荐为什么值得保留但不是当前第一？
4. 哪些看起来诱人但现在不应该做？

排序综合考虑：

```text
验证程度
× 项目匹配
× 利润潜力
× 实施难度
× 资本要求
× 获客难度
× 风险
× 可逆性
× 验证成本
```

# 六、P19-P20：从商业判断走向真实经营

## P19 最小行动与验证

分析最后必须收敛到：

> **现在只做哪 1-3 件事，才能最快减少最大商业不确定性。**

每个关键验证至少明确：

```text
要验证什么判断
准备做什么
投入上限
看哪个指标
什么结果继续
什么结果修改
什么结果停止
```

详细行动层见 `06_从商业判断到实际赚钱.md`。

## P20 持续经营与更新

项目不是一次分析完成。

每轮保留最小商业状态：

```text
当前阶段
当前核心决策
已经验证的事实
已经验证的假设
已经失败的假设
当前候选方案与排序
关键未知
已经做过/正在做的实验
最新经营数据
市场变化
下一步行动
```

新数据进入后，不重新从零回答，而是明确：

```text
什么信息变了
→ 哪个假设受到影响
→ 哪套方案上升/下降/淘汰
→ 下一步做什么
```

# 七、不同现实输入不必从 P01 机械跑到 P20

P01-P20 是完整地图，不是固定流水线。

例如：

```text
只有灵感
→ 通常从 P01-P05 开始

已有产品和功能
→ 强化 P06-P07-P11-P14

已有收入但利润低
→ 快速进入 P06-P15-P16

已有一批真实数据
→ 可以直接进入 P15-P20

看到别人一个奇怪赚钱现象
→ 先做商业模式逆向拆解，再进入 P08-P18
```

具体入口与分支见：

> `05_真实商业项目与商业现象解析.md`

# 八、默认给用户看的“决策面板”

详细分析完成后，最先展示：

```text
项目一句话判断
当前最重要的商业问题
市场已经验证了什么
市场已经证明哪些方式容易失败
当前最值得赚钱的 3 个位置
第一推荐
第二推荐
暂时不要做什么
当前最大未知
下一步只做哪 1-3 件事
```

用户即使不阅读后面的详细研究，也应该知道：

> **当前项目是什么、钱在哪里、优先做什么、为什么、下一步怎么验证。**

# 九、工作流的完成标准

不是：

- 列出了很多商业模式；
- 加了更多 Atom/Pattern；
- 输出很长；
- 做了很多技术架构。

而是：

> **一个普通用户把真实项目、灵感、经营问题、数据或市场现象交给 AI 后，AI 能够主动理解项目、研究现实市场、发现利润和上下游机会、形成少量真正不同的方案、算经济账、识别风险、排序，并把结果推进成下一步实际行动。**
