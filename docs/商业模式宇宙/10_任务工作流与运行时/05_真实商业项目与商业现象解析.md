# 真实商业项目与商业现象解析

> 本文件解决第二层问题：**用户现实中会以什么方式把商业问题交给 AI，以及不同输入应该从 P01-P20 的哪里开始。**
>
> 核心不是把用户强行塞进同一个问卷，而是先判断：这是“我自己的生意”，还是“我看到别人的生意”；然后选择最有价值的分析入口。

---

# 一、两类现实入口

```text
A. 我自己的生意
├─ 已有项目
├─ 已有功能/资产
├─ 一个灵感/想法
├─ 一个具体经营问题
└─ 一批真实数据需要判断

B. 我看到别人的生意
├─ 一种奇怪的赚钱现象
├─ 一个反常价格
├─ 一家成功/失败公司
├─ 一种渠道玩法
└─ 一个想判断能否迁移的商业模式
```

这两类输入都进入同一个 P01-P20 主干，但**起点和重点不同**。

---

# 二、八类常见入口与推荐起点

| 入口 | 用户可能怎么说 | 优先进入 | AI 首先解决什么 |
|---|---|---|---|
| **A 已有项目** | “我已经有一个 AI 阅读器，但不知道怎么赚钱” | P02-P07 | 当前到底是什么生意、已有资产怎样商业化 |
| **B 已有功能/资产** | “我已经有上传、问答、总结、知识库这些功能” | P06-P07-P11-P14 | 功能如何变成商品、套餐和付费层 |
| **C 灵感/想法** | “我想到一个作者思维 AI” | P01-P05-P07 | 谁需要、为什么需要、怎样变成可收费项目 |
| **D 具体经营问题** | “每天 500 用户但利润很低” | P04-P06-P15 | 漏钱在哪里、哪个变量最影响利润 |
| **E 已有真实数据** | “9.9 元卖了 1000 单，CAC 12 元” | P15-P20 | 经济性是否成立、下一步应该扩大还是修正 |
| **F 商业现象逆向拆解** | “闲鱼电子书只卖几毛钱，他怎么赚钱？” | 逆向拆解→P08-P18 | 表面交易解释不了利润时，钱到底可能来自哪里 |
| **G 成功/失败案例拆解** | “Costco 为什么能靠会员赚钱？” | P08-P09-P16-P17 | 真正成立机制是什么、哪些是条件而非表面形式 |
| **H 商业模式迁移** | “这种玩法能不能放到我的项目？” | P09-P12-P13-P18 | 哪些机制可迁移、哪些条件不可复制 |

P01-P20 是完整地图，不要求每次机械跑满。

---

# 三、A：已有项目——先诊断，不重新从零设计

已有项目先回答：

```text
现在是什么业务？
现在已经有什么用户？
卖什么？
谁付款？
怎么获客？
收入在哪里？
成本在哪里？
复购/续费在哪里？
最明显的漏钱点在哪里？
有哪些已有资产没有被商品化？
```

重点检查五类问题：

1. **用户没有被正确分层**：所有人只卖同一个商品；
2. **功能没有商品化**：产品有价值功能，但没有形成明确付费权利；
3. **前端没有后端**：第一次成交以后没有下一步；
4. **价格没有对应价值层级**：免费、低价、Pro、企业混在一起；
5. **单位经济有结构性问题**：CAC、退款、履约、推理成本、渠道分成等吞噬利润。

已有项目的目标通常是：

> **把现有用户、功能、流量、品牌、技术、数据、供应商和渠道重新组合成更高价值的商业结构。**

---

# 四、B：已有功能/资产——从“功能列表”变成“商品结构”

很多软件项目的问题不是功能少，而是：

> **有功能，但没有清楚回答哪些功能属于哪个商品、谁为什么为它付钱。**

标准转换链：

```text
已有功能/资产
→ 解决什么任务
→ 对谁最有价值
→ 使用频率/价值强度
→ 能否独立收费
→ 适合入口、核心、利润还是后端
→ 形成商品组合
→ 再设计价格和升级路径
```

例如：

```text
上传 PDF
AI 问答
总结
知识库
```

不能直接等于四个收费功能。

可能重组为：

```text
免费层：基础阅读
个人 Pro：AI 问答 + 高级模型
知识会员：多文件知识库 + 长期记忆
专业版：项目知识库 + Workflow
团队版：协作与权限
企业版：私有知识、实施、SLA
```

具体结果必须由市场、用户与经济性决定，不能机械套模板。

---

# 五、C：灵感/想法——把一个点子展开成多个可验证的生意

灵感阶段不要马上讨论“做哪些功能”。

先完成：

```text
灵感是什么
→ 它解决什么具体问题
→ 谁最痛
→ 用户今天怎么解决
→ 当前替代方案有什么不足
→ 谁愿意付钱
→ 可以卖什么权利/结果/服务
→ 能形成哪些不同商业结构
→ 哪个最便宜验证
```

同一个灵感可能产生完全不同的项目。

例如“作者思考方式 AI”可能分化成：

- 个人订阅；
- 作者 IP 数字产品；
- 出版社白标；
- 课程附加产品；
- 专题知识库；
- 企业培训/决策工具；
- API；
- 咨询辅助工具。

AI 的任务不是把想法写得更漂亮，而是：

> **找到真正有人愿意付钱的版本。**

---

# 六、D：具体经营问题——从问题所在环节切入

如果用户已经明确说：

> “利润低”“转化低”“复购低”“获客贵”“退款高”“企业客户成交慢”

就不要从项目历史重新讲起。

先定位问题属于哪一段：

```text
获客
→ 转化
→ 客单
→ 毛利
→ 履约
→ 退款
→ 复购
→ 后端
→ 企业销售
→ 供应链
→ 返点/账期
→ 现金流
```

然后优先进入对应的 P04/P06/P15/P16/P18/P19。

目标是：

> **找到最值得修的约束，而不是给整个商业模式重新写一份介绍。**

---

# 七、E：已有数据——让数据改变方案，而不是只生成分析报告

如果已经有：

- 成交价；
- 销量；
- CAC；
- 毛利；
- 退款；
- 后端转化；
- 复购；
- 会员续费；
- 企业线索；

应直接计算关键经济性，并判断：

```text
哪个方案已经成立？
哪个只是在表面增长？
哪个用户群贡献最高？
哪个渠道应该停止？
什么价格/套餐需要调整？
CAC 上限是多少？
哪个后端最值得扩大？
```

新的真实数据如果没有导致方案排序变化，AI 必须解释为什么。

---

# 八、F：看到别人一种“奇怪赚钱现象”——先逆向拆解商业模式

这是一个独立且重要的入口。

用户可能只看到：

> “某平台上有人把一个商品卖得特别便宜，感觉根本赚不到钱。”

这时候不能立刻替用户设计项目，也不能直接假设“低价就是引流”。

应该执行：

```text
观察到的现象
→ 表面交易是什么
→ 表面收入能否解释这个生意长期存在
→ 如果不能，建立盈利假设树
→ 搜索每个假设的现实证据
→ 排除不成立假设
→ 找出最可能的完整收入结构
→ 判断可持续性、风险和条件
→ 最后才讨论能不能迁移
```

---

# 九、商业模式逆向拆解：盈利假设树

面对“看起来不赚钱”的生意，至少检查：

```text
H1 表面商品本身赚钱
│  └─ 成本极低 + 大量订单 + 自动履约
│
H2 表面商品只是入口
│  ├─ 更高价商品
│  ├─ 合集/套餐
│  ├─ 会员/订阅
│  └─ 后续复购
│
H3 真正价值是获得用户
│  ├─ 私域/社群
│  ├─ 再营销
│  ├─ 线索
│  └─ 更高价值客户识别
│
H4 后端卖相关软件/工具/服务
│  ├─ Affiliate
│  ├─ 分销
│  ├─ 自营软件
│  └─ 专业服务
│
H5 平台/渠道存在额外收益
│  ├─ 官方邀请
│  ├─ CPS
│  ├─ 渠道奖励
│  ├─ MDF/返点
│  └─ 其他已确认激励
│
H6 高价值知识/服务后端
│  ├─ 课程
│  ├─ 咨询
│  ├─ 知识库
│  ├─ 培训
│  └─ 企业实施
│
H7 店铺/流量/成交历史本身有经营价值
│  ├─ 提升交叉销售机会
│  ├─ 提升用户触达
│  └─ 提高后续商品成交概率
│
H8 供应端或运营端有特殊经济结构
│  ├─ 极低边际成本
│  ├─ 自动化
│  ├─ 规模采购
│  ├─ 返点/账期
│  └─ 库存/容量等特殊结构
│
H9 模式依赖违规、漏洞或不可持续条件
   ├─ 版权/授权问题
   ├─ 账号/许可违规
   ├─ 平台漏洞
   └─ 短期规则套利
```

H1-H9 是**待验证假设**，不是默认事实。

# 十、示例：看到闲鱼上 0.01-3 元电子书，应该怎样分析

用户的问题是：

> “这么便宜，他到底怎么赚钱？”

正确第一步不是直接回答“靠引流”。

应建立证据问题：

```text
1. 这个价格是否是真实成交价，还是展示/促销价格？
2. 一本的边际履约成本是多少？
3. 店铺还有哪些更高价商品？
4. 购买后是否存在合集、会员、持续资源等下一步？
5. 是否存在相关软件、工具、服务或分销收入？
6. 平台或交付平台是否存在官方佣金/邀请/合作收入？
7. 用户是否被引向其他合法可持续的后续交易？
8. 是否有企业、咨询、知识库等高价值后端？
9. 该模式是否依赖版权、平台规则或其他不可持续条件？
10. 低价商品的 30/90/180 天用户贡献是多少？
```

然后才判断最可能属于：

- 直接薄利规模；
- 低价入口；
- Cross-sell；
- Lead Generation；
- Affiliate/分销；
- 高价值服务后端；
- 其他真实经济结构；
- 或不可持续模式。

最终输出应该是：

> **最可能的盈利结构 + 支持证据 + 反证 + 仍未知的关键变量 + 是否值得迁移。**

# 十一、G：成功/失败案例——拆机制，不复制表面形式

看到一家成功公司，应区分：

```text
表面形式
vs
真正机制
vs
成立条件
```

例如“会员制”只是表面形式。

真正需要拆的是：

- 会员为什么愿意付费；
- 会员费是不是主要利润；
- 高频还是低频；
- 是否带来更高复购/更低 CAC；
- 是否依赖采购规模、稀缺供给或低毛利主商品；
- 现金流和续费怎样；
- 用户离开的成本是什么。

失败案例同样要拆：

> **它失败的是整个模式，还是错误用户、价格、渠道、成本或阶段？**

---

# 十二、H：商业模式迁移——最后一步才问“我能不能学”

不要这样推理：

```text
别人成功用了会员
→ 我的项目也做会员
```

应该：

```text
拆出真正机制
→ 列出成立条件
→ 判断当前项目具备哪些条件
→ 找缺失条件
→ 设计迁移后的新结构
→ 重新算经济性
→ 小规模验证
```

迁移输出至少包括：

```text
可直接迁移的机制
需要改造的机制
当前不具备的条件
不可复制的优势
迁移后的候选方案
最小验证
```

---

# 十三、默认第一屏：不同入口都要让人迅速看懂

无论从哪种入口进入，第一次回答都应该尽快让用户看到：

```text
我目前怎样理解你给的对象
它属于哪一种商业问题
现在最值得解决什么
我接下来会重点验证哪些假设
哪些信息暂时不知道但不妨碍先推进
```

然后再进入市场研究、商业知识调用和方案设计。

最终目标不是把输入分类得很漂亮，而是：

> **让用户无论拿来的是自己的项目、一个灵感、一组数据，还是现实中看到的奇怪赚钱现象，都能进入同一套商业推理主干，并得到真正可执行的商业判断。**
