# 专业建模与表征｜总览与边界

> 本目录独立保存专业领域中的建模语言、图类型、架构视图、工程表示法与标准化表征。
>
> 它与 `docs/思维与方法宇宙/` 有关联，但不是“思维与方法宇宙”的子分类。主思维宇宙只收录能够直接改变思考、分析、判断、决策、设计或学习过程的原理、模型、框架和方法；仅因为“可以帮助理解”而与思考有关的专业图、标准子图、交付物和实现表示，不进入主清单。

## 一、为什么独立

“组件图”“类图”“部署图”“时序图”等名称容易被理解为软件开发过程中的具体产物。它们的真实身份通常是：

> **某一专业建模语言、建模体系或工程活动中的具体表示类型。**

它们不是软件开发阶段本身，也通常不是与“第一性原理”“六顶思考帽”“问题树”同粒度的思维方法。

因此采用两层分工：

- `思维与方法宇宙`：回答“有哪些可主动调用的思维、分析、决策、设计和学习方法？”
- `专业建模与表征`：回答“一个专业领域用哪些模型、图、符号和视图表达系统、流程、结构、交互与约束？”

## 二、正式收录边界

### 收录

- 专业建模语言与标准，例如 UML、SysML、BPMN、ArchiMate；
- 一个建模体系下的正式图类型，例如组件图、类图、序列图；
- 软件与系统架构视图，例如 C4 系列；
- 功能、依赖和系统结构表示，例如 IDEF0、FFBD、N² 图、DSM；
- 数据、信息和系统边界表示，例如 DFD、系统上下文图；
- 未来其他专业领域中具有稳定语义和使用规则的建模表示。

### 不因为“画成图”就收录

以下仍保留在 `思维与方法宇宙`，不迁移到这里：

- 因果回路图：核心用途是系统思维与反馈推理；
- 决策树：核心用途是结构化决策；
- 故障树分析：核心用途是风险与失效推理；
- 甘特图：核心用途是计划与进度管理；
- 用户旅程图：核心用途是用户理解与体验设计；
- 思维导图、概念图：本身就是通用认知外化工具。

判断标准不是“是不是图”，而是：

> **该对象是否拥有脱离某个专业标准后仍然成立的独立认知方法价值。**

## 三、知识层级

为避免把一个标准下面几十张图误算成几十种独立“思维方法”，本目录区分：

- **M1｜建模语言 / 建模体系**：UML、SysML、BPMN、C4、ArchiMate；
- **M2｜建模目的 / 图族**：结构、行为、交互、需求、架构、流程等；
- **M3｜具体图类型 / 视图**：组件图、序列图、部署图、参数图等；
- **M4｜元素、符号与规则**：节点、关系、接口、消息、状态、约束等更低层语法。

主 `思维与方法宇宙` 不再把 M3 / M4 当作独立思维方法统计。

后续只有在知识量足够大时，再按数据建模、业务流程、企业架构、系统工程等方向拆分文件；不预先制造空目录。
