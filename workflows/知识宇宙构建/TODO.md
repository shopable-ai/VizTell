# 知识宇宙构建工作流｜待验证问题

> 本文件只记录尚未稳定的问题、验证任务和未来方向。
>
> 未经真实案例验证的内容不得仅因为“看起来合理”就提升为 `workflow.md` 正式候选规则。

## P0｜必须先解决

### 1. 最小关键环节是否正确

当前候选主链路为：

```text
目标识别
→ 范围确认
→ 内容扩展
→ 整理与分类
→ 完整性审计
→ 正式成果
```

需要验证：

- 6 个环节是否已经最小且完整；
- 是否有环节可以合并；
- 是否缺少真正不可省略的环节；
- 用户是否能够不理解 S1—S8 也完成整个任务。

### 2. 每个环节的标准输出格式

需要为每个主环节确定：

- 输入；
- 必须回答的问题；
- 必须产生的数据；
- 人工可读输出模板；
- 进入下一环的通过条件；
- 失败时的最近回退点。

特别验证统一阶段结果块是否足够：

```text
【阶段结果】
当前阶段：
核心结论：
用户已确认：
AI 默认假设：
尚未确定：
下一步：
是否需要用户输入：是 / 否
```

### 3. 人工决策节点

需要验证：

- 哪些节点真的需要用户参与；
- 是否存在不必要的打断；
- AI 给 2—4 个候选 + 推荐的格式是否好用；
- 用户只回复“A”“第二个”“范围再宽一点”“按你推荐的”等自然语言时能否正确续接。

### 4. 自动推进规则

需要确定：

- 什么情况下自动继续；
- 什么情况下说明默认假设后继续；
- 什么情况下必须等待用户；
- 用户说“继续”时，AI 应怎样判断下一步，而不是重新询问已确认内容。

### 5. 内容产出防空转规则

重点验证：

- S3 是否会真正生成具体知识，而不是继续解释研究方法；
- S5 是否会输出“一级分类 → 二级知识群 → 具体知识”，而不是只有类别名称；
- S6 是否会实际补入遗漏知识，而不是只说“可能有遗漏”；
- S8 是否会形成正式知识地图，而不是再次生成研究报告。

## P1｜真实案例验证

至少使用以下类型进行压力测试：

### A. 极少知识种子

输入只有 3—5 个模型、概念或关键词。

验证：

- 目标反推；
- G1 是否必要；
- 是否过早锁定分类。

### B. 一本书 / 大型清单

输入是一份 100—300 项左右的方法、模型或概念集合。

验证：

- 是否把来源当种子而不是知识边界；
- 是否能扩展到来源之外；
- 是否能处理大量重复与粒度混杂；
- 是否能重新发现更合理分类。

### C. 已有知识宇宙升级

输入已经具有定义、分类和大量条目。

验证：

- 是否能够直接进入覆盖审计或分类收敛；
- 是否会错误地强制从 S1 重跑；
- 局部修改是否能够只回退到最近受影响阶段。

### D. 用户中途修改目标

验证：

- 修改目标、范围或分类后怎样回退；
- 哪些已有成果还能保留；
- 哪些必须失效并重算。

### E. 跨对话恢复

验证：

- 下一轮 AI 最少需要哪些状态才能继续；
- 是否真的需要独立 Workflow State 文件；
- 哪些状态可从正式文档恢复，哪些必须额外记录。

## P2｜验证稳定后再研究

以下内容当前有价值，但不应抢在 P0 / P1 前工程化：

- Workflow Router / 统一入口路由；
- Workflow State / 长任务状态模板；
- Orchestrator / 工作流调度器；
- 独立 Skill 抽取；
- 语义去重 Skill；
- Taxonomy 发现 Skill；
- Coverage Audit Skill；
- Ontology / 正式关系模型；
- Agent Runtime；
- 数据库、Schema、ID、图谱等机器化结构。

## P3｜未来 Skill 化的准入条件

一个阶段能力只有满足下面条件后，才考虑提取为 Skill：

1. 已在多个不同知识领域重复使用；
2. 输入与输出边界稳定；
3. 不依赖某个具体知识宇宙；
4. 失败模式已经比较明确；
5. 可以独立测试；
6. 从 Workflow 抽离后仍然有通用价值。
