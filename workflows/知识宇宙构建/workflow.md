# 知识宇宙构建工作流 V1（候选）

> 状态：**候选工作流 / 待真实案例验证**。
>
> 当前已经确定的是基本研究方向、S1—S8 详细链路和人工决策门；尚未确认的是最小主链路、各环节统一输出契约、跨轮状态传递和未来 Skill 化方式。在完成多类真实案例验证前，不将本目录视为稳定 Skill 规范。

## 1. 工作流定义

本工作流负责把模糊、零碎、局部的知识输入，推进为可长期维护的知识宇宙。

它不是“输入一次提示词后全自动跑到底”的流水线，而是一个带人工决策门的交互式研究工作流：

> AI 自动研究 + 关键决策点人工确认 + 必要时回退重做。

书籍、文章、模型清单、几个术语都只可以作为“知识种子”，不能自动等同于最终知识边界。

## 2. 用户可理解的候选主链路

为了避免用户必须理解 S1—S8，当前先把详细流程压缩成 6 个用户可理解的关键环节。**这 6 环仍是待验证候选，不是最终定论。**

```text
零碎输入
→ ① 目标识别
→ ② 范围确认
→ ③ 内容扩展
→ ④ 整理与分类
→ ⑤ 完整性审计
→ ⑥ 正式成果
```

与当前详细阶段的映射：

| 用户主环节 | 主要回答的问题 | 当前详细阶段 |
|---|---|---|
| ① 目标识别 | 我真正想构建的是什么知识空间？ | S1 |
| ② 范围确认 | 哪些内容应该纳入，做到多宽？ | S2 |
| ③ 内容扩展 | 这个知识空间实际有哪些具体内容？ | S3 |
| ④ 整理与分类 | 哪些重复、怎样规范、最合理怎样分类？ | S4 + S5 |
| ⑤ 完整性审计 | 是否漏掉整片知识群，分类是否稳定？ | S6 + S7 |
| ⑥ 正式成果 | 怎样转成用户可快速浏览的正式知识地图？ | S8 |

原则：用户可以只按这 6 个环节理解任务；S1—S8 是内部详细研究步骤。

## 3. 详细推进逻辑

```text
种子输入
→ S1 需求反推与目标识别
→ G1 目标确认门（必要时）
→ S2 知识对象与边界定义
→ G2 范围确认门（必要时）
→ S3 系统知识发现
→ S4 规范化与语义去重
→ S5 分类体系发现
→ G3 分类确认门（必要时）
→ S6 覆盖审计与查漏补缺
→ S7 分类收敛与质量验证
→ G4 正式化确认门（必要时）
→ S8 正式知识地图生成
```

## 4. 默认输入

用户可能只提供其中一种：

- 几个零散概念；
- 一本书；
- 一本书中的部分目录或条目；
- 一组来源不同的模型 / 方法；
- 一个已有分类或知识库；
- 一个模糊目标，例如“我想把这类知识整理完整”。

工作流不能要求用户一开始就知道准确术语、完整边界、最终分类或内部阶段编号。

## 5. 人工决策门规则

### G1 目标确认门

当 AI 对用户真正想构建的知识空间存在多个显著不同解释，并且不同解释会改变后续搜索范围时触发。

应输出：

- 2—4 个候选目标；
- 每个候选的范围与区别；
- AI 推荐项；
- 用户可直接回复“A / 第二个 / 按你推荐的 / B 但范围再宽一点”等自然语言。

如果目标已经清楚，则自动通过，不额外询问。

### G2 范围确认门

当狭义 / 中等 / 广义等不同收录边界会显著改变知识规模时触发。

AI 应先给出候选范围和推荐范围，而不是只抛开放问题给用户。

### G3 分类确认门

当存在多套都合理但用途明显不同的主分类方案时触发。

AI 应给出：

- 分类方案；
- 每种方案的优缺点；
- 推荐主分类；
- 哪些其他分类更适合作为辅助导航。

一旦用户确认主分类，再进行大规模正式归类。

### G4 正式化确认门

仅研究或讨论时不需要触发。

当任务涉及覆盖、替换或正式写入 `docs/` 中的事实源时触发；如果用户已经明确要求直接写入，则不重复确认。

## 6. 歧义处理等级

### 低歧义

AI 直接继续，不询问用户。

### 中歧义

AI 写明默认假设并继续；只有后续出现实质冲突时回退。

### 高歧义

AI 给出 2—4 个候选解释，请用户选择或修正。

判断标准不是“AI 是否有一点不确定”，而是：

> 这个不确定性是否会导致后续大量知识发现、分类或正式写入工作失效？

## 7. 阶段契约

| 阶段 | 主要输入 | 必须产出 | 是否允许人工门 |
|---|---|---|---|
| S1 需求反推 | 种子信息 | 目标定义、需求、候选知识空间 | G1 |
| S2 边界定义 | S1 | 纳入 / 排除规则、知识对象类型 | G2 |
| S3 系统发现 | S1 + S2 | 大规模具体知识内容 | 否 |
| S4 规范去重 | S3 | 规范化独立知识清单 | 否 |
| S5 分类发现 | S4 | 一级分类、二级知识群、具体归属 | G3 |
| S6 覆盖审计 | S5 | 遗漏知识群、新增知识 | 否 |
| S7 分类收敛 | S5 + S6 | 稳定正式分类与清单 | 必要时回到 G3 |
| S8 正式输出 | S7 | 总览、分类地图、完整清单 | G4 |

## 8. 候选统一阶段结果块

为了避免下一轮重新猜前文，当前建议所有关键阶段在末尾保留一个最小结果块。该格式仍需通过真实案例验证：

```text
【阶段结果】
当前阶段：
核心结论：
用户已确认：
AI 默认假设：
尚未确定：
下一步：
是否需要用户输入：是 / 否
```

这个结果块用于传递“已经确定了什么”，不是数据库 Schema，也不替代阶段正文中的具体知识数据。

## 9. 回退规则

工作流不是单向链。

- 回退到 S1：最初理解的目标知识空间明显错误。
- 回退到 S2：大量新知识反复落在边界之外，说明收录标准过窄或不清楚。
- 回退到 S3：出现整片知识群没有进入数据集，而不是只漏几个条目。
- 回退到 S4：分类问题实际来自名称混乱、粒度不一致或重复条目。
- 回退到 S5：大量条目无法稳定归类、一级类高度重叠或分类轴混杂。

用户只修改某一个局部决策时，应优先回到受影响的最近阶段，不要无理由从 S1 全部重跑。

## 10. 停止条件

V1 不以固定条目数量作为完成标准。至少满足：

- 目标和边界稳定；
- 一级分类具有可解释的一致逻辑；
- 主要分类都有真实具体知识；
- 大规模新增搜索主要落入已有分类；
- 新一轮搜索的新增知识群明显减少；
- 没有持续出现无法归类的大片知识；
- 明显重复已经清理；
- 用户能够从总览快速判断整个知识空间。

这些条件仍需在真实案例中验证其可执行性。

## 11. 数据优先级

优先级从高到低：

1. 具体知识内容；
2. 分类结构；
3. 去重与规范名称；
4. 覆盖缺口；
5. 简短解释；
6. 数据工程结构。

不得因为设计 ID、Schema、交叉索引、本体关系或数据库而挤占具体知识内容。

## 12. 默认正式输出形态

### 总览文件

- 总体定义；
- 主分类总表；
- 一级分类说明；
- 代表知识；
- 条目统计；
- 压缩版全景清单。

### 完整分类文件

```text
一级分类
→ 二级知识群
→ 具体知识
```

## 13. 与 Taxonomy / Ontology / Knowledge Mapping 的关系

- **Taxonomy（分类体系）**：主要是 S5—S7 的分类成果。
- **Knowledge Mapping（知识地图）**：贯穿 S3—S8，对知识空间进行铺开、定位与覆盖检查。
- **Ontology（本体 / 语义关系模型）**：分类稳定后的后续增强能力，不强制进入当前工作流。

## 14. 当前成熟度与升级纪律

当前阶段目标不是立即制作 `SKILL.md`，而是先验证：

1. 6 个用户主环节是否真的是最小完整链；
2. 每个环节的输出格式是否足以支撑下一步；
3. 人工决策门是否只在真正需要时触发；
4. 用户简短反馈能否稳定续接；
5. 三类以上真实场景能否跑通。

未完成上述验证前：

- 不创建正式 Skill；
- 不开发 Agent Runtime；
- 不把 Ontology 工程设为必经步骤；
- 不将 Draft 中的候选规则自动提升为正式规则。

待验证问题统一记录到 `TODO.md`，研究中的候选提示词和方案保存到 `drafts/`。
